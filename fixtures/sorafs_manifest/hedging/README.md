# SoraFS Hedging And Billing Fixtures

This directory is reserved for deterministic SFM-5 hedging and billing
fixtures generated from `sorafs_manifest`.

`fixture_manifest.json` is the checked-in inventory that the generated fixture
byte suite must satisfy. It records each expected `.to`/`.json` pair, the
`sorafs-validate hedging` command that should be used, and whether the payload
is expected to be accepted or rejected.

The generator covers:

- `price_feed_primary_v1.to` / `.json` for `HedgingPriceFeedV1`.
- `price_feed_secondary_v1.to` / `.json` for a degraded
  `HedgingPriceFeedV1`.
- `reference_price_decision_v1.to` / `.json` for
  `HedgingReferencePriceDecisionV1`.
- `billing_line_storage_v1.to` / `.json` for a storage debit
  `BillingLineItemV1`.
- `billing_line_egress_v1.to` / `.json` for an egress debit
  `BillingLineItemV1`.
- `billing_line_incentive_credit_v1.to` / `.json` for an incentive credit
  `BillingLineItemV1`.
- `billing_statement_v1.to` / `.json` for a weekly provider
  `BillingStatementV1`.
- `negative/stale_reference_price_decision_v1.*` for a decision rejected by
  feed age policy.
- `negative/line_usd_mismatch_statement_v1.*` for a statement whose line USD
  replay does not match the reference price.
- `negative/tampered_totals_statement_v1.*` for a statement whose totals do not
  match line replay.

Regenerate after hedging or billing schema changes:

```sh
cargo run -p sorafs_manifest --bin generate_hedging_fixtures
```

Validate the checked-in manifest structure before generated bytes exist:

```sh
python3 scripts/check_sorafs_hedging_fixture_manifest.py --manifest-only
```

Manifest-only validation also checks that accepted fixtures do not live under
`negative/`, rejected fixtures do live under `negative/`, and each rejected
fixture uses its reviewed `negative_case` label.

Validate the generated byte suite after regeneration:

```sh
python3 scripts/check_sorafs_hedging_fixture_manifest.py
```

If `sorafs-validate` is not on `PATH`, point the checker at the built binary:

```sh
python3 scripts/check_sorafs_hedging_fixture_manifest.py \
  --validator-bin target/debug/sorafs-validate
```

Full validation requires each generated `.to` file to match its JSON
`norito_bytes_hex` field, requires each JSON sidecar to carry the expected
kind-specific top-level and nested fields, checks V1 versioning, duplicate
nested ids, account-id hex binding, and statement timestamp ordering, and
requires even-length lowercase hex payload mirrors, positive prices,
timestamps, canonical unsigned `u128` billing amount/quantity strings, and
bounded basis-point fields before the pinned `sorafs-validate hedging` command
produces the manifest's expected accepted or rejected outcome. It also rejects
extra generated `.to` or `.json` files under this directory that are not pinned
by `fixture_manifest.json`.

Validate the positive payloads:

```sh
sorafs-validate hedging --feed fixtures/sorafs_manifest/hedging/price_feed_primary_v1.to
sorafs-validate hedging --feed fixtures/sorafs_manifest/hedging/price_feed_secondary_v1.to
sorafs-validate hedging --decision fixtures/sorafs_manifest/hedging/reference_price_decision_v1.to
sorafs-validate hedging --line fixtures/sorafs_manifest/hedging/billing_line_storage_v1.to
sorafs-validate hedging --line fixtures/sorafs_manifest/hedging/billing_line_egress_v1.to
sorafs-validate hedging --line fixtures/sorafs_manifest/hedging/billing_line_incentive_credit_v1.to
sorafs-validate hedging --statement fixtures/sorafs_manifest/hedging/billing_statement_v1.to
```

The generated `.to` and `.json` fixture files are checked in with this
manifest. Regenerate them after hedging or billing schema changes, then run the
full manifest checker before updating this directory.
