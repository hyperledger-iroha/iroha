# Native outbox release and recovery

This first-release ABI25 source uses coordinator frame schema2. Method10 grants only an exact durable device command; monetary capacity remains held until method3 authenticates the original signed operation12 result and the native checkpoint publication finishes. C/JNI cannot install a signer, finality owner, policy, clock, checkpoint or storage destination.

Payment request is `[terminalID32, kind0:u32LE, originalPaymentRequest, originalEnvelope, tag0:u32LE||originalACK, qualification5]`. Redemption request is `[terminalID32, kind1:u32LE, amount:u128LE, bareV1AccountId, originalEnvelope, tag1:u32LE||canonicalCompactReceipt, qualification5]`. The native frame bounds apply before dispatch. Account bytes must equal the actual indexed native beneficiary's maintained bareV1 encoding. The response is exactly `[nativeOperationID32, originalPreparationArchive, envelopeDigest32, originalEnvelope, originalCoreP256Authorization]` for both kinds.

The exact actual installed native record selects the operation. Payment admits the full original receiver ACK against the stored request/envelope. Redemption additionally requires the once-installed immutable Rust-only `KagemushaNativeRedemptionFinalitySourceV1`: original bounded full operation status, threshold-signed bootstrap package, independently held authority policy/scope/replay floor, and current trusted native time. The actual Core matches the policy to its opaque authenticated release and verifies full finality/checkpoint/receipt membership against the actual installed voucher. A compact receipt supplied by the application must equal the native result of that verification; it supplies no finality authority. The native clock is checked before and after private signing. A backwards time value cannot renew a selection.

The concrete retained signer matches the actual native P256 key reference and independently verifies the returned low-S signature. The full original finality/policy/freshness evidence and complete signed operation12 command are fsynced in the original `outbox-release.norito.wal` before the authorization response can be exposed. Original physical one-use nonce, intent path and publication path/checkpoint ID come from retained Rust-only sources. No new nonce, signature or destination is generated for an uncertain request.

Method3 receives the original canonical operation12 reply plus its original authenticator and original command, under the current account/device lease. Canonical lifecycle framing is deterministic from those exact original fields. The concrete Core independently verifies the full signed `IKGMJRS1` success, original Core signature, selected device credential and native record/context. The complete original response and publication destination are fixed before mutation. An uncertain completion retains the same exclusive capability/publication; another command and a usable predecessor are unavailable. A completed original cannot produce another dispatch command or current-recovery token.

Restart intake consumes only `KagemushaAuthenticatedOutboxReleaseV1` recovered by the concrete native owner/journals. Command-only recovery verifies/reuses its exact original command and permits the same device retry. If completion was fsynced before publication, the recovered coordinator retains a deferred Original → Publication → Published(actualCore) handoff. `Open` finishes that exact publication before constructing an observer or account/device challenge. An unavailable hardware publication retains the same pending owner. A signer/catalog refusal after a successful hardware CAS retains the actual returned successor through `new_or_retain`; no public snapshot reconstructs it. The independently selected destination must equal the original completion path and checkpoint ID. Already-selected successor recovery remains the Core's separate exact-original checkpoint recovery path.

`KagemushaNativeEnrollmentProvisioningV1::from_recovered_outbox_release` and `KagemushaAuthenticatedRecoveredCoordinatorV1::from_native_pending_outbox_release` provide this concrete composition. They accept no application-selected owner or backend callback. The generic installed provisioner and mobile path-only installer remain the sole platform intake. Ordinary KeyMint/AppAttest keys cannot substitute a qualified secure-element credential, private Core signer, nonforking native journal, hardware CAS or independently trusted finality owner.

Method18 reads the same admitted release/catalog under twice-checked current native recovery custody and the authenticated session. It returns only `[releaseID32, hardwarePolicyDigest32, providerPolicyRoot32]`, including an unfinished exclusive native operation. This read permits no observation renewal, proof, release or monetary owner; completed publication must first advance to its actual returned owner. The provider policy root remains distinct from the aggregate manifest hardware policy digest.
