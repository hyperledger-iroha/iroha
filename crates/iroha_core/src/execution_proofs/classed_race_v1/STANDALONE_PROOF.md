# Standalone Touring S1 proof

This module proves Touring's complete staged arithmetic with the existing native Goldilocks/Fp4, Poseidon2, DEEP-ALI and FRI driver. It is not registered with the generic execution registry and cannot authorize a ledger settlement. It has no cryptographic or resource qualification claim.

`prove_classed_race_v1` accepts public worker inputs and uses the reference simulation to construct the claimed final state. It builds every staged witness row, produces the native STARK, and self-verifies. `verify_classed_race_proof_v1` requires a separate expected `ExecutionPublicInputsV1`, compares it exactly with the envelope, reconstructs canonical public fixed columns, and verifies the complete AIR proof. Verification never calls the driving reference. Ranking is a bounded deterministic projection of the proof-constrained final state; an arbitrary claimed order or winner set is rejected.

The source-bound profile identity includes the application model, admission, rules, reference, both arithmetic graphs, integer helpers, proof adapter, cryptographic driver, field implementation and Poseidon implementations/constants. It excludes dedicated test files, exports and the parent registry; whole committed source files retain any inline test content. Stock source/profile identities remain separate. Changes to committed source produce a different standalone identity; there is no obsolete-profile dispatch.

The distinct wire is `CLS1`, version 1, with separate Touring commitment and Fiat–Shamir domains. The fixed candidate geometry is 136 queries, one security lane, blowup log2 3, four composition chunks, terminal log2 10 and terminal degree bound 143. Trace log2 ranges from 13 to 19. Touring uses at most 409 arithmetic columns plus the driver's eight copy columns and 118 auxiliary columns. The native cryptographic wire is capped at 3,500,000 bytes and the complete generic envelope at 4,194,304 bytes. These parameters and codec bounds do not establish 128-bit soundness; independent analysis and maximum-duration proof qualification remain required.

The Fiat–Shamir public digest directly includes the exact expected statement, manifest, admission body, replay, canonical grid, final state, optional checkpoint and complete terminal result. The manifest commits the versioned class, track, rules and NFT catalog. The admission commitment binds every original wallet, Ed25519 input key, cosmetic selection, wager and returnable NFT resource, including its full metadata hash, role and original slot. Inputs use the canonical generic `GameTranscriptV1` and network-domain `input-transcript` commitment, including the exact empty genesis emitted by `StartGameSessionV1`. Session/class/track binding comes from the full public statement, manifest and proof digest. Opaque states use the generic `simulation-state` commitment over canonical classed bytes. The computation-only verifier includes the statement's dispute root without interpreting its history.

Every entrant must supply exactly one distinct kit resource under the same immutable role:

```text
Hash::new(b"sora-cars:equipment-role:v1\0TouringS1\0one-kit-return-to-original-owner")
```

The only accepted resource policy returns it to its original owner at a valid terminal transition. Missing, extra, duplicated, overlapping or differently scoped resources are rejected. Participant data has an exact version, class and cosmetic slot; it cannot set multipliers or override the role. The catalog commitment is a public manifest value authenticated by the expected statement, never arbitrary verifier code.

This admission checks a proof instance's shape and commitments. It does not prove current NFT ownership, the catalog issuer's eligibility rules, resource custody or finalized ledger inclusion. The separate `verify_classed_race_proof_for_session_v1` bridge derives the public statement from an authenticated retained `GameSessionRecordV1`, compares the exact immutable admission, recomputes its generic dispute commitment, verifies retained checkpoint signatures (with the native exact unsigned-genesis exception), and checks checkpoint presence/state/prefix/terminal status, every retained anchor, every forced control, original epochs and the complete removal mapping. It rejects later removals or later batches being silently dropped to claim an earlier result. One forced removal at the terminal boundary may terminate before its following control batch executes. The bridge still requires independently authenticated consensus state; it does not authenticate a caller-supplied record's ledger inclusion. Future consensus admission must authenticate NFT and custody facts before invoking this bridge. A worker's own statement is not a trust context. No kit purchase or live staked Touring session should be enabled from standalone verification alone.

Both verifier and prover reject malformed/canonical encodings, invalid dimensions, nonterminal prefixes, controls outside six bits, nonconsecutive ticks, noncanonical removals, removals outside six-tick boundaries, post-removal controls, impossible state bounds and incorrect terminal outcomes. Intermediate checkpoints must also use six-tick boundaries. The AIR independently constrains all initial, carried, terminal, inactive and padding state, preserving the producer/FINISH range schedule described in `RANGE_SCHEDULE.md`.

The focused test suite includes all-track/roster/log wire bounds, a coherent false final-state claim that passes public hashes but violates the real arithmetic boundary, real native six-tick proofs on three tracks, refunds and technical wins, and cryptographic rejection after consistently recommitting changed equipment, catalog, keys, controls, state, checkpoint, network, session or dispute history. Every whole-tick, staged and reference state matches across three full eight-car, 5,400-tick replays and padding; separate full traces have zero arithmetic residues.

The isolated native candidate `079cd3c2136a0fc41f58a494a8bf2183a1acc1cd32368033b1f844246e839961` also produced an eight-car Harbor timeout proof over 524,288 rows. Its native wire is 2,946,432 bytes and its complete envelope is 3,160,592 bytes. On an Apple M4 Max with four Rayon threads, proving and self-verification took 1,113.08 seconds with 27.2 GiB peak resident memory. Verification against retained history took 7.96 seconds in the proving process; a separate non-test-library executable reloaded the canonical proof, request and session files and verified them in 2.41 seconds with about 595 MiB peak resident memory. These timings were collected on a shared development host and are not controlled validator performance qualification. The saved-artifact verifier calls no driving reference.

The public module exports are installed, while normal Cargo/Core composition, CPU/accelerator parity, authenticated ledger inclusion, catalog/custody qualification, four-validator integration and cryptographic security review remain separate gates. The retained session fixtures are typed development records, not finalized inclusion evidence. The complete provenance and benchmark records are in `sora-cars/output/qualification/classed-stark-v1/report.json`; earlier candidate proof identities are explicitly superseded.
