# Execution STARK commitment owner

Every stock RaceV1 and standalone TouringS1 STARK Merkle commitment and Fiat–Shamir frame calls `fastpq_isi::hash_bytes_384_v1`. Incremental final-field hashing uses that owner's `GoldilocksDigest384LastFieldStreamV1`. The canonical implementation is [`poseidon_digest384.rs`](../../../fastpq_isi/src/poseidon_digest384.rs), with six independently generated width-three Goldilocks Poseidon-x7 lanes and six canonical field words encoded in 48 bytes. There is one construction and no hash selector.

The exact generator, seed, IVs, round constants, MDS and framing are owned by `fastpq_isi`; no execution-local permutation or parameter table exists. The pinned parameter SHA3-256 metadata identity is `84c5055b47cc7289835e0a5f31d4563849244ffddbf51f5d67b1db95222ce3e6`. The independent Python reference under `scripts/fastpq/reference_digest384.py` reproduces that identity and framed digest vectors using standard-library SHAKE256 and integer arithmetic.

The execution catalog is SHA-384 of the fixed UTF-8 label `iroha:execution:catalog:v1:goldilocks-poseidon-x7-six-lane`. This catalog identity is metadata, never a Merkle or transcript oracle. Every native frame separately binds that catalog, `native-execution-v1`, the stock or Touring profile label, role, phase, level, index, counter and ordered length-delimited fields. The execution context has no privacy selector or alternate catalog, label or byte ceiling.

The stock and Touring source inventories bind the shared primitive implementation and parameter asset. Their source-bound identities change with this first-release correction; stale profile identities and proof frames have no dispatch path. Old Poseidon2 permutation, framing and proof measurements do not qualify the current construction. Public gameplay and ledger `Hash` commitments keep their specified semantics and need separate whole-settlement composition review.
