# Ordinary carrier membership source admission — 2026-09-23

Status: bounded implementation on the existing `optimizations` checkout; release gate F02 remains open.

The signed ordinary validation path previously built up to two replay identities per external entrypoint in uncharged `Vec`s at both `ValidBlock::finalize_owned_execution_metadata` and `StateBlock::prepare_deterministic_carrier_metadata`, after block-start and transaction effects. The same source then entered the finite transaction-history tip. Those late allocations could fail outside the original Kura membership budget and could not safely turn into a consensus-invalid carrier.

The current source path reserves a fixed `ChargedBuffer<HashOf<TransactionEntrypoint>>` for exactly `2 × external_entrypoint_count` from the original `Kura::transaction_history_budget()` before acquiring the executing State block. It fills the outer identities and only authenticated sealed-reveal aliases against that block's pre-State, then retains the charge in the original `StateBlockFields` owner. All three ordinary `state_block_for_execution` branches and soft-fork replacement use this source path before their pristine control stages. Both the output seal and later metadata tail check the exact signed source and stage its funded slice directly; repeat staging preserves the original signed ordering and reuses the charged tip. Missing funding for a nonempty external source returns local `MembershipAdmissionError::SourceNotFunded`. Finite-pool, checked-size, and allocator refusals use the typed local membership-admission path, leaving the caller's signed carrier available for retry.

The `ordinary_signed_carrier_` selector passed 2/2: actual `state_block_for_execution` capacity refusal and retry of the same signed carrier, funded first/repeated tip staging, and the exact source-plus-block-owner budget boundary. The authenticated sealed-reveal two-alias boundary, checked count overflow, and injected allocator refusal controls each passed their separate focused selector, 1/1 each, on the same fresh binary.

This does not close F02. `State::block_with_pristine_stage` and other producer/scratch constructors do not yet receive a nonempty signed source; the metadata tail now refuses one locally rather than creating a late unfunded vector. Native and certified-merge source inventories, merge/alias hash scratch, the earlier `prepare_pristine_consensus_effects` and DA hydration work, snapshots, output/publication overlap, and aggregate ownership still need concrete admission. The source buffer covers its fixed hash backing only; computing and authenticating aliases may require separate bounded scratch. No release qualification is claimed.
