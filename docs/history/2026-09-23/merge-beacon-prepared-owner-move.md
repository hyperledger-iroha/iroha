# Certified-merge beacon prepared-owner move — 2026-09-23

Status: bounded F02 ownership improvement on the existing `optimizations` checkout; focused Core test passed. No release gate closes here.

`ValidBlock::state_block_for_execution` prepares the parent-validated NPoS effects, evidence-prune keys and validator roster before acquiring the executing State owner. For a certified merge with a beacon pulse, it formerly cloned all three into `VerifiedMergeBeaconPulse`, allocating a second effects tree and two extra vector backings while the original prepared owner remained unused. The branch now consumes that original `PreparedPristineConsensusEffects` with `Option::take()` and moves its effects, prune list and roster through `block/merge_beacon_owner.rs` into the capability. The pristine stage still receives the same header, network, parent-surface and validated contents; the non-merge path still consumes its prepared effects through `apply`.

The focused `merge_beacon_takes_original_prepared_npos_allocations` test retains nonempty effects, prune and roster backings and checks pointer identity after capability conversion, so a clone or reallocation cannot satisfy it. `CARGO_BUILD_JOBS=1 cargo test --offline --locked -p iroha_core --lib merge_beacon_takes_original_prepared_npos_allocations -- --nocapture` passed 1/1 on the combined source. This does not fund the first `prepare_pristine_consensus_effects` allocation: its evidence snapshot, prune derivation, nested effects and roster remain resource-admission obligations. QueuePlan certificate copies, merge-source inventory and aggregate ownership also keep F02 open.
