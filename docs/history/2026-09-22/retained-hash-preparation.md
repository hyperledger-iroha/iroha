# Retained hash preparation custody

Retained carrier hash preparation now has a caller-owned slot installed before
advisory predecessor observation, admission or native writer preparation. The
actual reader release event remains owned through refusal, success and unwind.
`FencedHashPreparation` releases the hash writer and every original State, Queue
and Kura fence before payload cleanup or notification delivery.

The same slot kernel serves the standalone test adapter. Production uses the
retained owner directly. Foreign-family and reader-Busy checks still precede
admission; admission still precedes writer acquisition. Normal refusal recovers
the exact journal. An unwound or released slot cannot mint retry authority. A
successful handoff carries its original preflight notification in the prepared
hash owner through publication or abort.

## Remaining production boundary

Later membership, runtime and World preparations still consume owners in a
callee. A later callee can unwind while earlier sibling writers remain held.
The next change must install every original partial acquisition in one caller
aggregate before preparation, then release all physical owners before any
callback. It must preserve original admitted World shell storage and the scoped
Prepaid allocation policy, without another field inventory or publication path.

Complete execution/resource admission and the retained production
Validate-to-Apply cutover remain open, as do unchanged four-/seven-validator
loss, restart and final-transaction qualification. All L1–L6 remain open.
