# Interrupted Native publication and completed-pair maintenance

The generation159 candidate extends the
[completed-repair correction](native-repair-partial-write.md)
to actual initial `CanonicalWrite` publication. Initial publication can crash
with an empty or partial manifest, receipt or latest-pointer temporary after
its original pending index and canonical carrier are durable. Strict inventory
previously rejected those files before their existing owner could recover them.

## Shared recovery and distinct authority

Strict startup and live retry use the same indexed-publication kernel. The
original index, selected executed carrier bytes, exact merge association,
verified finality and journal-bound physical route independently reconstruct
the expected artifacts. Completed repair additionally requires its finalized
WSV join and retained original receipt/latest. A canonical owner with no
artifact temporary can still restart before finality; existence of an index
alone does not imply that the evidence writer ran.

Only a strict proper prefix, including the actual zero-byte exclusive-create
cut, can enter incomplete-write cleanup. Manifest and receipt targets must
still lack their stable file. Latest recovery requires both exact stable
artifacts; it may retain a valid previous latest pointer. Bounds include the
physical prefix, ordinary inventory remains strict, and every selected route
passes before any unlink. Recovery retains each original no-follow descriptor,
checks the original object and namespace again, removes that object and syncs
its parent directory. Complete temporaries retain the existing authenticated
promotion path. Invalid or unowned residues remain errors.

There is one unfinished publication owner per route. Admission rejects a new
carrier until durable completion retires the preceding index and reservation.
Recovery does not infer a newer owner from partial bytes or bypass that rule.
The regression follows actual refusal, completion, successor admission and an
interrupted latest replacement while the preceding latest remains stable.

## Completed-pair maintenance

Once durable completion retires the publication index, rebuilding a derived
latest pointer is maintenance of the completed pair. Strict startup may recover
an empty or partial latest temporary only after authenticating the highest
stable manifest and receipt, canonical carrier, available finality, complete WSV
join and journal-bound physical target. That authority cannot publish a missing
manifest or receipt, and live indexed callers do not gain it. The collector adds
these retained files to the same authenticate-all-before-unlink pass used by
indexed recovery. Missing authority or an invalid later route leaves all files
unchanged.

## Physical allocation versus application completion

Startup can reconstruct latest pointers from authenticated stable pairs before
WSV application. Exact durable readback now consumes only the original matching
component allocations at that point. It does not retire the original pending
publication index, create WSV metadata or authorize retention cleanup. Those
remain under their existing application-completion checks. Repeated recovery
cannot reserve the same physical file again. Existing maintenance allocations
are distinguished by their original absent index; consuming them requires
independent completed-pair authority. An indexed owner still requires its exact
original index, without synthesizing an owner after the fact.
