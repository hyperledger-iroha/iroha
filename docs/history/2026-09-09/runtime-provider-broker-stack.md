# Broker dispatcher stack ownership (2026-09-09)

The debug broker dispatcher previously reserved 1,993,696 bytes before selecting
an operation. Unrelated branches shared one function frame, nearly exhausting a
normal 2 MiB worker before its selected validator ran. The correction gives 126
operation bodies separate functions in 16 capability modules and preserves all
128 routing patterns, guards and their order. Initial binding qualification,
post-operation qualification, canonical validation, errors and scrubbing remain.
The 4 MiB server worker override, enlarged test dispatcher thread and 8 MiB
privacy-reader fixture thread are removed; every fixture assertion is retained.

The rebuilt ARM64 macOS debug artifact reserves 12,608 bytes for the router and
at most 50,816 bytes for an operation handler. The privacy fixture is unchanged
at 84,752 bytes. These are disassembled static frames, not whole-call peak-memory
measurements or measurements for other targets. All 203 broker tests pass on
ordinary stacks when run sequentially. The five independently selected cases
also pass: maximum 31-member beacon and TLE signing, canonical bounded privacy
readback, compact cumulative admission and fenced publication accounting. Those
five overlap the 203 cases. Every run retains the same source fingerprint
`c2ae8345fa5cf9cd56daaa6433b2dba5419eb051513a70363fb87d82f13558f7`.

The four-worker run passes 198 cases and fails five on shared process decode-pool
contention, with no stack overflow. Those independent in-process fixtures shared one production admission pool;
the process-ownership correction and its qualification are recorded below.
Neither serial success nor a larger pool qualifies concurrent production behavior.
The production memory ceiling remains unchanged.
Earlier broker records with `stack_override: false` mean only that `RUST_MIN_STACK`
was unset: those artifacts still contained internal 4/8 MiB overrides and do not
establish ordinary-stack server qualification.
