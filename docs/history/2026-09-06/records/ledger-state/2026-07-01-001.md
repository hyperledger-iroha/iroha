- Public-lane staking ISIs now re-check lane activity at the transaction block
  height before validator-mode admission, so Nexus-enabled blocks cannot
  register validators, bond stake, mutate validator lifecycle, record rewards,
  or claim rewards against a catalog-present future-created autoscale lane.
  Torii public lane validators/stake/rewards endpoints now also hide stale
  persisted economics rows for inactive future-created autoscale lanes at the
  committed lane-authority height. Soracloud runtime validator-authority and HF
  placement stake aggregation now apply the same transaction-height active-lane
  boundary, so stale future-created autoscale validator rows cannot grant
  runtime authority or inflate placement stake before activation. Sumeragi NPoS
  penalty derivation now filters public-lane validator locators through the
  committed active-lane boundary, penalty application ignores crafted jail/slash
  actions against inactive future-created autoscale lanes, and NPoS election
  candidate profiles exclude stale validator/stake-share rows on inactive lanes
  before they can influence validator selection. Torii route discovery now
  filters inactive lanes before resolving direct dataspace routes, all-dataspace
  fanout, restricted ingress, or public-dataspace visibility, so corrupted
  autoscale-range lanes cannot be exposed as live read/proxy routes. Explicit
  public-lane Torii handlers and receiver-side read/verified-query proxy
  validation now enforce the same active-lane boundary, so peer-supplied route
  hints for future-created autoscale lanes fail as stale routes instead of
  executing locally. Transaction gossip send/receive validation now also
  rejects catalog-valid but inactive lane routes and Native AMX plan legs before
  semantic transaction materialization, so future-created autoscale route hints
  cannot enter local gossip admission. Soracloud status routing now reports
  configured lane count separately from active lane ids/count and live
  autoscale-capacity lane ids/count, so future-created autoscale lanes remain
  visible as configured catalog entries without being advertised as active
  horizontal capacity. Soracloud status also separates configured lane
  namespace size from declared lane metadata entries, so sparse catalogs are
  not underreported as smaller configured deployments. Accepted Nexus lane
  lifecycle responses now return the same configured/active/autoscale-capacity
  split while keeping legacy `lane_count` as the configured count, so
  automation cannot mistake catalog entries for live scale-out capacity. Torii
  OpenAPI and the latest/current portal snapshots now advertise
  `/v1/soracloud/status` with the same routing field split, the live
  `/v1/nexus/lifecycle` route now documents its `202 Accepted`
  `NexusLaneLifecycleResponse` contract and operator tool effect, and the Nexus
  operator docs describe the expanded lifecycle success payload instead of the
  old `{ ok, lane_count }` shape. Deterministic autoscale transition telemetry
  now reports `active_lanes` from live default-route autoscale capacity instead
  of raw configured catalog length, so unrelated configured dataspaces cannot
  be mistaken for active horizontal capacity in scale-out/scale-in events.
  Autoscale localnet transition evidence now rejects lines whose `active_lanes`
  and `autoscale_capacity_lanes` disagree, so stale pre-capacity-split logs or
  forged counters cannot satisfy scale transition quorum evidence; zero
  active/capacity lane counters are rejected as non-evidence too. Fresh
  scale-out/scale-in transition deltas now also require a matching baseline
  entry for each peer, so truncated baseline snapshots cannot turn old peer log
  counters into quorum evidence.
