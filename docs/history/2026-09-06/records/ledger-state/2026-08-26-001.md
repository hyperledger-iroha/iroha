## 2026-08-26 Kura emergency Fast startup and first-release simplification



<a id="record-852cf6582cbeb6f844a5b1eb51829fd712238cca458ba72d53992b2a0aba4669"></a>

- `kura.init_mode = "strict"` remains the default and performs complete canonical-body,
  finality, retained-record, lane-sidecar, recovery-stage, and capacity validation. The explicit
  emergency `"fast"` mode now trusts the Strict-published marker/count/tip boundary and never
  opens Sumeragi finality, checkpoint, manifest, active-height, or historical inventories.


<a id="record-848708b0b02cb89c7a622afc9c982a3187548e83cc83bec4edcd7171e8dd1777"></a>

- Fast startup ignores pending rollback, prune, rewrite, compaction, canonical-association,
  geometry-publication, and marker-publication artifacts without reading or mutating them; Strict
  owns their audit and recovery. The imported hash-only snapshot-tail marker remains rejected
  because an ordinary emergency manifest cannot authorize that distinct trust lineage. Historical
  bodies are decoded only when a bounded diagnostic read actually needs them; every lazy read is
  checked against the trusted height/hash/parent journal and poisons canonical storage on
  disagreement.


<a id="record-d652c9136fd39af5c7dc412d89b80767ac9a70f3e580396843e5f0e80408bfac"></a>

- Fast no longer requires, opens, decodes, indexes, truncates, or repairs the variable-length merge ledger,
  the lane-geometry journal, or Queue plan/reservation journals, and it skips recursive autonomous
  bootstrap and geometry-GC audits. Merge history and other skipped derived inventories return
  typed unavailable errors. The Queue reservation gate remains closed, the local validator and
  threshold-beacon producer are passive, canonical mutation is rejected, and active-height body
  and Certified-Serve stores remain empty/read-only without directory inventories. An
  already-current State snapshot is required so Fast cannot silently degrade into historical WSV
  replay; a missing or invalid snapshot now fails immediately before empty-world construction or
  lane-geometry preparation.


<a id="record-b22e3f2f689fdbc1b6f2896e58ba46f37c51f073f8edf77644fe0145f153d238"></a>

- Strict disk accounting now computes enforced and total usage in one traversal, and the canonical
  hash-to-height reverse index uses expected-linear hash-map construction instead of an ordered
  tree. Pipeline recovery persists only the first-release indexed Norito pair; the unused
  pre-release per-block JSON probe/deletion, prune/recovery directory scans, and optional
  accounting branch were removed. Strict rejects retired per-block JSON without interpreting or
  mutating it, while Fast defers that one-pass artifact audit. The
  current pipeline, proof, checkpoint, and commit-manifest Norito records now require every V1
  field even through ordinary decode helpers; omitted pre-release fields are no longer defaulted.
  Granular raw `BlockStore` index/data/hash rewrite, batch-append, and prune methods are now
  crate-private; external tooling retains only the explicit offline initialize/single-append
  builder surface plus the exact sequential reads Kagami consumes. Unused file-length, durable
  count, individual-index, and hash-journal readers are internal. Raw arbitrary-offset data writes
  and index-count truncation are test-gated because no production caller needs them. The
  production-dead direct merge-ledger append surface was removed; only its test helper remains.
  A snapshot lane-restore shim used only by unit fixtures is test-gated, and unused future
  compaction/projection wrappers plus an unreferenced Merkle default alias were deleted.


<a id="record-867d985fcf8319f28deb5067df328a3b2daaab191e2fb6bcbf89f8b100b56398"></a>

- Fast retains only the exact durable block count, not an in-memory vector or reverse index for
  every historical hash. Height-based reads fetch the exact hash/index slots on demand and retain
  bodies and reverse bindings only inside a recent-block window capped at 256 entries; unknown
  historical hash-to-height lookups remain unavailable until a Strict restart rebuilds the
  complete index.


<a id="record-eb67dcc43aac7ae86cdd934da7a0f7a85fb8a47314a8ce03782ae079d383c8f5"></a>

- Fast snapshot restore requires an exact five-artifact generation: payload, SHA-256 sidecar,
  operator signature, bounded Norito emergency manifest, and Merkle sidecar. Four-artifact and
  extra-artifact generations are rejected under the first-release format. A domain-separated
  bundle signature binds both the advertised payload digest and the manifest hash. The manifest
  carries payload length, chain/network identity, terminal height/hash, SCCP policy hash, and the
  bootstrap-lineage flag; Fast rejects bootstrap lineage and requires the exact durable Kura
  count/tip boundary.


<a id="record-a4e0f0b02b24b8bebc3fcd9976bb6d4a49debdb1ad33061f82360d7ad974570e"></a>

- Fast inventories all five names and metadata-binds the payload and Merkle files, but never reads,
  hashes, parses, or decodes their contents. Resource/Merkle/canonical-WSV scans, full snapshot
  decoding and reserialization, SCCP/privacy/Musubi/Soracloud/AXT/governance semantic audits,
  checkpoint checks, and full-prefix hash reconciliation remain deferred to Strict. Fast builds a
  minimal World/Nexus directly from the signed manifest, installs only its SCCP policy-hash
  override, and exposes Kura's exact hash prefix through a read-only mmap. The signed snapshot
  World, block-hash array, transaction membership, lane records, rewards, manifests, and consensus
  topologies remain unopened; every derived World index is absent rather than rebuilt. The mapped
  block-hash container also rejects block-scoped mutation before it can copy the mapped chain into
  memory. The full World decoder now has one unconditional Strict path; its unreachable
  `emergency_fast` validation branches were removed because manifest-only Fast restore never calls
  that decoder. All 55 fields that previously used a missing-as-default compatibility helper are
  now required by the exact V1 schema, and the unused helper was deleted.


<a id="record-d8417be5e21b86978611af22ff22f758938cb95fa6c7aedacb8e08acb166a820"></a>

- Fast startup never constructs a full `StateView`, so the read-only historical hash mapping is not
  copied into a process-sized vector while deriving peer capabilities. It installs the configured
  ZK policy against the minimal World and combines it with the signed SCCP policy. Torii does not
  resolve environment-provided dataspace upstreams, retain a P2P proxy handle, or subscribe to its
  control route, closing non-HTTP paths that could otherwise bypass the diagnostic-only surface.


<a id="record-29081ccabdb6d4ec17670ec1c57c8e1fc99fcdde1f5d658aaf76e10a100f30f1"></a>

- The canonical fixed-file store is opened read-only and must already have been initialized by a
  Strict boot. Fast checks the exact published marker/count/tip but ignores auxiliary recovery
  artifacts and leaves every unpublished suffix untouched; the next Strict restart owns their
  audit and recovery. Kura's central durable-mutation authorization rejects Fast, the public
  writer start entry point cannot spawn a worker, and pipeline/FASTPQ sidecar queues reject work
  before proof encoding or queue insertion. Pending snapshot authentication and poisoned canonical
  storage reject queue admission too, and a later authorization failure leaves already accepted
  queue entries undrained. Public lane, receipt, certified, execution-input, pipeline, and payload
  reads select repair-disabled paths in Fast, including the public execution-preflight reader;
  progress-sidecar sync has a central Fast backstop, so a read cannot promote temporary recovery
  artifacts, publish a missing sidecar, or fsync a durability barrier. Finalized merge-carrier
  repair and lane-geometry checkpoint boundaries also require central durable-mutation
  authorization. Read-only operation is therefore enforced by the storage library, not only by
  daemon startup wiring.
