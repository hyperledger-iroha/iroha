## 2026-07-08 Localnet lifecycle cleanup and memory guard



<a id="record-4238ce46436a187385e34751d689dc808bd818ea161bebe0328f4d40350b712c"></a>

- Audited the local restart/OOM evidence. The 2026-07-07 jetsam reports showed
  27-30 live `irohad` processes with aggregate current RSS around 11.3-12.4 GiB
  and summed lifetime peaks around 20.7-22.9 GiB, while individual peers peaked
  below roughly 0.9 GiB. The live orphans were CBSI full-journey localnet peers
  under `cbsi-deploy/output/localnet-ui-full-journey/.../iroha_localnet`, not a
  single confirmed runaway Iroha peer.


<a id="record-28d025fc85710c04744820f357d46506442df89aded6cbed4a8a7d5f6cacb39b"></a>

- Fixed the root lifecycle gap in the CBSI full-journey harness: managed cleanup
  now stops manifest `localnetDir` targets and discovered `iroha_localnet`
  directories through the generated localnet stop path, and the top-level runner
  cleans retained stacks on exit unless `--retain-stack-after-run` is passed.


<a id="record-dc329c454beb6adcbaa2ae87a7a51c2755ddd489a8b6809bc2e296492e9de564"></a>

- Hardened `scripts/run_localnet_memory_guard.py` so guarded localnet memory
  repros fail preflight when unrelated `irohad` processes are already live. The
  JSON report now records `preflight_error`, `existing_irohad_processes`, and
  `existing_irohad_total_rss_bytes`; `--allow-existing-irohad` records those
  processes separately while guarding only the newly deployed localnet.
