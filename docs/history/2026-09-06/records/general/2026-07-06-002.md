## 2026-07-06 Nexus finalized lane-block proposal broadcast



<a id="record-93647eae518935c4da3cc458a4259a832ec7b9ca97d9a678b140ccd4c27f5d34"></a>

- Final proposal assembly now preserves the finalized lane-block proposal
  artifacts and local prepare-vote plans produced by lane payload planning.
  After stale-proposal checks pass, Sumeragi broadcasts each finalized
  `LaneBlockProposal` plus the local validator's BLS-signed
  `LaneBlockPrepareVote`; commit votes remain gated on prepare-QC evidence.


<a id="record-901c7b7e83aedc286397a014894b1607b208768ea4d33caf09589375eec35c70"></a>

- Added focused main-loop coverage proving finalized proposals and local
  prepare votes are scheduled together, the local prepare vote signature
  verifies, non-local prepare votes are not signed or broadcast, tampered
  signing hashes are skipped, and no lane commit vote is broadcast from the
  proposal-finalization path.


<a id="record-507b33985cca10d4ed96219d5aab4493ed1b8d519b6d5a35788a3c7051d89bd6"></a>

- Added mixed-committee final-assembly coverage proving a local leader can
  broadcast finalized lane-block proposals for two active lanes while signing
  and broadcasting a prepare vote only for the lane whose bound validator set
  includes the local peer.


<a id="record-bff78aa978914a3c547092c46c8ecc9ee41a0f8c4ec9d045644ae6db11a79208"></a>

- Hardened standalone lane-block reset handling so ingress and local broadcast
  preflight reject proposal/vote/QC artifacts at or below a lane reset
  watermark, and cache/committed-queue pruning drops those reset-era sessions
  before status publication while releasing stale slot claims.

## 2026-07-06 Nexus prepare-QC gated lane commit votes



<a id="record-c90983e9748765c4af60659a83964e7f52dc004b1520c895912f2e8a56bfc1e0"></a>

- The lane-block session cache now exposes a one-shot commit-vote request drain
  once a validated proposal and prepare QC are cached. Sumeragi drains those
  requests for the local validator, signs a BLS commit vote only when the local
  peer is in the lane committee, broadcasts that `LaneBlockVote`, and caches the
  local vote so single-validator lanes can seal commit QCs and enter the
  committed-session queue without waiting for network loopback.


<a id="record-fc0efcc8b9f5669e558cde3abcffd269ad26732b20380646659e90947a6d1080"></a>

- Added cache coverage proving commit-vote requests wait for proposal plus
  prepare QC, drain once, skip non-members, and skip sessions where the local
  commit vote is already cached. Added main-loop coverage for locally sealed
  prepare QCs, inbound prepare QCs without QC echoing, duplicate suppression,
  non-member silence, commit-QC sealing, and committed-session queueing.

## 2026-07-06 Nexus lane block sealed-QC transport handoff



<a id="record-17880ba7df9d14c4386cdbb2323595e93b50abcefdd95798f04413289510de8b"></a>

## 2026-07-06 Nexus lane block committed-session drain



<a id="record-8d9fe48639711b157bfc0af38c4c419c985f5981fac035dcb9920c6d237f28d0"></a>

- The bounded lane-block session cache now exposes a separate one-shot drain for
  committed lane sessions once the matching proposal, prepare QC, and commit QC
  are all present. This drain is independent of transport broadcasting, so
  inbound QCs can make a session executable without being echoed as locally
  sealed certificates.


<a id="record-0505be9be4f325f89708f59f213433a3caa2f57fe8af67f6780d9d1047eba9a6"></a>

- Added adversarial coverage proving sessions do not drain before both QCs and
  the proposal are available, duplicate drains are suppressed, inbound QCs can
  complete a session, and body-drifted orphan QCs are discarded during proposal
  reconciliation before commit readiness is exposed.
