## 2026-07-30 Deterministic finite JSON floats



<a id="record-496ba79c8a487df5713e4f8b3367a44849d35ad396ab58bfdf4a95204f533e79"></a>

- Exact-bit regressions cover positive and negative zero, the smallest
  subnormal, the smallest normal, ordinary irrational values, and both finite
  extremes through both decoder paths; positive and negative overflow are
  rejected.


<a id="record-626d27078fc1dc0ec21897d7b20d98018c95db15f4be489e5b051167f3b08852"></a>

- The audit premise that these floats live in on-chain `Parameters` was
  refuted. Nexus decision thresholds are startup configuration committed as
  validated finite IEEE-754 bit patterns in the signed peer policy digest;
  WSV snapshot runtime state contains integer windows and samples, not those
  thresholds. Focused Cargo validation remains queued for the serialized lane.

## 2026-07-30 Signed-query resource admission



<a id="record-6c400afb62e509804352beac56c4a80747b4c8210cfb4396b2b425fcb1fb340a"></a>

- `POST /v1/query` no longer uses unauthenticated `x-api-token` text as a
  rate-limit identity. Public requests first consume either an exact validated
  API-credential bucket or an effective-client-origin bucket that ignores raw
  token text, then every physical execution consumes a canonical
  verified-`AccountId` bucket. The two dimensions use independent bounded maps,
  so authority churn cannot evict and refill the pre-auth budget.


<a id="record-67a6d6f0b4af974d2e6edfa7c07ae44f011dbb50eeae9defefb5dbb4c3acdf23"></a>

- Direct, proxied, and multi-dataspace query execution now shares the bounded
  general/heavy admission corridor. Each owned permit moves into the blocking
  snapshot worker, so HTTP cancellation cannot free capacity while executor
  validation is still consuming its per-query fuel.


<a id="record-8085d3c3c35bf15eaf40539c3dbbea933af7dd926de73fd49f9440d0d0918eea"></a>

- Regression coverage exercises raw-token rotation, canonical authority keying,
  and the existing fail-fast/physical-completion semaphore invariants. Exact
  formatting and whitespace validation pass; focused Cargo execution remains
  pending the shared serialized build lane.

## 2026-07-30 Queue proposal gas and tombstone lifecycle hardening



<a id="record-57c4d19b1750e31d995af4aefdfc9821d98837dfa1ad1ab21cf74469a54e51f4"></a>

- Proposal gas derivation now returns a typed failure instead of silently
  assigning zero gas. Raw/proved IVM, deployed-contract calls, and mixed
  executable batches consume their complete signature-bound gas limit during
  proposal selection; native-only payloads retain deterministic instruction
  metering. Admission rejects an invariant violation with the existing
  `invalid_gas_limit` fee code, while recovery and selection retain accepted
  ownership and fail closed.


<a id="record-bfb4ab4f207397593a336187ec2dd5e8825c0448eba7c8f2a487d95968e7d970"></a>

- Queue removal creates a `removed_hashes` marker only when the removed
  transaction still has a stale ordinary FIFO cell. Popped and lane-reserved
  transactions have already surrendered FIFO ownership and therefore cannot
  leave unreachable process-lifetime tombstones.

## 2026-07-30 Executor migration fixture isolation



<a id="record-2bd760ffe15d583dba5e24d98b7d26e09802af712b7e4ee6d686f4ab2dd95589"></a>

- Removed synthetic executor classification from every default production
  validation, migration, and instruction-dispatch build. A user-provided
  executor now always runs its admitted IVM guest logic, and migration accepts
  only the guest's canonical Norito result; a tiny header-plus-HALT program can
  no longer select host-side permission or data-model mutations.


<a id="record-452fc750bf038ff4925b2540d24c867e1460334028e62ebddbf15a53548203af"></a>

- The legacy synthetic executors remain available solely behind the existing
  non-default `iroha-core-tests` feature so integration fixtures must opt into
  their emulation explicitly. A default-feature integration regression checks
  all eight former vector-length tags and requires each HALT-only migration to
  fail without installing the executor or changing its data model.


<a id="record-0f9e6f4ca07c172a704e81230c003170ab36d023fb79c92d957b0393ffdfd7ac"></a>

- A focused migration-result regression proves that a bare `Ok` discriminant
  cannot decode as an empty `ExecutorDataModel`; the same bytes are the
  canonical unit-success result and return `None` without installing a model.
  Complete data-model results are accepted and trailing-byte payloads rejected.


<a id="record-498329b72bf5cfb051d4c57b9e67e6476ff82f5fc4b435bc872f797d8a56091a"></a>

- Exact Rust formatting and whitespace validation pass. Focused Cargo
  validation is pending the shared serialized build lane.

## 2026-07-30 Trigger execution-depth boundary hardening



<a id="record-4785ec1f7349496342ce66ba5abb7852d9b80ca78de911fd4add924a16e3299c"></a>

- Trigger DFS and synchronous-entry depth counters now use fixed-width `u16`
  accounting while the on-chain limit remains `u8`. The runtime can therefore
  represent and deterministically reject depth 256 when
  `smart_contract.execution_depth` is 255, instead of debug-panicking or
  release-wrapping back to zero.


<a id="record-3eb70bb9c002c9cc579c197f89a0fbefd935534945fab03b4f999be8efacdf30"></a>

- A focused self-chaining data-trigger regression sets the parameter to
  `u8::MAX`, proves exactly 255 executions are admitted, and requires the next
  depth to return `MaxDepthExceeded`. Focused Cargo execution remains pending
  the shared serialized build lane.
