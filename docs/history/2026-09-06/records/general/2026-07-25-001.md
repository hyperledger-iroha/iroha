## 2026-07-25 SFM-4b3 evidence-viewer implementation foundation



<a id="record-49fd02a23c3566bfa07b303cdfd438a5399b99cf66e8620ccd727443190e718c"></a>

- Added strict `iroha_config` policy and runtime identity injection, the
  finalized Torii adapter, the authenticated `/v1/evidence/*` API family,
  route-catalog/OpenAPI coverage, and a strict-CSP/no-store embedded
  same-origin viewer shell with visible watermarking and no service worker,
  offline storage, or download surface.


<a id="record-f67ac2036d42d7970069049347901b1f289f22882eefbb5333f06dad87acf267"></a>

- Focused source tests cover the 15-minute and HTTPS policy bounds, opaque
  secret redaction/bounds, receipt and checkpoint-envelope tampering, canonical
  input parsing, sensitive challenge/grant headers, and viewer CSP/offline
  controls.
  The signed receipt checkpoint and exact predecessor-bound transparency
  projection are now the sole evidence-access audit authority. Each durable
  checkpoint carries an Ed25519-signed anchor over its canonical digest,
  receipt count, and exact chain head; even an empty installation must persist
  a signed genesis anchor before becoming available. Audit pagination requires
  that exact checkpoint digest, an explicit digest-bound page limit, and one
  canonical raw-query field order. It returns `409 Conflict` rather than mixing
  pages if the checkpoint changes, and read paths reuse the retained signature
  without invoking the signer. Typed OpenAPI schemas now cover the anchor,
  cursors, receipts, status, projection, canonical-auth headers, and negative
  responses.
  The old
  aggregate-audit POSTs authenticate and authorize before returning `410 Gone`;
  their scheduler and all Torii calls into the former local viewer registry are
  removed. Moderation GETs read only a fresh worker-owned finalized projection,
  while supervised deadlines, non-overlap fencing, monotonic cursors, dead
  letters, and typed payload-free startup failures make stale or stopped
  workers fail closed.
  This is not yet a production-readiness claim. Local blockers remain under
  `V1-BLOCK-MODERATION-VIEWER-RUNTIME-01`: reference runtime construction for
  external signing, WebAuthn, and authenticated downstream boundaries, a durable
  notification-delivery worker, settlement/publication adapters, semantic
  operation-ID CAS, monotonic multi-instance checkpoint fencing, signed
  replay-safe terminal compaction/archive, and the signed receipt-projection
  producer plus a monotonic external head for first-contact freshness. A
  first-time client cannot distinguish an older validly signed anchor without
  that independent head. Rustfmt/static checks are recorded with the
  implementation handoff. Focused Cargo execution, deployment, adversarial and
  recovery rehearsal, and genuine payload-free promotion evidence remain
  pending.
