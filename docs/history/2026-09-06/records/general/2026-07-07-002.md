## 2026-07-07 Direct lane execution input duplicate guard



<a id="record-3adcf1eb7a9ea90860669fe04dcf5c9cb95b42e0650b201e1f4bd3e154af5607"></a>

- Direct standalone lane-block execution input now rejects duplicate
  entrypoints, duplicate signed transactions, and duplicate sealed commitments
  before any state execution is staged. This mirrors the canonical block
  duplicate guard for recovered lane payloads and prevents same-input
  duplicate no-op transactions from being applied while only one membership
  hash is recorded.
