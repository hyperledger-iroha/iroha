## 2026-07-08 Cross-dataspace applied route evidence and lane-local baselines



<a id="record-0a7a43a21b34fad7876ec535f051b0cfe8707fcddfe18735d6577585db207387"></a>

- The 12-peer cross-dataspace route-probe corridor now requires both active
  dataspaces to expose certified committed-lane rows with embedded lane quorum
  signer counts and at least one applied certified row with executable payload
  material. Certified committed-lane evidence is scanned across all peers
  because the row itself carries the lane QC; operator status fanout is no
  longer treated as the safety proof.


<a id="record-95613f29b434594b27984bf0338c47e1cd8f87ad9502318094c98c4392722e73"></a>

- The route-probe harness keeps the stricter latest-row application helper for
  parser regressions, while the end-to-end gate accepts the highest applied
  certified row so later pending predecessor-application rows cannot erase an
  already receipt-backed executor-boundary proof.


<a id="record-e2ca77b4376e2641c27fb07b43b7b161d5f8d70472fd05a759bc0181ad9c9604"></a>

- Localnet rollback verification no longer spends 600s in an uncapped blocking
  confirmation fallback when committed-history lookup is inconclusive; the
  balance rollback assertion remains the safety gate.

## 2026-07-08 Committed-lane status certified identity gate



<a id="record-65c895e940e1904cc70bc83e32c7af7a0bc2d8734a4382afaa908f4e9d5ad82d"></a>

- Hardened `set_committed_lane_blocks` so committed-lane status rows are
  validated against their embedded proposal, prepare QC, and commit QC before
  they are exposed through Sumeragi status.


<a id="record-8bccd196655fbedde14a7431d69436c8c2d8ccce935654dbf41443452eec2cd3"></a>

- The gate rejects summary/proposal drift, malformed proposal hashes, wrong QC
  phases, QC/proposal committee drift, missing aggregate signatures, and
  under-quorum signer bitmaps by reusing the canonical lane-consensus committed
  session validator.


<a id="record-c1f208ff41cb2272e8be93e530fd3c049546403c87b28ffd5bae1e8bc40f75cc"></a>

- Invalid committed-lane rows are dropped before the status cap is applied, so
  malformed certified evidence cannot evict valid recent lane-block evidence.

## 2026-07-08 Autoscale committed-lane evidence hash identity



<a id="record-8aae3ad5d540be66a8b92f56da05f0a3cc349c8eb31af87792158336ae3aba0f"></a>

- Hardened the autoscale localnet committed-lane status parser to retain
  descriptor, proposal, subject, payload-ownership, RBC-instance, and QC-mode
  identity from the Sumeragi status payload. Same-height committed-lane rows
  now have to match that full identity before being treated as idempotent
  duplicates.


<a id="record-fec9aa38ac8a9b94c7cff09433369db53132e72a0621ee7e04402f798cf638c9"></a>

- Added negative parser coverage proving descriptor/proposal hash drift,
  subject hash drift, payload-ownership hash drift, RBC-instance hash drift,
  or QC-mode drift cannot fake scale-out progress and cannot prove safe
  public-profile scale-in/contraction.


<a id="record-b45a1fd40d6f57d01e2a72a7de40b21c5fe771e142864f51a47a17514c18be9e"></a>

- Hardened the runtime committed-lane status merge to require the same
  certified session identity, including descriptor hash plus proposal,
  prepare-QC, and commit-QC equality, before replacing an existing status row.
  Malformed in-memory descriptor or QC drift now remains visible as separate
  suspicious evidence instead of overwriting the original row.


<a id="record-9ebb17d7a8e91a7487e39f883bf9a98c077594b1e94d035a8728f8d97840e91f"></a>

- Validation passed:
  - `cargo test -p iroha_core --features sumeragi-main-loop-tests committed_lane_block_status_merge_requires_full_certified_identity -- --nocapture`
  - `cargo test -p integration_tests --test nexus_and_streaming committed_lane_block_status_rejects_ambiguous_latest_rows -- --nocapture`
  - `cargo test -p integration_tests --test nexus_and_streaming public_profile_contraction_rejects_ambiguous_committed_lane_block_rows -- --nocapture`
