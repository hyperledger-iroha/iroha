## 2026-08-01 Genesis authentication and bootstrap authority



<a id="record-5cbb4c210d33de158f7aae11b44b8bcebb3cad3c00a4df6ef92ce7b79066f3aa"></a>

- Resultless height-one proposals now authenticate the unique index-zero
  configured-key block signature, transaction-intent Merkle root, chain, authorities,
  transaction proofs, executable shape, and DA sidecars before any genesis-only
  instruction executes. Deterministic result/error commitments remain a
  separate post-execution check.


<a id="record-59d438b4600f7b7afbfcfc2b73acfdfcf866db07aa779fe68362ee927fba526e"></a>

- Executor bootstrap exceptions share one height-one-plus-empty-history
  predicate. A genesis-shaped header over committed history cannot recover fee,
  permission, metadata, or registration exceptions, while the authenticated
  state root retains its explicit closed bootstrap instruction surface.


<a id="record-5d0c6f6bf483ffde385ee7690b44f1d9fe7f54199d15f53e5f62a289c4e293e9"></a>

- `specs/startup_trust_roots.md` records the complete composition with the
  configured key and independently configured exact-hash anchor. Exact-file
  Rust formatting, source diff checks, the Python and JavaScript Compose
  artifact preflight tests, and `sh -n` validation of the embedded validator
  launcher pass. Prepared-bundle positive and signer/hash/roster/PoP mismatch
  Rust regressions are implemented. Focused Rust execution and generated-Compose
  consistency remain pending until the shared Cargo/rustc lane is free; no
  focused Rust result is claimed yet.

## 2026-08-01 Storage-budget, RAM-LFE secret, and pre-auth ban hardening



<a id="record-a3b4be9ba042482cc663d9d1da80fb3a75150d6212f4a1f1969a2ac257523885"></a>

- Runtime budget application now rejects empty, noncanonical, duplicate, and
  zero-share filesystem component metadata before mutation. Proportional
  splitting uses exact `u128` intermediates and checked accumulation, including
  max-width `u64` coverage; explicit budgets that would leave a zero component
  cap are rejected during parsing.


<a id="record-ba2fabfe9f84a0c658f7e4d7d0fec5d740bf9c7179f97f5e0e2b1e2876f898f8"></a>

- RAM-LFE runtime secrets now use a validated, allocation-sharing zeroizing
  owner with redacted debug output. Config-to-runtime clones share the secret
  allocation, Torii lookups clone only an `Arc<ProgramRuntime>`, and config,
  runtime, and service debug views redact hidden secret/program/signer material.


<a id="record-8de558a6659d719a07907d1c7f02add667bb42dd8a5ce710e5ef7bd2fca8ddf0"></a>

- Focused Cargo validation remains queued until the coordinated source patch is
  complete; formatting and source-level diff checks are recorded with the final
  remediation validation.
