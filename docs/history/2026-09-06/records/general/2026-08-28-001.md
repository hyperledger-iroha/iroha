## 2026-08-28 Hijiri validation-fee production readiness



<a id="record-de6b7697bd5401f47edadbaa69070320c93a40d541f747bbd4605f8d13c62970"></a>

- Updates use `SetParameter` under the dedicated `CanSetHijiriParameters`
  permission in both default executors; generic parameter authority cannot
  bypass it. Bootstrap parameter administrators receive that capability.
  Production deployment still requires Parliament to enact an enabled
  exact-network base policy, the mandatory 120,960-block activation delay, and
  same-revision four-peer qualification.


<a id="record-f9a39eb28ea7a021239bd6e19faf7e69ca6fac9175a12b173bf5180e53348ca5"></a>

- Validation-fee admission resolves the execution account for each fee context,
  aggregates the qualifying base transfer amount, and applies the selected Q16
  multiplier once with checked upward rounding. A production-blocking nested
  multisig defect was fixed: signed metadata now binds the explicitly selected
  nested fee context instead of always binding context zero, while the nested
  marker continues to bind that execution context. Both bind the composite hash
  of global parameters and the exact account-risk presence/value, so missing,
  stale, malformed, or extra bindings fail admission.


<a id="record-516a7edf8652e78e3b6e1a0ebdb2d2bfe9f2d947ca8563454b3c9d587184b49c"></a>

- Unsigned multisig and ordinary contract-call response parity needed by the
  Hijiri flow is now closed across Rust, C#, Kotlin, Java, Swift, JavaScript, and
  Python. Callers supply a trusted off-wire draft intent, and every client fails
  closed on network, authority, executable, metadata, fee, timing, selector,
  payload-digest, detached-signing, or receipt substitution. Contract receipts
  additionally bind the canonical address and code hash, ABI, alias and its
  requested dataspace, entrypoint, transport, gas state, fee, and unsigned
  transaction identity. Direct-address calls bind the exact address but cannot
  independently authenticate Torii's textual dataspace label without a trusted
  local numeric-ID-to-alias catalog. Java and Kotlin expose no throw-only
  no-intent overload, and every transport response construction supplies final
  URI and redirect provenance explicitly.
