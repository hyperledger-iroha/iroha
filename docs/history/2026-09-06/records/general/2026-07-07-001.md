## 2026-07-07 Autoscale committed-lane evidence ambiguity hardening



<a id="record-95d4d4290570c0b343d0696c3bb045bd3fe3eb949d8c82bfcc9311d5b305d743"></a>

- Autoscale localnet rollout evidence now treats conflicting latest
  committed-lane status rows for the same lane height/view as ambiguous and
  fails closed instead of selecting the row with the highest dataspace id.
  Exact duplicate latest rows remain idempotent, but conflicting generic or
  direct-applied rows no longer count as expansion or direct-execution
  evidence.


<a id="record-ccffb359faa19a703b11d88b79837d64b358ca75124745db1d1ab13606febb1a"></a>

- Autoscale committed-lane rollout evidence now also requires the status row to
  target the default `DataSpaceId::UNIVERSAL` route before it can count as
  expansion, direct-execution evidence, or lingering elastic-lane state. Rows
  from a stale or foreign dataspace are ignored rather than inflating progress
  or blocking destruction of the active default-dataspace elastic lane.


<a id="record-cb64155e646e2918eb0682ea03509e37057b2b3faa853ffa05662f731f43c025"></a>

- Autoscale expansion status and deterministic transition comparison now also
  require provided baselines to cover the same peer set as the current snapshot.
  Mismatched peer counts no longer count current-state lane evidence or
  transition deltas as fresh expansion/scale-in quorum, preventing partial
  snapshots from manufacturing quorum.


<a id="record-e8c10bc42327bf8e2cdc62012b0d92bec42000b4503eb40df33c378b09f7c2d0"></a>

- Scale-in profile checks now also distinguish missing committed-lane block
  evidence from ambiguous or unambiguous certified committed-lane evidence on
  the elastic lane. Conflicting certified rows cannot be treated as absence,
  malformed latest rows cannot be treated as absence, and any certified
  elastic-lane committed block blocks lane destruction until the lane is plainly
  idle.


<a id="record-2cb48ad90f18ee7d63ba20dfc08c1f295f377eb299eef57e8789bc52a147135e"></a>

- Elastic-lane status evidence now follows the same scale-in safety rule:
  duplicate status rows are malformed evidence and cannot be treated as a
  missing lane during destruction checks. A single zero-capacity/zero-committed
  elastic status row remains an unambiguous terminal idle row.


<a id="record-7b0da50504af4f88308a5432006251ef9617ab0f53ae26e3269c0d9c2ce5d2cb"></a>

- Expansion declaration/progress transitions now fail closed if either the
  current peer snapshot or its baseline peer snapshot has ambiguous lane
  evidence. Ambiguous baseline status, commitment, committed-lane block, or
  validator rows cannot be "repaired" by later clean rows into fresh expansion
  proof.


<a id="record-0ebad2f041fad7a68b0b4be1a5b048684db2c1e660eefa00c905fe2da517f232"></a>

- Lane-specific autoscale transition logs now count unambiguous transition
  heights instead of raw matching lines. Exact duplicate rows for the same
  height are idempotent, conflicting same-height rows are dropped as ambiguous,
  and ambiguous transition heights remain visible in the snapshot. Fresh
  scale-out/scale-in delta quorum now fails closed if either the baseline or
  current peer evidence for that direction contains ambiguous heights, so
  same-height duplicates or later "repair" lines cannot manufacture a fresh
  transition.


<a id="record-a436893981f07c6f1e43c704730abf8605ef5220925344e860ba254cf55eefc2"></a>

- Elastic-lane storage fallback progress now requires structural growth:
  increased file count, increased total bytes, or first presence of the lane
  store. Metadata-only timestamp movement is diagnostic only and no longer
  satisfies expansion fallback evidence.


<a id="record-114c49e68fe77924ec03bdcf4565bae6f8bb3f087844f286800c7a456364bc44"></a>

- Autoscale storage fallback also requires a complete peer storage snapshot and
  aligned current/baseline elastic-storage rows before storage progress can
  satisfy expansion fallback. Empty or partial snapshots cannot prove
  provisioned lanes or post-baseline storage progress.


<a id="record-d56de7dbe82c456847d5e64946be9c44b2ff257a9eb010de5ca705d6cfdb8699"></a>

- Public lane-validator summaries now distinguish missing, unambiguous, and
  ambiguous evidence. Conflicting validator rows cannot fake expansion, and
  they also cannot be treated as idle proof for scale-in; exact duplicate live
  or terminal rows remain idempotent.


<a id="record-f528133bcf1daeae0e77a603a48ea89357a25fe0ddf66d053ce8d4ed4a9ae52a"></a>

- Lane-block ingress now checks Nexus-active lane routing before caching
  proposals, votes, or QCs. Messages for inactive lane/dataspace routes are
  dropped as invalid payloads before they can seal or rebroadcast QCs, emit
  local commit votes, or enqueue committed lane-block sessions.


<a id="record-b5aa2306e84f7cb08e4d9f63e4277a07694afc8d3a27b4d411b851de49975ae4"></a>

- Lane-block ingress now also verifies committee authority for Nexus-active
  routes before session insertion. Shared single-routable-lane mode checks the
  embedded validator set hash/count/full set and quorum threshold against the
  live consensus roster used for lane-block planning; independent-lane
  lookahead mode checks the same fields against
  `State::authoritative_lane_peer_ids`. Vote ingress also requires the vote
  signer to belong to that expected committee and requires an authenticated
  sender before session insertion, so senderless votes or orphan votes with
  spoofed committee metadata are dropped before they can populate the cache.
  Active-route messages signed by a self-appointed committee, or by the exact
  live shared committee with a downgraded quorum threshold, are dropped before
  they can cache proposals, seal QCs, or emit local commit votes.


<a id="record-ec2002eb778e4b29a0f23fa1887f4b136729e037100d7ad547b6ea099586293d"></a>

- Local lane-block commit-vote production now revalidates the cached proposal
  artifact, active route, authoritative validator set, canonical quorum, and
  local signer before producing a BLS signature. Forged cached prepare-QC
  sessions for inactive routes, spoofed committees, or quorum-downgraded live
  committees are skipped before a local commit vote exists.


<a id="record-1bc80dfc054194bf48c21c44b51a29e5478c92992f9a7e7a5059ac4ed02205c7"></a>

- Local lane-block prepare-vote production now applies the same pre-sign
  active-route, authoritative-committee, canonical-quorum, and local-signer
  checks to scheduler vote plans. Spoofed or quorum-downgraded prepare plans are
  skipped before a local BLS prepare vote exists, so they cannot create orphan
  lane sessions, invalid-vote drop counters, or background broadcasts.


<a id="record-0b3c749f8dc84c0b651333ebe5e385ffd6d6fb6bba83f7776d597ca8c5c85a48"></a>

- Local lane-block broadcast preflight now has active-route spoofed-committee
  and exact-committee quorum-downgrade regressions for post-prepare commit votes
  and sealed prepare/commit QCs. Even if a forged session is already cached
  before pruning, non-authoritative validator-set metadata or lowered quorum
  thresholds cannot reach background transport or enqueue committed lane-block
  execution.


<a id="record-d2922574f37f36bb0de5e996a07cfa2632f857c71efdc72a3cc4cbeeebb62064"></a>

- Final proposal assembly now loops locally produced lane-block proposals and
  locally signed BLS prepare votes back through the same ingress handlers after
  scheduling their background broadcasts. Leaders no longer wait for network
  echo before caching their own lane-block proposal/vote evidence, while
  nonlocal or tampered prepare-vote plans still skip local vote caching.
  Main-loop coverage now also assembles a four-peer final proposal with two
  active non-idle lanes, proving it emits two lane-block proposal artifacts and
  two local prepare votes while advancing the lanes at independent lane-local
  heights without requiring an idle default lane. Mixed-committee coverage now
  proves the same final path still broadcasts both lane-block proposals while
  signing and broadcasting a local prepare vote only for lanes whose
  authoritative validator set contains the local peer. Negative coverage now
  proves a cross-lane batch with one missing lane authority is deferred as a
  whole, clears stale ownership status, and returns both transactions for
  requeue instead of partially accepting the authorized lane.
  Local lane-block transport now preflights route, committee authority,
  signature, and cache-conflict admissibility before scheduling proposal,
  prepare-vote, sealed-QC, or post-prepare-QC commit-vote broadcasts, so
  duplicate, same-slot conflicting, or stale-route locally produced artifacts
  are recorded as duplicate/invalid without reaching background transport.
  The same cache, queue, ingress, and local-broadcast paths now reject or prune
  lane-block artifacts at or below the lane reset watermark, so recreated lanes
  with the same route cannot retain old-incarnation slot claims, committed
  execution queue entries, status rows, QCs, or commit-vote side effects.
  Proposal planning now applies the same route/reset filter to in-memory
  committed-queue lane tips before mutating prune runs, so a stale queued
  old-incarnation session cannot become the predecessor for a fresh proposal.
  Committed block-artifact tips read from Kura and cached relay envelopes now
  also honor reset watermarks, so stale old-incarnation lane payload artifacts
  remain historical proof material without exporting predecessor descriptor
  hashes or global-height compatibility coordinates to proposal planning.


<a id="record-da814e4b09cc9c0be30136064e6194f3c0a9d8eb712c23a750ce624c8e5273db"></a>

- Lane-block vote-body tests now also pin the signer preimage against each
  standalone replay and quorum field: lane/dataspace coordinates, lane-local
  height/view, proposal/subject/ownership/RBC hashes, accepted candidate
  indices and transaction hashes, validator-set hash version/hash,
  validator/quorum counts, and QC mode tag. This prevents future scheduler
  work from accidentally narrowing the BLS-signed lane vote payload while
  preserving the existing phase/descriptor domain-separation checks.


<a id="record-b208839220e4b39e11994fd507823d616fa98e64b86552c4f06af2028aa7baee"></a>

- Lane-block descriptor/proposal hashes now bind validator-set hash
  version/hash metadata in addition to canonical committee order, and
  data-model drift tests mutate every descriptor/proposal replay, predecessor,
  ownership, validator-set, quorum, and QC-mode field.


<a id="record-423a82100f9e2f90093a7eae3f525a758e28f0f783e12920c1b3b0a1a8db2d93"></a>

- Certified lane-block sidecar snapshots now also honor lane reset watermarks:
  stale same-lane sidecars at or below the reset height are excluded from
  proposal tips, restart execution-session hydration, and autoscale unapplied
  progress checks, while fresh post-reset sidecars remain visible. Sumeragi
  startup preloads DA reset watermarks before certified sidecar recovery so
  persisted reset journals take effect during restart.


<a id="record-258732addba6ac4e900b2d1f38eac2ee09899792ac00051591d9860ce2a6ffd7"></a>

- Direct application marker scale-in guards now also apply lane reset
  watermarks per queried lane: stale key or marker evidence at or below the
  reset height cannot block fresh-lane scale-in if it is reintroduced after
  lifecycle cleanup, while fresh post-reset unrepaired markers and malformed
  key/payload rows still block destruction. Autoscale commit now re-prunes
  lane-scoped block-local cleanup state immediately before publishing the
  world block, covering AXT replay rows, DA pin indexes, direct application
  markers, public-lane validators/economics, and verified relay contract
  storage, then repeats durable cleanup in committed storage so late inserts
  after lifecycle staging cannot survive scale-in for retired lanes.
