## 2026-06-24 ISO XSD Pending Source Evidence



<a id="record-85a4f273850c55a14524b213b523ec462c2812b8f073a71531043d2eaf584c85"></a>

- Added explicit `pending_schema_sources` to the ISO XSD fixture manifest for
  official ISO catalogue/archive coordinates and direct XSD download URLs whose
  redistributable schema bytes are still not checked in. The current checked-in
  manifest records pending-source evidence for `colr.012.001.05`,
  `sese.023.001.09`, `sese.023.001.11`, `sese.024.001.09`,
  `sese.024.001.10`, `sese.025.001.08`, `sese.025.001.10`, and
  `sese.025.001.11`.


<a id="record-4280ac0deb92ab0e27ea7c7d2a288ad58cb289d712792a53184aaa2e455e0c4a"></a>

- Bumped the XSD summary contract to version 3. XSD summaries now emit
  `pending_schema_source_count`, `pending_schema_sources`, and a
  `pending_source` flag in `missing_profile_schema_message_ids`; final
  readiness validates those fields from raw summary evidence instead of
  trusting the aggregate. Pending-source evidence removes the previous
  unreviewed unique securities profile-gap blocker, but it does not satisfy
  `--require-schema-backed-fixtures` or
  `--require-profile-schema-backed-versions`.


<a id="record-dd4fd2c9fee39245958da2ada2d950a9e0255800b4a3f8fe7ef98acfe79d9efc"></a>

- Tightened pending-source provenance so each record must carry an exact
  official `https://www.iso20022.org/message/<id>/download` URL. Direct XSD
  preflight and final readiness replay reject missing, non-ISO, non-numeric,
  overlong, percent-escaped, secret-looking, or duplicate pending
  catalogue/download coordinates, require archive catalogue URLs to use canonical raw
  `page=<nonzero decimal>` queries, and replay includes the direct URL in
  within-summary and cross-summary pending-source reuse checks.


<a id="record-502ff167a0b49c5923e2b3f678535d90ff290367bcbc31c5aee4412f85a6e518"></a>

- Direct XSD preflight and final readiness replay now also pin the eight known
  pending message definitions to their exact recorded official ISO catalogue
  URLs, direct download URLs, download type, message names, and submitting
  organisations, so a forged summary cannot swap one official-looking ISO
  coordinate for another while preserving the same `message_def_id`.


<a id="record-f88d258597502bca7f59bdf81b9790c1a4904ff849e547e47f78d6fdf5f0e8a7"></a>

- Pending-source message names now have to be unique, use canonical ISO-style
  CamelCase ending in a `VNN` suffix matching the final version segment of
  `message_def_id`, and replay as distinct cross-summary material, so a forged
  official-looking source cannot relabel a different ISO message version,
  preserve spaces/punctuation in the official message-name field, or reuse one
  official name under a different pending download URL.


<a id="record-3b9b41d801e0cf9837b899f87a66610b45ae361dad1e781d742cacaf816a9b97"></a>

- Pending-source `submitting_organisation` values now have to be bounded
  canonical ISO-style organisation labels: printable ASCII, comma-space-separated
  names, slash only inside organization tokens, no semicolon path parameters, no
  URL/contact delimiters, and no placeholder submitter names. Direct preflight
  and final readiness replay both pin those checks so a forged archived summary
  cannot smuggle URL-like or placeholder pending-source provenance.


<a id="record-7dbab769a81106d89387a80a45adea9f764297a3d21d4bf8f57234a3cda0d4f6"></a>

- Final readiness now treats pending-source material like other XSD package
  evidence in cross-summary replay checks: repeated pending-source message IDs,
  message names, or official catalogue/source/download references across
  distinct XSD summaries produce `xsd.pending_source_message_id_reused`,
  `xsd.pending_source_message_name_reused`, `xsd.pending_source_reused`, or
  `xsd.pending_source_download_url_reused`
  blockers, and forged single-summary pending-source counts, duplicates,
  already-checked-in, already-blocked, or no-current-gap records are pinned by
  adversarial tests.


<a id="record-fb580d1e0a3b251638b4e2b4dee1ea451fac8c010b5dc4fc78a30f9933059b44"></a>

  readiness replay.
