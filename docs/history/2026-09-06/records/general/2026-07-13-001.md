## 2026-07-13 AED/SBP retail FX fail-closed routing



<a id="record-ed121a52a62994e10aa127c35b8744f1ba743300ef665b968306c58735a7fe0f"></a>

- Added signed `POST /v1/retail/recipients/route`, returning exactly
  `{account_id, alias_fqn, fi_id}`, and applied the same fail-closed gate to the
  existing bank-name lookup. Both require an existing signer, an enabled
  configured `transaction_authority` policy, positive policy-scoped source
  balance, and the dedicated `torii.recipient_lookup.requests_per_minute`
  limiter (default/maximum 30). Configuration selects the policy with
  `torii.recipient_lookup.policy_id` (default `cbuae_aed_sbp_pkr`).


<a id="record-27d1bdc0de6158b2e537dca0e71bf2b278870d2d8a77e91aaa67917840d46900"></a>

- Added signed `POST /v1/fee-sponsor-policies/by-id`, which returns the direct
  canonical on-chain policy only when that exact sponsor/name is selected by
  dataspace configuration. Removed runtime and SetNexus synthetic allow-all
  policy fallback/seeding; missing stored policies now fail closed. The Taira
  helper accepts an exact canonical policy JSON document and rejects broad
  allow rules instead of constructing one.
