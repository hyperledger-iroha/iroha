## 2026-06-09 ISO CLI and XSD identifier guards



<a id="record-79d8cc8bf6acc792703b7baaca8d30bf955f98762a3816b3e95bfa2d73124939"></a>

- Hardened the raw CLI secret preflight shared by the ISO rail gateway, audit
  notary adapter, operator canary, receipt verifier, trust-bundle verifier, XSD
  fixture verifier, evidence verifier, and production-readiness rollup so every
  entry point rejects the unsupported `--` argument terminator before argparse
  can echo trailing unparsed values.


<a id="record-e6f08ec3b9dd51682025cbda608e647ba1b18d2f7351b957e2367258495cf38f"></a>

- The same raw preflight layer now rejects unknown CLI tokens carrying ASCII
  control characters with label-only diagnostics, so terminal-control bytes
  cannot reach argparse's unknown-argument output.


<a id="record-db45aed8e2d08ee08c1b17b4124a1f28b61a4bd2520dcab0dc95fc8ae72934dd"></a>

- Unknown raw CLI tokens must now be printable ASCII as well, preventing
  Unicode-confusable option spellings from reaching argparse diagnostics.


<a id="record-6357d33f064b33c455db01a38de8cd209d9947ca51c597becd9c33f182c04df0"></a>

- Required notary/rail URL values now reject control characters, non-ASCII
  characters, surrounding whitespace, and non-URL-shaped secret-looking
  material in the preflight layer before unrelated required file or directory
  checks can mask the malformed URL.


<a id="record-0596141719d4dcbd804964617647fe572149f3e777b0b3a7544f64f773572211"></a>

- Shared ISO URL host validators now reject non-ASCII raw host labels before
  secret, IP, or numeric-label checks run, so Unicode digit confusables cannot
  be accepted as numeric host material or preserved in diagnostics.


<a id="record-7bbb1e41eec9f6f7c89afe4447b081ffd8c50ddd3529025c6a6c0d7b533a68b4"></a>

- Direct numeric CLI values for rail, notary, canary, trust, XSD, evidence, and
  readiness tooling must now remain printable ASCII before Python's numeric
  parsers can accept Unicode digit confusables as timeouts, byte limits, or
  evidence age budgets.


<a id="record-fd8ddbc6af96b699000fcbb8d652029acaa764c8b651c0d40479652e9ea663f3"></a>

- Archived canary command replay now rejects unsupported flags with
  secret-looking material or non-ASCII spellings using label-only diagnostics,
  while preserving explicit unsupported-flag names for ordinary benign typos.


<a id="record-b1a532baa486e5fcbb78e3521028d7924dd8765d7d63ae2f84293d4e1ef51b84"></a>

- Archived canary child-command interpreter names now accept only ASCII decimal
  version suffixes, so Unicode digit confusables cannot satisfy runner-shape
  replay as Python version numbers.


<a id="record-16d3770961ad659f5ce77d8fb55a231ba57b5168585bfe4009a15ab8d9770d4b"></a>

- Archived canary child-command floating timeout flags now reject non-ASCII
  numeric spellings before Python's `float()` parser can accept Unicode digit
  confusables as production replay evidence.


<a id="record-4cce1681c90fc42dc8ce855cb1ffac156590cb14d4e226665430b81a08c2154c"></a>

- Canary runbook path strings and archived canary child-command local path
  values must now remain printable ASCII and within the 4096-character local path
  cap, while production-readiness compact summary/config/receipt path strings
  retain the stricter 2048-character archive cap. This prevents
  Unicode-confusable or oversized path evidence from being planned, replayed, or
  preserved in release archives.


<a id="record-d4a46b63f50627fdd20bbb18311832db1907b8fd4d9cae12a424e2f13c5ae503"></a>

- Direct ISO local CLI/output/artifact path validators now also cap path strings
  at 4096 characters across rail, notary, canary, receipt, trust, XSD, evidence,
  and production-readiness tooling before secret scanning, filesystem expansion,
  summary emission, child command construction, or archive replay can process
  oversized operator-local paths.


<a id="record-265e3180b0f53409b7838e952021a9685e8fe562d9083b3beef8b182b6b2cfd1"></a>

- Notary and receipt replay clean metadata strings from audit indexes, persisted
  records, nullable context/metadata/history fields, and rail sidecars now cap at
  4096 characters with label-only diagnostics before mismatch, source replay, or
  sidecar validation can retain oversized operator evidence.


<a id="record-c168bb96fffe47732c33dea128211c50b61ce7b82e94abcd73e4e30555119c2e"></a>

- Direct trust-bundle generic strings/OID lists, XSD profile-catalog generic
  strings/lists, canary runbook generic strings/lists, and evidence replay clean
  strings/lists plus production-readiness compact clean strings/lists now share
  the 4096-character label-only cap before trust preflight, XSD profile
  validation, planning, archive replay, or final readiness replay can preserve
  oversized metadata; embedded trust/profile DER base64 still uses its separate
  decoded-size guard.


<a id="record-580a2fba9f182d064eb1f7ffe3b8eab9c85b93845cafeffc27828c24c9f34ad0"></a>

- Summary/profile outputs and rail/notary receipt output directories now reject
  checked-in `fixtures/iso20022/` artifact destinations before parent creation,
  temporary output creation, or receipt writes, so operator release evidence
  cannot be emitted into the repository fixture corpus.


<a id="record-413c0a941eda511693292e1a39385d56c5bfe71b4470f932ae434f435cb59c54"></a>

- Production-readiness replay now reports XSD summaries generated from the
  checked-in `fixtures/iso20022/xsd/fixture_manifest.json` corpus as
  `xsd.repository_fixture_manifest` blockers by default, and rejects XSD summary
  input files under checked-in ISO fixture coordinates as
  `xsd.repository_xsd_summary` blockers. Local `--allow-reviewed-xsd-gaps`
  diagnostic runs can only downgrade reviewed corpus warnings, so repository
  fixture summaries cannot pass as production XSD package evidence.


<a id="record-2377e76bbeeb9f91e31a20f5b42af78eefd70e0f2aa182244bff3443ddb8bed4"></a>

- Rail receipt verification now preserves source XML paths as compact
  `source_path` evidence and rejects checked-in `fixtures/iso20022/*.xml`
  fixture paths; operator evidence and production-readiness replay reject forged
  compact receipt source paths that point back at repository XML fixtures. The
  rail gateway adapter now rejects checked-in ISO XML fixture inputs before
  network delivery or receipt output.


<a id="record-9eb83acaf485af19228fe40b022e8f2f51f55c1a5824765743b3037c06bad06c"></a>

- Notary receipt verification now preserves compact `anchor_path`, `store_dir`,
  and `index_path` evidence, requires the anchor path to stay either
  `latest.notary.json` or `anchors/<index_sha256>.notary.json`, requires the
  index path to remain the `messages.index.json` peer of that anchor export, and
  includes all three values in evidence/readiness direct-archive metadata
  binding so copied summaries cannot strip or drift the operator notary preimage
  path, source store, or exported audit index while retaining matching digests.
  Raw receipt verification rejects notary anchor/store paths under checked-in
  `fixtures/iso20022/` artifacts, and compact replay rejects anchor/store/index
  paths under those artifacts. The audit notary adapter now rejects checked-in
  notary anchor/store fixture inputs before network delivery or receipt output.


<a id="record-5f77fcece605270413f233c10c16f54ff2d588e497cc9512f793d463e40b2211"></a>

- Unknown JSON field names with non-ASCII characters, overlong spellings, too
  many entries, or collectively oversized spellings now use the same label-only
  unknown-key diagnostic as secret-looking and control-bearing keys across the
  eight ISO scripts, while ordinary ASCII typos still list the field names.


<a id="record-a7d866c7b4fbce3e3e5ae5315c04d129552e19d87c58fa11b82d89c1fd1c7ea9"></a>

- Receipt verifier, evidence-verifier, and production-readiness `receipt_kind`
  values must now remain printable ASCII, so Unicode-confusable unsupported kind
  labels fail before diagnostics or blockers can echo them.


<a id="record-0c60d659b27ee0228bddf63c10f83a0c89361f433d0f7f597661dc07c4165434"></a>

- Trust source authority/version provenance must now remain printable ASCII in
  trust-bundle verification, evidence replay, and production-readiness rollups,
  preventing Unicode-confusable source labels from being archived as release
  provenance.


<a id="record-1619ed915c0fc65219929c026f4aac907f098fc5c0ac891709d74303eb0989b7"></a>

- Trust-bundle preflight, evidence replay, and production-readiness replay now
  cap trust-source `retrieved_at`, compact trust `verified_at`, canary
  timestamp windows, and top-level evidence/XSD `verified_at` values before ISO
  timestamp parsing, so oversized timestamp evidence reports label-only
  diagnostics instead of being parsed, echoed, or preserved.


<a id="record-715d5b783cbb282659826aabcb3b858e6f278d92077870d46e91e3c371937ee9"></a>

- Direct trust-bundle DER labels and archived evidence replay DER labels must
  now remain printable ASCII before summaries can preserve Unicode-confusable
  material.


<a id="record-e7ac5a797ba5fd512332deba142fab6544ee4e0404d34ff6b2b45e4851123568"></a>

- XSD manifest `payload_root` values, checked-in schema `targetNamespace`
  attributes, schema payload element names/types, XML fixture namespace/name
  identifiers, and schema-root attribute names must now remain printable ASCII
  and no longer than 256 characters before mismatch diagnostics can quote schema
  or fixture material. Optional `xmllint` diagnostics now redact non-ASCII output
  as well as secret-looking and control-bearing output.


<a id="record-f502704956186da1c04413bf6a2ada880f1ddd7655010adad7d9da7532520d63"></a>

- Checked-in and blocked-candidate XSD source provenance paths must now remain
  printable ASCII and no longer than 2048 characters before direct XSD
  summaries or production-readiness replay can preserve them.


<a id="record-dbad53621cbc451bfa2b6b82073eed45d56d5c4a2ac215f011774d60911f72ed"></a>

- XSD manifest schema paths, fixture paths, and fixture schema references must
  now remain printable ASCII and no longer than 2048 characters, and archived
  readiness replay rejects URI/drive prefixes plus malformed or smuggled
  percent escapes before preserving relative path evidence.


<a id="record-679d27893d03005566193934055287dfa4df02d00dbaf8833f619bfc2bd51116"></a>

- Optional XSD `xmllint` schema validation timeouts are now capped at 300
  seconds in addition to being positive and finite, so oversized timeout values
  fail before a validator child can be launched.


<a id="record-b2fb2e2e00eacbfa547ecd95584344b1bb6ad3f36a4d72db67467c272ca4d1a7"></a>

- Reviewed XSD gap reasons and blocked-source review reasons must now remain
  printable ASCII, secret-looking-free, and capped at 1024 characters in direct
  XSD verification and production-readiness replay. Archived
  `missing_schema_fixtures` and `schema_only_entries` copies now parse their
  paths and reasons with the same validators before readiness can preserve or
  compare them, so Unicode-confusable, oversized, or path-smuggled reviewed-gap
  material cannot be retained by digest-bound summaries or echoed by readiness
  diagnostics.


<a id="record-106ef77042005fb0a5c75836d9a2776e8ca4ddf9c50b1623173b01ce9d5fb27d"></a>

- Live rail sidecar and archived rail receipt `message_type` values must now
  remain printable ASCII before unsupported-message diagnostics can quote
  material. Live rail sidecars must also match the lowercase ISO family-id shape
  before an unsupported-message diagnostic can print a short family value. Rail
  message-type regexes now use ASCII-only digits, and XSD profile-catalog
  `message_def_id`/version regexes now use ASCII-only digits before
  missing-schema or skipped-version classification.
  evidence and readiness archive/canary receipt kind, filename, and metadata
  mismatch blockers no longer print receipt kind values, receipt leaf names, or
  full metadata tuples after invalid marker material is detected.


<a id="record-a51da7517a9688d7c95ef6695c12cd9d2c28efe29cf5f698354d272aed74cc44"></a>

- Evidence and readiness canary rail trust-coverage blockers no longer print
  compact receipt profile IDs or canary environment labels when a rail receipt
  lacks matching trust material.


<a id="record-a6b32b9d6db25607eb286e1088c7fb9252d25b9b4a45c8071d30ec5cd5866e7c"></a>

- Trust-bundle preflight, evidence-verifier archive replay, and
  production-readiness compact trust profile IDs, override IDs, and embedded
  signature policy strings must now be no longer than 128 characters, and
  trust-source authority/version provenance must be no longer than 256
  characters, while trust/evidence/readiness timestamp strings must be no
  longer than 128 characters, before preflight/replay diagnostics, archived
  compact trust summaries, or readiness blockers can print them.


<a id="record-b4344a86acfbb4b2fcd0a43138481ed2e4ab2c4ce3dd67784fb3ac5bdb3201f3"></a>

- Provider/environment context labels must now remain printable ASCII at the
  canary runbook, trust-bundle environment, evidence-verifier CLI/archive, and
  production-readiness CLI/archive layers, so Unicode-confusable release
  context cannot be persisted or reflected in mismatch diagnostics. Expected
  provider/environment mismatch diagnostics now report label-only failures
  without printing the observed or expected context values.


<a id="record-eab8f9f665e9d121d2e4407240e6718b180088e90985e54f18261cced5dce3a7"></a>

- Archived canary stage names must also remain printable ASCII in evidence and
  production-readiness rollups, so Unicode-confusable stage labels fail before
  unsupported-stage diagnostics can echo them.


<a id="record-fd39d275539e782c4c4506cfdfe0bae90a03d8ea52fb99f677dce52f12d35942"></a>

- Extended the same fail-closed terminator rule into boolean, path, context, and
  numeric preflight helpers so direct helper calls cannot silently stop scanning
  at `--` either.


<a id="record-25b738902a3a994c7f8fd49a5573c125173e142d32c164677264c58f8882f0c8"></a>

- Added adversarial helper-level coverage across all eight ISO entry points for
  `-- --summary-out token=...`-style inputs, asserting each helper layer reports
  only the terminator policy and never reflects the hidden token material.


<a id="record-e8199dbf820db0bdce350d9a1236692fdd11c486ef1be68eeeec48efc600f453"></a>

- Disabled argparse long-option abbreviation for the same eight ISO CLIs, so
  partial flag spellings such as `--summary-ou` and `--receipt-di` cannot be
  accepted as exact production options after preflight matched only canonical
  flag names.
