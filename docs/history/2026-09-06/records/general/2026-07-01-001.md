## 2026-07-01 Nexus autoscale future-created repair



<a id="record-8858406a7a0ac3e0e9db6a4d5017df0ceae6b155bd0d28c68c41771507ecc1ab"></a>

- Kept valid committed autoscale lanes protected from manual retirement while
  allowing explicit operator repair retirement of future-created corrupted
  autoscale lanes. Torii and queue valid-lane fixtures now seed the committed
  height so endpoint and routing coverage distinguish valid committed ownership
  from future-height corruption.


<a id="record-fec610c6753ed57963b6fa21d067a7e14e5d8ff1ad6c0560061cbf26c8393ebb"></a>

- Public-lane staking mutations now bind authority to the account whose
  validator or economic state is being changed: validator registration and exit
  require the validator account, registration initial stake must be
  validator-owned self-stake, and bond/schedule-unbond/finalize-unbond require
  the staker account. Added adversarial `iroha_core` tests for non-validator
  registration/exit, mismatched initial stake accounts, and non-staker
  bond/unbond/finalize attempts.
  IVM AXT policy snapshot derivation,
  cached-policy reads, and AXT policy cache rebuild/prune paths now also
  re-check target lanes through that
  height-aware active-lane boundary, so Space Directory manifests or stale cached
  entries cannot expose or persist future-created autoscale lanes before
  activation. The low-level active-lane authority boundary now also verifies
  the caller-supplied dataspace against the lane catalog and requires a live
  dataspace catalog entry, so forged dataspace context or removed dataspace
  bindings cannot keep an otherwise active lane authoritative.


<a id="record-3bc5ed261db48edc661549e714a692dd79407dc4e610bae3d1d87d8ba71b236e"></a>

- Stake/QC active-lane filters now exclude autoscale-reserved lanes and manual
  occupants of the elastic range, preventing corrupted lane records from
  contributing public validator stake as ordinary active lanes.


<a id="record-3d28c6859dfea5ec89fe24d08aefffd402fd49a2841da09c76d4488210c91b3d"></a>

- DA active proof-policy admission now rejects manual lanes in the autoscale
  elastic range and malformed autoscale-reserved metadata while preserving DA
  policy for valid autoscale elastic lanes. Consensus and state DA commitment
  validation now pass the candidate block/proposal height into that policy so
  future-created autoscale lanes cannot carry accepted DA commitments before
  their declared creation height. DA pin-intent sanitization and inbound block
  validation now apply the same candidate-height boundary, preventing local
  spools, received blocks, state ingestion, or Kura replay from sealing pin
  intents against not-yet-created autoscale lanes. Torii DA commitment,
  proof-policy, and pin-intent read APIs now apply committed/proof/intent
  block-height policy views so stale future-created autoscale lanes are not
  advertised, listed, proven, or verified through public read surfaces. Block
  validation and proposal assembly also compute DA proof-policy header hashes at
  the block/proposal height, so headers cannot advertise proof policy for
  future-created autoscale lanes before activation. State DA commitment
  materialization and Kura replay now use the commitment block height for
  query/identity visibility of current-catalog lanes, preserving canonical
  historical bundles for removed lanes while refusing to reserve visible
  identities for not-yet-created autoscale lanes. Torii DA ingest proof-scheme
  selection now uses the committed-height policy view, rejecting writes to
  future-created autoscale lanes before they are active.


<a id="record-548baf9a7c5111e8f22ce10060452cf7f855e1cfa17b8557076f097dd4d7b703"></a>

- Proposal queue lookahead now counts active lanes at the candidate proposal
  height instead of raw catalog overrides before it overfetches up to the scan
  budget. A catalog-present future-created autoscale lane therefore cannot make
  an otherwise single-lane proposal pop extra transactions for deferred requeue,
  while active multi-lane rotation still uses lookahead.
