## 2026-07-31 Finalized reserve transparency scanner



<a id="record-4a503531e49d46a14ad033bc7cd9b2fa6dd666f71679d940b5e65668213c30f2"></a>

- Added an opt-in standard-daemon scanner from the daemon-owned immutable
  reputation archive's bounded reserve-event pages into the existing durable,
  idempotent transparency source index. It reuses the canonical reserve-event
  adapter and accepts no credential, key, token, endpoint, or private payload.


<a id="record-cee2402f9a4d832b28217e15fdf8ae1a62bca8837fe0bd346227368387e3cefb"></a>

- Each tick selects the fresh committed head, queries that exact immutable
  anchor, and verifies the persisted cursor, selected anchor, and every event
  height/hash against another fresh committed projection before publication.
  Query-binding drift, malformed pagination, fork/reorg evidence, source-index
  rejection, and checkpoint failure stop the supervised service. Ordinary
  archive lag or query/projection unavailability uses bounded exponential
  backoff.


<a id="record-4af7ec78635e86d58f5e45a79ddaae46bd8869dd0b6fcf22eeea31753de80c6a"></a>

- The canonical digest-bound checkpoint advances only after source-index
  durability, making the crash boundary replay-safe. Focused tests cover
  restart continuation, exact replay after a source-write/cursor-write crash,
  persisted-anchor reorg rejection, bounded backoff, and exact config/query
  binding. Rust formatting and execution remain pending the coordinated Cargo
  lane. This closes only the local finalized reserve producer path; the other
  transparency producers, external threshold providers, public replicas and
  proofs, hardened explorer, four-validator evidence, and promotion remain
  open.

## 2026-07-31 Nexus storage-budget trust-boundary correction



<a id="record-57848bc52a4238320b26f5ca0c29dfe631030a4d07376fa4f34516bca91ce50c"></a>

- Made configured-budget application precede runtime reconciliation after the
  Sora profile, preserved the original component ceilings across repeat
  reconciliation, and removed the post-reconcile reapplication that could
  overwrite a runtime-derived result.


<a id="record-6d5c11c70e63f0e4b5893d541fac1edf21b2151a63aaa37b6bfb649c25877115"></a>

- Runtime filesystem budgets now use checked
  `(managed + available) - ceil(total * 20%)` arithmetic and fail startup on
  underflow, zero, overflow, or a cap below current managed usage. Explicit
  budgets retain warning-only low-space diagnostics but no longer downgrade
  structural probe failures.


<a id="record-12cf31a7dd021e6e0632a522a58eb8c41d9059ea6ae5aa977c26917d13ecc574"></a>

- Required every subsystem storage weight to be non-zero as well as preserving
  the exact `10_000` basis-point total, and moved checked aggregate computation
  into runtime budget application so callers cannot pair filesystem groups with
  inconsistent aggregate metadata.


<a id="record-e6e7b14524913818bb19bffc55341022a633c8c9ecaa34dd543a2ca1b4a81828"></a>

- Canonicalized accepted storage roots while permitting links only strictly
  above the managed root. Exact-root, descendant, dangling, and Windows reparse
  paths fail closed; managed-tree traversal rechecks filesystem identity and
  rejects cross-mount entries instead of silently excluding them.
