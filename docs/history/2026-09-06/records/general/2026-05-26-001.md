## 2026-05-26 Rotating Byzantine 30 TPS soak follow-up



<a id="record-01fc18c5d064e42053bd4846b752dcdd3d528180b50434c7a7792f05854aed92"></a>

- Added the 4-peer NPoS realistic transfer soak with a single rotating
  conflicting-READY peer and re-ran the requested 7,200 second path twice. This
  is still not a two-hour pass: the first run failed after 2,107.41 seconds
  because the rotating fault controller could not observe peer recovery within
  the previous 60 second timeout, and the second run failed after 6,187.40
  seconds with the 180 second recovery window before reaching 7,200 seconds.


<a id="record-8201490dae3a327e6bf880841db2ba4c22825e8f6208ad903fcfbe5e1f6caab2"></a>

- The first partial artifact at
  `/tmp/iroha-rotating-byz-2h-current/throughput-1779773155446` kept approving
  transactions with zero rejected transactions but was below the 30 TPS target
  under backlog pressure: min approved reached 32,622, min non-empty blocks
  reached 281, and queue depth peaked at 23,289 against the 3,000 soft limit.
  The second partial artifact at
  `/tmp/iroha-rotating-byz-2h-postpatch/throughput-1779783649496` also had zero
  rejected transactions, reached min approved 102,047 with max queue 65,466,
  and then failed on peer status recovery before completing the full soak.


<a id="record-d2c6552a1a013d410fcdb1788f0a6aba656a4942668d45a4b75576a22f63fc0c"></a>

- Retuned the rotating-fault defaults to a 300 second recovery window, 512
  transaction blocks, a 20,000 queue soft limit, and an 18 second average block
  interval budget while keeping the non-faulting realistic soak defaults
  unchanged. The load and drain loops no longer count scheduled fault rotations
  as consensus progress, so the stall detector now measures only committed
  blocks or approved transactions.

  `/tmp/iroha-rotating-byz-retuned-smoke/throughput-1779784524940`.
