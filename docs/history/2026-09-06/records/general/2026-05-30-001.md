## 2026-05-30 Strict rotating-fault proof, replay-only transcript fix, and soak results



<a id="record-76bf14714c07df9b7e7348e60d34ca0e19bf6689678abff0d6f316c12543aa30"></a>

- Added an opt-in strict convergence mode for the ignored 30 TPS rotating
  Byzantine soak via `IROHA_REALISTIC_30TPS_STRICT_ROTATION_CONVERGENCE=1`.
  In strict mode the harness heals the current peer, waits for all 4 peers to
  converge, and only then starts the next injected fault. When the
  test-local recovery/convergence bound is explicitly set, the status recovery
  and all-peer convergence waits are now total elapsed-time bounds; otherwise
  the full 7,200 second soak records unbounded-history catch-up tails while
  still enforcing no overlapping injected fault windows.


<a id="record-842bb98a156b831ec9ca06e071fe5063a56431db78de94fbd72faf967cae0d13"></a>

- Extended the soak artifacts with `strict_convergence_windows` and
  `strict_convergence_summary`, including the healed peer/fault, convergence
  wait duration, starting/ending block and approval gaps, and a boolean proof
  that later fault windows started after convergence.


<a id="record-8cf0817bcd8c8d1be3ca66e62499c1ae7a7b38febb05faac8178646d597d770d"></a>

- Bounded recovery gate: the current-code 900 second, 4-peer, 30 TPS strict
  rotating-fault run with `IROHA_REALISTIC_30TPS_RECOVERY_BOUND_SECS=120`
  passed at
  `/tmp/iroha-rotating-byz-strict-900s-current-BpiOvE/throughput-1780159132881/summary.json`
  with `submitted=27000`, final `min_txs_approved=27016`, final queue size
  `0`, `max_txs_rejected=0`, 11 recovery samples, all three configured fault
  kinds observed, max status wait `21685ms`, max total restart/status duration
  `28710ms`, and max strict convergence wait `6085ms` under the total
  convergence bound.


<a id="record-0f56788263264ffbc3e7aefd765683a520aba2f9de17cadaabecbba88fe53b80"></a>

- Full broadened soak: the 7,200 second, 4-peer, 30 TPS strict run passed at
  `/tmp/iroha-rotating-byz-strict-7200s-yTIzBw/throughput-1780156901915/summary.json`
  with `submitted=216000`, `target_approved=216016`, final
  `min_txs_approved=216016`, final queue size `0`, `max_txs_rejected=0`,
  `load_submitted_tps=29.997792`, `load_committed_tps=29.468991`, and final
  committed TPS `26.714793`. The harness recorded 35 non-overlapping fault
  windows across the default matrix (`conflicting-ready`: 12,
  `duplicate-inits`: 12, `drop-validator-chunks`: 11), 35 status recoveries
  with max status wait `403282ms`, and 35 convergence windows. The largest
  post-heal convergence tail was `335509ms`, shrinking a 76-block /
  10757-approval start gap to a 1-block / 418-approval end gap before the next
  fault. During the longest restart tails the healthy validators continued
  approving transactions and reached the target before the restarted peer
  finished final catch-up, so the measured issue is replay/startup latency, not
  a quorum consensus stall.
