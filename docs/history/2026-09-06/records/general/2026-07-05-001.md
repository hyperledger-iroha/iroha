## 2026-07-05 Nexus lane block session cache



<a id="record-9c7b384ea42706dd19b48320e68b680dcb25f7e7858d41cefead1d8d974fdee4"></a>

- Added a bounded `LaneBlockSessionCache` for standalone lane-local proposal,
  vote, and QC artifacts. The cache accepts out-of-order artifacts, deduplicates
  exact replays, rejects conflicting proposals/votes/QCs for the same lane
  session, checks votes and QCs against the cached proposal once available, and
  drops orphan drift during proposal reconciliation.


<a id="record-a6ebbf9b3f55ea965679fe34c7adb17475925a8f73f28761825774535046eabf"></a>

- Main-loop lane-block handlers now insert validated artifacts into that cache
  and record valid ingress as deferred `payload_unapplied` work instead of
  dropping it. Invalid proposal shapes, sender/signature mismatches, malformed
  QCs, and conflicting cached artifacts still fail closed with status counters.
  Lane QC insertion now also rejects missing signer PoPs, invalid signer PoPs,
  and forged aggregate signatures before a QC can occupy a cached session.
  Remaining live-lane work is to broadcast cached proposals/votes, execute lane
  payloads, use sealed QCs to advance lane state, replay cached lane blocks
  after restart, and cover the flow with multi-peer rollout evidence.

## 2026-07-05 Nexus artifact-backed lane proposal tips



<a id="record-458ec18e73bf4595d6276a0e57133757f847a26051d01418972a798865602a63"></a>

- Added a reusable scheduler-level lane payload plan that reduces known tips,
  applies reset watermarks, assigns next lane-local slots, derives subjects, and
  validates DA/RBC ownership identities in one deterministic step. Proposal
  preview and final execution-context assembly now share that planner so their
  lane-local ownership decisions cannot drift. The planner now also emits
  invariant-checked per-lane descriptors bundling each domain, selected tip,
  next slot, subject, ownership, and accepted transaction hashes for the future
  standalone lane scheduler, and canonical lane subject/ownership hashes now
  bind the accepted transaction hash sequence that validators recompute from
  execution-context entrypoints. Planning fails closed if those internal stages
  drift or an accepted candidate is missing a stable transaction hash before
  handoff. Each descriptor now also carries a Norito-backed lane block
  descriptor hash binding predecessor lane height, accepted work, DA/RBC
  ownership, optional predecessor descriptor hash, validator set, quorum, and QC
  mode tag, with adversarial coverage proving committee-only drift and
  predecessor-only drift change the standalone descriptor while leaving payload
  identity unchanged. Artifact-backed proposal tips now carry the predecessor
  descriptor hash forward, reset-floored synthetic tips clear stale predecessor
  hashes, and same-height tips with conflicting descriptor hashes fail closed
  before standalone lane planning can choose an ambiguous predecessor. Proposal
  execution contexts and persisted Kura
  lane artifacts now carry that descriptor hash plus replay material with each
  lane payload ownership: accepted transaction hashes, predecessor lane height,
  predecessor descriptor hash when known, canonical validator set, validator
  count, and quorum. Block validation first binds those fields to committed
  route/candidate hashes, topology or lane authority, and QC mode tag, then uses
  the same embedded replay-hash verifier as Kura artifact reads before accepting
  committed ownerships or persisted sidecars as lane tips. Validators and Kura
  reject lane ownerships that omit the descriptor, reuse subject/payload/RBC
  identity hashes, drift in replay material, claim a predecessor descriptor for
  the genesis predecessor, or carry a descriptor hash built over a different
  committee or predecessor.
