## 2026-07-04 Nexus lane block subject planner



<a id="record-a9e2df17f2a8811e04f29e5fb1bfc059d0c53015dc8ce737fa27aeee545fcafe"></a>

- Added an internal `LaneBlockSubject` planner in
  `sumeragi::main_loop::lane_scheduler` that binds lane id, dataspace id,
  caller-supplied lane height/view, QC mode tag, and exact fetched-batch
  candidate order into a stable Norito-backed digest.


<a id="record-5e59c3a6d7cdba4802bc8ef53317ec91682dd933d29c1643597fb803bb4a9a59"></a>

- Added scheduler regressions proving subject hashes change when view, mode tag,
  or candidate order drift; subject output is sorted independently of domain
  input order; malformed domains with blank mode tags, empty work,
  count/index mismatches, duplicate candidate indices, or duplicate lane
  domains are rejected.

## 2026-07-04 Ed25519 signing-seed admission

> Historical record: the Torii stream-token key-file parser and the focused
> `load_signing_key_rejects_all_zero` test named below were subsequently
> removed by the V1 hard cut. Current production issuance is controlled only by
> node TOML and an exact runtime-injected external Ed25519 signer
> handle/public-key/revision/public-policy-digest binding;
> it has no file-key or environment fallback. The remaining parser
> results in this section retain their original historical meaning.



<a id="record-05c28e0d553cdd89e5f21811ac3a5f46d1a5480e017b8ec1578a627d0e89692b"></a>

- Hardened externally supplied Ed25519 signing seed parsers that still reached
  `ed25519_dalek::SigningKey::from_bytes` directly after length checks. Torii
  SoraFS stream-token key files, SoraFS CAR provider-advert signing keys, SoraFS
  CAR provider-admission council secrets, and the `sorafs-validate` signing
  seed CLI now reject inert all-zero seed material before constructing a signing
  key.


<a id="record-7c77a3ee8ae56d547797bda95ab236c8de444e0fbf791c96bd70f224ccb736e9"></a>

- Added focused negative coverage for raw 32-byte seeds, hex-encoded key files,
  64-byte expanded-key inputs whose seed half is all zero, and prefixed
  `ed25519:0x...` CLI seed text.
