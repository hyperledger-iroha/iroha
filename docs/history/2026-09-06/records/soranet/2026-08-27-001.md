## 2026-08-27 SoraNet first-release simplification and admission hardening



<a id="record-60671069e5d20678e709dc0aefc96aae4da132374058041b11d5837d1780b44c"></a>

- SoraNet handshake admission now has one mandatory Argon2 puzzle path. The
  actual/user config, live config DTO, Kiso updater, CLI, direct P2P runtime,
  relay, and puzzle issuer no longer carry `pow.required`, puzzle-enable state,
  optional-puzzle branches, or the plain hashcash adapter. Retired JSON and CLI
  fields fail closed, every direct P2P runtime owns a durable bounded replay
  ledger, and Argon2 mint/verify work stays behind bounded blocking-work gates.


<a id="record-2d2a314ac00426a23517989ebd3c1acaf28206d1ddfbf9db1094d473519541bb"></a>

- The relay removed unused descriptor quota/replay configuration, state,
  telemetry, and privacy discriminants. Its per-remote limiter caches the active
  cooldown count and batches stale-entry cleanup instead of scanning the full
  bounded table on every admission, while forcing an exact cleanup before a
  capacity rejection. Dead production-only helpers and duplicate ML-KEM helper
  aliases were removed; ML-KEM suite parsing now accepts only canonical labels.


<a id="record-d935b405137290feef88a2659043f600de22a381e23b901f33d98af6e9abc6de"></a>

- The puzzle service keeps raw and ML-DSA-44-signed tickets as explicit
  server-selected relay policies, but exposes one tagged `credential_b64`
  response instead of a client-selected signing toggle and two nullable output
  fields. Signing key material is represented as one all-or-nothing issuer,
  mint DTOs reject unknown fields, and the reserved v1 token-flags input/output
  plus unreachable disabled-policy branches are gone. The JavaScript client,
  types, tests, and operations specification use the same first-release API.

## 2026-08-27 SoraNet VPN and shared pre-auth boundary hardening



<a id="record-aafc8b9c51a20f6c390fbf0d06bad46f172b57fd35d247c25615458917986b5e"></a>

- VPN quote issuance is stateless. A paid session is reconstructed from both
  active WSV indexes and the exact retained signed lease, bound to its canonical
  escrow-opening transaction, then revalidated against a fresh WSV view before
  Torii signs a helper ticket. The bounded session cache is optional and cannot
  override lifecycle state or reject a valid paid lease when full.


<a id="record-9f4b40d7628c566bdc00bb6cc5a67cdc6ea189017508a02d8db6eedad6686412"></a>

- TCP and address-validated QUIC share one configurable RAII per-source gate
  acquired before global pre-authentication capacity. One absolute deadline
  covers capacity waiting through signed application authentication, and exact
  reservations are released on rejection, timeout, shutdown, or task abort.
  The rejection counter is registered in the pinned telemetry catalog.

## 2026-08-27 Inrou fee-quote first-release convergence



<a id="record-72307f9360567430550747d642f728d46fb1763a812759e7f59d7d6ee42b0a86"></a>

- The typed fee-quote boundary now has one first-release contract across Rust,
  JavaScript, Swift, Python, C#, Kotlin, and Java: account and sponsor identity
  is controller-based rather than presentation-string-based, canonical aliases
  are left for Torii to resolve, signed payer/revision/gas selections remain
  immutable, component and sponsor-capacity sets are exact, JSON objects are
  closed and duplicate-free, successful responses require exactly one JSON
  media-type header, and actual success and error response bodies have an
  inclusive 65,536-byte ceiling. Sponsor-program lookup results are pinned by
  controller identity and exact program name rather than I105 display
  discriminant, including the bounded typed Rust lookup and Taira receipt
  validator. Comma-folded duplicate media values are rejected even when hidden
  inside a quoted parameter; one case-insensitive `application/json` base media
  type with optional RFC HTTP parameters, including quoted `obs-text`, is
  accepted consistently, while Unicode lookalikes are rejected by ASCII-only
  media-type matching. No compatibility spelling, fallback decoder, or policy
  toggle was added. A follow-up production audit removed the stale
  dual-revision hosted-Inrou path: deployment validation, Core/Torii placement
  resolution, daemon egress and checkpoint accounting, placement
  reconciliation, persisted snapshots, runtime-state publication, and worker
  startup all reject an active Inrou rollout and serve only the exact current
  revision. The daemon now binds every Inrou plan to the exact current block,
  admitted bundle, process/material generations, peer identity, and local
  placement set; any reconciliation error or task panic stops all tracked
  Inrou workers and withdraws their local routes. A parsed V1 runtime snapshot
  is treated only as derived node-local state: any non-authoritative Inrou plan
  is atomically scrubbed before startup reconciliation without removing generic
  deterministic-IVM plans, while malformed JSON and unknown schema versions
  remain fatal. The restart regression retains
  retired bundle and placement metadata across an atomic upgrade and proves
  that startup rebuilds only the exact new revision rather than serving a
  fallback. Retired runtime-state clears are owner-bound,
  incarnation-CAS protected, idempotent, and retried until WSV catches up, while
  checkpoint GC no longer retains a non-current revision. Core, Torii, and the
  CLI reject staged Inrou rollout transitions; generated Inrou guidance exposes
  atomic exact-revision upgrades only. Generic deterministic-IVM rollout remains
  supported. Sponsor lifecycle responses are closed, duplicate-free strict
  UTF-8 JSON with positive revision and activation values, explicit-null
  optionals are rejected, and sponsor
  names enforce the exact Rust `Name` scalar/NFC/255-byte policy. Swift rejects
  duplicate keys before decoding, the JVM clients no longer replacement-decode
  malformed UTF-8, C# fee responses ignore permissive caller JSON settings, and
  JavaScript sponsor lookup now uses the status-independent strict 64 KiB
  lossless reader rather than its generic JSON path.

  per-remote burst is disabled.


<a id="record-4a033da5098d143726c7899130ca5aaaafec80fcda608b4ed21cda42389799dc"></a>

  runtime preflight. The authenticated fixed-rate scheduler now carries

<a id="record-c2ee9836878b0730045528e61e54ca4fc51d251afff05021a211ace903d62fe7"></a>

  outbound handshakes snapshot the current policy; replay and work-admission

<a id="record-4c7eff4caa8b155798a17511d995158f7b8f831d973b4c48c40aaba5aeaec4cb"></a>

  `STARTED`; readiness requires both exact live children and a prepared journal;
  legacy state is recoverable but cannot remain active; and authenticated
  cumulative traffic reports are rollback-checked, capped at 64 per second,
  coalesced to one periodic durable write, and force-flushed on handled exits.
