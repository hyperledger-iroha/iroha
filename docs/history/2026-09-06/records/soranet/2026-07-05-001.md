## 2026-07-05 Nexus relay descriptor lineage binding



<a id="record-b68aa7452185ea7abc1318d5bc863e8a8652871f14d7417ef24e0c5465c37afc"></a>

- Lane relay envelopes now carry an optional lane block descriptor hash. The
  descriptor is included in both the FastPQ lane-relay claim digest and the
  merge-hint root, so descriptor metadata cannot be changed without changing
  the authenticated relay material.


<a id="record-2052eef549dcf1d69e2f9021d734b2e64b1d5142af25c5e54366b8ec3d95a39d"></a>

- Proposal tip planning now only trusts relay-carried predecessor descriptor
  hashes from merge-admissible relays with QC and valid FastPQ proof material.
  Pending or partially authenticated relays may advance the known height, but
  they do not bind descriptor lineage into the next lane payload ownership.


<a id="record-77621895d92e4353e0f7802e4bd831bd33b9bed3f59528be2af19d954b04f6d1"></a>

- Added model-level negative coverage for descriptor drift in FastPQ claims and
  merge hints, plus proposal-boundary coverage for QC-only and FastPQ-only
  relay metadata.

<a id="record-18546ce906e5644ac5e6cb4d51f0e984aa120a5914c8ddc946e7c832aaf95ad0"></a>

- Relaxed the in-memory lane relay cache so future relay artifacts can arrive
  before missing lower heights, while `record_lane_relay` rejects relays already
  covered by committed merge snapshots.


<a id="record-5ba47369530df4f9bf61cbe7bf8123e6358c8448c5d8790fe3d7771b57082e58"></a>

  merge-admissible relay per lane/dataspace, using lane reset watermarks as the

  `NonContiguousLaneSnapshot`, preventing externally supplied merge entries from

## 2026-07-05 Nexus verified relay reset-watermark replay guard



<a id="record-b23dc7c11415d56eeb60ceb57e3569bf6a78392876f79b1098036c8d34622d58"></a>

- Extended lane relay admission with a reset-incarnation check: relays whose
  lane block height is at or below the persisted DA lane reset watermark now
  fail with `LaneRelayError::StaleLaneIncarnation`, while catalog/activity
  validation order still preserves existing `unknown_lane` behavior for missing
  dataspace catalog entries.


<a id="record-f5d0ea2c1505774d2cdd210d6eede8d3d308b7500f4fc55a7c4f41e94c9154ac"></a>

- Added adversarial restart coverage proving a verified lane relay record from
  the old incarnation can hydrate before reset, is rejected after retire/recreate,
  has its replayed canonical and contract-map state pruned after failed
  hydration, remains rejected after JSON restart plus contract-state replay, and
  does not block a fresh post-reset relay from hydrating and producing merge
  candidates.


<a id="record-277512a04eb8e87fec81c5a70cb25ac367511737e2699d1c392377ca6ca25523"></a>

- Updated `specs/engineering_backlog.md` so the remaining independent-lane
  consensus breadth points at the multi-peer corridor rather than the now-covered
  unit restart/replay case.
