## 2026-08-03 VPN MCP and Torii-origin content security boundaries



<a id="record-54014f5dd7b913c6e4a77cf5c30c5515cafaaecea1f11d4b0ba4579ce1fcb330"></a>

- Protected VPN MCP tools now require a separate closed `canonical_auth`
  signature tuple or witness for the exact inner method/path/query/body. The
  bridge removes outer `/v1/mcp` canonical headers, accepts no generic-header
  proof injection, and routes the target proof through the unchanged VPN
  canonical verifier. POST bodies and session identifiers are exact and
  unambiguous first-release shapes.


<a id="record-e1c770a060e81106a010e87d36c5991b9be44861f7dbf5f42da2842475bd7dd4"></a>

- `/v1/content` now behaves as a byte-delivery origin. Only inert text, JSON,
  and raster-image media retain their type; active, unknown, octet-stream, and
  header-invalid values become non-sniffable attachments under a restrictive
  sandbox CSP. Protected manifests cross authentication, authorization, PoW,
  and range validation before Torii clones the bundle projection.


<a id="record-02ca5560e81ed002fae67821265617b6a11aaf2bd07635be24688f5be1f17597"></a>

- Source, focused regressions, OpenAPI, both tracked OpenAPI documents, and the
  private audit ledger are aligned. Scoped Rust formatting, JSON parsing,
  artifact equality, jq contract checks, diff checks, and audit reconciliation
  pass. Focused Cargo tests remain a coordinated release gate; this pass ran no
  Cargo command.
