## 2026-07-08 Runtime relay status identity preservation



<a id="record-2b25294b0f150a8bc73da8f359d9f03120dbe7af3a208c0ac1deeb24664d1d2c"></a>

- Merge-admissible relay rows can upgrade pending rows for the same identity,
  but later non-merge rows cannot downgrade an already merge-admissible relay.
  Descriptor drift at the same lane/dataspace/height remains visible to status
  consumers instead of overwriting the earlier row.


<a id="record-2a3bb14eaa4234336d971dd7c6c3630f066e89452ab281b4300eedc8443e6e11"></a>

- Hardened the state-side `LaneRelayStore` with the same immutable identity
  boundary before pending relay rows can be upgraded with QC/FastPQ material, so
  descriptor drift cannot overwrite a pending relay under the guise of a
  verified upgrade. The public `State::record_lane_relay` admission path now has
  regression coverage proving the rejected drift cannot overwrite either the
  state relay cache or the Sumeragi operator-status cache.


<a id="record-a10a5e356ad25b2a555b3398a1e81371116b6b621f205fc218b4eac6a028408c"></a>

- Validation passed:
  - `cargo test -p iroha_core lane_relay_envelopes_preserve_descriptor_drift_and_verified_upgrade -- --nocapture`
  - `cargo test -p iroha_core lane_relay_store_upgrades_existing_pending_after_newer_height -- --nocapture`
  - `cargo test -p iroha_core lane_relay_store_rejects_identity_drift_during_pending_upgrade -- --nocapture`
  - `cargo test -p iroha_core record_lane_relay_rejects_identity_drift_during_pending_upgrade -- --nocapture`

## 2026-07-08 Autoscale relay evidence descriptor and ambiguity gate



<a id="record-a2da358de18b8fd22e0e07e775d84962f0c991fcce45c646b84fefcc9e8a4ca4"></a>

- Hardened autoscale localnet relay parsing so lane-relay rows retain
  standalone descriptor-hash presence and merge-admissibility state instead of
  collapsing to lane/dataspace/height only.


<a id="record-4205cae1e06f2f14f33ef118079b415a32fa47e401d480b821d1e27dd42834bd"></a>

- Expansion evidence now counts only default-dataspace relay rows that are
  merge-admissible and descriptor-backed, while descriptorless or non-merge
  relay rows cannot fake scale-out progress.


<a id="record-e0713eafb98813aaaf6fe5172e1b12b25b2493373d6afd21491fb2a1f0a79f73"></a>

- Latest same-height default-dataspace relay rows now have to agree on
  descriptor hash and merge-admissibility before they are treated as
  idempotent duplicates; descriptor drift or merge-admissibility drift is
  ambiguous and cannot prove expansion.


<a id="record-d4eccb43d6d04127aa628416f25b29cbeb1364bc75c6efda69cc625aa1e7ed13"></a>

- Scale-in remains fail-closed: any default-dataspace relay row for the
  retiring elastic lane, even descriptorless or non-merge-admissible, keeps the
  lane non-idle and blocks contraction, and ambiguous latest relay evidence is
  non-idle as well.


<a id="record-50b09537e6316b56b55e4e404f163707654dee2e455084d5692ff7a2b6c4847e"></a>

- Validation passed:
  - `cargo test -p integration_tests --test nexus_and_streaming public_profile_expansion_requires_target_lane_relay_progress -- --nocapture`
  - `cargo test -p integration_tests --test nexus_and_streaming public_profile_contraction_rejects_missing_base_or_lingering_elastic_state -- --nocapture`

## 2026-07-08 Descriptor-backed relay predecessor planning



<a id="record-4ba3af099ef6dcadd8b783bfc52251c036e50023d39e1d6d4d4bb10ceb997db9"></a>

- Hardened proposal predecessor-tip assembly so cached lane-relay envelopes only
  seed lane-local predecessor tips when they are merge-admissible and carry a
  standalone lane-block descriptor hash.


<a id="record-8c66b71d3078c7a2399783d1da8e89fe272785df89a180fcf4007bb7236efcda"></a>

  descriptorless relay cannot outrank a lower descriptor-backed lane artifact
  and cannot make the next ownership row inherit a descriptorless predecessor.
