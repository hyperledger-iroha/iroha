## 2026-08-26 SoraNet admission, replay, and relay hardening



<a id="record-bb06725a0fc99db5c1bd45c109bc0c1a1aad43b16c500766cb128eeaed60413f"></a>

- SoraNet startup now cross-checks the selected ML-KEM suite and descriptor
  commitment against both advertised capability roles, synchronizes only the
  bundled default capability vectors when operators override those selections,
  rejects replay-store TTLs shorter than the accepted ticket window, and rejects
  duplicate relay IDs. Argon2 difficulty replacement revalidates the full policy
  and cannot create a zero-work verifier.


<a id="record-1620275e9c310c33f5bb0065946a9d453ae2ce35ca231df1dc5454844d41186b"></a>

- Durable replay state rejects terminal `.lock` names and filesystem aliases that
  can collide with its ownership sidecar. Missing parent chains are now synced
  directory-by-directory, including failure/retry repair. Relay admission accounts
  by canonical IP instead of source socket, treats IPv4 and mapped IPv6 as one
  client, and evicts bounded inactive congestion history before it can deny all
  unseen clients. VPN routes and resolvers reject host-bit, semantic-duplicate,
  and non-unicast inputs consistently across the relay and privileged helper,
  including IPv4-mapped aliases.


<a id="record-95feca7ec6788c8bf7e25b8e4773e48bec24eab1df959dde3a7d65bf06a06ec7"></a>

- Focused validation passed: the 403-test `iroha_crypto` SoraNet filter, the
  runtime handshake regression, the complete 460-test relay library suite, and
  the focused VPN route/DNS suites. Relevant Rust formatting and whitespace
  checks passed. The several-hours full workspace suite was not run.

## 2026-08-26 SoraNet correctness audit



<a id="record-f61fbae6f41b4c4e6ac117a04bb581a11c3b5d0e3e591e5bec355925e63cb86b"></a>

- Constant-rate cells now use deterministic smooth weighted round-robin for
  their documented 8:4:1 control/interactive/bulk shares, so sustained control
  traffic cannot starve lower-weight queues. Decoding also rejects undeclared
  nonzero data and dummy padding instead of accepting noncanonical covert bytes.


<a id="record-a85a2c587119ab8afcd6139caddd55f66b10d00538189a7baa17962e5d1ffad8"></a>

- NK2/NK3 client and relay parsers reject reused static/ephemeral Noise keys,
  including alternate X25519 encodings of the same effective point. Capability
  comparison no longer treats the advertiser-local required-policy bit as
  capability identity. Certificate encoding enforces the exact ML-DSA-65
  public-key length, and the canonical C++/Go/Rust interop vectors now reflect
  mandatory dual-signature relay authentication.


<a id="record-c5e257dda0173d1f88280799be09f0ff710ea1ee3a140ced540df2ffd25a29fb"></a>

- PoP validation rejects health checks and promotion gates that name undeclared
  services, including direct `evaluate_health` callers. The guard-capacity
  helper is directly executable, rejects invalid modes and non-positive tuning
  values, avoids zero-size cooldown advice, and fails closed when a scrape lacks
  any required counter for the requested mode.


<a id="record-3335301ea122263252bb2e6f26b92bdca98c330cf8605e9f9ea4f4a6dd475908"></a>

- Focused evidence is green: the rebuilt `iroha_crypto` SoraNet filter passes
  397/397; relay PoP validation passes 5/5 plus the direct-health regression;
  the Cargo scheduler suite passes 14/14; interop mirror parity passes 1/1; and
  the Python capacity suite passes 8/8. Scoped Rust formatting, JSON parsing,
  whitespace checks, and the retired-codec guard pass. The full workspace and
  strict all-target Clippy matrices were not run.



<a id="record-c2d973d3b14c654718719e265485f1fc15c5e2cb9f901fda3146d4a77515d82a"></a>

<!-- Original context: Status / 2026-08-26 Kaigi lifecycle and projection correctness -->
- Account and relay teardown no longer decode every reserved Kaigi value in the
  world. A snapshot-skipped reverse account-dependency index selects only the
  active calls, relay descriptors, and feedback rows that can reference the
  requested lineage. Exact metadata/key validation remains fail closed, and
  both the current and latest-block undo projections are rebuilt on restart.


<a id="record-c88273f0b0c97445ddf2746d1f05d889acfec24e0930d85d708bfc2c797f84a6"></a>

- Relay home-domain selection is bound to the active relay account's live
  domain-qualified primary alias. The insecure world-wide allowlist fallback is
  removed, unrelated malformed allowlists cannot redirect or block a relay,
  allowlist membership follows explicit typed rekey lineage, and two IDs from
  one relay lineage cannot fill separate manifest hops. Descriptor and feedback
  metadata retain exact key/embedded-ID integrity; corrupt retained rows fail
  closed in alias-move and teardown guards. A relay's primary alias may change
  within its storage domain but cannot clear or cross domains while either a
  descriptor or feedback remains.


<a id="record-7b442c2289be36c40d9bb665596d9c6997d386c24d716e187611d29d88e5e79d"></a>

- First-release relay descriptors now have immutable protocol bounds: each HPKE
  public key is non-empty and at most 4 KiB, and each manifest contains 3–8
  hops. Core enforces the limits before JSON persistence, event emission, or
  manifest set construction. Core mutations and Torii projections also reject
  persisted manifests that violate the V1 constraints, so legacy rows cannot
  bypass the new admission checks. Torii rejects stale oversized descriptors;
  and the CLI plus JavaScript, Python, Swift, Kotlin, and mirrored Java builders
  enforce the same exact 4096/4097-byte and 8/9-hop boundaries.


<a id="record-0d8ed220041b96db22b97c674fa71c8c556e5644713f724acbed906f2180dc85"></a>

- The live relay registry is capped at 500 validated descriptors. Exact
  re-registration is an event-free no-op, key rotation remains available at the
  cap, and `UnregisterKaigiRelay` lets a relay or its unique active account-ID
  rekey successor atomically remove the descriptor and retained feedback even
  while repairing a legacy over-cap registry. Existing manifests keep their
  pinned keys, while future admission requires a live descriptor. A derived,
  snapshot-skipped relay-to-domain index is rebuilt from authoritative domain
  metadata, rejects malformed, duplicate, or mis-homed rows, and bounds Core
  admission plus Torii relay reads independently of unrelated metadata volume.


<a id="record-478b4319eadaff962f5718e1c317efd0f2a32496ff9ffba9938879b2b6737256"></a>

- Governance relay allowlists now share the 500-identity registry ceiling and
  the immutable 1 MiB native-metadata bound. Generic domain metadata writes,
  domain creation, runtime loads, snapshot rebuilds, and undo-layer rebuilds
  reject malformed or oversized state. Manifest validation caches one decoded
  allowlist per domain and performs the full live-versus-persisted lineage check
  on the matched identity, preserving retired-predecessor authorization without
  scanning and resolving every allowlist member.


<a id="record-7981bce12f4a247a3cfd99a018009a18ad5b51874318504642414118dc16812f"></a>

- Expired relay aliases no longer make their already-persisted descriptors
  unmanageable: the validated registry retains the authenticated storage home,
  subsequent admission ignores the stale alias, and the relay can still retire
  its descriptor and feedback. Strict snapshot finalization rejects malformed,
  duplicate, and mis-homed relay rows.


<a id="record-e6d6f0a48f09dfe41a868e96729ff8eaeefbf6697c1c14cb523368eb45cfd05e"></a>

- Relay feedback is block-time bounded and nondecreasing without allowing one
  transaction arrival order to decide equal-time observations: every
  non-identical equal-timestamp report rejects across calls, exact duplicates
  are event-free no-ops, and call feedback remains diagnostic rather than a
  global manifest-admission veto. Unicode-facing limits count characters rather
  than UTF-8 bytes. Restore applies the same 1 MiB JSON, 512-character note,
  registered-home, and authenticated ledger-time bounds to both current and
  latest-block undo projections, so a wrong-home or future singleton cannot
  strand relay state or poison all later reports.


<a id="record-69df69447b55afad124315a5e4325e1747010ad811a3b2519321d2544881bc8d"></a>

- Roster, usage, manifest, relay-retirement, and lifecycle summaries/telemetry
  are emitted only after the bounded metadata write succeeds; rejected
  transitions leave both state and external observations unchanged. Full
  reserved Kaigi metadata events remain available to native trigger processing
  but no longer enter the public event buffer.


<a id="record-e330579d667c161d5bd1a7e112820848388e42dd93ab7cd10839a601c754fde3"></a>

- Python and JavaScript relay-summary/event decoders now require dense bounded
  arrays, present exact unsigned counters, a bandwidth class in `1..=255`,
  exact 32-byte HPKE fingerprints, and canonical nonempty HPKE Base64;
  booleans, floats, coercible status objects, malformed notes, and incomplete
  SSE envelopes fail closed. JavaScript Kaigi
  builders also reject non-null unit-enum state and every nonzero legacy
  nullifier timestamp alias instead of allowing one canonical zero field to
  hide another alias.


<a id="record-e4e152fd207876106ba1b246d4ff7b25ce35e536eeed60408eb9a45eca7d8dd9"></a>

- Kotlin and Java Kaigi templates retain 64-bit usage durations, bound relay-hop
  indices before allocation, require contiguous manifests, and reject clear
  privacy identity/timing hints. The CLI now rejects zero limits/durations,
  third-party billing, empty relay keys, zero relay weights, duplicate manifest
  relays, oversized notes, incomplete or empty proof groups,
  transparent-create privacy payloads, and every on-chain privacy leave payload
  before submission. Hash inputs accept either bare hex or one lowercase `0x`
  prefix, but reject repeated prefixes instead of letting the underlying hash
  parser reinterpret them. The demo uses its `TORII_URL` override for both
  readiness and transaction submission.
