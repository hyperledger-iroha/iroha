<!-- Original context: Status / 2026-07-01 Nexus autoscale future-created repair -->
- Lane relay authority now applies the same activation-height boundary before
  accepting manifest-bound or commit-topology-derived validator sets for
  autoscale elastic lanes, so relays for not-yet-created lanes fail closed and
  are not cached. Corrupted manual lanes inside the reserved autoscale elastic
  id range are also denied relay authority. Lane-relay emergency override
  admission now uses the same height-aware active-lane dataspace boundary before
  storing override validator sets, so a catalog-present future-created autoscale
  lane cannot persist emergency relay authority before activation; record-level
  relay admission now also rejects inactive lanes before consulting any stale
  emergency override already in state. Merge candidate synthesis and commit-time
  merge snapshot validation now apply the relay snapshot height before accepting
  lane snapshots, so legacy relay store entries or persisted verified relay
  contract-state records for future-created lanes cannot hydrate, restart-hydrate,
  or merge. Verified relay contract-state cleanup now also trusts exact
  canonical reset-lane key ownership even when the decoded payload claims a
  different lane, while still refusing payload-only deletion of unrelated
  contract-map keys. Public manifest validator-binding reads now also use the
  committed lane-authority height, so Torii's manifest-preferred authoritative-peer
  and proxy candidate paths cannot expose future-created autoscale lanes before
  activation. They now also apply the same live consensus-key filter as relay
  authority before exposing explicit manifest peer bindings, so pending,
  future-active, disabled, or expired manifest keys stay installed as raw
  fallback-suppressing manifest entries but are not advertised as active
  public-lane validator bindings. Manifest, commit-topology, and stake-derived
  authoritative lane peer sources, plus account-level authoritative validator
  reads, now also require the peer to still be present in the world peer set as
  well as having a live consensus key, so stale peer membership cannot remain
  authoritative through leftover key or stake records. Account-level manifest
  authority now honors explicit validator-to-peer bindings before falling back
  to validator-account signatory inference, so manifests can bind operational
  BLS peers without making the validator account key itself the consensus peer.
  Explicit manifest bindings are now normalized to one live binding per
  validator and per peer before public binding, route-authority, peer-authority,
  or account-authority reads consume them, so duplicate manifest rows cannot
  inflate validator or peer weight.
