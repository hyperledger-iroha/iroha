## 2026-08-25 Inrou PortableVM V1 admission



<a id="record-ed13bd71f4da878ae043e609d864084bb0b45a35ed4d27405e8c5a27cbfa13cb"></a>

- `soracloud_runtime.inrou.enabled` remains false by default. Enablement is
  accepted only in production mode; non-production enablement is rejected. An
  enabled production runtime has no backend or concurrency selector: it has one
  fixed PortableVM V1 path with one VM, mandatory canonical-slot uid/gid, one
  exact operator-approved guest artifact, bounded immutable guest-image
  materialization, and CPU, memory, and writable-storage budgets. Retired
  backend, accelerator, concurrency, supplementary-group, and control selectors
  remain hard configuration errors; disabled configurations cannot retain an
  identity or trusted guest artifact. The generic guest-image bound defaults to
  4 GiB and cannot exceed the 16 GiB production ceiling.


<a id="record-f32330ecf204d66f7eb97fe115228c68ac6b153e22932890721170b1c6b5fe08"></a>

- Public Inrou host records advertise exactly one guest ISA and capacity one,
  bind the canonical peer spelling to an active validator, and reject unknown
  fields. Placement and runtime-state writes fail on absent assignments,
  non-assigned authorities, identity drift, invalid schema versions, and stale
  timestamps instead of normalizing, clearing, or succeeding as no-ops.


<a id="record-fe1412117d1af4a90223d3743f2bd8b3b05fad766bf01a5964186b6b51ea2cb8"></a>

- Stateful Inrou placement is fail-stop for one economic lease. Reconciliation
  preserves each slot's exact validator, peer, guest ISA, and placement
  incarnation, marks the assignment unavailable when that exact host becomes
  ineligible, and permits only the same host to reactivate. There is no
  in-lease reassignment or migration flag. Sparse bounded slot records remain
  canonical, and unavailable or stale-incarnation runtime state cannot serve or
  enter Torii routing.


<a id="record-480041a581c4f89886497a5cd990c10aa6951468faa5fae59eeb1d68918c0bdc"></a>

- The one-variant backend enum and its `selected_backend`, `backend_mix`, and
  devnet-output projections are deleted. Staged service/container records,
  Inrou instruction wrappers, and persisted runtime plans reject unknown fields
  and require every canonical key, including explicit nullable keys. A corrupt
  or empty persisted runtime snapshot is an error rather than an absent
  snapshot, and Torii routes only through an authoritative healthy placement;
  no host-local snapshot bridge can override it.


<a id="record-5eedc9470d46ce3c1a4ada6a6c6b4e664cf9071967e065658529fdb414c840f9"></a>

- First-release hosted Inrou services have one active revision. Admission and
  runtime projection reject `1..=99` canaries because host-local lease disks
  have no authenticated state-migration protocol, and Torii rejects any
  persisted hosted active-canary state on both ingress and exact peer proxy
  paths. An unavailable current revision fails closed instead of falling back
  to another revision. Deterministic IVM services retain canary rollout.


<a id="record-41b75907b3874a1d583d731e76bd81bda31bf48f09360ba95762e87cbad4e1c5"></a>

- Every admitted Inrou guest-image record now carries one concrete
  `SoraPublishedInrouGuestImageArtifactV1`; null, omitted, and bundle-local
  fallback forms are not admitted. The CLI's private unpublished workspace
  records instead require the publication field to be exactly null, consume
  that draft during publication, and construct the admitted bundle only after
  its immutable artifact references exist. The canonical
  `manifest_digest_hex` is the sole storage identity; the retired nullable
  `manifest_id_hex` field is rejected in JSON and Norito. Runtime hydration
  fails closed when the signed bundle has no Inrou manifest, selected guest ISA, or exact
  authenticated published artifact, and never substitutes a bundle-local kernel or
  root filesystem.


<a id="record-1844bb4c891ba0529ac11eaf1feb77a6731194b3bb37d36d710b2d7ece512eae"></a>

- The test-only blanket admission bypass was deleted. Runtime managers begin
  without an Inrou capability; the production startup routine is the only path
  that installs one. Its static checks authenticate the minimal runtime closure,
  and its artifact-free live probe exercises the production machine type and
  host CPU under KVM, private mount/network/IPC/UTS/PID/cgroup namespaces, exact
  cgroup-v2 limits, locked identity and filesystem custody, anonymous QMP, QEMU
  user networking, the private loopback connector, and the owner firewall. It
  does not boot a guest or launch a workload. Reconciliation re-runs the static
  checks; a static failure suppresses capability publication, while the complete
  live boundary is re-attested at worker launch rather than continuously probed.


<a id="record-62ffa7889c8fdaf8778148c8c15d9788d2aea95a6a25af0fa4d175c2625b4d70"></a>

- Guest preparation now fails closed unless root has a locked password and a
  `nologin` shell, all four SSH service/socket units are masked to `/dev/null`,
  and a root-owned read-only hardening marker is present. The guest attestation
  endpoint reports kernel-observed process, cgroup, tmpfs, identity, login, SSH,
  and listener state. The supervisor smoke uses the real start/stop lifecycle,
  bounded identity-vacancy cleanup, and bounded streaming stdout/stderr tails,
  so a verbose child cannot fill a pipe or grow capture without limit.


<a id="record-c3afa221245a8eafa116a9d890e5222af422cbbfa59123e5737e703afdae68c8"></a>

- Start and stop grace values are exact 100 ms--600 s minima in both the
  signed manifest and operator configuration. Admission rejects a manifest
  value above 600 s instead of clamping it. The effective workload grace is
  the maximum of the node and manifest minima; there is no hidden startup
  floor. Teardown requests QMP `system_powerdown`, waits the effective stop
  grace, then uses one bounded kill-and-reap path.

## 2026-08-25 Inrou and SoraNet security audit closeout



<a id="record-800b336da29db7e1af7f33a83be3bf95106668abf97bf39ec1cbe9826adfec90"></a>

- The scoped audit validated and remediated two vulnerabilities. Torii now
  retains the hosted-route semaphore and upstream-connection guard for the
  complete streaming response-body lifetime, closing a high-severity
  listener-wide resource-exhaustion path. Remote SoraFS hydration now performs
  bounded all-answer DNS validation and uses a no-proxy, no-redirect, no-retry
  client pinned to the validated public addresses, closing a medium-severity
  DNS SSRF path. Focused semaphore-lifetime, IPv4/IPv6 address-policy,
  mixed-answer, obfuscated-literal, and redirect regressions pass. The upstream
  abort guard and client proxy suppression, address pinning, and retry
  suppression were verified directly in source; an independent final bypass
  review found no remaining path around either fix.


<a id="record-289e7cb8b2cea870cfc5ec412c48ca5e02a1001601cdba98d17e5fa6a40c6219"></a>

- The fresh focused Core binary passes all 18 `inrou_` tests plus the adjacent
  reporter-scoped lease-accounting, authoritative lease-update,
  replica-private-volume rejection, and signed model-host validation
  regressions.


<a id="record-d9193a4962f238cf8aa89db0613e4dd7043c541f157226bda5e6b52414054282"></a>

- The ABI V1, header, predecoder, executor, Android, Kotodama, JavaScript, and
  AXT fixtures were regenerated after removing raw credential/read/network
  syscalls `0xC5` through `0xC7`. Each SoraNet Rust/C++/Go interop fixture is
  byte-identical to its corresponding published/test mirror, and production

  custody. Privileged Linux/KVM and TUN qualification, full workspace
