## 2026-07-02 ZK-ACE asset routing and I105 numeric sentinels



<a id="record-4fa69454a82c3bbc0f7ad2a434f8c3c405d337240e13165d4f47902dc0e35881"></a>

- Asset-bearing ZK-ACE instructions now participate in the implicit
  asset-definition dataspace route used by native ZK asset instructions, so
  custom-dataspace assets do not fall back to the universal/default lane.


<a id="record-6ccf87cad2adf7524fd78345d4c5052cbb1e3c1bfd893950bd59dfafa3a81289"></a>

- Core I105 decoding now resolves numeric sentinel boundaries by validating
  candidate payload checksums and decoded account-address structure. Ambiguous
  numeric sentinel splits are rejected.


<a id="record-b3145fd29dcc6deaf5ab5b84a7da28372570e4a4740fb14b9e8ef208a274e7d1"></a>

- I105 discriminant inference now also validates that the checksum-valid payload
  is a canonical account address before returning a prefix.


<a id="record-d2c98a5d14563823b2dc2bc3d79b674bf7324e064720845dcf9ed4680f3023b4"></a>

- Explicit expected-discriminant decoding now still derives the embedded
  discriminant first, so a foreign numeric sentinel such as `n421...` cannot be
  accepted or misclassified by the shorter expected `n42` prefix.
