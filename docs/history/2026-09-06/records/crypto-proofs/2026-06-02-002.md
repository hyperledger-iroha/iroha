- Extended the Python native registry guard to bind every SDK-builder/component
  privacy row to its concrete Python module. The guard requires cataloged dev
  SDK entrypoints to remain exported and callable while exact and snake_case
  planned production entrypoints stay absent from module attributes and
  `__all__` until the corresponding production gates pass.


<a id="record-306452d31b28fb1c262eb8315f35c2e20de86fccb35df81a756399897c5ac888"></a>

- The same Python guard now checks the `iroha_python` package root: every
  cataloged component dev entrypoint and its module-defined Python alias must
  remain exported and callable from the top-level package, while exact,
  snake_case, and Pythonic planned-production aliases such as `zkat` and
  `verange` stay absent. The JavaScript cross-SDK declaration scanner now uses
  those Pythonic alias forms as well when it checks public API files.


<a id="record-e840a925ca62262ecc3042a6bda0ddce5f382da2710c8022a7129ce6833f90c5"></a>

- Tightened JavaScript source/dist and Python privacy catalog descriptor
  validation so `plannedSdkEntrypoints` / `planned_sdk_entrypoints` cannot
  contain dev-fixture names. Planned entrypoints represent future production
  APIs only; descriptors that try to park `DevFixture` or `DevProofFixture`
  builders in the planned production surface now fail catalog loading, and the
  JS/Python parity guard checks the committed catalogs contain no planned
  dev-fixture entrypoints.


<a id="record-b00c05b84f2024e9dffbcfbc4067fdb52511bc867ea7230632a14f786199135d"></a>

- JavaScript source and checked-in dist tests now lock the direct
  `getPrivacyCapabilities()` runtime object to the four catalog-only keys:
  `javascriptSdkAvailable`, `bridgeAvailable`, `privacyAlgorithms`, and
  `privacyCriteria`. Production-looking status booleans or builder flags must
  stay inside the fail-closed catalog descriptors until the production gates
  pass.


<a id="record-2dd005c9e6bca715826b7db029763795bec7528289077e061fb5c2984de5ca2a"></a>

  `PRIVACY_NATIVE_AVAILABILITY_PROBE_ARCHIVE` constant in the C bridge,

  adversarial rejection coverage for one-byte output, bad magic, bad version,
  unsupported flags, non-zero padding, and bad CRC.
