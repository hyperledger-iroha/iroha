## 2026-08-26 ZK correctness and verifier hardening



<a id="record-1a4d83c68c0d738f08b1df6da16d30fbfffe1c21d9b1a6876f0f8de6f28ef981"></a>

- Goldilocks field helpers and IVM field opcodes now reduce every raw `u64`
  operand before arithmetic. This removes non-canonical addition/subtraction
  errors, debug underflow, and acceptance of the modulus as an invertible zero;
  the opcode reference and native/circuit regressions cover the corrected
  semantics.


<a id="record-7213c292c58d94a5e1e02d70d4cc7ba5b30db9beefe0fcf2b5cf27b609f396b3"></a>

- IPA parameters, wire envelopes, and transcript projections now require a
  power-of-two dimension of at least two. Dedicated Pallas and BN254 tests pin
  rejection of the former zero-round forged-opening construction. The IVM
  batch smoke fixture now exercises the minimum accepted dimension.


<a id="record-2110c1bd22c47b3b01bc3f55ab6c51a138bb03a7c8aee104824e329d07da622e"></a>

- Formal-trace verification no longer rejects an arbitrary magic register
  value. The ZK-lane cache key is now domain-separated and binds the complete
  program, register trace, constraints, memory/register events, intermediate
  roots, and transport metadata. Normal Halo2-enabled ZK overlays enable trace
  collection before execution, so their background verification jobs are no
  longer silently empty.


<a id="record-951e1a765ce5c99a7865ae66066a0e7be1a1173ea69a31f5767ccbbefc198a46"></a>

- Transparent-STARK query derivation now uses an unbiased sparse partial
  Fisher--Yates shuffle. Every valid dense request can produce the requested
  unique in-domain indices instead of failing after a duplicate-prone `2n`
  attempt cap.


<a id="record-aa90eacaed4b5fda69cd65d4eed02ede369a74a49ba21c4526491c3e04ab445b"></a>

- A focused Codex Security Standard scan validated two additional findings: a
  medium-severity public proof-registry availability issue and a low-severity
  safe-API memory-safety issue in the IVM register logger.


<a id="record-38f3ebc83df9200307489bcbe34ff4c4845dbb8c2f4a3b4c6ee222ded4df6fa0"></a>

- Proof list/count traversal now runs as admitted blocking work with a
  cooperative deadline. Offset pagination retains only a bounded ordered
  prefix, rejects excessive windows, and clones only the selected page instead
  of every matching proof record; the physical worker retains its heavy-query
  permit even if the HTTP request is cancelled.


<a id="record-0dd0c1b94c74fd5e25006015af517f48c8154b2cecfc3eb6ce9047464c348ddb"></a>

- The raw-pointer register-logger setter is private and its guard is
  crate-private, removing the lifetime-free pointer hook from the public safe
  Rust API while preserving the VM's scoped internal logging path.


<a id="record-6bdef3a3a361c052a52171e881d9221e3e6837b3cbcdbe1ef51a471f6088a0a7"></a>

- Validation passed for the standalone Goldilocks suite (9/9), the dedicated
  Pallas/BN254 minimum-dimension target (3/3), the production
  `iroha_zkp_halo2` library check, strict Clippy for that library and dedicated
  target, scoped Rust formatting, and whitespace checks. The broader IVM/Core
  build originally stopped in unrelated existing `iroha_config` `HexBytes`
  conversion errors; a later Core retry now stops in an unrelated
  `kotodama_lang` `SourceFile::lines` error, and the focused IVM logger target
  stops in an unrelated `iso20022` moved-value error before running tests. The
  all-unit Halo2 target also reaches unrelated existing missing MKHE test
  imports. Scoped formatting and whitespace checks cover the additional
  security fixes; workspace formatting remains blocked by an unrelated syntax
  error in `crates/iroha_core/tests/isi_gas_fees.rs`. The multi-hour full
  workspace suite was not run, and no lockfile was modified by this work.

## 2026-08-26 FastPQ correctness and tooling audit



<a id="record-fbc60c7579f644b83f67378049ba3d6818428b08b82865d774a21b0a4907b293"></a>

- Removed a GPU-lane self-deadlock from split FFT, inverse FFT, and LDE dispatch:
  when another asynchronous dispatch owns the lane, the split path now finishes
  deterministically on CPU instead of blocking while retaining a pending GPU
  handle. Poseidon sponge misuse is also rejected consistently in debug and
  release builds.


<a id="record-19061524e218aba866fb66934ef19813904ffb6f577873be3bee974f3766f87a"></a>

- Tightened proof admission and transcript validation. Finalized transfer
  transcripts require their Poseidon preimage digest, AXT-bound proving enforces
  the same default transition and batch resource limits as verification, and
  padded I105 remote-account text receives the stable canonical-form diagnostic.


<a id="record-60ca5c2b9b178e630418124a4f35ffec7e7e80a4658dbfe0b42e791581133305"></a>

- A scoped Codex Security Standard scan found and fixed three low-severity
  FastPQ issues. Transfer SMT materialization now assigns colliding 32-bit base
  paths with a full-key-sorted, wrapping allocation that the verifier
  reconstructs exactly; non-colliding roots remain unchanged. AXT producer,
  decoded verifier, and envelope paths preflight default batch/proof limits
  before batch-binding reconstruction, including a transition-count check before
  model conversion. The CUDA benchmark parser test now uses in-memory bytes and
  read-only repository fixtures instead of a predictable shared-temp write.


<a id="record-b99f45d21a66e5771dc85a7e936148d3c1b5c23669e65bb7e2b756d9baf25a38"></a>

- Hardened FastPQ automation around subprocess timeout byte streams, explicit
  accelerator metadata, untrusted/non-finite metric inputs, device-class metric
  selection, malformed queue profiles, nested output paths, and durable
  release-evidence paths after staging cleanup. Release rollout stamps and
  inventory labels now reject traversal and symlink escapes before export work.


<a id="record-adec8ba1f962b1b412388225c00c6905ba7e3d00214be97320743a46043f2974"></a>

- Focused validation passed: all 455 `fastpq_prover` library tests, all 13
  `fastpq_cuda_bench` dev-tool tests, all 11 `fastpq_isi` tests, all 105 FastPQ
  Python tooling tests, and all 43 release-profile tests. The `fastpq-gpu`
  library check, scoped strict Clippy without dependency linting, touched Rust
  formatting, and whitespace checks passed. Workspace-wide formatting stops in
  an unrelated malformed `iroha_core/tests/isi_gas_fees.rs` expression, while
  dependency-wide strict Clippy stops in unrelated `iroha_crypto` warnings; the
  several-hours full workspace suite was not run.

## 2026-08-26 digital-signature SDK hardening



<a id="record-bc1bacdac9929824606ca98ecd1ebebeaaa6a45ba509a38fb0e8fc04eb47632d"></a>

- Kotlin and the mirrored Java Android SDK now bind every Ed25519 deterministic
  export to its private key. Export rejects an inconsistent input pair, and
  import derives the public key from the decrypted private seed and compares it
  with the canonical SPKI, closing public-key substitution without changing the
  v4 bundle layout.


<a id="record-d042521e4cb8c1d3a11911efa7393b8e76b9b5db641dd9e0b4f940f87c8f00ee"></a>

- Focused Kotlin core, the complete Android unit task, Kotlin release
  compilation, the Java pair-binding and keystore tests, and Android Java
  compilation pass. The complete Kotlin core task ran 1,116 tests with the new
  regressions green; 47 unrelated dirty-tree, fixture, or missing native-ABI
  tests fail. Wider Java harnesses likewise reach the relevant checks before an
  unrelated `connect_norito_bridge` ABI 22 requirement, and full Android release
  assembly still needs the pinned NDK. Physical-device KeyInfo/StrongBox
  qualification and the full release matrix remain outstanding.
