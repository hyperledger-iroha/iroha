## 2026-08-09 ZK tenant and compute route authentication hard cut



<a id="record-089446c187bd576673d06a238d643d9fc789344295e610c2b020304160b1a0a6"></a>

- Attachment list, count, read, create, and delete routes now declare exact
  canonical-account authentication and authenticated-account admission;
  create/delete are catalogued as mutations. Their sealed route middleware
  bounds and authenticates the raw body, runtime `NetworkId`, method, URI,
  freshness nonce, and account before Axum query/path/body extraction. Disabled
  routes retain the same authentication boundary.


<a id="record-0d7f36a83194d6b4b9554001e7438cce5936f1198d92b4bfb3315e81538d4585"></a>

- On-disk tenancy is derived only from the verified `AccountId`; API tokens are
  an optional additional gate and cannot select an anonymous or shared tenant.
  Rust attachment clients now sign every exact method/path/body with fresh
  one-shot headers. Route/middleware/client regressions cover unsigned malformed
  pre-decode rejection, nonce replay, canonical signatures, and honest effects.


<a id="record-7bc029b00d8d4263427777bfb2d9d58b2c95c59da5e11f2a0bf01ae1e1787d48"></a>

- The expensive IVM-derive and batch-verification routes now use the same sealed
  exact-network account-authentication boundary before content-type inspection,
  decode, state access, or blocking work. IVM derive additionally requires the
  authenticated account to equal the body authority. Rust clients sign both
  JSON and Norito variants with fresh one-shot nonces; route, middleware,
  authority-mismatch, and exact signed-body regressions cover the boundary.


<a id="record-91b620cc95ea4d53d699230d4d5ee55a4dd75f92ae2042b25788f04509b472a4"></a>

- Direct edition-2024 formatting, scoped diff checks, codec guards, and source
  budgets pass. Rust compilation remains blocked by the immutable manifest/lock
  mismatch; no Cargo command or `Cargo.lock` edit was used.
