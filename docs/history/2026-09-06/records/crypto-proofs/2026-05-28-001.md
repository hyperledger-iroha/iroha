## 2026-05-28 Kura replay FASTPQ witness skip and broadened rotating fault matrix



<a id="record-872a72dd7dc30e4f223fdd8830bfa5abfce71a8df62ddef1cda3fba99471a41b"></a>

- Kura replay validation now keeps transaction execution, WSV mutation,
  committed-result comparison, and result/root checks intact while avoiding
  replay-only FASTPQ transcript and execution-witness generation.


<a id="record-cc7e9cbe94588ca53872532c15c47207e92581a2c7bb316302a4d6a379b50365"></a>

- Replay-mode transfer transcript recording now returns before requiring a
  transaction call hash or computing FASTPQ authority/Poseidon digests, and
  replay validation no longer starts or captures execution witness blocks.


<a id="record-6d5da390a5d819582dfb56a8b123d40db8989df6f7773beea226b5d21a942a55"></a>

- The ignored 30 TPS rotating Byzantine harness now cycles a test-local fault
  matrix across exactly one restarted peer at a time. The default matrix is
  `conflicting-ready`, `duplicate-inits`, and `drop-validator-chunks`; fault
  windows record both peer and kind, reject overlaps, and require every
  configured fault kind once enough windows are observed.


<a id="record-73cd4e55a393d706b1a00ae37aeb76e73d8211ef8a287caff01b27bae6008c92"></a>

- Added an opt-in ignored-test recovery bound
  `IROHA_REALISTIC_30TPS_RECOVERY_BOUND_SECS`; the existing 900 second recovery
  timeout remains the default when this selector is not set.
