## 2026-07-06 BFV and Norito accelerator TODO cleanup



<a id="record-888802edf34a5b7d75e59a6fc7e3568b84806688fa51e0f9c50c3db15ecf06e6"></a>

- Removed the remaining BFV exact plaintext-multiple bridge TODOs by
  documenting the first-release boundary: exact plaintext-multiple paths are
  compatibility diagnostics and artifact-bound corridors, refresh jobs stay
  scoped to `RefreshOnlyV1`, and governed `FullBootstrapV1` execution must use
  artifact-aware APIs.


<a id="record-4cb33a8548266660d1aca5deff17b890a48351b0703ccd5423b1fab2bc5e9af9"></a>

- Removed the dead Norito `jsonstage1_metal` test-only CPU sequence-planner
  scaffold now that the public sequence-planner ABI routes to Metal on
  macOS/aarch64, and added public FFI negative coverage for invalid sequence
  planner pointers.


<a id="record-ca271aee21a353f185a38864f7cecd5201774219d068c629129065a585d3708a"></a>

- Escaped BFV full-bootstrap placeholder payload literals so the source no
  longer carries uppercase follow-up marker text while preserving the exact
  adversarial bytes covered by release-audit and native-payload placeholder
  rejection tests.


<a id="record-2f348759893260919aab327a677c2e023a9398a66f61bf3a1caccf63ac595872"></a>

- Updated the IVM README and proving-optimization notes so the status no
  longer presents production ZK verification as a TODO/mock-circuit gap: runtime
  proof checks are documented as OpenVerify IPA/Pasta envelope verification,
  with `MockProver` scoped to circuit-gadget tests and off-chain proving flows.

## 2026-07-06 FastPQ Metal Poseidon command-batch parity



<a id="record-1fbde99ff2612b1ddf3adceb7cf592aee3229c0b41dc9a2b346ff004f8dd1a49"></a>

- Removed the remaining FastPQ Metal Poseidon TODOs by enabling adaptive
  cross-column command batching for `poseidon_hash_columns` while keeping one
  sponge state per Metal lane.


<a id="record-62dde56f63ab5682a46ee5b1ced0fd9b7db91033053d0eb16d8498080576d63e"></a>

- The focused parity tests exposed a packed multi-state lane divergence for
  non-leading lanes on this Apple GPU, so column and low-level fused hashing now
  fail safe by disabling packed lane state reuse instead of silently trusting it.


<a id="record-b3b014f352538190550cf3c16b7058b26349ae174aea5e6b6e510fd80dc38f4a"></a>

- Added Metal CPU-parity coverage for vectorized command batches over
  multi-block column payloads and Merkle-pair payloads, with kernel-stat
  assertions proving the dispatch processed more than one column per command.


<a id="record-90214b2ea9c1dd78d437814a2220784fb0e312a8d4ff6de83696fada62ebca32"></a>

- Validation passed:
  - `cargo fmt --package fastpq_prover`
  - `cargo test -p fastpq_prover --features fastpq-gpu poseidon_hash_columns_batches -- --nocapture`
  - `cargo test -p fastpq_prover --features fastpq-gpu metal::tests -- --nocapture`
  - `cargo test -p fastpq_prover --features fastpq-gpu fused_poseidon -- --nocapture`

## 2026-07-06 FastPQ Metal completion-backed Poseidon staging



<a id="record-a867d3d54fa70de913b9f202f7ccf18f66d50d797b4a6c8fb3dea28c507c924c"></a>

- Released FastPQ Metal command permits from Metal command-buffer completion
  handlers instead of only from explicit host waits.


<a id="record-0a41212d62c1f61b7ce4a2bdbe47e53ea5921cfae456126b3d2b49969b22e59e"></a>

- Made command completion idempotent across completion handlers, host waits, and
  dropped tickets, preserving queue-depth accounting while allowing Poseidon
  staging to use a deeper two-command pipe.


<a id="record-a520598f07b533906aa6f054bf29395a512cc6c2caec5117807bf5993ba175c5"></a>

- Added unit coverage for idempotent completion, permit release, queue stats,
  and the restored Poseidon staging depth.
