## 2026-06-02 Privacy catalog production-gate parity



<a id="record-5b3981c8bac9ee4bedd1f5ac07209f85570d6ae36ffaeab8dd0a6890288199c1"></a>

- Added a JavaScript test that imports both `src` and checked-in `dist`
  privacy algorithm catalogs, loads the Python privacy catalog by file path,
  and compares their shared production-gate metadata. The guard fails if JS
  source, JS dist, or Python drift on algorithm id order, privacy criteria,
  verifier metadata, SDK entrypoints, planned entrypoints, production-ready
  flags, missing gate reasons, audit references, or duplicate/planned
  entrypoint overlap.


<a id="record-536ef3d69ef7dcd6e9c6bea840d224316acc056ca31dbe44426fae61cd40b75e"></a>

- Extended that guard to read the Java Android, Kotlin/JVM, Swift, and C#
  privacy native bridge source declarations and require their fail-closed
  missing production-gate reason sequence to match the catalog-derived
  canonical sequence.


<a id="record-a4598edd7322e4718657f846c3112d3b99dc76fbd93b8eab7c6d638fa94055bc"></a>

- Extended the same guard to parse the Rust native
  `PRIVACY_ALGORITHM_ENTRIES` declarations in `connect_norito_bridge`,
  `iroha_js_host`, and `iroha_python_rs`. The test now locks native capability
  row order, proof families, backend families, executable SDK entrypoints, and
  planned entrypoints to the SDK catalog contract.


<a id="record-e967d662515bb56e2e55e91c37f49e91aacadfd750d0f81d1cca3a5e63824420"></a>

- The Python privacy catalog now exposes derived `backend_family` metadata for
  every row and rejects otherwise valid synthetic catalog rows whose algorithm
  id lacks backend-family registration. Python and JavaScript parity tests now
  compare native Rust backend families against that SDK catalog value instead
  of keeping backend selection as native-only metadata. The Python loader now
  also treats raw `backend_family` / `backendFamily` fields as derived metadata
  and rejects forged backend-family claims before descriptor enrichment.


<a id="record-20a1df4725290eb39cc8228b54feb5d132137018d8d4f4d9da5afd1d090c5d76"></a>

- The JavaScript source and checked-in dist catalogs now expose the same
  derived backend metadata as `backendFamily`, reject raw descriptors that try
  to supply forged `backendFamily` values, and reject otherwise valid rows
  whose ids lack backend-family registration before they can enter the catalog.
  The JS/Python parity guard now compares backend family as part of the public
  descriptor shape, not only the parsed Rust native capability rows, and the
  package declaration guard requires `PrivacyAlgorithmDescriptor.backendFamily`
  to remain readonly in `index.d.ts`. The same parity test now parses the
  private JavaScript source/dist backend-family registration maps and compares
  them, plus Python's `BACKEND_FAMILY_BY_ALGORITHM_ID`, against exact catalog
  row order so stale extra keys, missing keys, reordered rows, and value drift
  are caught.
