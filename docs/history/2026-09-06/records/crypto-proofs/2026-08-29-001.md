## 2026-08-29 FastPQ first-release simplification and safety pass



<a id="record-513bc28ea056e822d2aebf51845e7edaaab4f30a21a85fa018b087e3dca0778a"></a>

- FastPQ now has one V1 proof format and one release parameter set,
  `fastpq-state-transition-stark-v1`. The unused latency catalogue entry, pre-release
  `params_version` branch, legacy permutation/lookup domain fields, redundant
  batch ordinals, the externally unusable backend trait/configuration surface,
  whole-module trace/ordering/packing exports, unused backend-artifact fields,
  one-variant LDE state wrapper, dead witness accessor, and byte-unpacking test
  API/fixture were removed rather than retained as compatibility scaffolding.
  The sole record explicitly pins Goldilocks/Fp4, its six-lane 384-bit Poseidon
  commitment construction, the 128-bit aggregate arithmetic target, zero
  grinding, binary FRI geometry, and 136 queries. Merkle fuzz helpers and BN254
  CUDA benchmark wrappers now compile only for tests, `dev-tools`, or GPU builds
  instead of shipping in the ordinary CPU library.


<a id="record-870ba7a65530daded4401d6a797a424297d40aadad160b9a6b89918e9f567295"></a>

- The first-release statement surface now contains only witnessed `Transfer`
  and `MetaSet` rows. Unused mint, burn, role, and permission variants, columns,
  lookup products, selectors, errors, fixtures, and fuzz targets were removed.
  Their replacement wire indices are disjoint from the complete pre-release
  range, which makes retired payloads fail decoding instead of relabelling an
  old mint as metadata. The smaller batch, proof, public-I/O, and outer AXT
  proof-payload wrappers likewise use explicit release-V1 Norito schema
  identities and reject pre-release headers rather than field-shifting them.
  The canonical trace has three selectors and sixteen AIR residues/challenges;
  permission/supply bookkeeping is no longer allocated or committed for proofs
  that cannot consume it. Metadata-only proofs also omit all 128 transfer-SMT
  projection columns instead of FFT/LDE-expanding constant zero columns.


<a id="record-6c7b231ec58dbe3f44513bed4e9a62eaceacf9c33c5d8ce5f12dc90d1364f20b"></a>

- Trace construction keeps only row-varying values in its temporary row
  records, emits batch-wide metadata/dataspace/slot columns directly, and
  allocates the 32-level transfer projection buffer only when the batch
  contains transfers. Row-usage evidence counts selectors exactly and reports
  `MetaSet` rows directly instead of masking inconsistent counts with saturating
  subtraction.


<a id="record-b20b4c49c33a3cf33d5685e5b57021c895d5029878f78ada15404c9d180ab238"></a>

- Proving and verification sort each batch at most once, derive trace polynomial
  data and its commitment together, reuse prepared commitments, and perform AXT
  binding/preflight work once. AIR evaluation caches column positions and uses
  fixed-size residues; leaf hashing streams through scratch batches capped at
  4,096 messages and roughly 8 MiB of prepared limbs instead of materializing
  hundreds of MiB of temporary input.


<a id="record-651a2a823406cf03b85b85ad1bd1466bbff136868981e953889b14b43ad9af07"></a>

- Scalar Poseidon hashing calls the canonical implementation directly instead
  of allocating a boxed dynamic backend/sponge for each operation; explicit
  batched GPU dispatch remains available. The parameter generator validates the
  power-of-two domain geometry, derives the trace root from the LDE root at the
  exact blowup stride, and rejects a coset inside the LDE subgroup.


<a id="record-f591b4eb7dccc50396273e55a126916ef9e62fd7daf605bb86dada9c727adf92"></a>

- Poseidon column commitments now have one accelerator path: the proven column
  batch kernel followed by the shared guarded Merkle-pair batch. The unused
  leaf-plus-parent Metal/CUDA kernel stack, FFI wrappers, shaders, tests, and
  `metal_debug_fused` configuration were deleted. A failed high-level dispatch
  falls back to CPU once rather than immediately retrying the same raw GPU
  column kernel, and telemetry uses the single `path="gpu"` label. Synthetic
  column-window copying, pipeline depth/chunk telemetry, and the unused
  `FASTPQ_POSEIDON_PIPE_*` and `FASTPQ_METAL_POSEIDON_BATCH` tuning surfaces
  were removed; Metal retains only its real completion-backed internal batches.


<a id="record-a4f3a5178eb56bb2191495bae82b23530c1a72b1370822d40e84d1a97fa9be35"></a>

- The ordering commitment is now a domain-separated full-width BLAKE2b-256 digest
  instead of one Goldilocks word padded into a 32-byte value. Native-STARK
  Merkle/FRI roots and transcript state use six independently domain-separated
  Goldilocks lanes, while FRI challenges and folds use the degree-four
  extension. The exact qROM arithmetic selects 136 queries and passes the
  128-bit aggregate target. Ledger qualification remains blocked because the
  arithmetic does not replace the missing independently reviewed
  protocol-specific reduction or final-artifact multi-target digest review.


<a id="record-a768d6923c80d5da62f32de2a9963340699bfc2f9b64762748631b2b73440623"></a>

- Public I/O preserves the caller's exact transaction-set hash, including the
  all-zero value, rather than interpreting zero as a sentinel and deriving a
  different commitment. Mutation tests cover every public field.


<a id="record-1ff4dddd20dd76f0b5db45ebc3b5f4f0bdd3c5c72a3b3190564abd6981a1a2e9"></a>

- Cargo's FastPQ build script no longer downloads an Xcode component or clears a
  system compiler cache. It reports explicit manual remediation and keeps the
  existing runtime Metal-source fallback. The duplicate synchronous Goldilocks
  CUDA FFT/IFFT/LDE API was removed; production uses the single pending-dispatch
  path. Grid sizing and kernel index arithmetic are checked without overflow.
  Any failure after CUDA work is submitted, including every non-success
  stream/event completion, now quarantines that backend for the process lifetime
  and abandons resources whose ownership is uncertain, preventing unsafe reuse
  or repeated device-buffer accumulation. Direct CUDA calls return an error;
  proof hashing records the dispatch failure and uses its deterministic CPU
  fallback. This is separate from mandatory-GPU startup preflight, which
  remains fail closed.


<a id="record-828b6187d693850dc28334244b885952a1d05dacd8d86474cf61002baf58a791"></a>

- Benchmark wrapping accepts only the current Metal or CUDA schema, validates
  V1 row/operation/backend bounds, rejects duplicate operations and divergent
  nested CUDA report copies, and retains exact row-count-derived ratios. The
  implementation-coupled and public FastPQ documentation now matches the sole
  parameter record, exact public-input binding, 16-residue AIR, required
  transfer witnesses, and execution-captured AXT semantics.


<a id="record-ae9f9c141c33f5c924c250899da4fc087766607fde557a8a49304a6454b8903f"></a>

- The retained Merkle fuzz target now supplies the exact evaluation length to
  the strict path builder, and the nested fuzz workspace uses the same vendored
  Halo2 sources as the root workspace. A focused trace test proves repeated
  identical transfer rows consume distinct transcript proofs in FIFO order and
  cannot reuse an exhausted proof.


<a id="record-14d304fef81e8ba529439fe8ad8ee513530a586f900fae4ba94b2d8f1ee56b88"></a>

- Focused validation passes: `fastpq_isi` library tests pass 18/18, the final
  `fastpq_prover` library suite passes 445/445, default integration tests pass
  10/10 without warnings, data-model FastPQ tests pass 9/9, and the canonical
  64-row raw-transcript proof fixture verifies. The retired 1k/5k byte-golden
  fixtures were removed; larger CPU/GPU cases compare proofs directly instead
  of preserving pre-release serialized artifacts. The full
  GPU/dev-tools library-and-binary check passes using the documented runtime
  Metal-source fallback, and both standalone fuzz binaries check cleanly with
  an external temporary lockfile. Targeted formatting, the legacy-codec guard,
  Python byte-compilation/manual validators, environment/stale-surface scans,
  and whitespace/diff checks pass. Native Metal and CUDA compilation remain
  unavailable on this host, Python lacks `pytest`, and the full workspace and
  all-target Clippy were not run.
