## 2026-08-28 ZK attachment, prover, and verifier hardening



<a id="record-1aba77caf746af0fcdd79bf61e2447d6be8222cee0220237193b313de8cf6517"></a>

- Torii ZK attachment POST acquires route-specific proof capacity before body
  polling or authentication, enforces one absolute read deadline and exact byte
  cap, and carries an owned admission lease through in-process and subprocess
  sanitizer work. Compressed-origin export GET uses the same bounded lane.
  Cancellation cannot release capacity while a blocking worker, sandbox child,
  or inherited-stdout reader is still live; saturation returns `429` without
  polling an upload body.


<a id="record-085557cd76feab3ef60fb77ac0ed66a000a05f767b00cf19cebf05d42455a3ae"></a>

- Attachment retention combines per-item, per-tenant, and nonzero node-global
  limits; defaults are 128 entries / 64 MiB per tenant and 4,096 entries / 1
  GiB per node, with the configured global count capped at 20,000. Accounting
  has one aggregate raw-entry budget across tenant directories and fails closed
  on malformed or over-limit inventories. One mutation lock covers POST,
  explicit deletion, tenant-local eviction, and TTL collection. A bounded,
  fsynced Norito-JSON intent makes quota eviction recoverable: partial incoming
  commits roll back, complete commits finish same-tenant victim deletion, and a
  deletion failure returns `500` while retaining the intent. Empty tenant
  directories are removed, and Torii refuses startup when enabled attachment or
  prover services cannot recover a pending transaction.


<a id="record-f9ed7a08f463e046f3d1f280f6085dc65170222822f9824527347d9baacb9241"></a>

- The prover records one durable content-ID disposition shared by tenant
  reference shards. A retry receipt checkpoints strictly ordered successful
  proof indices only under a canonical context hash binding build features,
  configured backend/circuit allowlists, one immutable Core state view,
  consensus ZK policy, verifier record and active-height state, and every
  attachment identity. Matching siblings are reused, policy drift invalidates
  them, transient verifier gaps retry with a bound, and terminal siblings
  dominate. Report commit and retention reconcile newer checkpoints and
  terminal dispositions before deletion, so report eviction or a crash window
  cannot requeue completed content; omitted or malformed disposition fields
  fail safe.


<a id="record-31563a442744aaa349deeae0a6c45f72b1c62a27d5c52b61a3fda72425f7a108"></a>

- CLI verifier-key submission preflights base64 containers and decoded/declared
  key lengths against backend-specific limits, requires withdrawal strictly
  after activation, rejects initially withdrawn registrations, and retains
  withdrawal as an update transition. Microsoft Vega-MC proof/PK/VK codecs
  precompute exact lengths, reserve fallibly, reject impossible sequence lengths
  before allocation, stream shape digests without large temporary buffers, and
  canonicalize Hyrax generator uniqueness modulo sign. The adjacent compact
  MKHE switch adapters and transparent-STARK integer fixture are repaired.


<a id="record-0eb9d06b3f054c1d6b5c3c41b3fc72347cfcbd9cbcfd48fc70bb45c93233f1ef"></a>

- Focused evidence includes all seven `vk_submission_` CLI tests, all three ZK
  attachment global-quota configuration boundary tests,
  `cargo check -p iroha_zkp_halo2 --lib`, the Microsoft-MC slice (`57` passed,
  `1` ignored), and both compact MKHE switch regressions. The Torii library
  check passes; the final current-tree attachment filter passes `90/90` and the
  prover module passes `79/79`, including the report-retention regression. The
  telemetry catalog Rust test, deterministic guard, and mutation self-test also
  pass. Codex Security sealed the audit with one medium finding, recorded as
  remediated and regression-tested in the current worktree. The full workspace
  and strict all-target Clippy matrices were not run; the ZK patch does not
  modify `Cargo.lock`.

## 2026-08-28 Post-quantum cryptography boundary hardening



<a id="record-ecc9bedc58373a180fac56e9ff3052482142e6609afd4dca10717423788cf777"></a>

- Completed a whole-worktree audit of protocol-facing ML-DSA boundaries across
  Rust, JavaScript, Swift, Kotlin, Java, Python, and C#. Canonical derivation and
  its native callers reject empty and all-zero seeds before expansion while
  preserving deterministic non-empty derivation.


<a id="record-0ed1fbab381feb4e35bd2eb4b608a373e5b927d02095a637e4b28caf2c4fb2ac"></a>

- Protocol algorithm parsers now use a raw-ASCII grammar and only recognize the
  fixed ML-DSA-65 aliases. ML-DSA-44/87, retired Dilithium labels, controls,
  Unicode confusables, and explicit empty labels reject; API-specific omitted or
  null defaults remain unchanged. Swift signing also pins suite 65 and rejects
  inconsistent public/secret keypairs.


<a id="record-812b8f3a14462d68471c9056f51b20385ace1f420b508a11ac978df9c14abc2b"></a>

- Account-address and public-key boundaries require curve tag `0x02`, exactly
  1,952 nonzero ML-DSA-65 public-key bytes, and the canonical extended controller
  form with a big-endian `u16` length. Address headers now require version 0,
  normalization 1, and a controller-matching class (`0x02` single key or `0x0A`
  multisig) across constructors, canonical bytes, and I105 decoding.


<a id="record-162d84d649f24769257e37a2044f4a65c848093330a20dbb7714788dbe4c5e61"></a>

- Swift receipt verification pins suite ID 1 and exact 1,952/3,309-byte material.
  Kotlin and Java validate primary and multisig signer output as 64-byte nonzero
  Ed25519 or 3,309-byte nonzero ML-DSA-65 signatures. Python signed-transaction
  envelope JSON round-trips are algorithm-aware, and both JavaScript governance
  manifest entry points reject malformed ML-DSA keys before emission or fetch.


<a id="record-49d6016b42d4cbc9d0b788babc22bb8dff2d75fafb2f4493d3690066d680705f"></a>

- The single final adversarial review found two fail-closed SDK admission gaps:
  retired Python Dilithium aliases and JavaScript governance builders that only
  trusted a self-declared multihash length. Both were fixed with positive and
  malformed-shape regressions; the same reviewer confirmed closure with no
  actionable residual and no authentication or consensus bypass.
