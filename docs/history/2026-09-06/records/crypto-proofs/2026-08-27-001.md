## 2026-08-27 IVM resource, privacy, and persistence hardening



<a id="record-c6ca10cd9c3382b0a3c8afed0842a8bf9d8f6541ef02e668bb3c867e4eec2104"></a>

- A scoped Codex Security Standard scan validated six IVM issues. Direct
  Ed25519, secp256k1, and ML-DSA opcodes now precharge every operand payload
  byte before hashing; the versioned formula is bound into the signed gas
  schedule, including independent charges for aliased operand roles. Unsupported
  fixed-header TLV versions retain base-only rejection, while version-1
  checksum work receives the byte surcharge. Overflowing public TLV addresses
  remain malformed even when unrelated private ranges exist, while a genuine
  private operand still takes precedence.


<a id="record-0a1b38f5eef66b1d3ccef1f7314c7c2998fe3d67a9b0806b8d373b7eaf1ee13c"></a>

- The predecode cache now partitions its configured byte ceiling across shards
  instead of multiplying it per shard. Cache configuration publication and
  overlapping scoped-limit guards are serialized without breaking same-thread
  capacity changes; ambiguous same-thread nested guards fail before mutation.
  Warm hits are rechecked after a decoded-op limit reduction, and byte-limit
  evictions reach global diagnostics. Program metadata rejects images above
  the 1 MiB V1 code-memory boundary before section dispatch, and `CNTR`/`DBG1`
  decoding has explicit Norito element, allocation, field, and depth budgets.


<a id="record-2af648312fff3a0099a2684f6a35da781a933b04ad5ddac8d1c63f30b82974c7"></a>

- ZK-to-public transitions, program replacement, and reset zero all
  private-tagged registers as well as private memory while preserving public
  arguments; formal trace values and retained memory-write history are scrubbed
  rather than left in reusable allocations. Non-ZK
  execution also rejects an inconsistent retained-private state instead of
  laundering it through a reused engine. Warm-runtime templates are bound to
  the loaded program and restore their ZK mode together with private bytes and
  tags.


<a id="record-82c9a287cc0036fa2e0710463f9c59e083fd719389204eef25b50545a7a9bcc0"></a>

- Register-proof logging no longer exposes a thread-local raw pointer across
  host callbacks. Owned snapshots, reference-counted log storage, invocation-
  wide traced/untraced scopes, and callback masks isolate production nested
  contract setup and policy probes. The active log is detached while the host
  owns `&mut IVM`; only net changes on the resumed VM are recorded, and VM,
  program, or ZK-mode replacement fails closed without reattaching private
  history. A proof-state epoch also rejects reset, same-program reload, nested
  execution, mode round trips, and trace-limit changes during callbacks. Host
  panics, including pre-isolation syscall-policy probes, are resumed only after
  detachment ownership and every proof artifact are scrubbed;
  post-failure diagnostics remain outside the logger scope, and untraced
  invocations likewise clear prior proof artifacts. Execution-proof
  quoting and generation select the invocation-owned log while callbacks are
  detached, so the charged event count and committed register-log hash remain
  complete. Every invocation receives a fresh register log, and a VM moved out
  of an active callback rejects reuse until it has severed the borrowed logger
  aliases, preventing cross-thread trace truncation.


<a id="record-073b035125fee8e4734fc892eaded1467641d8476ac2855ea5c8d83b74b4d0f9"></a>

- The development/test durable overlay publishes mode-0600 Unix sibling files
  by atomic replacement and rejects stable links, hard links, and special
  destinations; Windows uses reparse-aware validation and write-through atomic
  replacement. WSV rollback restores the complete in-memory checkpoint and
  reports persistence failure without panicking.

## 2026-08-27 cross-SDK digital-signature and Android attestation hardening



<a id="record-16640c6912f75b3dcc94ddc8f07b2c0d2e3a769582180e92e21c57216507d2d7"></a>

- Browser Connect approval and raw-signature verification now use the shared
  strict Ed25519 verifier, rejecting canonical mixed-torsion signature points
  that the underlying Noble verifier accepts. Swift now performs complete
  Edwards decompression, rejects negative-zero encodings, and requires both
  public keys and signature `R` points to be non-identity members of the prime
  subgroup; signature scalars must also be canonical (`S < l`). Canonical
  single-key and multisig account-address admission enforce the same key rule.


<a id="record-397b66ce49ca2e345d66b7a27fea8a23fab8770462985fd534f2c59742666449"></a>

- Mirrored Java/Kotlin Android attestation requires a non-empty expected
  provisioning challenge, rereads and independently verifies the recorded
  chain, and binds its leaf public key to every configured provider resolving
  the alias. Cross-provider alias collisions and backend read failures fail
  closed. The platform backend explicitly reports that an existing alias cannot
  be re-attested; fresh challenges require provisioning a new alias with
  `setAttestationChallenge`. Java attestation certificate arrays are defensively
  copied at every boundary.


<a id="record-67a06cc3bc1c608eed9d0d05c1eb1f3696b518589ceae7bced65e8ed71858ca1"></a>

- Mirrored Java/Kotlin Android attestation policies now accept only one strict,
  domain-separated canonical V1 snapshot plus its separately trusted SHA-256
  governance commitment. The committed bytes contain the exact upstream
  payload digest, freshness metadata, sorted non-valid serials, and sorted
  supplemental TBS digests; independent production builders were removed.


<a id="record-a84f162afc493c288fba816b930f873510fc9be750ca04f3d368ea651510e117"></a>

- The combined Android attestation certificate-profile, device-lab checker, and
  report/CI suites pass 659/659, including freshness-boundary and empty-evidence
  controls. The fixed Java/Kotlin/Python canonical-vector commitment is
  byte-identical. Python compilation, shell syntax, scoped whitespace checks,
  the direct Java provider and verifier harnesses, and the focused Kotlin
  `AttestationDispatchSecurityTest` Gradle run pass. The full Java test runner
  remains blocked by the unrelated existing checked-exception compile error at
  `AliasSetupModelsTests.java:755`.

- Removed hardware transactional memory and the `runtime`, `halo2`, `halo2-params`, `sm`, `htm`,
  and `merkle_incremental` compatibility or no-op feature switches. ABI v1 accepts only ZK and
  VECTOR mode bits; CPU SIMD, Halo2 verification, ML-DSA, and SM syscall code remain unconditional,
  while Metal/CUDA stay explicit deterministic acceleration features. `Cargo.lock` is unchanged.
