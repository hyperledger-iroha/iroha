## 2026-08-23 FastPQ correctness and production handoff audit



<a id="record-aeaf541f7f61d21416865a824e3ec22b0945300ad96c5f6d23c0967c0d660af7"></a>

- Transfer witness materialization now uses one stable decimal scale per asset across a batch,
  and recurring transition rows consume their distinct SMT authentication paths in FIFO order.
  Mixed-scale repeated balances no longer change integer meaning midway through the state tree.


<a id="record-f50e1655a9d9bec9ff7e69acaba0f41daf2bce6e6510484e55e829f01e5e04b0"></a>

- Full-width slots are represented canonically in Goldilocks trace columns while remaining bound
  exactly in public I/O. Proving now honors configured FFT/LDE and Poseidon modes, Metal column
  hashing derives geometry from the pipeline it dispatches, and local skipped sort ordinals no
  longer break canonical Norito equality. Forced GPU startup now parity-preflights real IFFT/LDE
  dispatches independently from the configured Poseidon backend and fails closed when unavailable.


<a id="record-a0213befe90d09d738e56dc8fec5991c177c66a354823530b36058e8eff47fb0"></a>

- Finalized execution witnesses are submitted to the background FastPQ lane only after successful
  WSV publication. The bounded lane buffers jobs during backend initialization, and proof-sidecar
  persistence fails closed when positional transcript identity conflicts with batch metadata.

## 2026-08-23 ZK algorithm correctness audit



<a id="record-231783e417543ed53a87dd2dc473151110a35c21e7abf3dda527b4edec84271f"></a>

- Generic native STARK binding AIR now compares every sampled current/next-row
  coordinate with the verifier-owned deterministic row. This removes a fixed
  public residual kernel that let `(1, -2, 1)` row mutations retain a zero
  composition value. It also reconstructs and exactly matches the complete
  canonical trace root and all-zero composition root, so sparse unsampled trace
  or composition substitutions fail. Binding verification is capped at
  `n_log2 = 12`, and canonical ledger verifier keys require SHA-256 instead of a
  one-field commitment.


<a id="record-35aa9eecd4d3928deee6c98d6ff9596deaee1428b394f5bc28362b3c4595931f"></a>

- FASTPQ verification now rejects alternate Goldilocks representatives in every
  proof-carried scalar, Merkle path, AIR/FRI opening, Poseidon root, and
  permission-field container before transcript work. Opaque public hashes remain
  outside the field-encoding preflight.


<a id="record-515e88f027a604c7d17dfcdcecf2a6a030d62fa4835371b811b0e96958cda29c"></a>

- Native binary FRI now derives each `(x, -x)` pair coordinate from the
  bit-reversed layer index. FASTPQ now opens strided multiplicative cosets,
  applies the inverse-subgroup residue decomposition with the correct domain
  point, advances both generator and coset offset by the fold arity, and uses a
  real adaptive final subgroup. FASTPQ now stops before collapsing that subgroup
  to one value, opens the complete 2--16-element terminal domain, and rejects
  interpolated coefficients above the verifier-derived quadratic composition
  bound. Independent fold and terminal-polynomial oracles cover both canonical
  schedules. Generic private native-STARK profiles still need equivalent degree
  geometry before their proximity claims are release-qualified.


<a id="record-fa4f2bc75e62395b7e2da6cb69c12eb49348cf858feb6f50b75c7eaeac02db6e"></a>

- FASTPQ trace roots are now derived from the LDE roots at exactly the
  advertised blowup stride. The former independently generated roots had exact
  orders but made `index + blowup_factor` open the wrong transition point.
  Both catalogue entries pin the cross-domain relation, the planner rejects
  incoherent roots, and public proving accepts only the exact named canonical
  records before trace planning. Pre-release numeric parameter versions are no
  longer part of the V1 proof format. The reusable Merkle verifier rejects
  indices with nonzero bits above the path depth.


<a id="record-1b8a75ed8a818967b4ec57330cca4ec5e07a689215dd79a35248ce2a3f03aa14"></a>

- Generic native-STARK FRI challenges now absorb the exact `u32` round index;
  equal commitment roots at different depths can no longer reuse one beta.
  Native batch inversion rejects empty or noncanonical field inputs, and
  aggregate proof layouts reject transcript domains that collide with the
  fixed DEEP or FRI-mask domains.


<a id="record-8b407c43241b368b8f32634a53b43583924aa1aa8838b72de9ef4a937df1a2fb"></a>

- Aggregate DEEP sampling now rejects zero, which previously collapsed every
  advertised current/next pair because `z * omega_H == z`. Rejected FP4
  candidates are retried with an exact bounded transcript schedule and are not
  absorbed; exhaustion leaves transcript state unchanged and fails closed.
  Aggregate, proof-managed, full-tree, streaming-tree, path, and multiproof
  boundaries also reject transcript/Merkle domains too large for their
  canonical `u16` framing before any infallible hash helper is reached.


<a id="record-65cb8477886693499d4a52a14ff91f120d31bda6f58164875abb5986aa93fa73"></a>

- The shared FASTPQ/ZK-ACE Goldilocks permutation now uses `x^7`; the former
  `x^5` map was five-to-one because `gcd(5, p - 1) = 5`, and concrete hash and
  valid ZK-ACE identity-commitment collisions are pinned as regressions. CPU,
  CUDA, Metal, AIR, parameter roots, and canonical fixtures were updated together.
  FASTPQ uses the actual base field and dense-MDS construction; unused Fp2,
  security-label, and grinding descriptors are absent rather than advertising
  properties the implementation does not provide. The one-field commitment
  still has a roughly 32-bit collision ceiling.


<a id="record-53cf2cc6c18eacce76c51d35d9c27cef6f0802bc05edff2ef7dba042b7d663aa"></a>

- ZK-ACE remains unavailable: four sequential words from one capacity-one
  sponge do not raise commitment binding above roughly 32 bits. Proving,
  verification, and compiled activation fail with `EngineUnavailable` until
  independent-lane commitment remediation and AIR/FRI recertification land.


<a id="record-6fb254cf5b9dd5704909e26b02856506d9b99ae1d29dd3ced415558bd9e67f0a"></a>

- BFV public-padding-only verification now fails closed because sampled public
  rows did not prove low degree for hidden trace columns. Governed full-material
  verification retains the structural precheck, then reconstructs and exactly
  matches all trace rows, composition values, and both Merkle roots.


<a id="record-f88d96dff71d4489d2b01fe2f9b31088e69a4131e426abf1b9a6b300899fed2e"></a>

- Shared transparent/aggregate STARK prover storage now wipes replayable masks,
  base/FP4 columns, and proof-managed-note IFFT temporaries through hardened
  `zeroize` operations instead of optimizer-removable ordinary stores. The
  masked-trace helper rejects noncanonical mask residues before arithmetic.


<a id="record-deeb9a8edd7feb2dda8cdb0e9025ba410673307a1f08409a808d8ac6e8c76d3a"></a>

- BN254 CPU, CUDA, and Metal FFT/LDE paths now bit-reverse coefficient-order
  inputs before radix-2 decimation-in-time stages. Independent direct-Horner
  regressions replace the formerly shared broken CPU/GPU oracle.


<a id="record-d43110afb71ed124c1f866d8d2f402593690f81c7742ca9df92152d4442f8cce"></a>

- Exact production Halo2/IPA labels now route through the authenticated outer
  envelope before raw decoding. All seven admitted circuits require their one
  canonical outer schema at preverify, guardrails, key-record preparation, and
  final dispatch. Production accepts only strict ZK1 inner carriers; legacy
  caller-controlled `n_in`/`n_out`/lookup headers and unknown raw flag bits are
  rejected. IVM verifier helpers use checked indices/arithmetic and enforce
  runtime-equivalent aligned jump, branch, `JALR`, instruction-fetch,
  memory-region, and allocation rules instead of panicking or accepting
  impossible traces.


<a id="record-e4f3a2361c8c39842757b6d0892efeddbadbbe82f94ce3752758f5c07a35c7bc"></a>

- Non-null standalone `AXT_VERIFY_DS_PROOF` now fails with a structured proof
  rejection before recording state or changing an existing proof cache entry;
  the zero-pointer clear operation remains available. Issuer-authenticated
  handle proofs enter only through the inline handle path, while finalized lane
  relay and authoritative fee-vault consumers retain their separate anchors.
  Handle signatures do not cover the exact intent, proof, or effective amount,
  so handle-backed remote spend remains outside release qualification while
  those facts depend on FASTPQ's roughly 32-bit binding ceiling.


<a id="record-3f1a9b4428a053c6e1e674688ce9e975bd3f2f9827070a72c98b536776d96c06"></a>

- The first-release Halo2 surface now exposes only the canonical strict ZK1
  inner carrier. Production instance extraction no longer probes the retired
  caller-shaped binary envelope, and the obsolete parser/module is removed.
  The ZK-ACE candidate helper is exported under its exact dense-MDS Goldilocks
  `x^7` construction name instead of retaining a misleading Poseidon2 source
  alias.


<a id="record-d8663ba23d1f46c4bf28c225ca8e7243e18ca0303b5cf260e457e0990b5d3ae2"></a>

- `cargo test -p fastpq_isi --lib` passes all 10 parameter, exact-order/coset,
  field-arithmetic, known-answer, and former-`x^5` collision tests. The complete
  `fastpq_prover` library suite passes all 409 tests. The ordering-hash KAT
  remains unchanged; the three trace-commitment vectors and the 1k, 5k, and
  preview proof fixtures were refreshed for coherent roots and versions 5/6.
  The tail-publication resource-ledger values are explicitly typed as `u64` and
  no longer block ordinary compilation. Metal and CUDA source compilation was
  unavailable during that earlier audit; current Metal hardware evidence is
  recorded in the 2026-08-24 entry above. The retired-codec guard, targeted
  Rust formatting, and whitespace checks pass.
