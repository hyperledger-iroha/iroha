<!-- Original context: Status / 2026-07-06 Public NPoS canonical XOR handling -->
- Kagami public NPoS profiles now treat `xor#universal` as an alias selector,
  not an asset-definition id. Taira defaults the selector to the canonical XOR
  asset definition `6TEAJqbb8oEPmLncoNiMRbLEK6tw`; Nexus deployable generation
  requires `--xor-asset-definition-id <BASE58>` so operators supply the
  canonical public XOR id explicitly.


<a id="record-556360cf0741d2da3e780b4c1369ec2f12e0bc1ebca66a29e6ebcf43016e9d64"></a>

- Verification and shipped-fixture guards now reject public XOR alias-as-id
  registrations, missing `xor#universal` bindings, unregistered binding targets,
  synthetic `nexus.universal/xor` public staking assets, and wrong Taira XOR
  bindings. Signing also rejects conflicting public XOR alias bindings and
  public staking config that bypasses the canonical `xor#universal` binding.
  The checked-in Taira fixtures use the canonical Taira id; Nexus public
  samples no longer register fake XOR ids and document the required
  operator-supplied id.
