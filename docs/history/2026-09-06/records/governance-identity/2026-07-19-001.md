## 2026-07-19 Declarative alias and SNS provisioning



<a id="record-ee3e3a6a34ee4be7da92a436e8fe3779c0b6196a3007b02374ce33228c1eaea6"></a>

- Alias setup now uses versioned resolved dataspace, domain, and account-alias
  names plus one registered `EnsureAlias` instruction per resource. Consensus
  revalidates each canonical text/ID pair, classifies exact state before quote
  validation, charges the transaction authority only for absent resources, and
  repairs derived indexes, bindings, primary state, and exact owner capabilities
  without renewing or charging an existing lease. Owner, controller, metadata,
  target-account, primary-role, and static/dynamic catalog drift fail closed.
  Create/repair execution also rechecks that the signed payer is the explicit
  owner or holds the exact applicable management scope, including when an
  ordered parent intent grants that scope earlier in the same transaction.


<a id="record-19766ffdacedae163490f8169da54189876096c327a9484be9b1a193dc8c1d4e"></a>

- Lease renewal is an absolute-expiry compare-and-set operation. Account-alias
  rebind and primary changes are lease-free compare-and-set operations, while
  owner-only auto-renew configuration persists a revisioned policy/asset/cap
  guard. Bounded native block maintenance debits the exact owner, retries
  insufficient funds deterministically, and suspends on policy/asset drift or
  exhausted failures. Renewal windows must be shorter than their deterministic
  365-day term, and invalid persisted timing suspends before any debit.


<a id="record-711aba5abd74f873ec8b99c70dc70a8065bc1ce4385f32a39c9149c33056ab9c"></a>

- Canonical-account-signed Torii planners return hash-bound, dependency-ordered
  framed instructions for one ordinary transaction; conflicts return a
  structured report and plans are never split. Sponsored onboarding is the only
  server-signing path and uses header-only credential authentication plus a
  stateless signed receipt that is revalidated against live state before
  submission. Obsolete SNS mutation and multisig-onboarding routes, split alias
  instruction registrations, client payment proofs, and key-bearing onboarding
  request shapes are retired.


<a id="record-17069dff9ccf00ab83828c510ebb7e7b27edf1b754faf609df8b37a3dd7edcf2"></a>

- Raw `Register<Domain>` is now genesis/bootstrap-only in both the initial and
  default executors, even if the retired `CanRegisterDomain` capability was
  seeded directly. The public CLI registration command, Mochi domain drafts,
  registrar templates, default capability grants, and runtime benchmark/demo
  producers are removed or migrated to `EnsureAlias`. The default instruction
  registry and shared schema target list contain no legacy SNS mutation or
  split acquire/bind instruction IDs, and the test-network/integration setup
  helpers now build ordered declarative alias graphs instead of fake payment
  proofs or post-genesis raw domains.


<a id="record-27a3d1feaff71b1991754d503e1eca17cd520d5a27aa3ea94853016b4036f0e0"></a>

- Structural file-backed onboarding configuration reports aggregated validation
  failures, `irohad --check-config` validates static/bootstrap inputs without
  opening sockets and semantically stages any available genesis in disposable
  storage. Authenticated readiness is recomputed from live state: empty joining
  state is `Pending`, while populated-state drift is `Blocked` without stopping
  the node.
  Rust, Kotlin, mirrored Java, and Swift expose typed plan verification and
  canonical-authenticated restricted reads; the CLI uses secret-free intent and
  plan files plus token files. Kagami emits four-peer localnets with separate
  operator/onboarding identities, random token sidecars, exact genesis
  capabilities and funding, owner-only runtime files, and a protective
  `.gitignore`. Private-profile genesis now provisions its dataspace and domains
  with one ordered `EnsureAlias` vector, uses only temporary exact bootstrap
  authority, and contains no synthetic payment proof or legacy migration
  command. Kagami signing, node startup, and `--check-config` share the same
  metadata-preserving genesis alias pre-seed semantics.


<a id="record-2da201cd6d47fdb8a868f54fc90e3ae6cfa11eb2ecc62bee4bad19760cf4ef46"></a>

- Canonical SNS guides were rewritten around signed planning, ordinary local
  submission, and native charging. Stale source localizations are explicit
  safety notices, and the portal translation generator now supports a
  traversal-safe, prefix-scoped invalidation pass; the SNS pass refreshed 280
  locale stubs and pruned 456 obsolete cross-locale generated copies. Torii's
  generated OpenAPI spec, root/current snapshots, and unsigned development
  manifests are regenerated and synchronized. `ci/check_openapi_spec.sh`
  passes with the alias read and planner/onboarding routes present and the
  retired SNS mutation verbs absent.


<a id="record-692a3299ce03999fa8340b572943e33ca4f3aff1e3fb7195ea4e1a65d5752e02"></a>

- The default executor now dispatches all five registered alias setup/lifecycle
  instructions, and dynamic-only SNS aliases use their resolved text/ID pair
  for exact manage/resolve permission checks. Restricted by-account filters
  return `401`/`403` before account lookup, unsigned aggregate reads retain only
  public aliases, and account-alias enumeration resolves SNS-only dataspaces.
  Client payment-proof DTOs are gone. The four older split lease/binding
  payloads and their Core handlers are deleted; regression fixtures now use
  declarative setup repair, guarded renewal, or the explicit rebind/primary
  compare-and-set lifecycle instructions.
