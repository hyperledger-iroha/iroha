  set for package exports, crypto exports, and capability keys, so a
  production-looking `build_zkat_*`, `build_verange_*`, or equivalent planned

- Closed the JavaScript/Python OpenVerify runtime alias gap for pending
  privacy backend labels. The JS source/dist envelope builders and Norito
  encoder plus the Python OpenVerify codec now compact labels with the same
  ASCII-alphanumeric rule and preserve catalog-shaped aliases such as
  `zcash-orchard`, `bls12-377`, `decaf377`, `monero-fcmp++`,
  `jindo-lattice-pcs-zk-v0`, `stark/fri/miden`,
  `stark/fri/pq-masp-stark-fri`, `anonymous-pgc-k-out-of-n-v1`,
  `verange-transparent-range-v1`, `zkat-policy-private-auth-v1`,
  `recursive-anonymous-admission-v0`, `vega-existing-credential-zk-v1`,
  `silent-threshold-anoncred-v0`, `zk-x509-onchain-identity-v0`, and
  `sis-hints-anoncred-pq-v0` as their exact pending enum families instead of
  rejecting or collapsing them into generic backends. The same JS/Python tests
  now reject punctuation-spliced suffix labels such as Orchard dev fixtures,
  claimed-production Miden labels, production-suffixed Anonymous PGC ids,
  dev-fixture SIS hints, and path-spliced BLS12-377 labels after compacting, so
  broader normalization cannot silently admit near-miss aliases.
