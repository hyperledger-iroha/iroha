## 2026-07-27 JavaScript governance private-file boundary



<a id="record-34a2cc2b820cd1e016e8058fa4224239755cee71e0071229135b150e20b4c9c9"></a>

- Added a versioned `iroha_js_host` secure private-file ABI for wallet
  governance state. ABI v1 exposes private-directory creation, bounded reads,
  and durable atomic replacement; the JavaScript publication probe requires
  the explicit ABI result instead of relying on N-API `Function.length`.


<a id="record-b323e35c1830bd461a148687cebcd7925b7bf9aa60f0c86185b69856f6d8a335"></a>

- Unix storage now enforces current-user ownership, private modes, no-follow
  opens, stable identities, single links, fsynced replacement, and fail-closed
  macOS ACL validation. Windows storage uses handle-pinned NTFS/ReFS paths,
  protected current-user/System/Administrators ACLs, reparse and hard-link
  rejection, long verbatim paths, and write-through atomic replacement.


<a id="record-712fc0ed407b085bd2f35cc3fbfc6ba4d7cdb24360e21900fd9da4ad34cf2611"></a>

- The focused macOS storage tests pass 7/7, the JavaScript native publication
  suite passes 116/116, and the Windows MSVC module plus gated tests
  cross-compile offline. Real Windows execution remains a required release-CI
  evidence step.
