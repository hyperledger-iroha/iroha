## 2026-07-25 Sumeragi V2 certified merge-sidecar generation fencing



<a id="record-1c4ebdf219ad494f4ee538f13cf97365be04070160c7a7a1e8b119dc73573ae9"></a>

- Certified merge-sidecar request identity now binds the responder's durable
  `NonZeroU64` `service_generation`, the requester's `NonZeroU64`
  `stream_epoch`, and the per-stream `NonZeroU64` `semantic_sequence`, together
  with wire version 1, payload or reference, and requester/responder peers. It
  excludes only the cumulative close floor. That floor may advance
  monotonically on the same occurrence without changing its request identity
  or rematerializing output. Request, Close, response-chunk, pending-flush,
  lane, worker, and refinement ownership use the same
  generation-then-epoch-then-sequence dominance, so a covered older occurrence
  is cancelled consistently while a successor occurrence remains owned.


<a id="record-746663379abf05607ce571710678e7c7cad5bb1e015ada1db8eff4423fdfb110"></a>

- A lower-generation, otherwise canonical Request or Close now receives an
  exact canonical `GenerationHint` bound to the observed message hash without
  allocating responder state or touching its lifecycle journal; future
  generations are rejected without a Hint or state mutation. The Hint retains
  the exact authenticated return route which carried its triggering Request or
  Close, just like CloseAck and response chunks. On the requester, an
  authenticated exact Hint from the expected responder must name an exact
  outstanding Request or Close and strictly advance the generation. It
  persists the replacement generation and a fresh stream epoch before retiring
  old partial chunks or rescheduling work.


<a id="record-c1c3f81c9fcb4ac33987fed690dfd1155c76c27206637155e50fcafdc6f5b7dd"></a>

- The responder keeps one bounded unified server-stream table plus request
  gates. It advances service generation only for a certified changed-roster
  geometry after every old stream, gate, transfer, and flush is terminal. A
  full same-roster table, checked overflow, and active-state exhaustion return
  `Capacity` atomically.
  The canonical `MergeSidecarLifecycleSnapshotV3` persists the incremented
  generation and empty responder state through a marker-selected alternating
  slot before memory changes or Hint emission. Recovery decodes only V3;
  V1/V2, corrupt, and unknown bytes fail closed without migration before any
  semantic cursor is restored.


<a id="record-7d57b2068cbf3dcb9a7c2efd58796e2e50e04d88aaad6634e1b3e176f91dea54"></a>

- Generation compaction does not authorize historical bytes. Current serving
  remains exact-context bound, while historical serving independently rereads
  canonical Kura material and its matching finality evidence before returning
  a sidecar.


<a id="record-99fe6a5af5ca9c980bfb410ac36ef3bbf8fc35e1de27a7d4b10a975459f1ec94"></a>

- The earlier source-level receipt and its superseded lifecycle selectors
  predate the final V3 two-slot schema, canonical identity, and exact routed Hint
  design. They are not validation evidence for the current tree; the final
  adversarial and full-module reruns are pending.

## 2026-07-25 Sumeragi V2 per-source ownership and liveness closure in progress



<a id="record-703f0ae7f457a8501edc115cd97521f3252aaf34a9fdd5500df4d370eba02612"></a>

- Replaced single-route reply ownership with bounded semantic-request route
  sets containing one independent attempt per authenticated source. Opaque
  actor-global delivery ordinals are separate from connection tenure; stale,
  foreign-owner, retargeted, and equal-ordinal/different-tenure capabilities
  fail closed. Same-source redelivery and reconnect preserve the current
  message/chunk cursor, while a new source begins at zero. At that checkpoint,
  canonical semantic identity excluded stream sequence and close-floor
  metadata. The current design supersedes that checkpoint by binding the
  positive semantic sequence and excluding only the monotonic close floor.
  Completed requests have no wall-clock TTL and retire only through an
  authenticated cumulative close over a contiguous terminal prefix.


<a id="record-f3cfcf42e3db092254fe10106d31bcb1c2dbd9cd1eb39690498a927f077b3855"></a>

- Threaded the exact route capability through ingress coalescing, worker
  output, certified sidecar chunks, runner dispatch, daemon Hold/Release, and
  rehydration. Sidecar accounting remains fixed at four gates, two sessions,
  and 16 MiB per authenticated source, with independent sibling reservations.
  Durable requester streams and the unified responder stream table are bounded
  independently of active source/gate capacity, so sequential semantic peers
  can rotate through one active source/gate slot without withholding peers
  exhausting future recovery targets.


<a id="record-1d01344e515130856ac01eb24c547b6e2953aee6cf586594d7770454f8bee457"></a>

- Added a canonical Norito lifecycle journal under the Kura root for requester
  sequences/floors and responder gates, authenticated-source budgets, cursors,
  and pending chunk identities. A typed hash binds the complete canonical
  payload, so structurally decodable corruption cannot silently advance a
  sequence, floor, cursor, or acknowledgment. Restart never serializes or
  reconstructs a process-local route capability. Injected write failures now
  latch the process-wide output guard before request dispatch, stale queued-chunk
  release, timeout rotation, or CloseAck completion; eleven focused restart,
  height-rollover, corruption, and fail-stop regressions cover those boundaries.


<a id="record-1cb7ea521dba98e9664de85cf305e2d23fe78918f120f8248ded830053ef8ca1"></a>

- Tightened timeout proposals and TC installation to carry the exact selected
  PrepareQC rather than a rank/subject reconstruction. Future PrepareQCs are
  transactionally ignored without acquiring retransmission ownership; an
  exact responsive source retains and redelivers its certificate after the
  lagger installs a TC.
