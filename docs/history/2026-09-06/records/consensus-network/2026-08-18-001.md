## 2026-08-18 Sumeragi stale-timeout recovery and restart attribution



<a id="record-7c9220fc39f3253a474ea794e665c8202061e83c8838e6194f35ed2412d4e648"></a>

- Cold recovered-Control-Sign startup now authenticates and atomically cancels
  one obsolete lower-view `BroadcastTimeoutVote` only when it is the exact
  roster-verified signed child of an advanced `SignTimeout` row in the same
  height context. The cancellation and current WAL Sign stage share one
  compare-and-fsync successor; same-view, foreign, malformed, non-timeout, or
  ambiguous rows remain fail-closed under the unchanged general census.


<a id="record-8d92032ffdda71e06b01691d2245ea8ca301b140aebb56b5482719f175aabe73"></a>

- CompleteTip binding now carries that exact timeout-supersession publication
  through a move-only successor witness minted only by the specialized
  compare-and-swap plus reload transaction. A frozen nonempty successor can
  advance only when its old digest, loaded and coordinator post-digests,
  canonical store target, context, retained ordinal floor, predecessor, Kura,
  body, payload, and registry ownership all still match; unrelated nonempty
  drift remains fail-closed, and a cold exact reopen mints no witness.


<a id="record-3c118a6ae02cb27917bad55a8e1cb776c876a6ac36276daced5925bbbe5fbb65"></a>

- Production height retirement now closes fair ingress and durably parks the
  exact queued leader-wire `Ingress` census as `Dormant` before detaching its
  gate. The queue, immutable ownership snapshots, mirror, and durable gate must
  agree exactly; persistence failure keeps the binding and carriers available
  for a fail-stop retry, while unrelated `Runtime` rows remain untouched.


<a id="record-d66f7e15a54ef69a8a577760abd75f6fe8c4d256d676088b3b91ab3665e4a48b"></a>

- Consensus output closure now records and logs the first restart origin once,
  including the causal trigger and caller location. Ordinary ingress capture,
  exact dequeue, consumption, lifecycle Completion classification, and
  recovered settlement paths retain their typed error at the fail-closed
  boundary instead of collapsing the initiating failure to a bare
  `RestartRequired`.


<a id="record-b3d9eea582eb9c7dc44731f2db14b18b7e457aa5bf5cf2310152822d46e359ba"></a>

- Incident-shaped regressions cover atomic cancellation and idempotent reopen,
  missing-current-Sign publication, first-CAS witness provenance, nonempty
  CompleteTip witness consumption, foreign-target and post-witness-drift
  rejection, persistence rollback, same-view and foreign-signature rejection,
  ambiguous/non-timeout rows, exact ingress parking and rollback, mixed
  Runtime ownership, ownership-census mismatch, and first-origin non-overwrite
  across panic and incomplete-operation drops.

## 2026-08-18 Sumeragi CompleteTip floor and durable-QC restart authority



<a id="record-65ce63354c4ba7f2cd81b8cdb6a4f34831cc0442a1f892d1b969a6a043ad882f"></a>

- CompleteTip recovery now admits an empty non-genesis lifecycle ledger only
  when the canonical frame is physically present and exactly bound to the
  Kura-authenticated predecessor root, height context, rotating-leader policy,
  and frame digest. Missing logical-empty fallbacks, foreign roots or contexts,
  drifted frames, unrelated nonempty work, and foreign successor floors fail
  closed; an exact cold restart initializes or stutters the canonical
  successor.


<a id="record-060fff9866b6870c868d68dfd3e1d5d1ce6d7244d38aded4d0fff4926fd3dd97"></a>

- Live finalization now publishes the retired ordinal high-water as a
  move-only, Kura-bound capability. Both ordinary and PendingKura tails consume
  it into the already-derived H+1 storage seal before successor startup,
  preserve the floor across idle heights, and recheck the exact store,
  successor frame, and coordinator projection before publishing the recovered
  owner.


<a id="record-4c4f022e01e5d741f4519b9b12c48d31587ded23fcee78c22466292e0f912476"></a>

- Commit-QC status now comes only from Kura-authenticated durable finality.
  Publication is monotonic and remains current while general telemetry is
  disabled; restart inventory separately retains the highest verified finality
  for status hydration when a durable block suffix extends beyond the latest
  QC, while exact-tip finality remains isolated for replay authorization.


<a id="record-32ec7e1931225929c388d0ee8a72679bd82201418b882237ae24a9ce4e7e2321"></a>

- Focused optimized regressions cover present-empty CompleteTip restart,
  missing/foreign/drifted frames, live and idle floor propagation, first
  successor admission at the retained ordinal, both production finalization
  tails, failed/idempotent finality persistence, disabled telemetry, exact-tip
  and lagging-finality restart hydration, late inventory installation, shared
  publisher ownership, and the public telemetry/Torii status projections.

## 2026-08-18 Sumeragi recovered-worker lease handoff



<a id="record-2aefd6887dd7a1200878d9bd08e47c02be9be1ab81e0d25b1a2928311dad5a05"></a>

- The active-height lifecycle runner now carries a typed asynchronous-owner
  disposition across outer batches. A recovered Sign, Apply, Fetch-persistence,
  or claimed Certified-Serve worker keeps ProducerTurn planning closed until
  its matching Completion transaction releases the sole coordinator lease;
  terminal Serve replay has a separate no-lease completion barrier.


<a id="record-3dd3fc19772f0929aed6d8478c6dbc8a827120027951e652f34fe69e8adb1998"></a>

- Completion handling first classifies parked and physical owners without
  authorizing fresh Ready work. An ordinary physical head drains exactly one
  item, so it cannot cross into a lifecycle completion queued immediately
  behind it. Non-eligible owners still receive one Runtime turn to release
  executor backpressure, then yield before ProducerTurn or fresh ingress.


<a id="record-d59003465100f55295d1c1d0638689e63e23cffcb0e8d33237f06b41f0f1e38b"></a>

- An executable Ready ProducerTurn now wins over both a parked recovered-Fetch
  response and a current Certified-Serve request without consuming either
  ingress carrier or installing a retry barrier. Authenticated current-Serve
  context drift is an invariant failure that closes output for restart instead
  of retrying forever.


<a id="record-69c6c9510d44f1e03d12e4dcab2288f528673def07b91332e43c02cb00906a81"></a>

- A production-shaped empty-genesis CompleteTip regression now activates the
  recovered H+1 Timeout Sign, proves its first drain yields with output open,
  settles the real worker result and durable Broadcast successor, and verifies
  the subsequent ProducerTurn point no longer observes an unsettled lease.


<a id="record-9e09ecfa6a6ee3de13787a705a5f9e5e55cbfcd50111b8f63354965abfbcd94c"></a>

- Recovered Decision Fetch request dispatch now installs the exact request
  owner and registry source, parks the Fetch on its request-derived external
  wait, releases the active lease, and only then publishes the signed fanout.
  Its exact authenticated response reclaims the same ordinal and holds the
  Fetch lease only while body persistence is queued; capacity and preparation
  retries remain parked without a lease.


<a id="record-e622132e394ed5d9ce4786e5f25e2d150fb0111f4d75706df4b6a9b9ee72cfaf"></a>

- Cold reopen intentionally reduces that volatile external wait back to the
  unchanged durable Ready row, then deterministically recreates the same
  dispatch key, signed-request hash, and wait source for an idempotent resend.
  The response seal rejects foreign sources and ambiguous duplicate waiters.
