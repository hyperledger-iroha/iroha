## 2026-07-26 Sumeragi V2 exact writer and typed rollover boundary



<a id="record-4f07480ba06cd8be1007cd26a51f02ebc25b0764089a5593d9f4ac5278c84311"></a>

- Exact authenticated replies now acquire one immutable actor-owned writer
  deadline at first dispatch, before bounded peer-writer admission. Full-queue
  retries preserve that deadline. Only `TimedOut` grows the source item's
  saturating adaptive attempt; ordinary writer closure and reconnect preserve
  it, while a successful full flush resets it. The actor polls an already-ready
  writer completion before route retirement, connection replacement, or
  deadline observation, so the exact full flush wins that boundary. Empty and
  closed completions cannot retain a stale route or terminate its replacement.
  The base deadline is a first-release `iroha_config` parameter with a 30-second
  default and 100-millisecond minimum.


<a id="record-a3022e2546a738d22ec560133c4abd6b4e0866ebbaf06a27a98b48c0943f8cea"></a>

- Certified sidecar allocation now requires the semantic requester, but not its
  authenticated relay, to belong to the frozen height roster. A durable
  two-level scheduler rotates requesters and then chooses the lowest exact
  occurrence within one requester. Kura absence/read/metadata/non-holder
  failures terminally retire their exact gates, while transient capacity or
  route loss remains retryable. An inactive or reply-unwritable source persists
  its current cursor before releasing the ephemeral attempt, queue position,
  and shared bytes; a draining inbound route can therefore no longer pin a
  roster transition.


<a id="record-4c871b19d9e6f84330aa8a7e7a8b4b417518c82c136a48fb7c27f6ae27cdfdd4"></a>

- Finality rollover now seals the empty exact-output corridor under its enqueue
  mutex and mints one move-only `DurableExactOutputHandoffReceipt`. The receipt
  binds the exact predecessor context/finality artifact, immediate successor,
  and private service/transport owner nonce. Foreign same-context owners,
  resealing, late enqueue, missing final seal, and wrong-successor use all fail
  closed. Ordinary changed-roster rollover still requires every predecessor
  stream, gate, transfer, and flush to be authenticated-terminal. The sealed
  move-only handoff, or a private fence minted only after complete semantic V3
  restoration, may instead durably supersede active predecessor responder
  state. Both forced paths require the lifecycle journal, commit the checked
  successor generation and empty responder projection before memory changes,
  clear predecessor responder/output debt, and never synthesize
  requester-authenticated close prefixes. Same-roster rehydration preserves
  generation and responder ownership; a new requester against a full
  same-roster table remains a fail-atomic `Capacity` condition. Overflow and
  unauthorized active-state replacement also reject without mutation, and a
  late predecessor flush cannot mutate the successor.


<a id="record-2915b1dcf7534cbd74d5c161afbc2feb7bc9b80179daefd2e92b162e387715c8"></a>

- The first-release wire remains version 1, updated in place. Responder
  `service_generation`, requester `stream_epoch`, and per-stream
  `semantic_sequence` are positive `NonZeroU64` coordinates. Canonical request
  identity binds the version, those three coordinates, payload or reference,
  and requester/responder peers; it excludes only the cumulative
  `closed_through` floor, which may advance monotonically on the same occurrence
  without rematerializing it. `GenerationHint` carries observed/current
  generations and the exact triggering Request or Close hash on that
  delivery's authenticated reply route. Alternate sources retain independent
  attempts, and a same-source redelivery refreshes only that source. Every
  frozen target now owns separate `SidecarTopologyProgress` and
  `SidecarReplyControl` Lane reservations. Parked ordinary same-target output
  and saturated shared capacity cannot consume either Request/Close or
  CloseAck/GenerationHint progress; alternate Hint routes coalesce without
  multiplying reservations.


<a id="record-33fb613d2e49af3ac4355f637253e74987abad5a1548740ee7c386cd9cc55d0c"></a>

- Durable lifecycle state has one first-release schema:
  `MergeSidecarLifecycleSnapshotV3`. It contains geometry, the next requester
  epoch, responder generation, requester streams, unified server streams,
  request gates, and the root generation. The root is atomically published and
  fsynced before the state directory as a generation-zero bootstrap sentinel
  with no snapshot hash. A surviving generation-one candidate is semantically
  validated and rechecked before root adoption. Later snapshots alternate
  slots; the fsynced root marker is the sole commit point, so restart selects
  exactly the predecessor before marker publication and exactly the successor
  afterward. Restore validates the selected candidate, rechecks the live pair,
  validates every cleanup target, and re-syncs the selected state and root
  directories before cleanup; unknown, non-regular, symlinked, or Windows
  reparse-point artifacts fail closed. Unix and Windows use native atomic
  replacement, while unsupported directory-sync platforms fail closed. The
  marker is a local trust anchor: replacing or rolling it back, including to
  the bootstrap sentinel, and whole-store rollback are outside the guarantee.
  V1/V2 and other unknown or malformed state fail closed without migration.


<a id="record-c0ba94c57ed7ac456aea01ca9916d957628c2b7bbb81c26ccc8b0f6199140ee0"></a>

- Drained certified-close prefixes now retain a process-local terminal-handoff
  barrier until the runner has applied the complete exact-output batch. A
  downstream failure requeues only the failed suffix; successful prefixes are
  not replayed, and responder-generation rollover remains blocked until the
  retained suffix is confirmed. The new exact runner regression and two
  cross-platform lifecycle V3 directory-sync crash regressions are pinned in
  the mechanically unique 732-test, 38-module production inventory. The
  canonical module/test TSV SHA-256 is
  `e4f9c69b5465ae3203d289394f490b4d98adb895dae8a6e0362092d7549a7169`.
  The
  source-bound route generation/epoch TLC trace is also wired into the
  canonical mutation runner and is green at exactly 7 generated/7 distinct

## 2026-07-26 Sumeragi V2 exact queue-plan restart ownership



<a id="record-4cae8c86a0e145d6d2e63af9a203422dfe6dc81ad591e7e514e0883a80bd4505"></a>

- Lane-reservation Commit recovery now authenticates the exact globally
  certified QueuePlan binding directly from the live V4 plan-journal record
  before appending its tombstone. This closes the crash boundary where the
  reservation journal replays before transaction payloads: startup can consume
  an already-committed plan without resurrecting it, while a mismatched queue
  hash, retargeted coordinator/incarnation, stale binding, ordinary claim, or
  same-plan ABA replacement fails closed without appending either the plan
  tombstone or `ForgetCommit`. Successful reconciliation now republishes the
  exact terminal backpressure/status snapshot. Startup validates the complete
  restored barrier set against one content-bound replay and persists its new
  tombstones in one atomic `RemoveBatch` frame; the 256-owner regression pins
  exactly two journal scans independent of barrier count. Reservation scope
  validation now uses consensus route geometry, so disabled Nexus admits only
  canonical `SINGLE`/`UNIVERSAL` ownership and rejects dataspace retargeting.


<a id="record-48c60da3a986e2d968acfd4e7bdc9bb85637115d06c212eed85fb3e63ac8f060"></a>

  chain-digest-and-entrypoint kernel used by construction, core admission,
  journal replay, certificate validation, and Torii. Connection tenure and
  actor delivery ordinal remain deliberately outside that identity, while a
  self-consistent but noncanonical request ID fails at every production seam.
  The obsolete journal-disabled startup finalizer, configuration switch, and
  data-dropping high-volume path were removed because production requires the
  plan journal in this first release. Supplying the retired switch now fails
  during configuration parsing, before runtime storage is opened.
