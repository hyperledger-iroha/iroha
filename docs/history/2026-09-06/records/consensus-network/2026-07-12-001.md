## 2026-07-12 Sumeragi v2/Kura fail-stop recovery closure



<a id="record-9e9e6d7be3243db73c2d0c5e3b64b14288d92f4b3993815991fe2acc478beb87"></a>

- Classified Kura publication failures at their durable marker boundary:
  pre-marker failures remain exact-retry errors, while ambiguous marker state
  and unresolved post-marker association or cleanup stages poison canonical
  mutation until restart recovery completes them.


<a id="record-76ff315139014d00ccb1efcafe2e4ce19a06e0deee03aae05a7d2bcd2339b3c1"></a>

- Added a process-wide consensus output guard across ingress, ordered I/O,
  candidate delivery, network effects, and fatal runner teardown. Fatal worker
  results close the guard before releasing their admitted output permit, so no
  second output can cross the durability-failure boundary.


<a id="record-c9237c2676c57d70391280a86e8d905bd2c5f100997358b5fe0792c554e16d03"></a>

- Made checkpointed or manifest-bound top blocks immutable before rewrite or
  budget mutation, and made ambiguous hash-only snapshot-marker publication
  fail stop under the same restart-required classification. Adversarial tests
  cover old/new marker outcomes, persistent cleanup failures, exact retry,
  sidecar preservation, and cross-thread output draining.

## 2026-07-12 Taira legacy-consensus stall snapshot



<a id="record-c0e6f6653d46abcfad3e7f3b3f57005febe58654e82a0bd67975e23bc41892e4"></a>

- A read-only public rollout probe against `https://taira.sora.org` rejected
  the deployed node because `/v1/sumeragi/status` still exposes the retired
  global-RBC/missing-QC schema rather than the Sumeragi v2 reducer schema. No
  signer, faucet, or transaction was used.


<a id="record-7ea00b30d0a38777d7dcccc74ceba11108378bbf9670bf8f34c9b589dc555312"></a>

- The captured public state was stalled at committed height `34971` while
  `pending_rbc` held height `34972` at view `1633`; `highest_qc` and
  `locked_qc` both remained at height `34971`, view `0`, and
  `missing_block_fetch.total` had reached `482033`. `/status` reported build
  `039af2d65e10b773be5031ab8fc07cf27b40e30d`, three remote peers, and two
  queued transactions.


<a id="record-ec380ba8473fd47bd5faa48cd1b531ecb03d010e65bb1bc88042db43dfce4a95"></a>

- This is pre-cutover incident evidence only. At capture time, the public edge
  remained closed to a Sumeragi-v2 rollout claim until a fresh-genesis
  validator set reported the then-current compact protocol-2 status schema and
  passed the all-validator fingerprint, common-hash, repeated-height-advance,
  and signed-canary gates. That protocol-2 gate is historical; the current
  fresh-genesis rollout gate requires wire revision 4.
