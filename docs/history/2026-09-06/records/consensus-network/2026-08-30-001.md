## 2026-08-30 revision-4 DA/RBC first-release hard cut



<a id="record-0ca17cea862854b4ff4050d0cf50f041dcc1f806ad0eb4b970cbe32d479800f2"></a>

- Revision 4 now has one availability transport: `Proposal` embeds the signed
  RS16 `PayloadManifest`, and authenticated `PayloadChunk` messages carry the
  shards. The standalone manifest message, proof-harness-only body request and
  chunk variants, unused chunk-filesystem lifecycle, and disconnected DA
  gate/spool telemetry were removed. Rust, Swift, Kotlin, mirrored Java,
  network-control, fixture, formal, runbook, dashboard, and public-documentation
  projections use the resulting first-release wire order.


<a id="record-ba8f4ca3e2b287f8cd82a54622c97ae3de517fbb3c60292e015d119b9764dba9"></a>

- Chunk admission rejects an unauthenticated outer identity before manifest and
  payload hashing, moves authenticated bytes into bounded session storage, and
  reuses the hash verified by the signature boundary. Sessions cache manifest
  identity and per-stripe readiness, so incomplete reconstruction is an O(1)
  check with no payload allocation. Batch signing validates and hashes the
  manifest once, and reconstruction no longer regenerates a complete RS16
  codeword merely to recover body bytes. The executor's `ReadyBody` derivation
  is the first canonical-body gate, and the durable store independently
  rechecks the body, block wire, and manifest before publication.


<a id="record-da404a5e67d1e56905dff2539f2d3e7d6dbd7a1ae5227ad1ba5ba59f89589ad8"></a>

- Outbound chunk frames are now canonically encoded once at payload
  registration and retained as shared immutable bytes, so first fanout and
  same-round fallback clone only their `Arc`s. The trusted canonical encoder
  reuses manifest-committed chunk hashes while signing instead of hashing every
  locally generated shard twice, while exact re-registration returns the
  retained frames before signing or encoding. Exact-output integrity checks
  cache the immutable outer-frame hash and invalidate it together with cached
  wire bytes on mutation, avoiding repeated full-payload scans during removal
  and finality handoff. Parity recovery borrows present rows and uses the
  selected scalar/SIMD backend to allocate and compute only missing systematic
  rows; it neither clones present shards nor regenerates unused parity. Wire
  bytes, signed preimages, quorum rules, and the later canonical codeword/body
  validation boundary are unchanged.


<a id="record-0926c6da9b0717a9e0167a88dc2964990ef3c9b72a0ff9f0e14a9bd33fb07dd0"></a>

- Focused validation for the performance pass covers all 12 default-feature
  RS16 unit tests (including scalar/SIMD differential recovery), the exact
  signed-chunk data-model test, formatting, whitespace, and the retired-codec
  guard. Core library and unit-test compilation is presently blocked by the
  concurrent SCCP/overlay and lane-certificate refactor, while the primitives
  no-default-feature run is independently blocked by missing `SocketAddr`
  Norito JSON traits; neither blocker reports a DA/RBC performance-path error.
