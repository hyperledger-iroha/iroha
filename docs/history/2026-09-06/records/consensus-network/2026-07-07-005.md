<a id="record-77586cefa37fcca2278010c7450382814c291e5b6a694487f26450c396182ef1"></a>

<!-- Original context: Status / 2026-07-07 Autoscale committed-lane evidence ambiguity hardening -->
- Default-dataspace committed-lane rows must now carry canonical quorum metadata:
  `min_quorum` must equal the deterministic commit quorum derived from
  `validator_count`, the advertised validator set must fit the fixed localnet
  peer set, and prepare/commit QC signer counts must be within the validator set
  while satisfying that quorum. Quorum-downgraded rows, impossible signer counts,
  or impossible validator-set sizes cannot prove expansion/direct execution, and
  malformed latest default-dataspace rows are non-idle for scale-in instead of
  being treated as absence.


<a id="record-6197e4b8ac3669bf32125b00ab4196a208c3cf13b2732d3d9d87c6e673e677c9"></a>

- Autoscale localnet quorum discovery now classifies peer-reported commit quorum
  evidence before falling back to peer-count quorum. Split-brain or out-of-range
  `commit_signatures_required` values, explicit quorum values that do not match
  reported validator-set length or peer-count fallback quorum, and conflicting or
  out-of-range validator-set lengths remain retriable during startup but fail
  closed after timeout instead of being masked by fallback.


<a id="record-5f8c9156ae7cf42b5bee29670bf65c7b01c4a82d634db0f6b81cf6c7d72b5f63"></a>

- Sumeragi lane-commitment summaries now use the same latest-unambiguous
  policy: conflicting latest rows for a lane block height no longer count as
  current activity, post-baseline progress, or post-baseline lane declaration,
  and stale positive rows cannot override a newer idle commitment row.
  Ambiguous commitment rows also cannot be treated as idle proof for scale-in.
  Exact duplicate latest commitment rows remain idempotent.


<a id="record-b45802e6952127ed2b4f889c393f3250a1fdc6e94a3e2e12a0dd3620c131f91f"></a>

- Lane consensus-domain planning now rejects explicit committee `min_quorum`
  values that diverge from the deterministic commit quorum for the canonical
  validator set. Lane-block vote planning applies the same canonical quorum
  policy to embedded descriptors before signing, even when a forged descriptor
  and proposal carry internally consistent hashes.


<a id="record-c94c4202b601cc9a379020d972beb6a134b999b60a158fef45cf99f1bdb5fb2b"></a>

- The generic `SumeragiHandle::try_incoming_block_message*` paths now treat
  standalone lane-block proposal/vote/QC messages as blocking consensus
  evidence, matching network relay ingress. Queue pressure on the block worker
  no longer best-effort drops lane-block evidence before the main loop can
  validate route, sender, and committee authority.


<a id="record-ff810915a7082c7e20903eb960664ff6532f7618a4a5b1fc504526f715b6c0a9"></a>

<!-- Original context: Status / 2026-07-07 Committed-lane queue redrive hardening -->
- Sumeragi tick now redrives the committed-lane executor queue even when no new
  lane-block message arrives. Existing pending certified lane blocks can
  recover payloads, record application receipts, prune receipt-backed queue
  entries, and admit protected committed sessions from the lane-block cache
  after backpressure clears. Same-tick status publication merges newly recorded
  applied-receipt evidence with the final post-prune pending queue so rollout
  observers do not miss either side of a backpressure recovery transition.


<a id="record-442490ba1f88757a5cb4e5dabc9fbffd47eae56174f1c7e4573b8e00faff5fa3"></a>

<!-- Original context: Status / 2026-07-07 Lane-block cache backpressure hardening -->
- Lane-local session-cache eviction now preserves quorum-certified committed
  lane-block sessions until the executor boundary drains them. Ordinary
  uncommitted session state remains bounded, but certified prepare+commit QC
  evidence is not discarded when the committed-lane execution queue is full.


<a id="record-179019f91d73e7eabc2c2b0b73bb1c8bcb82eab33dff5958d4778fad036d75d3"></a>

<!-- Original context: Status / 2026-07-07 Direct lane-block state application replay -->
