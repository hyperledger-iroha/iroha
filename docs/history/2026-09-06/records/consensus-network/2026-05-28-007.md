## 2026-05-28 Sumeragi quorum recovery vote-drain formal gate



<a id="record-5069760dbcd6342faf8b7f3f338543fa06cf19ee11a24270b0b16646b05ee30a"></a>

- Added `SumeragiQuorumRecoveryVoteDrainUrgentGate.tla` to model
  `quorum_recovery_vote_drain_urgent()`.


<a id="record-9a54836f3610a9fdec82821304587334ef67fd53c4abc0f069aba733bf927b6b"></a>

- Captured the urgency policy: zero quorum timeout disables the signal before
  scanning pending blocks; only non-aborted pending blocks that extend the
  current tip can drive urgency; local commit votes, observed commit QCs,
  stored votes, and cached QCs each count as evidence without requiring queued
  vote work; no-evidence pending blocks require waiting vote backlog and use
  inserted-at age; and scanning is existential, so one later urgent pending
  block is sufficient.

  first-pending-only scans, all-nonurgent acceptance, and no-pending
  acceptance. Wired the family through the formal runner, PR CI,
  expected-failure CI, Sumeragi formal README, CI documentation, and roadmap.
