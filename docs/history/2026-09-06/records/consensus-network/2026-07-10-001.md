- Closed the raw private-witness consensus corridor. `Secret<int>`,
  `Secret<decimal>`, `Secret<quantity>`, and `GET_PRIVATE_INPUT` remain usable
  by local/prover/test hosts, while ordinary production dispatch rejects every
  seiyaku selector with a reachable private-input read, including helper-hidden
  reads. `CoreHost` also rejects `GET_PRIVATE_INPUT` during both quote
  preparation and direct execution, so a resolver regression cannot expose the
  local `DefaultHost` witness transport. Raw witness bytes never enter signed
  transactions, `IvmProved`, overlays, public argument records, or
  deterministic validator replay. A production proof-carrying path remains
  release work and must bind the
  seiyaku address/code hash and selector, public arguments, authority/chain,
  state and exact accesses/effects, outputs/events, gas policy, and circuit/VK
  version before that fail-closed gate can be removed.

## 2026-07-10 SCCP consensus governance and predicate gate retirement



<a id="record-f643fe8957dc4a93f6a838f15e5c712111954a5c8e3561e2d29de987685c73e2"></a>

- Moved first-release SCCP lane material and wallet route manifests to
  consensus-owned state. Both are fields of the versioned `sccp_registry_v1`
  custom parameter; the typed SCCP route-manifest instructions validate and
  replace that aggregate rather than updating side state. Non-empty node-local
  `zk.sccp_*` startup lists are rejected instead of acting as policy authority.


<a id="record-e54becd4c584c2d4f75f81170626499051142d347f1061824cd955f52c3993ad"></a>

- `CanManageSccpGovernance` is retained only to administer who may submit SCCP
  proposals; it no longer authorizes lane or route mutation. The generic
  parameter permission likewise cannot authorize SCCP governance changes.


<a id="record-6108829e99adc722211cc47998890cf28f740e26fe5dd7ea0840fcc4f95fda48"></a>

- Retired the hard-coded SCCP launch-mode selector. Every supported lane is
  evaluated independently under the governed allowlist policy and requires
  exactly one production-ready wallet route manifest bound to its lane in the
  same registry. The all-lanes readiness result remains an operator/release
  diagnostic rather than an admission gate.


<a id="record-6529c54aacbe09d4b087a04995007fa7f3ad1a11573a6d2be19e365606752a9e"></a>

- Made SCCP snapshots generation-consistent and included every registry field
  in the canonical ZK consensus policy hash. The complete aggregate is
  validated before installation, commits transaction/block atomically, and is
  reverted by the normal MVCC soft-fork and snapshot rollback paths. Route
  manifests are limited to one per supported domain and pass a bounded,
  panic-free validator before their governed lane bindings are checked.


<a id="record-e49f1603f4643dfa89c6d3f3356e4d6fb2af90abf15bc0ea78b46145ed41e6dc"></a>

- Classified the checked-in BSC signal-binding and labeled-signal-binding
  circuits as `public-signal-binding-material-only`. Their artifacts remain
  useful for public-signal conformance, but are always non-production and
  cannot be attached to a production route.


<a id="record-c960748154fc0867af72aee8e408d1a72221bf5cffa7b9d47966fb7f74d2073d"></a>

- Removed the retired `tx_predicates` Cargo feature. Committed-transaction
  predicate evaluation is part of the `app_api` surface, with one strict typed
  JSON/Norito grammar, canonical literals, and shared depth, node, and
  membership bounds; invalid trees fail closed.

Historical SCCP entries below preserve the implementation state at the time
they were written. References to an Ethereum/BSC/TON launch mode, an
all-lanes-at-once admission gate, node-local `zk.sccp_*` authority, or a
separate `tx_predicates` feature are superseded by this 2026-07-10 design and
must not be read as current operator guidance.

## 2026-07-10 P2P newest-control-update retention



<a id="record-43776a6eb72f1e2857c438bf55a7ec34d2d686b3b7f77712fb1393ce5c804438"></a>

- Replaced the seven runtime topology, peer-address, peer-capability,
  trusted-peer, ACL, SoraNet-handshake, and consensus-capability update queues
  with independent Arc-backed, single-retained-snapshot latest-value slots. A
  new snapshot overwrites stale pending state, and receivers clone the retained
  Arc under the watch lock before cloning the full payload outside it, so burst
  publication remains non-blocking even for large topology or ACL snapshots.


<a id="record-38add3622eaf50e3ef1c3008375c7b609eabe44edafdc4e07d0bffa632845c9c"></a>

- Preserved reconnect intent across coalesced consensus-capability snapshots
  with a monotonic reconnect generation, made peer capabilities an independent
  full snapshot so topology/capability application order cannot erase state,
  and kept public update methods and message types unchanged.


<a id="record-265fffcce917790c9bc634d963f96df4d797e5157c038b3bc705bba36f852587"></a>

- The actor now selects control categories fairly, checks shutdown explicitly
  at loop and high-batch boundaries, and pre-drains a bounded number of peer
  lifecycle/admission service messages. This prevents a continuously refreshed
  control slot or saturated high-priority outbound queue from starving other
  controls, admission replies, or shutdown.


<a id="record-509c8d0505ada86a739b71464df2ce5edd5a5b9f09c27a7000bdcf7737c2b1ac"></a>

- Hardened P2P integration fixtures so tests unrelated to PoW do not time out in
  Argon2 admission, while a four-peer positive test still exercises three
  matching required-puzzle handshakes and the mismatch case remains covered.
