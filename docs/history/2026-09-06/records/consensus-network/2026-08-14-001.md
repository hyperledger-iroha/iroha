## 2026-08-14 Sumeragi V2 lifecycle cutover and proof-release freeze



<a id="record-dde3a935a9e35dfada609f173037c63a317890172cb9f7a0ce4239316630faea"></a>

- The production runner now routes both ordinary and recovered PendingKura
  heights through lifecycle-owned launch, recovery, active-turn, finalization,
  store-retirement, and successor-handoff type states. The superseded
  predecessor witness/episode protocol is replaced by direct observation and a
  move-only, one-turn predecessor-admission guard.


<a id="record-2653be8d7ae2c1c0fbd3c6aa4dbea2b18705f18f812fe716eba0059ccf2fbffc"></a>

- A rolled-back raw certified-Serve waiter can no longer deadlock shutdown.
  Only an exact `Shutdown` command may cross that dormant post-rollback state;
  ordinary and other control work remain blocked. The focused source contract,
  broad-control mutation, recursive worker seal, and regression inventory bind
  the exception.


<a id="record-4b77001d433abc6194130fe4bad734f2281c242d6f2a691e3a6847a310e5774d"></a>

- Production-trace certificates now bind cross-tool evidence to the byte-exact
  TLAPS proof-ledger digest while retaining the canonical JSON document digest
  as a separate field. A focused regression proves the two digests may differ
  and rejects substitution.


<a id="record-49bb83355026ddbf751b4d713dd3566ce4ce2836f72d73cafd9ed1e91b1c2a5e"></a>

- The canonical 54-obligation ledger now records 44 `tlaps_proved`, 3
  `cross_tool_proved`, 6 `trusted_contract`, and 1 `out_of_scope`, with no
  `specified_unproved` rows and `machine_checked_completion: true`. This is
  the checker-mandated revision-4 status inventory, not proof
  evidence by itself and not a deductive proof of revision 4. Release still
  requires fresh exact-source strict TLAPS, pinned Verus, derived cross-tool
  and production-trace evidence, the separate mandatory revision-4
  TLC/mutation corridor, same-source signed receipts, and the completion
  marker.


<a id="record-50a188083281ec1ad4b03512839894d4ef817859228594126a40c3c62f8a6aae"></a>

- The full non-release proof checker passed structurally, and the focused
  direct-Serve, same-round semantic-kernel, Serve-regression, and trace-link
  Python tests passed. Python compilation, diff checks, reviewed source seals,
  and the source-budget gate pass; `Cargo.lock` remains byte-identical. The
  concurrently merged confidential-spool dependency mismatch is now withdrawn
  as recorded above, so fresh Sumeragi compilation can resume after the active
  merge settles. Two pre-fix focused Cargo tests also remain blocked in the old
  shutdown path and were deliberately not interrupted. No Taira mutation or
  soak has begun.

## 2026-08-14 parser, consensus, decoder, and SDK query hardening



<a id="record-5ba87b56172113a4663dbc61c21fa9525dedfdb082d72f5992e02de608dc93d4"></a>

- Numeric text parsing now consumes at most one optional leading sign and
  rejects repeated or mixed signs instead of silently accepting values such as
  `++1` or `+-1`.


<a id="record-72ed8294184713547c54270485c0b8ca882edb7292d806c3210b783768f576a6"></a>

- Sumeragi V2 timeout-certificate validation now treats different deterministic
  execution commitments as conflicting same-view `PrepareQC`s even when their
  block subjects are equal.


<a id="record-e9db96cf95aee5e3e8f62016def59cad3bb378d160c156afc8c1912bfb6e9054"></a>

- The public Norito sequential vector decoder now rejects impossible declared
  element counts before allocating, uses decode-budget accounting and fallible
  reservation, and returns a typed error rather than panicking differently on
  32-bit and 64-bit hosts.


<a id="record-ff2a6283abe7dd4cec81b0ac63f7e50c3fa8d9d5485c17248299e641ef15dc84"></a>

- Kotlin and Java Torii HTTP, RPC, subscription, SSE, and WebSocket clients now
  insert encoded query parameters before a URI fragment while preserving both
  an existing query and the fragment.


<a id="record-ad36bc8d3633c74627a586226851bf8e1016c2450e30b6890a1feb8498fff481"></a>

- Focused Rust regressions, all 277 `iroha_primitives` unit tests, all five
  sequential Norito tests, the Kotlin SSE suite, Java production compilation,
  and the isolated Java SSE harness pass. Broader Java test compilation and an
  unfiltered data-model integration build remain blocked by unrelated existing
  test-source errors in the current worktree.

## 2026-08-14 Sumeragi lifecycle-owned non-Pending production cutover



<a id="record-ce0c550a23358194b5e4e603e36eda0964f17cb87cfd093d962c1a7e277070f7"></a>

- `LaunchedProductionLifecycleV1`, with narrow forwarding from the activated
  state, now owns one move-only API for each real borrow-bound Completion and
  Ingress turn. A lifecycle-selected branch consumes the current turn only
  after exact work has been classified; `PassThrough` returns the unchanged
  cursor so the ordinary owner can still run in that turn. Deferred recovered
  Apply, guarded Sign and Decision-Fetch completions, and recovered ingress
  capacity waits stay private in the launched stack.


<a id="record-8d04bae86c5aa09446e3ee12e9df20f53824ec663a90eab9cf02d13e41d28230"></a>

- Completion servicing checks retained owners before taking one physical FIFO
  head and then classifying the complete Ready census. It selects only the
  matching Apply, Sign, Fetch, or full-census Broadcast transaction, supports
  Broadcast coexistence with Validate and other authenticated Ready rows, and
  never probes mutually exclusive Sign settlers. The adapter preview chooses
  exactly one structural Sign successor family before the corresponding
  consuming settlement runs. Selected dispatcher drift and recovered Fetch
  service failures close output and require restart.


<a id="record-326e2845945ed196380e5d771c3c40a1045e04cc78e2c98963d6f71c0f566977"></a>

- Ingress servicing retries the retained service-generation wait before
  selecting one exact physical fair winner under a retained queue-service
  episode. Obsolete, ordinary, and foreign winners use the existing exact
  dequeue/accounting/rotation tail and move into an opaque fail-stop handoff;
  they never return an unchanged cursor or reselect. A selected response scans
  only its exact request family, while a recovered Decision-Fetch winner keeps
  its queue witness and enters the existing Phase-A path without dequeue.


<a id="record-f9cfb1ec7b75d3c2eb624a0f6d6d907770206ec28bec7cbf5af975cb214ba8c3"></a>

- Current-height Certified-Serve authentication, durable negative staging, and
  preparation now run only after the pure selector fixes one occurrence and
  before physical removal. Accepted/rejected/service results remain inside the
  opaque handoff. Backpressure retains the cut and off-queue debt without
  allowing a later row to leapfrog. Post-preparation failures and unconsumed
  token Drop close output before the retained queue/service authority or Serve
  admission is released.


<a id="record-b4e3a86d67e21d06a456c6ef188dce48c62aee0e56d5cc2817307c5801bc1268"></a>

- Mixed recovered Apply/Sign/Fetch rows now enter one authenticated Ready
  census. The service freezes the worker FIFO and exact-output corridor once,
  every row retains its physical availability and predecessor debt in the rank
  snapshot, and only the selected row receives its typed reservation. Saturated
  rows remain Ready without a class-specific re-probe.


<a id="record-a9ba554f02a76fc252069e7f2a37af75457c1a6cade11b2b209fc7b18c025673"></a>

- Every non-`PendingKuraApply` production height now runs through the sealed
  lifecycle owner. Its lifecycle-aware ordinary batch derives
  the output guard from the activated services, advances the real
  Completion/Runtime/Ingress cursor, gives recovered work first claim through
  the lifecycle drivers, and routes an ordinary dequeue through the shared
  opaque lane/Kura/historical-Serve/control/payload/NPoS consumer. No parts
  accessor or caller-supplied output authority crosses that boundary.
  `PendingKuraApply` now completes through its dedicated lifecycle-owned,
  no-clock recovery height, then transfers its verified successor and fresh
  lifecycle-storage authority into the same lifecycle loop.


<a id="record-7ffbd75a236d5ec3c276c111dfac806290f5b9de62ec80871f0b23730ad1c316"></a>

- A move-only runner key now admits bounded setup through the launched stack
  before activation. An armed non-permit fail-stop scope spans the callback and
  exact pre/post checks for executor/service output ownership, closed joint
  ingress, the retained completion observer, and unarmed live clocks; open
  output is witnessed before and after, but no read permit can deadlock a
  nested service failure. The generic callback can borrow only executor and
  services; the sealed CompleteTip H/H+1 wrapper delegates that same closed-
  ingress transaction without exposing either half of the join. A separate
  consuming initializer owns the exact runner-local Proposal key. A recovered
  ProposalIntent now retains one opaque attempted owner through cold adapter
  advancement. Recovery derives it from the replay-authenticated durable
  current-round intent even when later Prepare/Timeout or phase-vote authority
  owns startup; old-view intents do not suppress a successor view. The runtime
  independently closes direct local admission for a current-round durable
  ProposalIntent, TimeoutIntent, or Decision before candidate consumption.
  Preactivation compares the attempt with the reducer directive, binds that
  exact attempt into a non-cloneable prepared state, and makes ordinary or
  CompleteTip activation consume and retain that state. Discarding the
  directive or state therefore cannot reopen modular lifecycle activation.
  The activated runner borrow now carries that same
  opaque scheduler owner beside the lifecycle owner, executor, and services;
  the non-Pending production loop now mints and uses that state. Only the
  isolated PendingKura recovery height carries no local-Proposal state or
  pacemaker authority. Interrupted-tip `PendingKuraApply` now
  has an opaque Decision-Fetch/WAL/runtime replay join: same-height foreign
  blocks fail before owner launch, the exact Fetch remains a runtime sidecar,
  and preactivation verifies before local dispatch while ordinary activation
  stays closed. Its dedicated runner branch keeps the activated lane adapter
  affine with the lifecycle stack, publishes the recovered current-height
  snapshot without arming clocks, and finalizes through the shared durable
  output/store/cleanup transaction.


<a id="record-24ca9667ef711fc83b5195c8c2e04ba859f0c19cf7bd8139b1f259bd50d895d9"></a>

- Cold local-proposal recovery now distinguishes an exact fsynced body created
  before its ProposalIntent from unrelated durable catalog state. An exact
  current-round retry regenerates its closed replay lineage through one
  idempotent physical Store and one real deterministic Validate before queuing
  `LocalProposalReady`; byte/manifest/view drift and durable rejection fail
  closed before work admission. Every recovered body receipt hydrates durable
  comparison state, while retired rejection markers remain local-producer-only
  denial and cannot synthesize reducer `ValidationFailed` authority.


<a id="record-97f2dafb56347711f4ee61077b4b8b5a9763b3313855e520eccdad4519c741b8"></a>

- A verified live successor now consumes itself into context, activation,
  and one move-only lifecycle-storage authority. Successor construction retains
  the exact State-owned Kura identity; projection rejects a foreign Kura and
  fixes the post-genesis signature policy to rotating leader before minting the
  storage seal. Both ordinary lifecycle finalization and the dedicated
  PendingKura lifecycle tail consume this projection before successor startup.
