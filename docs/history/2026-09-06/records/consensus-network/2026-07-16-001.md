## 2026-07-16 Sumeragi v2 release-audit follow-up



<a id="record-bdca271d30170271165b47b36f7a581b939333abebfe3e0d856db62139530d97"></a>

- Classified `LocalProposalReady` as trusted Completion work in both runtime
  ingress and the adapter's Busy-deferred queues. It now uses the reserved
  Completion capacity instead of competing with Normal ingress, so saturation
  cannot strand a locally built, durably stored, validated proposal.


<a id="record-a739d337b3005538ea41da888b376dbee1fa72a9e66506105afdab9268596850"></a>

- Moved execution-commitment compatibility to the authenticated ingress
  boundary. An individual signed Vote cannot establish commitment authority;
  it requires an exact binding from a local validated receipt, verified WAL
  replay, or quorum-authenticated QC. An unbound Vote is rejected recoverably
  and may be retried after that authority arrives. Other commitment-bearing
  evidence is conflict-checked before serialized runtime ownership.


<a id="record-ef8d09b7ae3edb6b5659dc7e4306d155aa96fa18d44c79ea615d57919cd789d8"></a>

- Required every Commit vote, including a current-view vote, to match the exact
  active durable lock before it can enter a reducer pool. A pre-lock current
  Commit is ignored recoverably; after the matching `LockAndCommit`
  acknowledgement installs the lock, the adapter advances its locked-Commit
  consumer epoch and may admit that exact vote once. The acknowledgement applies
  the lock and then retires the superseded historical Commit pool before
  releasing the current Commit signature. Outbound retransmission remains a
  peer-delivery source, not a sufficient local reconstruction witness because
  broadcast excludes the sender.


<a id="record-8138f0cf2fbc13ea42a7b27af2f8902703f6dd6f8ab1a8211f364960554b16a7"></a>

- Hardened completion transfer and cleanup transactionally. `BodyAvailable`
  rebind requires the installed destination tag and preflights source plus
  destination ownership; it moves one exact source or coalesces one exact
  destination. An uninstalled destination is a recoverable non-mutating caller
  rejection, while conflicts or duplicate owners fail closed before mutation.
  Pipeline and Decision retirements likewise preflight every owner before
  removal. Certified-body request conflicts remain nonfatal, and conflicting
  Commit-certificate responses leave discovery outstanding for retry.
