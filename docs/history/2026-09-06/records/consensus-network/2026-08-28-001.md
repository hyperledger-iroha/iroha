## 2026-08-28 P2P security audit and hardening



<a id="record-e685aa1faf874b163908d90793864d692c4decc4ce29f879a10f68385b43a8d1"></a>

- A scoped static and adversarial P2P audit identified actionable issues across
  QUIC streaming, relay admission, HTTP CONNECT request construction, and
  peer-address gossip. The validated application-owned findings are fixed
  in-tree. Shipping P2P, Norito streaming, SoraNet relay, and VPN-helper QUIC
  now fail closed before endpoint creation while the lockfile resolves
  `quinn-proto` 0.11.15. Released 0.11.17 fixes unauthenticated remote-memory
  exhaustion in stream reassembly and connection-ID retirement in addition to
  zero-length DATAGRAM accounting. Mandatory TLS-over-TCP continues to carry
  P2P traffic, including best-effort topics. Streaming and SoraNet QUIC paths
  remain dormant. The streaming API now includes the deterministic bounded
  unidirectional-stream media fallback required for post-upgrade requalification.
  Each media window has one absolute transfer deadline capped at 30 seconds,
  failure closes the connection, and the transport advertises no unused
  bidirectional-stream credit.
  The dormant ingress implementation still eagerly drains before authentication, rejects invalid
  frames, compacts packet-backed payloads, and uses count-and-byte-bounded
  handoffs. P2P also serializes the authentication boundary and caps the ready
  pre-authentication drain at 256 entries. These defenses remain regression
  material rather than a claimed bound on Quinn's pre-poll queue. Quinn
  released quinn-proto 0.11.17 supplies the required fixes; upgrading the
  lockfile and requalifying the dormant paths remains tracked in `roadmap.md`.


<a id="record-a1c91f3d6c4f56fa0cf085eb3e118b5c609b64865ffdffc511ba904287928067"></a>

- QUIC control decoding now honors the frame bound before allocation and
  decompression. One absolute, atomic setup deadline covers connection and
  capability negotiation; negotiated DATAGRAM policy is symmetric, bound to
  the acknowledgement, and enforced on receive without an install/admit race.


<a id="record-fb6f47dfe20dc275fa02c7550ae69a62ba366f32a673a42f688f6e06185f8081"></a>

- Relay forwarding clamps and decrements the local TTL, derives queue priority
  from the authenticated message topic on both ingress and forwarded egress,
  quarantines invalid signatures and origin mismatches for only the exact
  connection tenure, and grants relay-hub authority only after an exact
  outbound configured-address proof. Assist and Spoke modes reserve one hard-cap
  slot for that proof or a proven-hub reconnect without allowing the physical
  connection count to exceed its configured maximum. HTTP CONNECT authorities
  are canonical strings derived from validated typed socket addresses before
  any proxy bytes are written.


<a id="record-e5832c57f6fb5db78e496b53d81635c1112d333eb20a1a987408197dc6209939"></a>

- Address gossip now accepts votes only from the exact active-validator roster,
  requires a uniquely top-ranked mapping backed by at least `f + 1` distinct
  active-validator reports, preserves startup mappings, and advertises only
  locally configured addresses. Third-party transport-capability claims no
  longer influence preferred-dial scheduling; only the capability subject's
  authenticated connection may update its hint. A supervised post-commit
  synchronizer publishes every applied validator-roster change and reconciles
  the latest committed state after event lag.


<a id="record-6d2bb5484ef26f4926e7b0fbc7a4f78c78d8dc94480763fe7ee60368c3f45635"></a>

- Operator outbound-dial policy now applies deny-before-allow CIDRs and DNS
  suffixes to literal targets, logical hostnames, every concrete DNS answer,
  proxy endpoints, and direct TCP/QUIC/SCION-preferred dials. IPv4-mapped IPv6
  addresses cannot bypass IPv4 rules, suffixes match only on DNS label
  boundaries, proxy CIDR policy uses one locally admitted numeric target while
  retaining the original TLS name, and one lookup is capped at 64 raw answers
  before retention.


<a id="record-608c1302f5a4c23c38bf1f14ffd199a693dd04219c68ed0ab6d392035a8215e6"></a>

- Inbound address admission, CIDR parsing, token buckets, and accept-throttle
  ownership now live in a focused actor module. Malformed startup or hot-reload
  CIDRs fail closed, IPv4-mapped IPv6 rules canonicalize without representation
  bypasses, and `max_accept_buckets` is one aggregate prefix-plus-IP cap. A cap
  too small for the enabled dimensions is rejected before listener binding.
  Authenticated Ping/Pong shares a per-connection two-frame burst refilled once
  per half-idle interval; excess health traffic neither amplifies Pong nor
  refreshes liveness.


<a id="record-f7b58449dc98112103f7706844b6aae95a4a0893614141257dc7b2668b9b285d"></a>

- Reliable actor retries retain one signed `Arc<RelayMessage>` across direct,
  broadcast, and relay-hub attempts, eliminating repeated BLS signing and
  retry-owned signature allocation while keeping exact byte leases. The
  process-local reliable state, inbound admission, and QUIC DATAGRAM ingress
  are isolated in private child modules, and an exact production-source inventory/module-graph
  test prevents shipping P2P code from becoming test-only or orphaned.


<a id="record-46d5bf75ea07f24817ddd0de08d22cf1f657ee66aa1c7c30adbd0505d6f998f4"></a>

- The authenticated 1024-byte strict SoraNet record/mux implementation now has
  bounded class scheduling, logical-channel lifecycle checks, fail-closed loss
  and deadline handling, a cumulative two-tick early-arrival envelope, and
  bounded, keyed lane-task ownership. Immediate
  lane-ID reuse cannot overlap a prior response, and completed OPEN/FIN churn
  is reaped. Future strict activation is additionally bound to the shared
  `core` 5 ms profile; `home` and `null` are rejected because the V1
  capability does not negotiate tick duration. Strict negotiation remains
  rejected at configuration and live preflight while the locked Quinn receive
  queue lacks fixed per-entry accounting. The ordinary VPN stream
  implementation remains record-protected, but helper endpoint creation is
  also blocked by the broader dependency gate.


<a id="record-76a84af7b6a85fc4655800fd48cb54bc16626702870e737ceffdbf32cd7d25d1"></a>

- Focused validation passes the `iroha_p2p --lib --features quic` check; all ten
  outbound-dial policy tests; six admission-actor tests; three shared Ping/Pong
  limiter tests; malformed-ACL and accept-cap startup tests; all three
  signed-envelope retry paths; one-shot materialization; the standalone
  production-source reachability guard; four receive-pacer tests; lane-reuse and
  relay silence-deadline regressions; the SoraNet PoW configuration regression;
  relay-library and VPN-helper checks; and scoped formatting. The current-mtime
  QUIC-enabled unit target also passes public dependency-gate, deterministic
  media-window validation, and partial-stream absolute-deadline regressions. The
  dormant post-upgrade QUIC abuse matrix and full multi-hour workspace matrix
  have not been claimed. The lockfile still resolves quinn-proto 0.11.15; this
  hardening work did not edit it.

## 2026-08-28 Sumeragi v2 liveness ownership repair



<a id="record-b60da661e1e94b9574ae15825693bc535dad43bfff3b222f761e86c88b6830a9"></a>

- Certified-body requests and responses now retain their exact-output owner and
  ranked actor ticket across later views. Completion and explicit cancellation
  retire the exact request fanout, while view cleanup still removes obsolete
  proposals, votes, certificates, timeouts, manifests, and beacon traffic.


<a id="record-ea0a55d6e6460ee35ad1336374c569732a321e31f5cafe368ab2ffaba55fcb2d"></a>

- Archive-target rotation no longer replaces an incumbent acquisition fanout
  or accumulates one fanout per retry. A different target batch remains with
  the durable fetch/discovery source until the single ranked incumbent drains,
  after which the next responsive archive can acquire the bounded corridor.


<a id="record-ea5ec7d3420637e9b4e088f2bf010bf1b1510b178fb574cf07ccabcc1e751144"></a>

- Certified-body fetch and Commit-certificate discovery no longer let
  ticketless network backpressure pin an archive target that may have left
  topology membership. That unranked target returns to the outstanding durable
  acquisition source so its next timer retry can rotate to another archive; a
  ranked actor ticket remains non-displaceable and is released only by delivery
  or authoritative cancellation.


<a id="record-1d351867e0f891351849c0261627bd98af216afa4a8a5ab19239a8e79d88988a"></a>

- Certified merge-sidecar requests and cumulative Close messages now apply the
  same ticketless topology rule. A departed predecessor responder cannot retain
  a Close forever without an actor rank, consume the shared non-roster corridor,
  and block a decided sidecar fetch from reaching a live predecessor; the
  durable request/stream tracker remains the retry owner while ranked attempts
  stay non-displaceable.


<a id="record-eb4003bfd02f4eb2f3901bf78392592e6e225defe44f21438f2512c742d5cd83"></a>

- A successfully authenticated successor-generation sidecar Hint now retains
  one strongest bounded cancellation fence per semantic responder after
  durably replacing the old stream. Before successor traffic is dispatched,
  its exact observed-message and endpoint authentication removes every
  canonical Request or cumulative Close for that endpoint pair below the new
  service generation, releasing ranked actor tickets even when the Hint
  observed a sibling occurrence. Worker failure requeues the fence; chunks,
  acknowledgements, unrelated endpoints, and equal/newer generations cannot
  match it.


<a id="record-a016c7b6d3019ca75d95aa5658108499a8e2c5626ee87dae223506bbfa74eb78"></a>

- Kura-backed autonomous payload/NewView output and historical lane
  certification also release a departed predecessor target which acquired no
  actor rank. Under a saturated one-unit non-roster corridor, an obsolete
  committee member therefore cannot suppress every later live member and pin
  autonomous view change or historical lane certification forever; the bounded
  lane-artifact scheduler retains exact retry ownership.


<a id="record-d2202857a47e33a22ac51e32cdbf6959936f27a021197d9dddb926ae45c1cbe7"></a>

- The chain-scoped CommitQC/body response cache distinguishes a request's
  coarse logical slot from its complete unsigned fingerprint. A separately
  authenticated signature variant over the same request can rebind a cached
  canonical response to its new exact hash without a Kura reread, while changed
  unsigned body evidence remains a conflict and cannot multiply cache entries
  or disk work.


<a id="record-7844c9b6c7dbe24f7ab5d6d833c13a99e85c04475237d9e89184c31eae386a2b"></a>

- A WAL-recovered Decision whose body is still absent now retransmits its exact
  signed certified-body request on the configured cadence from the retained
  executor owner. One actor-admitted but remotely lost occurrence can no longer
  leave the ordinary or pending-Kura lifecycle row waiting forever; an
  authenticated response claim suppresses further retries.


<a id="record-45ead9054fe4b0f1c6308aaf6c71babdedb39e8b6434f2749eab2481daeb213b"></a>

- Reconstructing that recovered fetch now refreshes only its bounded delivery
  destinations from the current authenticated configured-peer snapshot, with
  the frozen height roster as the empty-snapshot fallback. Offline topology or
  key rotation can no longer recreate the exact request forever against a
  departed roster, while the signed request, QC, context, and response verifier
  remain unchanged.


<a id="record-538f3b02912c6d60e1fd62818ea5b0b5b789c963f259b20751ba5026c8fd8670"></a>

- Historical canonical-body recovery also samples current configured archives,
  with the old CommitQC signer set as the empty-snapshot fallback. Every archive
  whose immutable request was actually queued stays authorized across later
  rotations, so a delayed exact response can still finish recovery. The union
  is atomically bounded by lane session capacity before fanout; overflow fails
  closed for restart without evicting live authority or exposing a partial
  attempt, and completion clears the full request-scoped set.


<a id="record-9c772acb69788c3439fb4b9ea57f25d588d0e641aa4cce79f6d30f282cbea9af"></a>

- Canonical executed-block recovery uses the same current-archive-first policy
  and pins one responder across an exact multi-chunk transfer. Timeout or a
  poisoned assembly clears the pin before resampling; mismatched senders,
  finality, wire hashes, or chunk geometry remain rejected.


<a id="record-5de49aa9565ab86963d0d7334a3f588a00e727bd158ffa23432813c488e29ad4"></a>

- Historical merge-sidecar service now accepts an authenticated requester from
  either the current roster or the exact historical finality roster. A current
  validator no longer needs to have existed in the old committee, while Kura,
  carrier, holder, route, signature, and finality checks remain unchanged.


<a id="record-90909c8d73a63db4278b60aecff4bd4263310cf6f246a6b6cbf9d9d7f369999b"></a>

- After `State` commits a height, ordinary exact-output retry can reread the
  cryptographically verified Kura finality artifact and retire only unranked
  topology output covered by the existing typed applied-height verifier. This
  releases stranded current-height global control and manifest-bound signed
  payload chunks without releasing ticketed, manual, wrong-scope, or
  substituted output; Kura persistence without State application is
  insufficient.


<a id="record-1f1f5c4e6b2f8e6842f22a4fbd915a9ae9142cd4a7ba6ef5c51a9659dffe56b7"></a>

- Durable Kura replica adverts use that same State-after-Kura ordering. Only an
  unranked, exact typed advert can release after application, and each released
  source height is rescheduled through the process-lifetime refresh owner after
  output locks drop.


<a id="record-a5e7d85f6348a0098c0831a22c2dd817ed33e69565577b2697c9d78adcd4b1cb"></a>

- Ticketless QueuePlan admission output now receives the exact read-only Kura
  source required by its applied-height verifier. Missing or mismatched
  certificate bytes and live actor tickets retain ownership; an exact release
  does not spuriously schedule replica-advert refresh work.


<a id="record-198ba4ecc35068399356414ecbf2ce7bf2760a136d349a57234e86298e39d5b9"></a>

- Successful recovered Decision-Fetch Store settlement now preflights
  cancellation of the exact request fanout before LedgerV1 publication and
  commits that cancellation only after fsync under the same fail-stop output
  operation. A ranked sibling target can no longer retain an obsolete actor
  ticket, keep terminal exact output nonempty, and block successor activation
  after another archive already supplied the body; pre-publication failure
  preserves both owners for exact retry.


<a id="record-3ca60f67cd4330fc00e48ddc2395b2f9bd11c06e7f761787be0f096bf553c3a6"></a>

- Certified body persistence now wakes a matching locked-candidate acquisition
  that previously observed the body as unavailable. A later leader can therefore
  reload the newly durable exact body and repropose its locked block instead of
  leaving the acquisition parked in `Waiting` forever.


<a id="record-66c8d3a0bbe21b9b1b9f7f90c59c27f0eb5c408fe65f1ce46f76e05917d71ce2"></a>

- Certified-Fetch persistence planning now attests the selector's consumed I/O
  target state after capacity capture moves the exact target seal into its live
  reservation. The reservation and final command preflight keep the target
  linear and exact; the former pre-capture-state check rejected every successful
  reservation as `InvalidSelectedCarrier` and could leave certified recovery
  permanently waiting despite available completion capacity.


<a id="record-86a67e07d440a39fe10ef21e7352d4c775348503968d0670e4f62f112ea8fed6"></a>

- Periodic Proposal retransmission now recognizes an already retained atomic
  Proposal/chunk component by its exact claim and message hashes, including a
  fast-path-to-all-voters target expansion. It leaves the retry with the
  semantic source until the incumbent drains instead of duplicating fanouts or
  fail-stopping during prolonged actor backpressure.


<a id="record-56e57cb12ec6840d7c6fa7008da964cdcdb6495ec02536239766af632df6254a"></a>

- An authenticated future-view PrepareQC now remains owned at its durable FIFO
  position while the pacemaker selector excludes only that blocked occurrence
  from Progress candidates. An admissible current-or-adjacent TimeoutVote, an
  at-or-ahead TC, or a same-height terminal CommitQC may overtake without
  consuming the retained owner. A TC-installed view makes the carrier retryable
  as current evidence; stricter TimeoutVote rules, stale/current certificate
  handling, full cryptographic validation, and future-vote rejection remain
  unchanged.


<a id="record-fc23e21c835b383ccfcc1633cf31acb5109372ad1f0ac72292d372a27c94d4c5"></a>

- Interrupted-tip pending-Kura recovery now services owner-held cold output
  before ProducerTurn and refuses final readiness while any recovered output
  remains. Rollover also carries the exact-output pending result through
  preflight and a dedicated finite closed-prefix loop, so actor backpressure or
  a newly published cancellation handoff cannot consume the predecessor or
  reopen ordinary no-clock work. Physical ingress closes once, its finite
  admitted terminal prefix drains, and only an empty closed cut can roll over.


<a id="record-1f0af47c24e46f079c56e183efa40ae85afb3f8865677f66e1bd2b2ee5281a74"></a>

- Ordinary finalized-height terminal cuts now apply every already-owned lane
  cancellation/admission handoff before sampling exact output, including the
  Apply-only barrier and post-preflight closed-prefix checks. Historical
  recovery completion and authenticated sidecar fences therefore cannot leave
  an otherwise unreachable actor ticket blocking successor activation.


<a id="record-616e705cb278ba1d12358b37ce345e6872eee16036f35cb555ba91feec3b0480"></a>

- Autonomous lane NewView votes and certificates have one bounded progress
  occurrence beyond the ordinary lane-effect capacity. A continuously full
  ordinary output queue can no longer reject every due view-change fanout
  before it acquires retry ownership, and a displaced ordinary owner can still
  requeue beside that progress occurrence.


<a id="record-b12ce83e0e9298ab1d3d38cefc4a2df6092cb781dff50ee157caab90b5ae8039"></a>

- Autonomous reservation planning no longer terminally suppresses a route for
  transient `BlockedPredecessor` or `PlanningSnapshotChanged` results. Its FIFO
  work remains intact and the configured bounded producer cadence replans after
  State/Kura progress; immutable planning failures keep their height-local
  suppression.


<a id="record-bc3cb2cb239558f0002ca8b6d2f5e2cf4ab097d7fa4db8e1277a1eafeba094bf"></a>

- Scoped Rust formatting and whitespace checks pass for the current Sumeragi
  patch, and there are no unmerged index entries. Focused Rust regressions and
  the strict Core test-target compile are pending the next stable shared-source
  build window; earlier binaries predate the final responder-bound and planner
  regression changes and are not acceptance evidence. The full workspace suite
