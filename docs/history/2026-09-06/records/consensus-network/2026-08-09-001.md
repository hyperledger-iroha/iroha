## 2026-08-09 Sumeragi v2 autonomous carrier terminal-persistence repair



<a id="record-ffbcbb88d32ba408a039f83542199bd260d6375e808b86adb8c0518bf584f7cc"></a>

- Kura now serializes ordinary autonomous executable-payload and execution-input
  persistence with exact application-receipt publication and bounded
  merge-frontier history maintenance under the same prune lock. Both
  durability boundaries return the typed `Persisted` or `AlreadyTerminal`
  outcome; an exact terminal receipt therefore prevents an ordinary late
  writer from mutating or republishing terminal
  auxiliary state, while unrelated I/O, validation, and corruption failures
  remain fatal. Authenticated NewView persistence uses the same prune-lock
  boundary and returns either the exact persisted cursor or `AlreadyTerminal`;
  its read-only main/crash-temp preflight validates the certificate before
  terminal classification without repairing terminal state. A pre-existing,
  source-authenticated signed bootstrap is the
  sole roll-forward exception: under the same ordered locks it completes the
  exact payload, Prepared cursor, and Live cursor before deleting the
  bootstrap, while Pending terminal-outcome publication waits. Receipt-terminal
  completion returns `AlreadyTerminal` without READY/fanout re-entry or Queue
  release. The crash-sensitive autonomous attempt/cursor/outcome unit remains
  retained; bounded indexed-history compaction still follows its independently
  authenticated terminal and retention gates.


<a id="record-962bc97f83bc85ab84e5d8fd4ec759d10f86c05c2f3e52c94643291f8de9b140"></a>

- Canonical carrier publication now reserves its exact post-WSV receipt,
  frontier, and terminal-work envelope at the sole durable pre-finality tip,
  matching the production block-then-finality commit order. Restart rebuilds
  that process-local reservation only from the same body/compact-reference,
  merge-log, and sparse-carrier proof; ordinary carrier lookup and all receipt
  or terminal-evidence publication remain unavailable until exact v2 finality
  is durable.


<a id="record-b47ee132817423f10dd8759ddfea14bc6f7c8bd8a116fae6a2e62e80c4465dcf"></a>

- The autonomous READY path distinguishes `Authorized`,
  `DeferredUntilCarrierProtection`, and `AlreadyTerminalApplication`. Losing a
  candidate carrier before global protection is a retryable deferral rather
  than a consensus-output failure. An exact applied receipt makes late ingress,
  READY authorization, cached-session progress, payload retransmission, and
  NewView timeout/retransmission paths terminal and idempotent; retained votes,
  QCs, and commit-lock evidence remain available for safety, while a stale
  locked carrier which still names the applied proposal is rejected without
  closing consensus output.


<a id="record-4689cb18db95b21c58e90950d09d624431e7dfc792d8a5516f87b45398dfff5e"></a>

- `merge_application_receipt_makes_autonomous_auxiliary_persistence_terminal`
  persists a real `MergeExecution` carrier, receipt, and frontier, then proves
  that later payload, execution-input, and valid NewView persistence returns
  `AlreadyTerminal` without changing the retained lifecycle evidence or
  indexed input state; an invalid terminal NewView certificate still fails
  closed. The extended
  `autonomous_ready_crosses_payload_and_certificate_durability_before_commit_vote`
  regression exercises the same exact terminal-receipt boundary during READY
  and stale-carrier handling, then checks that no READY, Prepare, QC, NewView,
  or payload-rebroadcast effect escapes and that a valid terminal replay
  remains a duplicate without closing consensus output.
  `autonomous_lifecycle_bootstrap_recovers_every_signed_crash_boundary` covers
  receipt arrival at BootstrapOnly, PayloadDurable, PreparedDurable, and
  LiveDurable, proves Pending publication waits for bootstrap completion, and
  verifies that every path reaches a restart-valid, Pending-publishable Live
  unit with no retained bootstrap. The unfinalized-carrier restart regression
  additionally proves that the post-WSV capacity reservation is reconstructed
  without promoting the pending tip to finalized carrier authority.


<a id="record-27079641c480a28aa8c8025ab0f5aa824bf77a28fc01f3b42236b789f87f19cd"></a>

- This repair does not change revision-4 empty-block admission: empty blocks
  still fail deterministic validation before Prepare or Commit voting, idle
  time does not create blocks, and epoch height continues to count only
  non-empty finalized blocks. A source-sealed four-validator canary and the
  coordinated live four-validator rollout remain release gates; no live cohort
  replacement is claimed by these source regressions.
