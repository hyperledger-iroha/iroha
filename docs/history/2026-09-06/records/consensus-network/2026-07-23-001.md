## 2026-07-23 JavaScript transaction-finality hardening



<a id="record-0943496c9f747c1813e34d59168761d9bc85c1b948e0b2d2815093b3b294a156"></a>

- JavaScript transaction finality waits are now uniformly global-only and
  settle only state-resolved terminal statuses. Cache-resolved `Applied`,
  `Rejected`, and `Expired` observations remain visible to callbacks but are
  retried until state resolution. Raw diagnostic status reads retain explicit
  `local` and `global` scope, while the pre-release `auto` mode, configured
  polling scope, and cross-endpoint fallback list were removed.


<a id="record-2bdbe91a696cc226e91edcff83d2d42f5d8c9c53e357085b66ac97c3c8f46f7f"></a>

- Validation-fee policy admission now rejects custom contract HRPs whose chain
  discriminant exceeds the I105 `u16` range before its account-key derivation
  loop, preventing hostile policy input from triggering an effectively
  unbounded retry.


<a id="record-434f99f3beaf0493650e52a5a78fed59306881b1974a562f9a0b68bd88ca5017"></a>

- Validation rebuilt the JavaScript distribution, passed package lint and
  changelog checks, 54 focused Node status tests, all 32 browser
  status/deployment tests, 8 Nexus finality tests, 72 validation-fee and
  high-level submission tests, and the dedicated package TypeScript checks.
  Source/distribution parity, diff whitespace, and `Cargo.lock` checks are
  clean.
