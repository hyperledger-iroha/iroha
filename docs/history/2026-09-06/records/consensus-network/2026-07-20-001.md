## 2026-07-20 Sumeragi v2 frozen exact-output reservations



<a id="record-ae9bfbada2787c381952d165d7fc9652b37460130ad08b360575f4dea2a0d7b6"></a>

- Fixed a production liveness defect in the bounded exact-output corridor:
  previously, every novel semantic target/class was treated as if it opened a
  frozen reservation, so authenticated non-roster reply targets could consume
  the full corridor and deny validator safety or lane output. The corridor now
  freezes the exact height-roster cross product with Safety, Lane, and Bulk,
  adds shared capacity instead of overlapping it with the reserve, and uses a
  deterministic maximum matching so one fanout claims at most one unique
  frozen reservation. Assignments are recomputed after every attempt, which
  reopens a completed target/class during partial multi-target progress.


<a id="record-4582a97b66d7ef5356d3f44d92f6d7456046f7b40ea871ee68c95275dbb6e3c8"></a>

- Added negative/adversarial coverage for non-roster identity churn, all three
  validator classes behind a blocked observer, reservation reassignment after
  partial fanout service, an augmenting-path reassignment with shared capacity
  already exhausted, reply-route cancellation/source release, invalid
  response-route fail-stop behavior, and the production runner scan which
  requeues an unserviceable head while dispatching later reserved work exactly
  once. The source-sealed pre-network inventory now contains 319 tests: the
  Sumeragi route/reservation slice contributes a net 13 beyond 298, and nine
  real P2P reply-route tests replace one phantom historical name for a further
  net 8.
