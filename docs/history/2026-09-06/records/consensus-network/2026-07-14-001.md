## 2026-07-14 Sumeragi v2 generation-scoped liveness closure



<a id="record-754aa454963e7cc0b3439adc3244f4283ec6d824a87ba4f454fc0ab5cd563280"></a>

- Split authenticated semantic admission into height-bounded equivocation
  history and generation-scoped delivery records. An exact Commit vote matching
  the durable lock's round, subject, and execution commitment can now cross
  admission once after each TC-induced pool reset, uses roster-plus-three
  reserved progress capacity, and remains retryable until either the reducer or
  a protected deferred queue owns it. Reducer progress-witness checks reject a
  transition which orphans a durable locked Commit intent or a durable
  decision's body/application pipeline.


<a id="record-ab12f118463f184dbade3b53d518567869e61cfc14a56133b7c27051c87a18ae"></a>

- Replaced serialized FIFO head blocking with bounded cyclic service for
  completion, progress, and normal work while retaining FIFO order within each
  class. Runtime and adapter snapshots expose queue capacity, oldest age, and
  eligible service debt. The roster-aware bounded network ingress now exposes
  its live depth, capacity, and oldest monotonic age distinctly from retained
  semantic-admission history; only the serviceable network queue can witness
  scheduler starvation. Exact locked Commit traffic can reach authentication
  through the progress reserve when normal ingress is saturated.


<a id="record-070efb5692ad84cc6b8b6802f02f1b99d8311c0e589357e83683fb62b84b8b59"></a>

- Extended the required `SumeragiV2Status.liveness` payload across Torii/SSE and
  the Rust, Swift, Kotlin, Java, JavaScript, and Python clients. It reports exact
  count-and-power vote/timeout pools, durable outbound intent stage, terminating
  local work, bounded queues, the last progress transition, height no-progress
  age, watchdog blocker, and all reducer ignore counters. The view-aware
  watchdog derives its deadline from configured round/retransmission timing;
  timeout votes and TCs remain visible transitions but cannot reset the height
  clock.


<a id="record-b7b2319c87c355db0c0a4eaa678307edb9d159636bbb965b42eb2ec731d9976c"></a>

- Added deterministic one-way-partition healing, leader-crash, WAL replay,
  saturated ingress, dual-quorum, and locked-round regressions. The pure reducer
  suite passes all 66 tests, and all eight fast adversarial network simulations
  pass. The four-validator genesis regression requires a durable genesis
  commit on every peer, and the real-network seed runner uses four PR or 32
  release seeds per genesis/restart/timeout/same-subject locked-reproposal/
  causally staged distinct-subject PrepareQC scenario. Those explicit releases
  are increasing captured subsequences rather than FIFO prefixes; only the
  final drain has a FIFO fence. The distinct-subject leg is implemented and
  statically checked, but its focused real-network execution remains release
  debt.


<a id="record-9a51952783edf4390d4ff6bc42570a176b51d8959476c9b126c21c47b64358f2"></a>

- Added one fail-closed release command covering the real-network matrix,
  source-bound formal corridor and trace replay, the ignored 100,000-height
  chain-prefix chaos gate, and a Taira soak which pins its seed, load, packet
  loss, churn cadence, acceptance bounds, and 86,400-second duration. Its
  workload rates use the complete wall-clock interval; process and membership
  churn must execute at least 90% of their anchored five-minute schedule,
  cleanup work is not counted as a scheduled leave, one bad cycle cannot hide
  behind ceiling rounding, and all churn work together may consume at most 25%
  of the soak; the workload window may overrun its deadline by at most 15
  minutes for an in-flight bounded churn action. The gate clears inherited binary overrides, uses a
  checkout-manifest-addressed build root, requires exactly one real-network
  test, and writes a fixed retained summary. That summary records the complete
  profile, Git/source, daemon/Kagami/test-binary and generated-config digests,
  plus authoritative initial/final Sumeragi status quorums. A separate checker
  re-hashes every retained artifact and rejects source drift, a weakened
  profile, insufficient cadence, or any unclassified no-progress interval.
  The formal ledger now names
  generation delivery, progress witnesses, post-GST enabledness, protected-rank
  decrease, and starvation freedom, but machine completion remains false while
  its explicitly ledgered obligations are `specified_unproved`; no bounded
  search or documentation change promotes them.

## 2026-07-14 Sumeragi v2 fail-stop and formal-ledger review fixes



<a id="record-4d39a6c38a5f3962d5bd736190287105b1ec6de554e8557deeffe0b43095601c"></a>

- Certified-body responses whose manifest differs from established proposal
  authority are now rejected as non-fatal remote input. After authentication,
  certificate-first responses also rederive the canonical DA manifest from the
  exact body before any proposal authority exists, while ordinary reconstruction
  rejects and retires a noncanonical proposal acquisition without advancing the
  reducer. The outstanding request is consumed only after that canonical body
  enters the reducer queue, so the same request remains available for another QC
  signer in every acquisition order. Canonical completion also rejects or
  removes conflicting authenticated proposals at the adapter and serialized
  FIFO boundaries instead of allowing later dispatch to fail-stop the height.


<a id="record-20ec668c5bfd87b9b51bda80861331cb511d9070087e94e3d59ee9557783c288"></a>

- Body persistence and validation now separate immutable receipt-bound work
  from view-specific reducer consumers. Certified view changes detach and
  rebind only the exact high-PrepareQC pipeline, preserve current FIFO delivery,
  cache detached terminal outcomes, and release losing-view work from bounded
  executor capacity; stale completions cannot route an old tag. A matching
  retired store completion that races a current fetch is now an idempotent
  current-tag `BodyAvailable`/`StoreBody` path in either completion order,
  without duplicate storage or retained ready-body bytes; conflicting durable
  manifests or receipts fail closed.


<a id="record-cd6babd11ef4465dceec7aab7374a31cf1459be42a1bb819b74dc1d80c592069"></a>

- The proof ledger now owns the async type and one-height liveness statements
  in their authoritative modules, audits proofless theorems as explicit debt,
  and distinguishes the genesis successor handoff from the still-unproved
  indexed multi-height `HeightLivenessObligation`. The indexed product now has
  a finite admissible context domain, private bootstrap-parent receipts, exact
  current-context ChainEpoch projection, atomic per-node successor joins, and
  explicit routing/certification/enabledness invariants. Validators absent from
  an old roster now have an explicit authenticated historical CommitQC
  recovery path that imports the certificate into the exact Async instance and
  uses ordinary decision/application receipts. It is weakly fair only after
  exact canonical signer-held evidence exists. Its
  fairness transfer remains part of the proofless height theorem; no legacy
  shadow transition or favourable-network wrapper was restored.


<a id="record-c3511d33b0e82f18c22cbb4da4b9046bcbd3ac385300dc8db0e1593e79ee2775"></a>

- The proof-ledger checker is structurally valid but release-incomplete, and its
  focused suite passes all 42 tests. The full Python script suite reached 1,849
  passes and 30 skips; its 15 failures are pre-existing SCCP
  fixture/source-hash drift. Direct TLA+ syntax and semantic analysis succeeds
  for the changed proof, async-liveness, and chain-refinement entry points; the
  complete underlying `SumeragiV2ChainEpochProofs` TLAPM run discharges all
  1,327 obligations. A line-selected refinement TLAPM run currently stops in a
  pinned-tool elaboration bug at the pre-existing asynchronous
  `ExecuteCommand(command)`/`ENABLED` dependency before selecting the requested
  theorem. The focused Sumeragi Rust suites pass all 160 tests across the v2
  reducer adapter, effects executor, worker, runtime, certified-body transport,
  and block-sync modules; the build emits only pre-existing workspace warnings.
  Rustfmt and diff checks pass.
