## 2026-08-13 Sumeragi queue-owned recovered Fetch selection prerequisite



<a id="record-0478f924b3b6bea0fcb9a73afa7925a8f9055d9fd590a1eac503a469610a2a13"></a>

- Fair ingress now shares one strict-before-dependency candidate selector
  between ordinary checked dequeue and lifecycle discovery. Both use the live
  ready-source rotation, per-source lane order, Serve/leader-wire gate verdicts,
  and obsolete-carrier rule. Lifecycle discovery retains the dequeue service
  lock but releases queue state before running the shared executor predicate;
  it neither removes nor rotates a carrier.


<a id="record-48e6b4bc26758d784eb04b170d01d4b122cf6e6fd9338cf9ece740b3b62fad0a"></a>

- The recovered Decision-Fetch selector no longer accepts a caller-supplied
  physical ordinal. It snapshots the reducer terminal state, asks fair ingress
  for the next admissible occurrence, authenticates the complete frozen census,
  and returns an opaque selector only when that exact fair winner is the
  recovered response-family owner. An ordinary or obsolete winner is a
  non-mutating pass-through, so a later recovered response cannot leapfrog it.
  Focused behavior coverage pins source rotation over raw ordinal order,
  ordinary-head pass-through, exact recovered-family selection, and unchanged
  queue depth/physical numbering during discovery.


<a id="record-454e5535daa0ebe2b6e36389e0f5a1a278dc3a7630da07bb616e0426b3e752f6"></a>

- The lifecycle-owned turn driver now consumes this selector without accepting
  an ordinal and extends it with the queue-owned ordinary/Serve transaction
  above. The lifecycle production runner now consumes that opaque handoff from
  its real borrow-bound current turn.

## 2026-08-13 Sumeragi recovered Decision-Fetch restart-closed Store settlement



<a id="record-bc83991e38f9162addaf5e3ee9975ef50b194673d6b6ad786ba3fe439a796562"></a>

- The parked, guarded recovered Decision-Fetch body completion now settles
  through one dedicated transaction. It revalidates the claimed recovered
  carrier and body receipt, reserves the exact request/response retirement,
  freshly recaptures and locks the fair-ingress occurrence, previews the fixed
  reducer Store successor, and stages the recovered-specific coordinator and
  registry successor before writing LedgerV1.


<a id="record-5919f7d4ac2562aa0f4b23e91f2e2d24fc4dcf0850dac89d59072284c0b1a494"></a>

- LedgerV1 publishes the payload-free Fetch `Advanced(FetchToStore)` beside one
  live body-frame Store. Every fallible semantic, storage, registry, request,
  queue, and output check precedes that fsync. After publication, only
  assertion-only coordinator/registry/adapter installation, request-owner
  retirement, locked ingress removal, worker-index acknowledgement/guard
  disarm, and output-operation completion remain. Pre-fsync failures repark the
  complete guarded owner; a failed publication latches durability failure and
  requires restart.


<a id="record-e05f05b4ad4e227da8316bf473a38c7dd558f1071270350fe2569667d7eec166"></a>

- Cold open now recognizes the exact two-row recovered Fetch/Store cut,
  reconstructs the Store authority from the fsynced body frame, installs a
  dedicated recovered Store carrier, and rebuilds the coordinator census. If a
  validation marker was already durable at that cut, recovered Apply staging
  advances the live Store and appends the exact Validate/Apply tail; reopening
  the completed chain stutters. Exact owner/key collisions fail closed.

## 2026-08-13 Sumeragi lifecycle-owned recovered Sign publication



<a id="record-880df7015dd5ae5740bf03be8f8abffab37db8e9d0eac50be5873bca8b097c12"></a>

- Recovered PhaseVote, Proposal, and Timeout Sign carriers now enter one
  dispatch-only owner path. It authenticates the current Ready carrier and, for
  PhaseVote, its unchanged terminal Validate parent; reserves dedicated
  class-sensitive Consensus capacity before the coordinator claim; and commits
  an opaque exact tag/request task directly to the worker queue. Historical
  Commit votes retain their exact later event tag without inventing equality to
  the vote's intrinsic view.


<a id="record-989d666c799683b6366b95fb2ae7f00750b5076c3d69efe0e199aef2c15fa724"></a>

- The worker retains Prepare-body successor metadata, restored Proposal body
  bytes, and the signature only inside its guarded task/result. Generic drains
  park that completion without acknowledging it; owner extraction transfers its
  exact FIFO-position metadata while retaining the dedicated
  `CompletionPending` index. The parked owner can now mint only one
  adapter-private preview authority: it rechecks the local signer and signature,
  steps `Signed` on cloned reducer/registry state, and accepts only the exact
  mandatory Broadcast, an optional already-authorized next Sign, or Proposal's
  Prepare-intent WAL request.


<a id="record-22cbae8fcd6bbb1c8e50a1dac71af218f83916a25e922a23b456f4fc2c48f327"></a>

- The single-Broadcast Vote/Timeout shape now has one restart-closed durable
  owner transaction. It stages the claimed Sign as `Advanced` with one live
  Broadcast child, fsyncs LedgerV1, then performs only assertion-only
  coordinator/registry/adapter/worker moves. Preflight failures retain the
  guarded completion unchanged; an ambiguous publication cut closes output
  and requires restart.


<a id="record-ea172aa3e2926407ce92179e0cc491ef431b1e90a341fef9ab3891cdc6077746"></a>

- Network publication is a separate typed refanout from that still-live
  Broadcast. It rejoins the claimed durable carrier, reserves exact output,
  then parks only volatile coordinator state before assertion-only enqueue.
  LedgerV1 remains Ready until finality, so a crash reconstructs the debt;
  within one process the recovery wait prevents unbounded duplicate topology
  fanouts while the exact-output corridor owns retries.


<a id="record-fc236181f35c73a5fac2ca1fe90f315575f24f23267a9ed616a385a21ebd87f3"></a>

- Cold open authenticates the exact Advanced Sign/live Broadcast row pair
  against its recovered WAL request and verified roster, cryptographically
  replays `Signed` on the cold reducer, and installs only that Broadcast carrier
  into the complete recovery census. The Broadcast-plus-next-Sign prerequisite
  now consumes one reducer-derived body lookup through the exact launched
  service/executor/body-store instance, rejoins equal validated, durable, and
  recovered manifest catalogs, and seals the latest matching WAL Vote together
  with the Broadcast. Its two-child staging assigns the Broadcast the
  recovered Sign owner and the follow-on Vote a fresh WAL-derived owner at the
  adjacent ordinal; executable registry ownership remains unsplit until an
  assertion-only post-publication tail. An exact recovered Prepare-vote
  completion can use that same durable cut without Proposal payload authority:
  it leaves both the Prepare Broadcast and adjacent Commit Sign Ready, with the
  Broadcast retaining typed refanout debt. The source-only already-WAL-ahead
  Proposal transaction can reserve output, fsync both children in one LedgerV1
  successor, install the registry and adapter pair, park only the Broadcast
  process-locally, retire the worker completion, and atomically enqueue control
  plus chunks. The next
  WAL-backed Sign remains Ready, while a crash reconstructs the durable
  Broadcast debt. Proposal control and canonical chunks share one aggregate
  exact-output preflight and FIFO commit: capacity
  pressure mutates neither fanout nor fast-path state, and recovered output
  returns its store/output-guard-bound move-only authority on both Unavailable
  and typed abort. The initial `ProposalPrepareWal` path now preflights its
  exact Prepare continuation/body, reserves the same aggregate output batch,
  fsyncs `PrepareIntent`, reauthenticates the resulting Prepare Sign from that
  frame, and then fsyncs the existing two-child LedgerV1 successor. Every
  post-WAL failure closes output for cold recovery; only capacity failure before
  the append remains retryable. The ordinary live Proposal path uses the same
  batch planner; restart retransmission targets all remote voters without
  consuming live fast-path state. The cold prerequisite now
  classifies the exact frame-bound Proposal-to-Prepare or
  Prepare-to-Commit pair without requiring it to end at the global high-water,
  and an affine WAL projection can cryptographically replay the lost historical
  signature only when the cold reducer emits those exact two children. The
  control-Proposal source branch reconstructs canonical chunks from the same
  revalidated body-store owner, installs the linked Broadcast/Prepare-Sign pair
  into the complete recovery census, advances the cold adapter, and opens the
  staged owner. The phase Prepare-to-Commit branch performs the same
  frame-bound two-carrier join from its retained Validate/body authority,
  installs the linked Broadcast/Commit-Sign pair, advances the adapter to the
  Commit-signature fence, and opens the complete staged census. Refanout
  authenticates every Ready row and follows only the Broadcast carrier's
  retained child address and digest, so unrelated work and an unrelated
  adjacent Sign remain independently ranked. The unified lifecycle
  Completion-turn driver routes both recovered Proposal settlement shapes,
  including the Prepare-intent WAL publication, and the live production runner
  invokes it through the activated lifecycle owner. Status publication and the
  atomic runner cutover use that same owner-held transaction.

## 2026-08-13 Sumeragi lifecycle-owned recovered Decision-Fetch prerequisite



<a id="record-293bc77dd0fdde9fd66316487399087fb24c25324fbb9c448c83607b7d915cad"></a>

- A Ready recovered Decision-Fetch carrier now projects one move-only,
  request-scoped authority. The owner reserves exact-output capacity and the
  executor's disjoint recovered-request slot before claiming the coordinator
  turn, then atomically installs the carrier key, request/reverse indexes, and
  signed request fanout. No `EffectWorkId`, runtime-effect owner, or ordinary
  outstanding-request entry is fabricated.


<a id="record-7588bba03b49942479e8f3bf65d5cd36bb99b9fdd68ab06b78309eac0e236df6"></a>

- Authenticated responses remain a separately typed selector family. Phase A
  re-probes the exact request, response, ingress occurrence, active lease, and
  carrier before claiming the response and publishing a dedicated body-store
  command. The worker persists the body durably, leaves its keyed index in
  `CompletionPending`, and parks a guarded completion outside the generic
  drain. A recovered completion behind a held ordinary result stays in the
  physical channel until that ordinary owner is acknowledged.


<a id="record-6a1f9b5af56753f9712eeea2d67c59f8b5107e7f2a19e574bbf5f862f42751b6"></a>

- The guarded Phase-A boundary is claimed-but-unsettled until the dedicated
  Store transaction above runs. A crash before its Ledger fsync discards only
  volatile claim/queue state and reconstructs the unchanged durable Ready
  Fetch; a crash after publication cold-opens the exact recovered Store cut.
  The ordinary lifecycle runner drives this activation; PendingKura drives the
  same durable recovery authority through its dedicated one-height no-clock
  lifecycle state.

## 2026-08-13 Sumeragi Kura-root WAL-directory capability



<a id="record-c1e5e5c0776f1b05b6b769cf4511a705a2770e0d906e45beaf30d3fb243dd153"></a>

- `SafetyWal` now opens and retains the post-open Unix directory and exact WAL
  leaf identities. WAL append verifies that binding before write and after
  synchronization; recovery brackets bytes with file revisions and exact
  length; initial publication and retirement use descriptor-relative leaf and
  directory operations. A pre-existing final `wal/` symlink, post-open parent
  rename/symlink substitution, or WAL-leaf replacement fails closed.


<a id="record-364e448efdca7e5172fbe0a4b5d7cb2e70662dc48bad2231ca9a2a0a2e8ec3ca"></a>

- `SafetyWal` alone mints distinct move-only, one-shot authorities for the
  fixed serviced-candidate and leader-wire sibling entries. Both stores use
  only bounded descriptor-relative reads, exclusive temporary publication,
  rename, post-directory-sync identity validation, and retirement. Adapter
  recovery opens the WAL before restoring serviced candidates, while the
  unified launch and current runner consume the WAL-minted leader-wire
  authority; production raw-path store constructors are gone.


<a id="record-f4d8943395ced2fe000fc87cdd6921098349bae599d88006a51158bc7c7feadd"></a>

- The serviced-candidate store now emits and accepts only its complete V4
  schema. The unused V3 structure, encoder, decoder, migration branch, and
  upgrade fixture are removed; every other version fails before payload decode
  or state restoration.


<a id="record-a2d889444a19c3f9266496bf4da87187d356c2f09b2dec4aea9092ebf5b33a4c"></a>

- Kura now retains its opened canonical store root after authenticating the
  exact locked root entry. Runner cutover mints a move-only, exact-instance
  `sumeragi_v2/wal` authority by `mkdirat`/no-follow `openat` traversal from
  that retained descriptor, and the production adapter consumes it instead of
  reopening a caller path. Legacy pathname opening is test-only. Non-Unix
  production opening fails closed until an equivalent handle-relative
  implementation exists. This is source-implemented but execution-unverified:
  no Rust build or test result is claimed by this update.
