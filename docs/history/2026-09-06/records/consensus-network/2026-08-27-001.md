## 2026-08-27 P2P first-release simplification and hardening



<a id="record-2284793655c38560c073cc0df82603f8597b65d6b97743ceb92c4494a7dbcd69"></a>

- Made TLS 1.3 over TCP unconditional and retained QUIC as the only optional
  peer transport. Removed the TLS/queue opt-out features and unused P2P GOST/SM
  identity feature forwarding without changing `Cargo.lock`; Snow remains only
  under an impossible target predicate to satisfy the protected lockfile and
  cannot be selected or compiled.


<a id="record-853e6487ed36118a59228e70eb967b8f8accf572501d6b3b7075c04e8c2869e7"></a>

- Fixed node identity to BLS-normal in both the encrypted identity hello and
  relay envelope. The hello no longer carries a redundant algorithm field;
  direct targets, relay origins, and exact 48-byte-key/96-byte-signature wire
  geometry now fail closed on any other algorithm or signature width.


<a id="record-4dc84dc2c2a9191c72ec7ee7a09dd9465757790c439350280f94e20eb5283d43"></a>

- Authenticated encrypted batches are atomic: an invalid inner header, schema,
  length, decode, topic cap, trailing byte, or 33rd message discards the whole
  batch and disconnects the peer immediately. Decoded prefixes are never
  delivered from malformed frames.


<a id="record-0cf88a00b6c3a980cc77d83ba5a492a5a8b8c1d92c15181aae98e5d5cc0473dd"></a>

- Removed the global production P2P packet-loss injector and its configuration,
  counters, branches, fixtures, CLI/sweep controls, and Izanami persisted-schema
  compatibility decoder. Izanami now has seven current fault toggles, requires
  one explicit V1 persistence layout byte, rejects bare, truncated, or
  unknown-bit or unknown-profile state, and models leader isolation only with
  its owned network-partition fault.


<a id="record-014f65009354edd09dc97cf68c3e40344e37ad30e18ac73ee7c56e7877ae0f12"></a>

- Removed the unused direct-node delegated signed-ticket verifier setting from
  actual/user configuration, client DTOs, runtime construction, fixtures, and
  tests. Pre-release node configs carrying `signed_ticket_public_key_hex` now
  fail as unknown; the separate relay/puzzle-service signed-ticket protocol is
  unchanged.


<a id="record-e8b41549036c89c5a126e01bc235ca3e0c58e44c724db3e54f2e3a4ba1c2ef53"></a>

- Direct posts move the caller's payload into the signed frame and retain at
  most one payload copy only when a live hub fallback exists; the fallback
  reuses the same origin signature. Broadcast signs once per retry pass, avoids
  an intermediate payload clone, moves the final frame instead of cloning it,
  and skips signing entirely for an empty target set. Admission sizing uses
  exact canonical node geometry instead of serializing keys or reserving space
  for rejected algorithms.

## 2026-08-27 Sumeragi first-release simplification



<a id="record-001a1e651dea75bbe0865e1078d405182cb14d303cbd58af4510834d023b74a2"></a>

- Removed the retired NPoS commit/reveal peer messages, producer lifecycle,
  retransmission path, preimage helpers, authenticated message-controller
  kinds, and historical production-shaped fixtures. The signed NPoS effects
  schema now carries only finalized threshold-beacon pulses, exact v2 evidence,
  and consensus-evidence penalties; always-rejected VRF seal and penalty
  variants are no longer decoded as compatibility input.


<a id="record-7d1739b56bc2fde3f23f13a100fb235bbdad8e2aab18cf12e1b85e96300f460a"></a>

- Removed the persisted `World::vrf_epochs` sidecar, its record/proof data
  model, snapshot plumbing, queries, Torii routes, OpenAPI schemas, and SDK
  deadline fields. Retired commit/reveal window configuration is rejected
  instead of aliased, and the exact-decoder regression keeps that rejection
  explicit.


<a id="record-76f07c408f117c591f01331784620130e55dbc1cfcff33a2d4e3e653c81f6e6d"></a>

- Made canonical block ingress exhaustive over the first-release message enum
  and removed the unreachable global-v1 fallback. Ordinary lifecycle ingress
  now dispatches auxiliary, lane-local, and global v2 traffic through explicit
  enum matches, so adding a message requires compile-time ownership decisions;
  the retained fair-ingress projection codes are dense.


<a id="record-1eab9226339dea82cb4459f3e39efb45189c6618550e6ab5b881dd293d3b713f"></a>

- Reused the already-computed ordinary write projection as both post-state and
  ordinary-write roots when a block has writes, avoiding a second 256-level
  sparse-Merkle reduction. Read-only blocks retain their distinct empty-write
  root, with a focused regression for both cases. Removed the retired
  per-block public-lane VRF-jail validator-table scan.


<a id="record-7326ebd14b291bcf2741bb522e08280fe7087587d181c282e3b71e88be8ab09a"></a>

- Faucet proof-of-work salts now bind to the newest eligible finalized global
  threshold-beacon pulse. The lookup revalidates world membership, network and
  session binding, DKG transcript, BLS signature, seed, and pulse identity
  before using persisted bytes; proof-valid fixtures exercise the path.


<a id="record-be63ca395d66f803e7f20f59b630d338ff19c237926fd791935e1566e3cabb71"></a>

- Removed retired VRF Prometheus series, alert rules, dashboard panels, and the
  default-rule fallback in the validation script. Sumeragi specifications and
  the operator runbook now describe only signed RS16 availability, exact v2
  evidence, and finalized global threshold-beacon randomness.


<a id="record-f2bf3512f1c0e11c3e3400c849f838d51635cb71c2a990d6956996766593f901"></a>

- `cargo check --lib` passes for `iroha_data_model`, `iroha_config`, and
  `iroha_telemetry`. The `iroha_core` check reaches the unrelated dirty-tree
  IVM build and stops because `prebuilt_fixtures.rs` and
  `predecoder_fixtures.rs` still import the concurrently removed
  `crate::kotodama::wide`; it does not reach Sumeragi. Focused Kotlin and
  Java/Android diagnostics suites pass, as do the two focused JavaScript tests,
  Rust/Python/JavaScript/shell syntax and formatting checks, JSON parsing,
  whitespace validation, and the two task-scoped formal source contracts. The
  full formal umbrella check fails closed on unrelated concurrent lifecycle,
  Kura, and frozen-source inventory changes; the full SDK diagnostics harness
  likewise stops at an unrelated missing Kotlin source-closure path.

- P2P TCP and address-validated QUIC listeners now share one exact-source
  pre-authentication gate. Its absolute deadline starts at TCP acceptance or
  completion of QUIC address validation and covers global-capacity waiting,
  transport setup, required-stream acceptance, and the signed application
  handshake. The default is 30 seconds with at most eight pending transports
  per canonical source IP; IPv4-mapped IPv6 shares the native IPv4 bucket,
  every exit path releases its reservation, and source-cap rejection has a
  dedicated telemetry counter.

  boundary, shared exact-source accounting, stateless quote issuance, and WSV
