## 2026-08-01 JavaScript Private Kaigi fixture-prover hard cut



<a id="record-122aa974cea67477489d6f9634aedfa79925669949b61cb8c4601f91f5d1cc6b"></a>

- Audited the JavaScript Private Kaigi fee-spend helper against the production
  confidential-transfer prover. The production prover requires the spend key,
  input-note witnesses, committed tree, Merkle positions, and output-note
  witnesses; the helper accepted none of them and instead wrapped an
  `iroha_core::zk::test_utils` fixture while fabricating nullifiers, output
  commitments, and change metadata.


<a id="record-b8cb3d9fb4a311abf92b183e8af7db25a19a96daea3d01e5dfcc27963732f498"></a>

- Removed that N-API entrypoint, its fixture-only helpers and result object, the
  JavaScript root/transaction exports, TypeScript input/result declarations,
  and the corresponding fake-native tests. `iroha_js_host` no longer enables
  `iroha-core-tests` as a normal dependency. Private Kaigi transaction builders
  remain available but require a fee-spend envelope from a production wallet or
  prover; the witness-bearing `buildConfidentialTransferProofV2` API remains
  available independently.


<a id="record-ff5feb9492173d47f24f78a22cee80158e0aa6396dc6d5c258bfa1c98592282e"></a>

- Regenerated the ignored JavaScript `dist` tree from `src`; source and
  distribution are byte-for-byte directory-equivalent. Focused non-Cargo
  validation passed: JavaScript syntax and ESLint, the five Private Kaigi tests,
  the confidential verifier-metadata regression, all eight package/declaration
  tests (including strict NodeNext compilation), distribution import/absence
  checks, static fixture-symbol checks, and `git diff --check`. No Cargo command
  was run for this source-level hard cut; a fresh native artifact rebuild and
  ABI smoke remain release-gate work.

## 2026-08-01 Musubi first-release V1 registry and Core reset



<a id="record-cc0ab18787113a87316795043abd8caf59cac51dbad0bf26c416b5289d9dfc59"></a>

- Replaced the pre-release Musubi public data model with bounded, namespaced V1
  identities, structured SemVer and comparator requirements, immutable release
  and archive commitments, exact publication proofs, package-scoped ownership
  and maintainer roles, permanent paid aliases, admission policy, archive
  availability, resolver-index rows, and finalized cursor/page records. The old
  Musubi ISIs, query shapes, permission token, lock format, and state-path
  vector contract are not compatibility-decoded.


<a id="record-d7b27d6cb6d388d5fd453e05f734306dba3051108a29ed7042585bba501a3e61"></a>

- SemVer requirement matching now preserves Cargo caret/tilde upper bounds at
  `u64` component limits by comparing compatible core prefixes directly;
  failed integer increments can no longer turn `^0.MAX.0` or `^0.0.MAX` into
  an unbounded range. Duplicate standalone equality comparators canonicalize
  to the single `Exact` wire form, decoded singleton-equality/multi-exact
  comparator ASTs and surrounding requirement whitespace are rejected
  consistently; only ASCII space around comma-separated items is normalized.
  The shared Rust/Kotlin/Java/Swift fixture locks those edge cases plus
  same-core prerelease eligibility.


<a id="record-748de0b5ba48018d5bba85f58b24e020979a36b601c928de9a057f05baa29f7c"></a>

- World state now persists authoritative package/release/governance records and
  compact universal resolver, archive, alias, reverse-reference, and public
  directory projections in typed ordered MV storage. Loading a snapshot with
  the reserved bare `musubi` generic state path or any `_`, `/`, `.`, or `:`
  descendant fails explicitly instead of deleting or migrating unenumerated
  legacy records. Native AMX routing coordinates home and universal mutations.
  A source regression now pins release publication to the universal coordinator
  and exact package-home participant. Snapshot fault-cut coverage rejects
  one-sided release, reverse-reference, resolver-row, and public-directory
  projections and accepts exact replay. A four-peer below-quorum queue-journal
  crash/restart regression is present; it queues an unavailable-archive
  publication and asserts one canonical rejection plus the package/release/
  resolver/directory/reverse-reference absence tuple at one snapshot on every
  peer after restart. The non-shipping adversarial-test daemon now exposes
  source-bound one-shot process cuts after the authenticated PrepareQC, after
  the authenticated CommitQC, and immediately before `StateBlock::commit`.
  Each cut fsyncs and reads back a canonical per-peer acknowledgement before
  aborting, and the test-network controller can arm and await the exact phase,
  source, and revision. The integration gate now constructs a real
  registry-grade SoraFS pin, three admitted providers, a canonical replication
  order, three finalized completion anchors, and three signed parsed-bundle
  attestations before driving one isolated four-peer network through each cut.
  PrepareQC and CommitQC cuts target the deterministic autonomous
  universal-lane author derived from the newest durable lane frontier; the
  other three validators keep the release absent until that sole author
  restarts. Only the pre-world-commit cut requires the other three validators
  to finalize while the target is down. The faulted peer is reaped and
  restarted from its original storage, and a finalized barrier binds all-peer
  exact home/universal tuple and single-occurrence checks. Execution of this new
  gate remains deferred pending its dedicated, long-running four-peer crash
  qualification; the current focused fixture build now compiles through the
  shared dependency graph.


<a id="record-3fc5a63741cf67b95b499b822cabeee957577004f1f1d6942305f4e2b8dcb6d7"></a>

- World state now also retains `musubi_resolver_index_checkpoints` as an
  unpruned ordered MV store keyed by the nonzero resolver revision. The common
  finalized-block apply path records genesis and only each later block's new
  final revision after appending its canonical block hash; unchanged blocks do
  not add rows, and intra-block revision jumps retain only the last revision.
  The store participates in block/transaction/view plumbing, merge write sets,
  commit/apply/revert, strict snapshot JSON decoding, and restore-time
  canonical block-anchor validation. Nonempty restored chains must retain the
  genesis activation, keys must match embedded revisions, activation heights
  increase strictly, and the last key must equal the current resolver revision.


<a id="record-6213b60bf0d966eab54b81d7a4f5e4491e61471f938caaa9a784379ac7b4ca1e"></a>

- Core implements all V1 registry instructions and typed queries: exact
  publication-proof checking against one finalized universal snapshot,
  replication-quorum selection state, reversible yank, independent takedown,
  CAS metadata/governance/location revisions, last-owner and last-healthy-pin
  guards, signed generation-bound namespace delegation, atomic XOR alias
  payment/history, and enacted action-bound Parliament recovery with delay and
  replay protection. Query cursors bind the finalized height/hash, canonical
  query hash, exact last key, resolver revision, and caller boundary; stale
  cursors return an explicit expiry failure.


<a id="record-4d1fe0dedec5f3840be0ba1639269f77449d66ff85b399c06ae451b0a4462140"></a>

- Publication proof validation now exact-loads the claimed resolver-revision
  activation checkpoint, canonical-checks the claimed tuple and the
  checkpoint's own block anchor, and requires the first higher checkpoint to
  activate strictly after the claim. A skipped same-block revision therefore
  cannot be fabricated, while a later unchanged block inside the activation
  interval remains valid. Resolver proof rows additionally validate each
  archive-availability projection against its own canonical finalized block,
  including anchors below the claimed snapshot height.


<a id="record-63fe085e35b0f2154bad5eec57a6e1e40cece06f43ce27845c4df63f76bc9983"></a>

- Every package-governance revision advance now atomically rebases every other
  pending, unexpired invitation, expires elapsed invitations, and terminalizes
  an accepted or revoked target. Snapshot validation requires pending records
  to carry the exact current package revision; invalid new invitations are
  fully validated before any prior invitation can change. Archive-availability
  recomputation preflights the authoritative archive and locations plus every
  reverse reference, release, resolver row, and distinct package before the
  unchanged-state return or any projection mutation.


<a id="record-f78e8cb269330ac330d8dff111ac721eb8b39ad03349222607fcbb2f99aaa3a4"></a>

- Core release publication now plans and validates the package/governance
  update, first-claim member and metadata, resolver-index successor, reverse
  references, exact row, and public-directory entry before its first write;
  invitation updates and all registry projections are then applied without a
  fallible interleaving boundary.


<a id="record-4cc7770f4853aa0bfe1d425e7396588d0628506028bf2015c9094a4a64b509a4"></a>

- The Cargo-style developer path is implemented in the existing crate split:
  strict manifest/workspace discovery and inheritance, one-root V1 locks,
  deterministic backtracking with lock preservation and targeted updates,
  registry/path/dev dependencies, clean positive-set packaging and compiler
  checking, immutable authenticated fetch/cache/repair, Cargo-style commands,
  stable diagnostics/JSON, and exact finalized cache-retention classification.
  Dry-run reports the complete candidate set; every non-empty live prune fails
  before candidate inspection or mutation until atomic handle-relative
  compare-and-delete exists. Failed and race-losing installs retain private
  staging plus payload residue; successful installs publish staging as `src`
  and retain the verified payload residue instead of attempting automatic
  destructive cleanup. The CLI never
  restores `install`, `pack`, cache import, or legacy-lock decoding; a recursive
  Clap grammar guard also rejects secret-bearing argv controls, arbitrary cache
  roots, source-plan controls, and the former no-op `--wait` switch. Network
  mutations already wait on their typed finality boundary, while publication
  uses the explicit `--detach`/`--resume` workflow. Cache repair validates
  finalized commitment
  and plan inputs before inspecting
  local state and quarantines only an actual `CorruptEntry`, so a malicious
  traversal plan cannot move a healthy immutable entry. Consumer fetch now
  rebinds each provider plan to the commitment's chunk inventory, registered
  profile, exact bundle metadata set, and complete file-plan-derived root CID
  before cache verification or repair. Deterministic failover tries distinct
  providers within each health rank before repeating one through another pin,
  and invalid plans produce one typed archive-integrity observation.


<a id="record-754602ef41281c16a69ced4d25f278510009515f92c35aa088f5ba10b604fb82"></a>

- Secure positive-set packaging now rejects expanded recognized credential
  filenames and assignment forms used by shell `export`, Windows `set`/`setx`,
  PowerShell environment assignments, inline or line-oriented object keys, and
  plain configuration files without echoing the secret. It pins and revalidates
  the final opened file identity. Its 64 MiB ceiling applies to the positive
  source tree, while the archive commitment separately permits up to 96 MiB
  for that source plus the three mandatory bundle metadata entries (still
  within the independent 96 MiB CAR ceiling), so an exact-limit source package
  is not rejected only after bundling. Rust, OpenAPI, Kotlin, Java, and Swift
  now share that full-bundle ceiling; focused SDK boundaries accept 64 MiB plus
  one byte and reject 96 MiB plus one byte.
  ancestor-directory confinement remains path-based before and after that open,
  so handle-relative no-follow/open-beneath traversal and its deliberate ABA
  race qualification remain an explicit release gate.


<a id="record-e0b40befa6262e458dc0283f6f2b515169ddc59cabc331bea0c6d2e9d57d2f07"></a>

- The production CAR worker/consumer bridge now uses a four-frame bounded
  queue and accounts all six simultaneously owned frames: four queued, one
  consumer-owned, and one producer-owned while a send is blocked. Every
  terminal path and reader drop closes the receiver and joins the producer;
  abandonment can wait for the configured request timeout but cannot leave a
  detached worker. An isolated logical-heap regression is defined to exercise
  that exact bridge and canonical CAR writer at the V1 64 MiB payload, maximum
  file count, and near-maximum SF1 chunk geometry. Provider JSON is
  allocation-free preflighted for nesting, token, string-byte, and unquoted
  scalar-literal envelopes before constructing a Norito value; cache admission
  separately caps retained plan allocations at 16 MiB and the SoraFS ingest
  estimate at 24 MiB, with launch-maximum geometry covered. This is bounded
  stream/envelope/accounting evidence only: deployment-equivalent HTTP/TLS,
  JSON-DOM, cache, allocator, thread-stack, and operating-system RSS or cgroup
  qualification against the 64 MiB fetch gate remains open.


<a id="record-f5e252c88a2b59bccdaa88d33c66ddf756bc127c96bfa9677ab7634a274f8477"></a>

- Manifest-declared test directories now expand to a bounded, bytewise-sorted
  portable set of direct `.ko` roots. Each stable no-follow source snapshot is
  passed as supplied text through the structured IVM test boundary, which
  rejects noncanonical logical names and performs no ambient reopen or sibling
  discovery. Clean publication validation now compiler-checks every declared
  contract and test from immutable package-plan bytes, recomputes every exact
  registry dependency interface against its lock digest, and preserves the
  library interface digest. Packaged tests are compile-only at this boundary;
  a development-only import fails explicitly because development dependencies
  do not propagate into the release verification graph. V1 lock parsing rejects
  noncanonical decimal identity/snapshot strings and dispatches schema/version
  before unknown-key validation, so every pre-release shape receives the
  required regenerate diagnostic. Targeted `--precise` updates are bound to
  every prior parent-local incoming target edge across parent-version
  backtracking, so an already
  selected sibling or parallel version cannot discharge the wrong occurrence;
  adversarial fixtures also lock Cargo-style same-core prerelease eligibility.
  Graph capture now records only actual manifest/dependency range queries, so a
  freshly populated online cache is replayable offline without invented
  exact-version lock pages. Reusing a compatible selected release also walks
  its resolved subtree at the new incoming depth; an over-depth newer parent
  can therefore backtrack to an older valid candidate instead of failing only
  during final lock construction.
  Offline resolver-cache freshness now requires exact snapshot equality at the
  locked finalized height and a nondecreasing resolver-index revision at every
  higher height. Per-deployment catalog history is validated before bounded
  retention, so truncation cannot hide a same-height equivocation or revision
  rollback and a rejected publication leaves the durable catalog unchanged.
