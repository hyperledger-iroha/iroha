<!-- Original context: Status / 2026-08-23 ZK algorithm correctness audit -->
- Kaigi commitment, nullifier, and usage artifacts now carry Pasta scalars
  injectively inside Iroha `Hash` values. The prior direct wrapper overwrote bit
  248 to satisfy the hash marker invariant, making the carrier two-to-one and
  corrupting roughly half of honest circuit outputs. The reversible packed
  encoding preserves all 255 scalar bits; all 9 Kaigi circuit/helper tests pass.

- Kaigi `ZkRosterV1` joins now fail closed in production because the current
  roster circuit proves knowledge of an arbitrary account witness but has no
  public input derived from the signed participant authority. A transferable
  proof could otherwise be copied into a transaction signed by another account.
  Transparent Kaigi and the independently bound usage circuit remain available;
  private join activation awaits a versioned authority-bound statement and key.
  Host lifecycle transitions now always require the stored host's signature,
  record the host-create nullifier, and reject its reuse. The public JS and
  native roster-proof builders reject with the same unavailable status instead
  of producing an unusable ledger proof. Internal test-only candidate and core
  fixtures emit the exact schema tag, canonical `CID1` key binding, nonzero
  verifier-key hash, and canonical outer Norito envelope required by strict
  Halo2 admission.
