## 2026-08-27 Taikai first-release simplification



<a id="record-b944b73b5be10cc6b5385e77b21bbadc449f7cad53886f0be6b2b9eaec28c675"></a>

- The unconsumed `taikai.cache_hint` metadata and per-chunk
  `taikai_segment_hint` carrier were removed across CAR planning, Torii,
  provider ingestion, Musubi, node storage, SDKs, fixtures, and specs. Retired
  JSON configuration and fetch-plan fields fail closed so a misspelled or stale
  deployment cannot silently select different behavior.


<a id="record-7914f2a93e0dc9b8aaaaea1ccab45581c48053de371e345902dbf4bc2a3318b8"></a>

- Taikai signing bodies now construct only V1, and infallible ingest metadata
  tagging no longer advertises an impossible HTTP error. Canonical Taikai CAR
  verification reconstructs its plan and PoR commitments directly from
  borrowed archive sections, eliminating the former payload-sized copy and
  second parse/rechunk pass while preserving byte-for-byte verification.


<a id="record-96d1bac440ee00cff9b40c2f0f603c45bba23662a97689e1937bdc2ea497cdee"></a>

- Signed TRM/SSM fields with no admission, routing, persistence, or viewer
  owner were removed: free-form SSM/TRM metadata, provider target lists,
  circuit labels, and the unused Taikai guard-policy types. The borrowed CAR
  parser now rejects a raw-section count beyond the canonical plan ceiling
  before allocation and uses amortized fallible reservations.


<a id="record-f21429e33413343e02c329fdbe26e2a0acf745e76c86708792da6d0b6b3be40c"></a>

- JavaScript lint, type, and wrapper tests, the Taikai dashboard contract, and
  scoped formatting/whitespace checks pass. The Swift sources parse, while its
  package tests require the absent generated `dist/NoritoBridge.xcframework`.
  The focused `sorafs_car` Rust check stops in unrelated concurrently edited
  `iroha_crypto` code because `soranet::puzzle` imports two absent constants;
  the multi-hour workspace suite has not been run. `Cargo.lock` was not
  modified by this work.

## 2026-08-27 Taikai DA ingest security hardening



<a id="record-baad5ffa57f93c9974c72256c177b42a7d9fed23169cd96e3e8b1aaacd0c96c9"></a>

- A scoped Codex Security audit validated seven Taikai/DA ingest findings. The
  candidate rejects saturated compute work instead of retaining decoded
  requests in an unbounded semaphore wait, binds the authenticated DA owner to
  the SSM publisher before any Taikai artefact is spooled, and requires exact
  manifest chunk roles and group identifiers so the stored vector matches its
  IPA commitment. Fresh DA namespaces start at sequence zero, advance by exact
  successors, retain retired sequence floors across cache eviction, and reject
  terminal `u64::MAX`; Taikai routing windows are nonterminal, contiguous, and
  cover at most 120 sequences.


<a id="record-c3f340c2fa089eb0d520d738a6e45deca678edd7f85c8dee48e99984bf335616"></a>

- Producer-approved `DaPinScopeV1` witnesses now bind the original request
  authorization to the exact storage ticket, manifest digest, and normalized
  alias. A first ingest durably returns `pending_pin_authorization` without a
  pin intent or Taikai readiness marker; one signed retry finalizes that exact
  scope. Core checks both witness sets against the same committed account
  controller. The Rust client and CLI perform one bounded retry and reject
  missing, substituted, or changed scope, receipt, and PDP response bindings,
  including immediate accepted duplicate/restart responses.


<a id="record-1355974b7aeb7b10f2010509d307c0493131242d4c75477b72e3a3a3ef6b8f20"></a>

- TRM alias lineage uses a receipt-bound two-phase update. Ingest first writes
  a non-authoritative pending record; recovery promotes it only after matching
  the exact durable receipt and staged TRM bytes, and discards it when no such
  receipt exists. Startup reconciles pending records before the anchor worker
  can observe receipt-backed envelopes.


<a id="record-47b40b42a74b8b09b8b5b7bdf44f5aeb4437eb06c51f0f2db352b9c15f096cb5"></a>

- Taikai anchors now return a bounded Ed25519-signed receipt bound to the exact
  canonical artefact id and BLAKE3 digest of the request bytes. Torii pins the
  receipt key, uses HTTPS outside loopback, disables redirects, applies an
  end-to-end deadline and bounded response body, and retires source artefacts
  only after the verified receipt is persisted.


<a id="record-4291c6e3a1a0e810100ab091e98f52f9ebc292230400fb16148e1d841c78c9d1"></a>

- Taikai ingest and TRM alias-rotation status now use bounded 256-entry LRUs
  coupled to removal of the underlying Prometheus children. Per-stream error
  reasons are capped at 32 with matching counter-child eviction.


<a id="record-a291c83d0f51dcdacd94984a9a1c9065afa27c42bddc8a9d2858dd7601bf05c4"></a>

- The required same-reviewer post-fix security pass closed all seven findings
  and the adjacent invalid-anchor-sentinel restart path. Five focused admission
  policy tests, two signed-anchor receipt tests, one routing-window bound test,
  and six Taikai telemetry tests passed at their checkpoints; production
  config, Core, and Torii library checks also passed before the final client
  hardening. Both immediate-accepted Rust-client regressions pass, proving that
  missing durable scope and a substituted scope sequence are rejected. Current
  exact-file Rust formatting, audited-revision whitespace, and retired-codec
  checks pass. The newest CLI, integration, and restart regressions remain
  runtime-unexecuted; the full workspace matrix was not run.
