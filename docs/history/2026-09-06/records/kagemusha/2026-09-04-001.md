## 2026-09-04 KAGEMUSHA unbounded-history proof work



<a id="record-06c5033557686774174c6d138e202f7e2b9ab9f4f30441185affdbb008eb2004"></a>

- The first-release source remains a hard cut to the public `KAGEMUSHA` name,
  `kgm1:` text transport and `/v1/kagemusha/*` routes. No compatibility decoder,
  migration path or historical hop, ancestry, input, origin, fan-in,
  proof-depth or receipt-count admission limit is part of this design. The
  scoped retired-surface guard is green, but it is not a universal proof that
  every historical implementation detail or persisted pre-release state has
  been removed.


<a id="record-fa1a5106323d1f8572027663ad2718028b8c67e7e270f0ccc8c0459beb140758"></a>

- The bounded SHA implementation is now Table8-only; the production Table16 and
  rejected Boolean candidates were removed from the current module graph. The
  focused Table8 suite passes 20/20 in 20.52 seconds after a 3m38s build, across
  both Pasta fields, FIPS vectors, exhaustive byte splitting, chaining,
  schedule/compression substitutions and the `k=12` one-block geometry. The
  wrapper/scheduler selection passes 18/18 in 435.68 seconds, including padding,
  length, endianness, IV reset, cross-lane chaining and copy-constraint
  negatives. Its parallel desktop run peaked at approximately 10.5 GiB RSS and
  is not device qualification. The separate Boolean candidate was rejected: a
  measured 3,200-byte parity proof exceeded the 2,495-byte slot and its observed
  401,735,680-byte RSS exceeded the 128 MiB profile.


<a id="record-2e7aca7f98adfe151af8ae6562365d798423970e5f41c20e4763a1258ee7b019"></a>

- Table8 does not by itself make the existing monolithic `k=16` MintAuthority
  feasible. For 176 SHA blocks across 36 jobs, five and six lanes require
  85,248 and 71,424 rows and do not fit; seven lanes fit the row schedule but
  require an estimated 966,796,270 processed-key bytes before Base, above the
  64 MiB profile. Even Base plus dense columns without SHA has an 85,984,030-byte
  lower bound. The lower-`k` Table8 hash shard now passes its focused suite 6/6
  after a 9m12s rebuild; it binds one exact compression, typed plan position,
  release, prestate, block and successor state at `k=12`. Its narrow `k=16`
  ordered claim fold and terminal monetary-relation integration remain under
  construction and unqualified. No proof, transport or device-resource ceiling
  was raised.


<a id="record-9ce142099935f8afa2974e7f6663e0b2e45ba82eb261b217168919f7e34450bf"></a>

- A separate canonical-frame circuit selection passes 22 focused checks. It
  confirms the bounded framing constraints, not a successful real mint circuit:
  the complete mint relation still exceeds its row budget.


<a id="record-4e252f42c785253d898cfe597330b6cbe28c1d650d3b19501f896334631d626d"></a>

- The data model now seals the allowlist of canonical mint root types and
  derives their fixed Norito header/alignment descriptors. The circuit-side
  bounded-frame assembler accepts only those model-owned descriptors, derives
  the active payload length and CRC64-XZ inside the fixed-capacity relation,
  and constrains the inactive tail to zero; its compact-length path is canonical
  at 127, 128 and 16,383. The two-byte `u14` helper is an encoding primitive,
  not a new protocol or account-length cap.
  The model frame-reconstruction test passes 1/1 and the Core suite passes 4/4
  across both Pasta fields, including payload, length, checksum and tail
  substitutions. This is exact framing infrastructure, not recursive
  MintAuthorization verification or monetary-relation closure.


<a id="record-9b764cbf8483ea6038c1a1cb9d82a0895399066ef2ae850f431218504decfc5f"></a>

- Exact assigned recursive proof-byte reconstruction passes 8/8 focused tests.
  State-owned MintFold private-input selection passes 3/3; its single focused
  redaction/reference-identity test passes 1/1. A checked
  `CreditFoldPreviewV1` retains the exact authorization, original recipient
  credential, credit opening, finalized credit and native stage certificate,
  and offers the first four through a non-detached borrowing projection. This
  establishes native witness provenance only: the projection is not yet
  consumed by the recursive generation witness or constrained MintFold
  relation. The stage certificate remains native provenance and is not circuit
  authority. The exposed-outbox successor-substitution guard passes 1/1 and the durable
  outgoing operation index passes 10/10. These close host/state binding and
  recovery gaps, not the outstanding in-circuit MintAuthorization,
  canonical-statement, recipient/lane, lifecycle and replay bindings; they do
  not authorize money on their own.


<a id="record-d34d2fc909ff4b73e3a89f9f221638edca3662d9fb7927d0a12d1909a3af6882"></a>

- The fixed-shape state model passes one 1,024-handoff run and one
  1,000-receipt-to-single-balance run. Both use mocked recursion. The distinct
  1,000-device top-up, aggregate spend and downstream partial/full redemption
  run is still executing and has not produced pass evidence. None of these runs
  supplies 1,024 real recursive proofs, a four-validator settlement corridor or
  qualified hardware evidence.


<a id="record-1c4780a837556f848899322bf2fa609462035924e0de03778b3cd7c20bca96d0"></a>

- `kagami kagemusha authenticate-release-v1` is now the sole release command and
  fail-closes over the exact release, authority-review and native-artifact input
  set. Its production binary check passes in 7m03s with two pre-existing
  warnings; the source hard-cut suite passes 21 tests plus 17 subtests and the
  focused CLI guard passes 8 tests. The combined hard-cut, package-surface,
  release-CLI and formal-proof Python gate passes 30 tests with eight skips in
  22.438 seconds. The broader Kagami test harness stops before these tests on 14
  unrelated shared genesis-test compilation errors, so it is not recorded as a
  full crate pass.


<a id="record-5535362ead6524a1a684cbd65f026e4bdb7d736cd28755b5916b7280cde92035"></a>

- Release completion is not claimed. Real recursive MintFold composition and
  proof generation, measured hash-shard/claim-fold keys and proofs, 1,024 real
  handoffs, the complete crash/adversarial matrix, fresh native artifacts,
  workspace/Clippy gates, independent review and physical hardware
  qualification remain open; monetary hardware profiles stay disabled.

## 2026-09-04 KAGEMUSHA V1 unbounded-history implementation



<a id="record-e687690fcc55e24ca9ae9b12658ca08fbd8d83f6bb88611afee1055755c51dc7"></a>

- `KAGEMUSHA` is the sole protocol and product name, `kgm1:` is the sole
  text prefix, and `/v1/kagemusha/*` is the sole product HTTP namespace. This
  is a first-release hard cut: there are no legacy decoders, message aliases,
  migration paths, or dual protocols.


<a id="record-c86fc61ef6e35163964b8cc0622255b6181cad4ce4219963bcf4f090783da6c2"></a>

- The public Rust peer model has been cut to exactly three IPM1 messages:
  `KagemushaPaymentRequestV1` (1), `KagemushaPaymentV1` (2), and
  `KagemushaAcknowledgementV1` (3). The request carries one positive exact
  amount, recipient encryption key, and complete lane/policy credential without
  a receiver balance head. The payment directly binds the request, amount,
  sender before/after commitments, hardware transition commitment, unique credit
  ID/nullifier, ciphertext commitment, trusted commit time/evidence, and paired
  proof. ACK validation consumes only the request and payment. Production
  request-mode, request-budget, acceptance-intent, acceptance-ticket, and
  precommit/no-commit public types have been deleted from the data model.


<a id="record-7543822ae99a0144a53482eee63ef89d157bbf75da9e4bc0ea651672ed4c1d8a"></a>

- Core, Torii, native bridge, and all SDK consumers of the deleted handshake are
  still being adapted. Until that dependency closure compiles and its focused
  tests pass, KAGEMUSHA is not fully implemented. The authoritative transport
  and KAGEMUSHA specifications now describe only the three-message protocol, and
  QR payload tags are Request=1, Payment=2, ACK=3 with no compatibility tags.


<a id="record-1bd7bf9071939eba47e2784a223fd342e2bf716d9f22dee4eeabb88209006aad"></a>

- The aggregate state model has one private `u128` balance per device
  lane/asset, exact-next hardware epoch/sequence, consumed-credit sparse-Merkle
  root, nonce, public commitment, and recursive proof. Protocol admission has no
  hop, ancestry, fan-in, origin, note, received-credit, or proof-depth count.
  Pending credits may add fold latency but cannot become unspendable because of
  queue length or history.


<a id="record-9a0a51d785f188842414afaf80bd7d29390ab88e3319e4c6f16879a857e1856b"></a>

- Table8 SHA-256 is the only current SHA circuit implementation; the Table16 and
  boolean candidates were removed after measured resource failures. The focused
  Table8 suite passes 20/20. The k=12 mint-hash leaf shard passes 6/6 and binds
  its typed plan, job/block indices, chaining state, block bytes, and digest into
  43 public cells. It intentionally grants no monetary authority by itself.


<a id="record-a70d2854ff7789cea1e3949308f8b8032f3b9f755cf2621f4dbf4f80597e581c"></a>

- The ordered mint-hash claim-fold is under active integration. Its current
  design lifts the k=12 IPA accumulator into the exact k=16 generator prefix,
  folds each authenticated leaf and prior history into one constant-size paired
  carrier, and binds ordered cursor/output state. Final common-public-cell audit
  binding, compilation, and adversarial tests remain release blockers.


<a id="record-348327c7fef33d387d28f4ad9d7fd81fc6f3d2e2c42da6baa2afec16fb85977b"></a>

- Focused aggregate-state evidence includes a mocked fixed-shape 1,024-handoff
  model, a mocked 1,000-receipt fold-to-one-balance model, assigned recursive
  proof-byte reconstruction (8/8), state-owned MintFold input selection (3/3),
  redaction (1/1), successor-substitution outbox protection (1/1), and durable outgoing
  operation indexing (10/10). A debug 1,000-device top-up -> merchant fold ->
  one spend -> redemption run is still computing. These runs do not satisfy the
  real-recursion or physical-hardware acceptance gates.


<a id="record-0d59d2b632552aad704bd403ae797ecc44a989e715b9475ceff8888792c38f9f"></a>

- `kagami kagemusha authenticate-release-v1` is the sole release
  authentication command. Its production check and focused guards are green.
  The combined hard-cut/package/release-CLI/formal Python selection passes 30
  tests with eight skips. Broader Kagami validation remains blocked by unrelated
  shared genesis-test compile failures and is not full-crate evidence.


<a id="record-239f080df4f03706f9d43edec460f9ed7684bad3cc73bc7b895decdee7eaad27"></a>

- The final source/recovery inventory must be regenerated after the current
  protocol and recursion edits settle. The previous 607-record seal and focused
  panic-boundary guard were green but no longer constitute a final source seal.


<a id="record-4f9d9b5f61646cfcce6ddaab30349ac728643c97aa88e85664e760a0ff31eb03"></a>
