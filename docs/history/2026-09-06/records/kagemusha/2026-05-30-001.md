- The live wrapper's `full_toml_ready`/`offline_full_toml_args` gate now also
  checks the carried raw-data owner, visible owner, recovered signer, signature
  hash, and single-signature count before declaring a replayed live summary
  ready for offline production TOML rendering.


<a id="record-6ac848349e39fda75344d05022c718966940ebc50d8cb979e3a33ca7fe9278ee"></a>

- Saved live JSON summaries are revalidated before offline full-TOML rendering:
  the gate now reparses the saved `raw_data_hex` and raw signature, recomputes
  the canary hash, and checks the submitted selector, Groth16 tuple
  length/version/source-domain header, public-input message id, target domain,
  commitment root, statement hash, and owner/signature fields instead of
  trusting `call_data_matches_event` alone. The route canary replay gate also
  requires the accepted event's source domain, destination binding, verifier
  backend, proof family, and network id to match the live destination verifier
  view even if a saved JSON file carries a self-consistent recomputed canary
  hash.
