## 2026-08-29 Telemetry first-release simplification



<a id="record-d7d11eceba62a4a08a97de5e37ff311ea4a4154ca40de55de40defbffd51a5a1"></a>

- The unused development-stream adapter and the `streaming-stats`,
  `tokio-stream`, and `async-trait` dependencies were deleted. Exporters consume
  Tokio broadcast receivers directly and reconnect without boxed trait futures.
  WebSocket code is isolated behind `event-exporter`, which the daemon enables
  but metrics/privacy-only consumers do not compile. The independent
  `dev-telemetry` feature shares only the integrity and Tokio file primitives,
  without pulling WebSocket/TLS dependencies on its own. `iroha_futures`
  telemetry instrumentation is enabled only by `dev-telemetry`, so normal node
  builds no longer time annotated futures or broadcast events without a
  subscriber. IVM also no longer enables `metric-instrumentation` transitively;
  per-call timing remains opt-in through `expensive-telemetry`.


<a id="record-f0a5401ef7754b28a27e172dea5077f1a5e8f2a59584f032f43ed83ac7c2957f"></a>

- Logger telemetry records explicit routing fields before adding universal
  defaults, preventing duplicate lane/dataspace labels. UTF-8 truncation is
  character-boundary safe, cyclic error-source chains are capped at sixteen
  entries, and sensitive-field classification borrows already-normalized
  snake-case names. Redaction is now unconditional: the unused configuration,
  runtime policy locks/hooks, build switch, override audit path, and three
  never-produced policy metrics were removed. The bounded event channel now
  reserves capacity before formatting or redacting, so a full channel does not
  pay allocations for an event that cannot be retained; sensitive debug and
  error values are likewise classified before formatting or source-chain
  traversal.


<a id="record-e77c6fee7748ff6fcb746afc5ba742ccde326307ad7767ab0492f01be921f61b"></a>

- The unused arbitrary telemetry node name is no longer configurable and is
  rejected as an unknown first-release key; Telegram uses the canonical peer ID.
  Structured WebSocket records also dropped the constant, information-free
  `id: 0` field. The redundant `telemetry_enabled` switch is also removed and
  rejected; `telemetry_profile = "disabled"` is the sole runtime kill switch.
  Capability predicates now live directly on the profile instead of
  materializing a parallel three-boolean wrapper. Core telemetry handles keep
  that startup decision as an immutable boolean, removing the shared atomic
  flag and its load from every observation as well as the unused runtime
  `set_enabled`/`enable`/`disable` API. Torii's handle is concrete over
  `TelemetryProfile`; the unused generic gate trait, generic gate remapping, cloned
  accessor, and configured-state accessor were deleted. `Torii::new` now has
  one feature-independent telemetry-disabled shape, while embeddings that
  collect telemetry pass an explicit profiled handle to `new_with_handle`.
  Telemetry configuration debug output redacts integrity, bot, chat, and URL
  credentials. WebSocket URLs/schemes and inbound frames are bounded, retry
  exponents are capped, and disabled profiles skip exporter/actor/probe startup.
  Partial, dormant, or build/profile-incompatible Telegram and integrity
  settings are rejected. Telegram HTTP uses fixed deadlines, refuses redirects
  and non-success responses, and strips request URLs from errors. Optional alert
  snapshots now request a bounded checked actor refresh before reading four
  atomics from the shared metrics registry; refresh failure omits the optional
  snapshot. The unauthenticated self-scrape, response parser, sampler task,
  URL/period settings, stale-zero path, and profile-dependent failure loop were
  removed.


<a id="record-6c851c8732bbdc7aa5413aa75325618c65671dafebd019b75a8e895013be4bde"></a>

- Validation covers the complete exporter matrix: all 133 `iroha_telemetry`
  library tests and all 23 telemetry-filtered `iroha_config` tests pass, and
  `iroha3d` checks successfully with `daemon,telegram-alerts`. The 12-case core
  telemetry source-inventory guard, the 756-row metric catalog guard plus its
  mutation self-test, the retired-codec and OpenAPI fail-closed guards,
  `cargo fmt --all -- --check`, and `git diff --check` also pass.

## 2026-08-29 Torii MCP security, protocol, and stale-surface audit



<a id="record-9b572bfa08fe4792368a6980bb28d66ef5ad7a001b4d154131bed512f6ebb22b"></a>

- A focused MCP audit closed attacker-amplified schema-regex compilation,
  unbounded tool and long-poll concurrency, invalid-token rate-bucket churn,
  response-size amplification, browser Origin ambiguity, and untrusted
  Host/forwarding-header derivation of credential-bearing Connect tickets.
  Runtime schema validation now enforces advertised combinators, conditional
  branches, and bounds, rejects unresolved OpenAPI references, and caps response
  projection selectors before using one deterministic lookup set. Response
  bodies remain typed data with bounded collection, and nested target
  authentication continues through the authoritative Torii router.


<a id="record-7d3eb65b2ee992b791f452d31e3ffe97246905d644fe250ec32d17d0b5d088c3"></a>

- The Streamable HTTP surface is POST-only and keeps the route registered while
  disabled so callers that pass listener-wide admission receive typed
  `mcp_disabled` errors. Initialization, negotiated protocol headers,
  notifications and client responses, JSON numeric IDs, batch charging, exact
  operator admission, semantic safety annotations, and package/toolset metadata
  now follow one tested contract. Configurable global dispatch capacity
  reserves a smaller quota for long polls.


<a id="record-0d38b3d2577cd3dda0c956ae1580a9e8873f90a4a069beb29918064c8a0e6dff"></a>

- Real nested-route concurrency tests now prove that the global dispatch limit
  and reserved long-poll subquota leave a bounded slot available and restore
  both permit classes after completion. Authenticated cancellation uses a
  domain-separated fingerprint of the exact validated API-token principal,
  lossless type-tagged string/integer JSON-RPC IDs, and an exact canonical
  32-byte per-call nonce advertised in initialization metadata. The nonce makes
  delayed cancellation harmless when a completed JSON-RPC ID is reused;
  anonymous, cross-principal, wrong-nonce, and malformed cancellation cannot
  target a live call. Floating-point-form and out-of-range numeric IDs remain
  valid JSON-RPC IDs but are fail-safe non-cancellable rather than rounded into
  an alias.
