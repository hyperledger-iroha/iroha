<!-- Original context: Status / 2026-06-01 ISO XMLDSig delegated OCSP KeyUsage criticality -->
- Tightened delegated OCSP responder admission for ISO 20022
  `require-verified` XMLDSig/XAdES profiles. Embedded delegated responder
  certificates now need a critical KeyUsage extension with `digitalSignature`
  before their OCSPSigning EKU can authorize a BasicOCSPResponse.


<a id="record-7654b8ff1e548aec36435ae89bef27d1211629d287254baa85e86abecee8924f"></a>

<!-- Original context: Status / 2026-06-01 ISO XMLDSig signer KeyUsage criticality -->
- Tightened X.509 signer admission for ISO 20022 `require-verified`
  XMLDSig/XAdES profiles. Signer leaves now need a critical KeyUsage extension
  with `digitalSignature`; a non-critical digitalSignature KeyUsage no longer
  authorizes XMLDSig material through either direct public-key pins or
  trust-anchor chains.


<a id="record-b5aaa55058a959347bd619007006a9f0bc085094e550a8d2db691f1ef7031414"></a>

<!-- Original context: Status / 2026-06-01 ISO XMLDSig NameConstraints criticality -->
- Tightened X.509 NameConstraints admission for ISO 20022 `require-verified`
  XMLDSig/XAdES trust-anchor chains. A constrained issuer certificate now must
  mark NameConstraints critical before its permitted or excluded subtree policy
  can authorize a signer leaf.


<a id="record-380c7783df156fe67b3b569736e849d220a9680d29813573eae21c1379802365"></a>

<!-- Original context: Status / 2026-06-01 ISO XMLDSig CA KeyUsage criticality -->
- Tightened X.509 CA admission for ISO 20022 `require-verified`
  XMLDSig/XAdES trust-anchor chains. A CA certificate now must carry a critical
  KeyUsage extension with `keyCertSign`; a non-critical KeyUsage extension no
  longer authorizes an otherwise valid issuer certificate.


<a id="record-b40031cb6981335e0133deb9c8e85199924c52596d85ee3a6d5105ac7720e254"></a>

<!-- Original context: Status / 2026-06-01 ISO XMLDSig AKI issuer/serial binding -->
- Tightened X.509 trust-anchor chain validation for ISO 20022
  `require-verified` XMLDSig/XAdES profiles. Authority Key Identifier
  `authorityCertIssuer` and `authorityCertSerialNumber` metadata, when present,
  must now match the actual issuer certificate before the signer leaf key can be
  accepted.


<a id="record-1f6071fe3481fa31ccf31989604a1acdc55f356c8e58ca195742407b32966776"></a>

<a id="record-4b095bc7d9c96045d61ebcd732e26421b017bc39d4c96e7b21815f87929cf619"></a>

<!-- Original context: Status / 2026-06-01 ISO XMLDSig unknown-critical extension rejection -->
- Added fail-closed critical-extension handling for ISO 20022
  `require-verified` XMLDSig/XAdES X.509 material. Certificates now reject
  before key acceptance when a critical extension is unsupported, unparsed, or
  failed to parse.


<a id="record-144204c946c5f6dd2dfb204a545a97b68df403602c68ab48cea09f864d40f74f"></a>

<!-- Original context: Status / 2026-06-01 ISO XMLDSig signer EKU purpose binding -->
- Added X.509 Extended Key Usage admission for ISO 20022 `require-verified`
  XMLDSig/XAdES signer leaves. Certificates without EKU remain accepted, but
  EKU-constrained leaves must allow code-signing, anyExtendedKeyUsage, or the
  document-signing OID before the leaf key can be used.


<a id="record-4ebdd98f2bd516237591f5affaed719512d446a3e59e7a511d6f0762ea7157a5"></a>

  BasicConstraints CA:true before they can act as a trust anchor or

<a id="record-0fa3a968f5340e04e10592450844974b0764648be18e2b70f9c144a056342614"></a>

## 2026-06-01 Torii sustained query load profiles



<a id="record-02f889cf95d407a4df5075ac77e6106bc8bb1b5d8d425c8a286ae9be1ac48d8f"></a>

- Added validated Torii query-load profiles for signed iterable stored-cursor
  continuations, account primary-alias projection queries, asset-holder scans,
  account-asset predicate queries, committed-history contract-activity
  predicates, and generic aggregate queries. The validator rejects zero,
  oversized, malformed-name, shallow-dataset, unexpected-continuation,
  unexpected committed-history rows, and page-limit benchmark shapes before
  fixtures are built.


<a id="record-4eb63719e9435f7abbce6fb635b529881c3ab91fbc637be3f7b22d2bf8858424"></a>

  route through Axum services and the existing signed-query/app-query handlers,
  including deep signed continuation chains over the Arc-backed snapshot replay
  path and a `/v1/contracts/activity` GET profile backed by real committed
  transactions carrying contract metadata.


<a id="record-7d7290d91bd13ce3b32c6413a8aa6d6e8c6d9047a021f1a6c0a100d91b160cc8"></a>

- Added a socket transport profile group for the same validated workload set.
  It binds ephemeral localhost Axum listeners and uses pooled `reqwest` clients
  so the in-process handler measurements can be compared with real HTTP
  transport, connection-pool, and body IO overhead.


<a id="record-f810e02f16dc5fc1197c0a67a019a59730beb75170a6f009c6bc45098ec10036"></a>
