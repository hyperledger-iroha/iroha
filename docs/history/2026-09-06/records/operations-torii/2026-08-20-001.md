## 2026-08-20 disposable Taira devnet replaces the local release-corridor harness



<a id="record-c546e5d82676420ccaecc6e29e91b0544ba125460b5402c2533374b400752da0"></a>

- Taira development deployment is
  `python3 scripts/taira_devnet.py up --inrou-canary-dir <owner-only-workspace>`,
  with matching read-only `check` and owned-cohort `down` commands. The command
  generates exactly four fresh-key NPoS Nexus peers on the canonical Taira
  chain, validates all four configs with the current daemon, and uses explicit
  loopback listeners and same-revision binaries.


<a id="record-d4e3a383137f10876653b32bd99da7113b2efcd3d539c5595abc8c2e51c39804"></a>

- Success requires all four `/health` and `/readyz` endpoints, a blocking signed
  transaction, converged advancing `/status/blocks` heights, semantic MCP
  capability/initialize/tools-list responses, and the exact guest workload
  qualification receipt. The broad public product doctor remains available
  only through the explicit `--full-doctor` option.


<a id="record-f765bc86b0e6ef6d1c9269dded694746a82ffa17085544d1405669c9399dba5f"></a>

- The obsolete reset/update/render/supervisor, release-authority, publication,
  evidence, and 24-hour-soak scripts and their dedicated workflows, host units,
  fixtures, and tests have been removed. Shared Sumeragi release receipts no
  longer treat a Taira soak as a prerequisite, and retained public Taira/SoraFS
  checks use current compiled CLI surfaces or require explicit runtime-only
  signer configuration.
