## 2026-08-30 Torii first-release contract and authentication closeout



<a id="record-f8639d0ecd338646a925c1ee7102d790bbd5a8b11a9ba39375bf32c307e47d77"></a>

- Torii now exposes only the exact diagnostic probes `/status`,
  `/status/blocks`, and `/status/peers`; the wildcard status dispatcher and its
  dormant path-value helpers are removed. OpenAPI discovery is exactly
  `/openapi.json`, and the legacy SoraFS storage-fetch diagnostic is removed
  instead of retained as a pre-release alias.


<a id="record-0fb6864d0d2ad8ce514fde0e2c0d6556fcd473d8a77688d67d79b1c49ce5db74"></a>

- Operator WebAuthn uses a closed, size-bounded credential envelope and the
  exact `none` attestation profile. Canonical base64url, authenticator flags,
  credential identifiers, algorithms, public keys, counters, persisted fields,
  and duplicate IDs fail closed. Credential files are atomically replaced and
  durably synced; policy-incompatible or corrupt state prevents startup.


<a id="record-7da74b52826ca06c0040868e7226056d75dd5cfee0b6ec19407282079228ecc6"></a>

- Challenges, sessions, lockout identities, and persisted credentials have
  explicit configuration-sourced capacities. Live ephemeral state expires via
  an indexed deadline heap, admission returns `503` at capacity without
  evicting valid state, credential enrollment returns `409` at its separate
  bound, and operational failures no longer poison the caller's lockout
  budget. Login-options requests cannot erase assertion failures.


<a id="record-eea1b6ea44b43448031b27f69a6640fb2021690d029b8adaadc4767e2153d344"></a>

- Operators can list closed, key-free WebAuthn credential metadata and revoke a
  credential through exact OpenAPI-only routes. Both require the canonical
  operator request signature and a live WebAuthn session; deletion persists
  atomically, revokes outstanding auth state, and preserves a bootstrap path
  before allowing the final credential to be removed.

## 2026-08-30 Torii first-credential operator bootstrap hard cut



<a id="record-1295b5b59cb6fffd48929a03c2960f0c03781a3844440d9f7739faccbc440f83"></a>

- Torii operator authentication now has one bearer credential: the dedicated
  `x-iroha-operator-token` allowlist can bootstrap only the first WebAuthn
  credential. It never authorizes ordinary operator routes, listener API tokens
  are never reused, and the retired `token_fallback`/`token_source`
  configuration selectors are rejected as unknown first-release fields.


<a id="record-15f96b30f1c8ece3a5b21899ba9bee1cab178c4ac4651d5a18ccab611d8a5ae4"></a>

- After the first credential is persisted, including across restart, operator
  routes require a valid WebAuthn session and only a valid session can enroll a
  rollover credential. Credential persistence rechecks the bootstrap boundary
  while holding the credential write lock so concurrent bootstrap ceremonies
  cannot race a second credential into the store.

## 2026-08-30 approved security-audit remediation source closeout



<a id="record-750cd50e562fad889dbf5fb59672da778010e776bbc2b7cd4dee1b5c0876fd2d"></a>

- The 17 findings selected for remediation now have enforcing source paths and
  named regressions for contract lifecycle ownership and emergency holds,
  registration metadata limits, reserved transfer-control metadata, bonded
  moderation challenges, scoped and metered data triggers, Torii identity and
  dataspace visibility, snapshot-bound Explorer cursors, ISO participant and
  replay controls, public local SoraFS gateways, relay-proof verification, and
  recoverable panic boundaries. Four additional findings retain explicit
  regressions for consensus-bound oracle economics, the gated debug-witness
  route, global Norito decode limits, and exclusion of development fixtures
  from release dependency graphs.


<a id="record-26fb4096cbfd468fb6042d3b576e888143f4710d062c09bb6ea437d14d487607"></a>

- Residual adversarial review tightened those boundaries without expanding the
  public model: data-trigger eligibility is generation-bound across
  registration, reactivation, and account rekey, the 256-firing ceiling spans
  every drain in one transaction, moderation custody references block removal
  and native multisig-controller rekey, ISO reads snapshot authorization and
  status atomically, and lifecycle settlement binds an exact record incarnation
  and transaction hash. All six production WebSocket upgrade callbacks own
  cleanup inside task-local recovery, and CID-host discovery reads now traverse
  the same local-manifest gateway policy as direct CID paths. The release guard
  also authenticates canonical prebuilt inputs and rejects alias, source-root,
  Python-shadow, and concurrent-rewrite bypasses before accepting its inventory.
  The canonical pipeline and standalone prebuilt verifier capture every
  repository bootstrap source before execution, reject path/link/mode/identity
  drift, and require exact reviewed source digests; the standalone SoraFS release
  gate runs the live feature-graph checker in addition to its adversarial tests.


<a id="record-bf7a5ab83e5947524699f0da92f5bea6d3bb6c65cb094d56ab899d904ebb6768"></a>

- This is a source-level closeout, not a release receipt. A settled candidate
  still needs regenerated OpenAPI/catalog manifests, all named focused and
  four-validator regressions, SDK and documentation parity checks, strict
  all-target Clippy, and the workspace test gate. This remediation authored no
  Cargo lockfile change; root `cargo metadata --locked` is coherent at the
  current head. The separate `crates/ivm/fuzz/Cargo.lock` still names the
  externally removed direct `halo2-axiom` dependency and must be reconciled by
  its owning IVM change before the candidate can be release-qualified.
