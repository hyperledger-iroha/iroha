## 2026-06-04 ISO 20022 readiness proof hardening



<a id="record-0ea1de9b873f5c0cf2d6d747c1f514e4e77d529866dfebf5fbb60efdd73be08a"></a>

- Tightened `scripts/iso_production_readiness.py` so aggregate evidence
  canary summaries must carry the digest-bound `require_explicit_policy`
  boolean emitted by `scripts/iso_operator_evidence_verify.py`; omitted values
  are malformed input and `false` is a production blocker.


<a id="record-e7608d8648e1f5884f59175679ec1d0ea15862ccd6461a882b869fb5628136ce"></a>

- The readiness summary now preserves the per-canary explicit-policy proof, so
  final release evidence cannot rely only on the upstream evidence gate's
  command-line posture.


<a id="record-50c58a659fbfbb87c9ef2573f68e68e4f05ffa8fa44c3f492190090fa5e51ef9"></a>

- Threaded compact trust revocation posture through
  `scripts/iso_operator_evidence_verify.py` into readiness summaries. The
  final gate now requires explicit CRL/OCSP booleans and material counts,
  treats omitted revocation proof as malformed, and blocks production when CRL
  or OCSP revocation checks are disabled or required material counts are zero.
  It also rejects compact trust summaries whose `verified_bundles` count does
  not match the number of compact profiles.


<a id="record-06d587e33fd0030fd3f6728931915a00da1694d984d679430e79d82b1c1abc1e"></a>

- The final readiness rollup now requires compact canary and trust summary
  entries to retain control-free, traversal-free source paths and canonical
  lowercase `summary_sha256` pointers, and preserves those pointers in the
  release summary for audit traceability.


<a id="record-df594d46ca4b11587561723a2411ca7896289dc987095377e164bb94d6e216c1"></a>

- The operator evidence gate now validates each canary summary's runbook
  `config_path`, preserves it in compact evidence, and the final readiness
  gate rechecks it as a control-free, traversal-free `.json` pointer.


<a id="record-d9ff097a00c898ba63895cebfcf53057ba468834f2a22f80726a144bbc0984fe"></a>

- ISO evidence, readiness, and XSD path validators now reject leading-dash path
  tokens before archive or release acceptance, preventing artifact/config paths
  from being confused with child-command flags.


<a id="record-8e52a5d3bdc0ff122ad29c170f2fe7595bfac6fe36ac7104e283b7031563bb62"></a>

- Canary child command arrays now reject control characters before archival,
  covering both executed stage commands and plan-only stage commands.


<a id="record-a9032ead759c3088462cc25b6900ed4caf0d1887c8c08e1d04783242383e8b85"></a>

- Canary child command arrays now also reject duplicate singleton flags before
  archival, so forged summaries cannot present multiple `--torii-base-url`,
  `--export-dir`, or receipt policy flag values.


<a id="record-4f23d11459d2e5c5f943df2809ecd5efe72ce4b22d3ddcd646f717f17e86c071"></a>

- Canary child command arrays now reject store-true boolean flags spelled with
  `=value`, so forged summaries cannot treat invalid argparse forms such as
  `--require-source-files=false` as proof of a production policy.


<a id="record-d2066ea8a61b2ee7da99fe953f2fad0f398b42818088423cc37d4a9c69f0ab38"></a>

- Canary child command arrays now reject non-positive integer caps and
  non-positive or non-finite timeout values before archival.


<a id="record-47ff29eb4c8ddb13f100e21ce37ad3c8c4c202db4c6c9ae421a9615784ca4e40"></a>

- Canary child command path values such as rail `--inbox-dir`, rail
  `--message`, notary `--export-dir`, and verifier `--receipt`/`--receipt-dir`
  are now path-hardened before archival.


<a id="record-ef6a3a408b25ffafd6343735b68377de3101754608a0c0e6eb630898c7e40679"></a>

- Canary child commands now require their production structural inputs, including
  rail `--inbox-dir`/`--torii-base-url`, notary `--export-dir`/`--endpoint`,
  and verifier receipt inputs plus source-file verification in plan-only
  runbooks.


<a id="record-0655673d5e27dec4c022fa88a680eda6d6d932de607dff3aa33ef4f0ef467b50"></a>

- Executed canary stages now reject truncated child stdout or stderr previews
  before archival, so rail/notary/verify evidence cannot rely on incomplete
  child-process output.


<a id="record-f54fce48013b8ed31a94402a35e7ae60d7fe21c82b3ca1bba7ec1e8cb345fe23"></a>

- Rail receipt source verification now rejects `xml_path` values that do not
  point at `.xml` leaves before sidecar convention and source-file cross-checks
  run.


<a id="record-8ed724ac7095c511ac167eebf9590787f30974b511a9de2e0124fb39e1c0deb9"></a>

- Rail adapter submission now rejects explicit `--message` values and discovered
  XML leaves that start with a dash before sidecar reads or Torii submission.


<a id="record-45f441710b74c9070962f9ba06d8f818dc3fd57dd4a32dca7a50e401a1ae2bc6"></a>

- Notary audit-index verification now rejects duplicate record identities before
  publication or archived receipt source replay, preventing digest-correct
  anchors from inflating record counts with copied rows.


<a id="record-c561f9c770c484e218158c39df77ecd2de4843952b3637ca82eaf1ec03a6e3c2"></a>

- Persisted notary record-source verification now requires status history
  timestamps to be monotonic and to end at the record's current `updated_at_ms`
  before publication or archived receipt source replay.


<a id="record-1d72744438be8073d8d8565082449883d84eff0ded14f900d6bbba8fd94a64f9"></a>

  anchor `store_dir` values that receipt source replay already required, so the

  Validation after the ISO output/path/command hardening pass:
  `python3 -m unittest pytests.scripts.iso_audit_notary_adapter_test
  pytests.scripts.iso_operator_canary_test
  pytests.scripts.iso_operator_evidence_verify_test
  pytests.scripts.iso_operator_receipt_verify_test

<a id="record-994d339b8b9dde708ab0b255a645a1dd4712e14ec17a65e550d734533eeff59a"></a>

- Canary rail/notary `receipt_dir` values now reject control characters and
  dot/parent traversal segments before the evidence archive accepts either
  executed or plan-only stage records.


<a id="record-7b86e0888f861fd951b7dbd9c43d3061926f63a0cf66be471faa03c646ff9ea8"></a>

  one child-command `--receipt-dir` argument and verifies that it matches the
  recorded `receipt_dir`, including `--receipt-dir=value` forms.


<a id="record-0f058ade62d5ed3b1bd308f76c9482717fb2bfab1c304db03ee1c3a27994f54a"></a>

- Executed verify stages now must include the rail/notary receipt directories
  generated by non-dry-run stages, and those verify-stage `--receipt-dir`

<a id="record-4f63b294e665e31ea58ca842e9d5a7640f41ac836afd43da8a328b0e13de5634"></a>

  characters before trimming, covering compact provider/environment, stage names
  and windows, receipt kinds, trust profile identifiers, rails, and policy
  labels.


<a id="record-cb4f535caf5aefabe50293130a2d222a6ede799129b62f5d9a5f1e2cda337682"></a>

  operator evidence objects, including the evidence policy, compact canary and
  stage-window records, nested receipt summaries and receipt entries, compact
  trust summaries, and compact trust profiles.


<a id="record-276439fc5db118148f9dbc43853ef6e57c626034b4b06500868a2086cb7423f5"></a>

- The operator evidence gate now also rejects unknown fields before archival in
  raw canary summaries, canary policy/stage records, embedded receipt-verifier
  summaries and receipt entries, trust-bundle summaries, trust bundle records,
  trust source provenance, material summaries, and profile override objects.


<a id="record-3b438fab786c5a2ee7b345b67e917f390706244f0bd22b27b7af403b27d6f36b"></a>

- The evidence and readiness gates now have direct negative coverage proving
  they reject omitted whole canary/trust and XSD/evidence input summaries,
  preventing empty archive or empty release reports from claiming readiness.


<a id="record-95ff40247ed1e4500d271dc6b5f80ac29719d93ce4c3855b172af44a2e5baec1"></a>

- The evidence and final readiness commands now require explicit `--provider`
  and `--environment` release context, and tests prove omitted or blank context
  is malformed rather than inferred from archived summaries.


<a id="record-81dfdd14c8360b0dd511871cf6e556cb4971ba9b6f297ccba72e3adaaa04615a"></a>

- The evidence summary now records that expected provider/environment context
  in its digest-bound policy block, and readiness rechecks the compact policy
  context before accepting an evidence archive.


<a id="record-9c5b0c97e3f459987d0892a083e6ea2c072ff76a2a62936af4b051b6081c0fc8"></a>

- Evidence and readiness now reject repeated summary paths and copied summaries
  with duplicate `summary_sha256` values, including compact canary/trust entries
  inside an evidence summary.


<a id="record-42fbb03e7f9c271b943ab79b1adb456a52523ba57481e10820344892777e85e7"></a>

- All ISO operator JSON inputs now reject duplicate object keys before semantic
  validation, covering rail sidecars, notary anchors/indexes, canary runbooks,
  receipts, trust bundles, canary/evidence/readiness summaries, XSD manifests,
  receipt-verifier JSON embedded in canary stdout, and direct archive
  receipt-verifier stdout.


<a id="record-960bce4fe5e9d0a3632556d7cd557c1ae970f906d766d8ace5143c45b6cfcdb9"></a>

- `scripts/iso_xsd_fixture_verify.py` now has a `--validate-xml-schema` strict
  proof mode. It records per-fixture `schema_validated` flags and a
  `schema_validated_fixtures` count, and
  `scripts/iso_production_readiness.py` blocks production summaries that do not
  prove XML schema validation for every schema-backed fixture.


<a id="record-7c33a6546cde15e427005b651a32fcd1603c33ada4d671c0b9131a2553e0a24e"></a>

- `scripts/iso_xsd_fixture_verify.py` can now parse the embedded default rail
  profile catalog with `--profile-catalog`, record concrete advertised message
  versions, and fail `--require-profile-schema-backed-versions` when an
  advertised version lacks a schema-backed fixture. The current checked-in
  profile scan records `55` concrete profile versions, `26` schema-backed
  versions, and `29` missing profile-version schema proofs, with the strict
  profile gate first failing on `generic-iso20022` / `pacs.008.001.10`.


<a id="record-7bddb01f8e1ee6b1ac57bb14ca0932ab5cf1b2b8e417d7752e61f1df7a9519fb"></a>

- XSD preflight summaries now bind the manifest SHA-256, each checked-in
  schema's canonical source repository, commit, path, SPDX license, and
  source SHA-256, plus profile catalog source-file and embedded JSON SHA-256
  values. The production-readiness gate rechecks and preserves those provenance
  digests in compact XSD summaries and treats omitted, non-canonical, or
  digest-drifted provenance as malformed release evidence or blockers.
  Direct manifest preflight and archived readiness replay now also distinguish
  omitted schema/blocked-source `source` keys from explicit null source objects,
  with regressions pinning both malformed paths.
  Readiness also requires archived XSD summaries to retain the emitted
  `manifest` path and `profile_catalog` key; explicit `profile_catalog: null`
  remains recorded no-catalog evidence and cannot satisfy strict
  profile-schema-backed proof.


<a id="record-b3f22ad259a4f6e15ad680241a6eef77bb49cbee559c7884ba3f0700b775b2cb"></a>

- Profile catalog checks now fail closed on non-canonical profile ids, malformed
  message family ids, unsupported directions, empty profile/version lists,
  duplicate profile ids, duplicate profile/message/direction entries, duplicate
  concrete versions, padded/non-ASCII/secret-looking skipped family aliases,
  concrete versions incorrectly placed in skipped family aliases, and
  inconsistent profile catalog count fields in readiness summaries.


<a id="record-d00f018ec6cd3fb80a9348883d765e8a029c49aa543a33c27e7bd1fe79122719"></a>

- XSD schema imports now fail closed if the manifest omits canonical source
  provenance or if the file contains known restricted Standards Editor
  redistribution terms. Public mirrors for
  `pacs.008.001.10`, `pacs.009.001.10`, and `pacs.002.001.12` were inspected
  but not imported because their embedded XSD headers prohibit redistribution.


<a id="record-81d83760395c4bd7d83bc69f4a8f0cb5c18dcad9258acc8a29db04ca763e3061"></a>

- `scripts/iso_production_readiness.py` now requires and rechecks the
  profile-catalog schema-backed proof, including count consistency, duplicated
  profile-version entries, and forged missing-version lists. Production
  summaries that do not prove `--require-profile-schema-backed-versions` are
  blocked.


<a id="record-afa7943829b1c62bf1a503cb8e49c2f8b213d14d88f052ceb93349158f187b2a"></a>

- The final readiness gate now treats XSD summary objects as closed schemas:
  unknown fields are malformed at top level, in strict flags, schema and
  fixture entries, source provenance, gap lists, profile catalog metadata,
  profile-version entries, skipped-family entries, and missing-version entries.
  It also recomputes `profile_catalog.missing_schema_versions` and schema-only
  flags/reasons from digest-bound schema and fixture arrays, and compares
  `missing_schema_fixtures` and `schema_only_entries` by exact path,
  `message_def_id`, and reviewed reason so forged XSD gap metadata cannot
  satisfy readiness.


<a id="record-9ad2e078cc38786a735ef41967146fa45e6490986ac19ac8bcf01a6dc44621de"></a>

- Digest-bound XSD `schemas[].path` values are now rechecked as canonical
  relative forward-slash `.xsd` paths with no empty, dot, or parent segments,
  and the filename must match the schema `message_def_id`.


<a id="record-9b63c1ccdc700a169280d9c517374b6810656f39e6c73e1744d1863c243f32b1"></a>

- Digest-bound XSD `fixtures[].path` values now reject backslashes, absolute
  paths, empty or dot segments, and non-`.xml` leaves while preserving the
  current parent-relative checked-in fixture layout.


<a id="record-76a955d6a76ca9ead367321d5bd942248411d34845c5a2ffa087433a5fa72631"></a>

- `scripts/iso_operator_receipt_verify.py` now rejects repeated receipt input
  paths and copied receipt files with duplicate `receipt_sha256` values. The
  evidence and readiness gates also reject or block duplicate per-receipt paths
  and receipt digests in canary-stage and direct archive receipt summaries, and
  compact receipt paths must be control-free, traversal-free `*.receipt.json`
  paths before either gate accepts the summary.


<a id="record-ccaa7ccf1cde0a60bb7c1d4941db96bdc0071827f5873eed252a56a464d093f5"></a>

- Archived trust summaries now reject duplicate compact `profile_id` entries at
  the evidence gate, and readiness reports duplicated compact trust-profile IDs
  as production blockers rather than allowing copied profile entries to inflate
  trust material counts.


<a id="record-597f0d113ec0961a9a73fa1fd99d5697719676ee3a45bb5dc2ca5b4f0a8366bc"></a>

- Trust-bundle preflight now requires every list-typed trust-material field to
  be recorded as an array, including explicit `[]` values for intentionally
  empty pin or DER collections. The checked-in templates and regression tests
  now reject omitted material arrays instead of silently inferring empty
  production evidence.


<a id="record-63c7f4e8e15b7b772de97b6a52f2ec65e43bc78152718400bdd5408acb4d539d"></a>

- Trust-bundle preflight now also distinguishes omitted source provenance from
  explicit `source: null`: omitted `source` is rejected as an unrecorded
  production provenance object, while null source remains malformed as a
  non-object. Regression coverage now pins both paths.


<a id="record-52e90bebdceae279e517f7eda4f87d7a55389da1415cad7fac686faabd44f1ce"></a>

- The XSD fixture preflight now rejects copied XML fixtures with duplicate
  fixture SHA-256 values, and the readiness rollup independently rechecks
  digest-bound XSD `schemas[]`/`fixtures[]` metadata for count consistency,
  duplicate schema/fixture evidence, schema-reference drift, and
  schema-backed/missing-schema count mismatches.


<a id="record-c708b7912525904e722d246bd7681994ca3078ddb8fc80ac09dfef48c2b1cf94"></a>

- XSD fixture manifests now must record `blocked_schema_sources` explicitly as
  an array, including `[]` when no reviewed restricted source candidates are

  silently treating absence as an empty gap review.


<a id="record-6999341545c534dc607dcd06641328bf7737f598ec7364a0f3184be95359a228"></a>

  rejects duplicate notary endpoints, duplicate explicit receipt paths or
  receipt directories, and shared stage receipt directories before a runbook can

<a id="record-e96f2e085c0cc664d8528ba2a4637d0a31aef5f7930e58f1e73f1bbb5e5cdfa5"></a>

<a id="record-d4309449ea6ea3d841722a3dba241cbc579a69720e12add806fa87cf3f11aabe"></a>
