## 2026-07-25 Taira independent validator supervision migration



<a id="record-e8d7033ebe72c6f8fa6ed478968b8e4eaf8a827a1bf368a3e51a2ac59547901e"></a>

- Added a guarded two-phase macOS migration for existing shared-host Taira
  deployments. The read-only plan seals the exact legacy
  `run-canonical.sh`/`launchd-run.sh` controller, all four validator
  PID/command identities, the deployed binary and configs, each peer's exact
  working-directory identity, and the separately guarded existing storage
  directory inode before rendering four independent KeepAlive LaunchDaemons.


<a id="record-485509e67c0741424b11847732f796b23d7beee7a2272697977034ebb51cc9e2"></a>

- Each launchd job owns one single-peer supervisor. Validator exits now restart
  only that peer with capped exponential backoff; binary, config, and storage
  identity drift fails closed. The explicit apply phase revalidates the sealed
  manifest before its one scheduled legacy-controller cutover and never
  deletes, moves, truncates, or recreates storage.


<a id="record-f63ed78564b0a3d2bf8cff511ef93611f141e7f95aafc2773946d18118115d3c"></a>

- Raised the source Taira per-authority query admission profile to 160
  requests/second with a 320-request burst so the browser's bounded alias
  resolution fan-out does not trip the former default pre-auth burst.


<a id="record-67f962664edc6152493a6a01648ebd49f0774e27f1a2726e493eb08199ee2fc6"></a>

- Focused migration/supervisor tests pass (`12 passed`). No live Taira process,
  launchd job, edge, or storage path was changed while implementing this tool.
