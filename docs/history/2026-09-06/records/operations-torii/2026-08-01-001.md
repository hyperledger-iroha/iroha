<!-- Original context: Status / 2026-08-01 Genesis authentication and bootstrap authority -->
- `genesis.expected_hash` is mandatory during configuration normalization,
  including when a signed genesis file is present. Normal startup and static
  validation compare every local body to that independently provisioned hash;
  Kagami-generated localnets write the exact signed header hash into every peer
  config, while checked-in signing profiles remain deliberately unrunnable
  until their explicit placeholder is replaced with Kagami's printed or
  `--expected-hash-out` value. Taira rendering and offline-reset preparation
  bind that value into the sealed manifest and every validator config;
  preparation and deployment preflight reject any disagreement. Docker swarms
  are now validator-only: every validator consumes a host-prepared signed body,
  verifier key, and independently approved exact hash through separate
  read-only inputs. No container receives the genesis signing key, source
  manifest, or client credentials, and no validator relies on peer genesis
  retrieval. Normal seedless `kagami docker` generation now consumes the exact
  prepared `peerN.toml` bundle, verifies signer/hash/chain/validator/PoP equality
  against the signed `RegisterPeerWithPop` roster, reuses those validator
  identities, and publishes only a policy-equivalent, container-safe
  file-secret projection plus concrete read-only public artifact paths. Only
  explicit non-empty `--seed` development mode generates identities and uses
  relocatable `IROHA_GENESIS_*_FILE` inputs; implicit random Compose identities
  are retired.

## 2026-08-01 Taira reset-gate and restart-proof closure



<a id="record-edc931df390e22914a4476d8b35d32a23bf608697d9d7da2ec8c0b9336dc9243"></a>

- Final release validation is pinned to the signed `optimizations` merge
  `7d0d0d29544cbeaae114c1c098ee1e41187634e2` and root `Cargo.lock` SHA-256
  `4318f92184fedb10e9bc5cb5c47f1df930c419221be4bd61fbc41741d02f6289`.
  This records the source anchor only; it does not claim that the pending
  guarded k17 generation or live reset has passed.


<a id="record-246164770b26d9524368b09a0310e9bd29ce50cce0e33274cacf194b15cceaca"></a>

- The guarded reset no longer treats a replacement PID as sufficient restart
  evidence. It binds a bounded same-inode log cursor before termination,
  requires exactly one authenticated snapshot-load success marker and no
  empty-state/Kura fallback marker, revalidates the exact supervisor and child
  identities after fleet advancement, and reports the ceil-rounded
  `restart_duration_ms`. Backward time or a duration above 45 seconds rejects
  the cutover.


<a id="record-dd7ad10082bb13e6044efc52f5712da9bff30bba7041819ae8365c72e1250a4f"></a>

- Controller and public rollout health parsing now accepts the complete
  canonical Iroha block-hash display (`hash:` prefix and four-hex checksum are
  optional exact syntax components) while retaining whole-string validation.
  Arbitrary suffixes, truncated checksums, and trailing bytes still fail
  closed. This prevents a healthy Taira cohort from being rolled back solely
  because live status includes its canonical `#ABCD` checksum.


<a id="record-9f0e6a7b4795ea0c1d27941679d40218e6cee185b241375b49156b48a2210f6d"></a>

- The detached pre-admission reset controller passes 112 tests and independent
  semantic comparison with the current controller. The current controller
  passes 122 tests; the rollout parser passes 25 tests plus its end-to-end mock;
  Python compilation, shell syntax, and diff checks pass. No live mutation is
  claimed by these source tests.


<a id="record-80c39f96d6bc5db4897186d55fef636f9f15e96c2338ed9e71bcd2452c3d36e5"></a>

- A read-only audit also isolated the previous unbounded rollout delay from the
  node restart: an obsolete cleanup wrapper deleted an old rollout and then
  called global `/bin/sync`, whose root process remains in an uninterruptible
  kernel wait. It owns no deployment lock or live Taira file. SSD SMART is
  verified, APFS reports no I/O errors, and directory fsync on the exact Taira
  install, reset, binary, and four storage paths measured 0.000--0.003 ms. The
  guarded controller does not invoke global `sync`; it uses targeted bounded
  fsync admission and therefore does not inherit this cleanup failure mode.
