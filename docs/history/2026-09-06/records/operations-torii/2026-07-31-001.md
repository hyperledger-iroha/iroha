## 2026-07-31 Taira snapshot restart canonicality and replay-floor closure



<a id="record-b849c48204dbae357b06e879d074d2343a07bebbc3d0a294e00a83cff6f86526"></a>

- The reset controller no longer parses `ps`'s rendered command string as an
  exact argv source. On macOS, both Homebrew Python and `/usr/bin/python3`
  replace launcher argv0 with the framework `Python.app` executable, which
  made old-cohort capture and new-cohort verification reject healthy managed
  processes. The controller now double-samples bounded NUL-delimited
  `KERN_PROCARGS2` data and numeric parent/UID state, launches the new cohort
  through the directly validated root-controlled Python.app executable, and
  binds that runtime identity across the deployment lock. The system launcher
  validator narrowly permits `/usr/bin/python3`'s root-owned system hardlinks.
  The first-release controllers require the observed supervisor argv to match
  the launchd `ProgramArguments` exactly; there is no framework-rewrite
  authorization path.


<a id="record-2d2b674625932fb2d0bb8173cf89a60110824eb3f1f2025f780c3804685d0d10"></a>

- Root-caused the slow/failing Taira restart to a semantic snapshot mismatch:
  the payload authenticated autoscale windows `48`/`192` and the derived
  history cap `193`, but reconstruction replaced the windows with process
  defaults `32`/`96` and re-emitted cap `97`. The restart reader therefore
  rejected writer-produced bytes as `NonCanonicalSnapshotPayload`.


<a id="record-e8a5f68b0c16fb041fe208acc2dd8a65b0b0fa904de874791129a78fabfe3ebd"></a>

- Snapshot reconstruction now fail-closes both window fields as `NonZeroU16`
  values, restores them before canonical reserialization, and keeps the
  derived history-cap validation exact. The snapshot writer now reconstructs
  every generated payload through the isolated restart initializer, validates
  the live ZK configuration without mutating process gas or live telemetry,
  validates SCCP rollback state, and requires exact canonical bytes before
  publishing any generation or compacting lane geometry. Snapshot capture,
  validation, and publication remain under one lock so concurrent writers
  cannot replace a newer pointer with an older captured state.


<a id="record-e98bf16b455b1ed5960888c1d677500b806ad7f39cd0aeebd0c0eea53b540c48"></a>

- Superseded on 2026-08-01: this change originally made the public rollout
  checker treat an offline-capability response as part of `/readyz` admission.
  That requirement has been removed. Current rollout gates use ordinary node
  readiness, advancing consensus, exact build identity, and signed canary
  evidence; offline app/device capability cannot make node health fail.

## 2026-07-31 First-release security-audit remediation



<a id="record-c74bb2c3198a484b8c7bba9c3b66e467b870d5b9c4a09ff07dc38c5d0a051749"></a>

- Reconciled the audit archive against the current first-release source. The
  supplied checklist contains 558 checkbox occurrences representing 540 unique
  identifiers, including 18 duplicate labels; the remediation archive contains
  298 finding reports. This corrects the earlier approximate inventory of 556
  items without discarding or renumbering any source record.


<a id="record-4b107da3da2b7e5b273c74e5d43f92730010cc3789927e127d5dd73f4729ed37"></a>

- Replaced the DA commitment and pin-intent proof shortcuts with versioned,
  domain-separated Merkle leaves, internal nodes, and descriptors that bind
  `(version, leaf_count, root)`. Verification enforces the exact path geometry
  and odd-node rule. Torii constructs and verifies proofs against canonical
  committed Kura blocks and historical policy sidecars; these endpoints do not
  independently re-establish block signatures or finality.


<a id="record-9c489857161982a9b711f0643772a3bbcf85c036ea1759278685b2801c6a30f4"></a>

- Bounded the unauthenticated DA proof surface with 64 KiB limits on all six
  list/prove/verify POST routes. List and exact proof-selector requests are now
  separate. Offset traversal is replaced by typed keyset cursors bound to the
  exact ledger tip; ordered-map seeks are logarithmic, each page examines at
  most 1,000 raw rows plus one continuation probe, and a changed tip,
  noncanonical cursor, or missing continuation key fails closed.


<a id="record-c56d91ad29fe4badef21af2c23c4b9ab0c70e3690b6685dbcc64a04fecbf91d8"></a>

- Removed the hash-expanded placeholder advertised as KZG. First-release DA V1
  is structurally Merkle-only across Rust, OpenAPI, Swift, Kotlin, and Java;
  unsupported proof-scheme discriminants and configuration fail closed instead
  of retaining a compatibility value that implies nonexistent algebra.


<a id="record-58f2a21a43930377b3fcce6ba63b2858c36f12ab3705469b8f5ba99fe695a248"></a>

- Refuted the reported local-autoscale fork path after tracing signed genesis,
  snapshot, Kura recovery, execution-policy, and P2P policy-digest checks.
  Deterministic post-commit autoscaling remains, and a recovery regression now
  rejects local autoscale-policy drift before ingress.
