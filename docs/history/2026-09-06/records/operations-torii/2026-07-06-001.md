## 2026-07-06 Committed lane-block queue releases applied sessions



<a id="record-47e5c785a00a69a37930014b24dc01b182d3caa964c465ca7eaf05a4e69b1099"></a>

- The bounded committed lane-block staging queue now prunes sessions only after
  Kura can validate a durable lane application receipt for the certified
  proposal, preventing already-applied lane blocks from permanently consuming
  executor-boundary capacity.


<a id="record-0ea9d584cec58bb27c184c0d9c0e243bb3cb1503cb319057a1ad1a3e38eb5ac1"></a>

- Actor startup hydration skips application-receipted certified sidecars before
  applying the queue capacity limit, so a restarted node cannot let old applied
  lane blocks crowd out unapplied committed work. Recovered execution inputs
  without application receipts remain pending and continue to report
  `payload_recovered_awaiting_state_application`.


<a id="record-3c20ab3f5cbcbab8fe9589cb0e4b77327f555e9f67aa12ebc8d4b7933cb33a9c"></a>

- Added a negative queue regression proving application receipts free capacity,
  while execution-input-only lane blocks do not.
