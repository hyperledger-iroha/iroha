## 2026-06-12 Torii DA Replay and Receipt Persistence Hardening



<a id="record-3f4ffb22107c089278c5d7725d7ff7c9953445c0fd18fd4c176abbfae780f53c"></a>

- Fixed DA replay-cache pruning so a restart-primed lane/epoch floor survives
  TTL eviction of cached fingerprints. Replayed sequences at or below the
  persisted cursor now remain stale after the live cache window expires.


<a id="record-1d368d837ce243b2f242aa8326fab075858060b61fd5cce6f1572ed0d29acd55"></a>

- Hardened Torii DA replay cursor snapshot recovery so completed temp snapshots
  are promoted when they monotonically advance the main snapshot, temp-only
  snapshots recover after interrupted writes, and stale, corrupt, or
  mixed-direction temp snapshots are removed without lowering sequence floors.


<a id="record-fa4ed32903d223919666c9c1ef5cda4f69190299d22f1f93821929c988e333ca"></a>

- Fixed Torii DA replay cursor recording for first sequence `0`; a new
  lane/epoch floor at zero is now persisted and survives restart instead of
  being mistaken for an already-stored default.


<a id="record-b2fef18e1268686745d6840d1c9af4f5a9338e9d8bd59b34fd57eccb736c7011"></a>

- Hardened Torii DA replay cursor snapshot writes by syncing the temporary
  snapshot file before replacement and syncing the parent directory after
  promotion, reducing crash windows around durable sequence floors.


<a id="record-508f51b36afb2f927e05cb8a8b22a8529bfa24e268678f23dba3a3971444934e"></a>

- Hardened Torii DA ingest responses so durable receipt-log stale-sequence,
  manifest-conflict, missing-outcome, and spool-write failures fail closed
  instead of returning `202 Accepted` after artifact spool execution.


<a id="record-a7f1d44e79ff9a7a2cdb33e418e8493e0dbe904495d4731e5603fed377a23291"></a>

- Removed the pre-validation `receipt_file` spool action from DA ingest; the
  receipt log now remains the single path that writes `da-receipt-*` artifacts
  after signature and ordering validation.


<a id="record-31c6734c5c16498edad6a90c5d3817fb9a313996509ca1ac48650fa8cb49b3fb"></a>

- Hardened stale DA receipt spool pruning to reuse the same validated receipt
  decode path before trusting a file's lane and sequence, so mismatched
  filename/body records are skipped rather than acted on during cleanup.


<a id="record-db9005e5da25fd6bf25fe1b68798d4d422b78847f153ea0075d00ae2c6aaa93e"></a>

- Hardened receipt-to-commitment alignment so duplicate commitment
  lane/epoch/sequence keys in the candidate bundle fail closed instead of
  silently selecting the first record during proposal filtering.


<a id="record-3eebac95e731d82867ec996c18342bfff2fe198635abe8d6a0cea9c5a5819011"></a>

- Hardened Torii DA manifest and PDP commitment readback by storage ticket so
  only production-shaped `manifest-*` and `pdp-commitment-*` filenames match,
  malformed ticket-containing names are ignored, and duplicate strict matches
  fail closed with `InvalidData` instead of returning an arbitrary directory
  entry.


<a id="record-adea1495ff388858c0f281a2aeb7932914bc93360fa0d78338bc549daa1e9f1b"></a>

- Hardened Torii DA PDP commitment readback further by decoding the matched
  Norito body and running PDP structural validation before returning bytes to
  SoraFS clients.


<a id="record-1585a5ec596756ce3eb28b53576dd4456bb5c5d1e5172d4879880c1430f53433"></a>

- Hardened Torii DA spool artifact writers so idempotent target-file collisions
  are accepted only when the existing bytes exactly match the expected
  manifest, PDP commitment, DA commitment, schedule entry, pin intent, or
  receipt payload. Mismatched pre-existing files now return `InvalidData`.


<a id="record-2f9cc1b57e94f4476399d8b3cd0639dfaa92a86dd9b44528a8bf143d0f9de727"></a>

- Hardened Torii DA spool artifact writers to reject mismatched self-describing
  bodies before writing: manifest bodies must match lane/epoch/ticket/fingerprint
  inputs, PDP commitments must pass structural validation, commitment and
  pin-intent bodies must match the filename tuple inputs, and commitment
  schedule PDP bytes must structurally validate and hash to the record proof
  digest.


<a id="record-90a8aaa63c42810678be1e36a4f2586cdddb07d0eceac28eeac8b46e037f61e7"></a>

- Switched Torii DA artifact installation from overwrite-capable `rename` to a
  no-clobber hard-link install path with existing-target byte validation,
  closing the race where a concurrent target file could be overwritten between
  the idempotence check and final install.


<a id="record-4ed26814db7ce1609714c010ed00c1ef80ac926273e54bf7a3fe41fc0b02b113"></a>

- Hardened DA shard cursor journal recovery so completed temp snapshots are
  promoted only when they monotonically advance the main cursor snapshot, while
  stale, corrupt, or mixed-direction temp files are removed without regressing
  any lane.


<a id="record-ba88b45190fd1e46603916211938bbc91311cbfa52e58c69bcd0832398b9e1e8"></a>

- Added adversarial coverage for primed-floor TTL pruning, stale/conflicting
  receipt-log outcomes, missing receipt-log output, spool action errors,
  filename/body tuple and ticket smuggling across receipt, commitment, and
  pin-intent loaders, malformed receipt/commitment/pin-intent and Torii
  readback filenames, duplicate manifest/PDP ticket readback matches,
  malformed Taikai anchor base ids, sequence-rebound receipt signatures, and
  rejected receipts not leaving extra durable receipt files.

## 2026-06-12 Torii DA selector consistency



<a id="record-a9c03ab48ee5c79e436d1cf82367679f21e025591f2f1b35e9738640461cf738"></a>

- Hardened Torii DA commitment list/proof lookup so a request carrying a
  `manifest_hash` plus lane/epoch/sequence selectors must describe the same
  committed record. Conflicting selectors now return no commitment instead of
  letting the manifest silently override the tuple.


<a id="record-1fd19c3f29982b0011a26b3312fe82d0c7faa2a6bef182c3d400aeedc95f22f4"></a>

- Targeted list requests with incomplete tuples no longer fall back to a full
  commitment listing, avoiding ambiguous query results for partial selectors.


<a id="record-454e16b3d772f4848577fb00efe317da783c2eee07348fa24e400db17fe8efe0"></a>

- Applied the same fail-closed selector matching to DA pin-intent list/prove
  lookups across storage ticket, alias, manifest, and lane/epoch/sequence
  selectors.


<a id="record-79c36153827f68c892bf22fab6775800dff991f37bc775b468b7eec5c5ade2cb"></a>

- Added Torii handler regressions for conflicting manifest/tuple proof requests,
  conflicting list selectors, partial tuple list requests, and pin-intent
  ticket/tuple conflicts.
