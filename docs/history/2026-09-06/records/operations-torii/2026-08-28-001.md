## 2026-08-28 Mochi first-release simplification and hardening



<a id="record-8afbbdece4236e3ef69f5ff120fd0138098a906d8b770f39101a9646fd211b1b"></a>

- Explicit binaries must be executable, signer-vault and bootstrap publication
  reject symbolic-link components observed during path validation, and
  secret-bearing custody fails closed on non-Unix hosts. Bootstrap/private JSON
  buffers are zeroized, unused secret-cloning APIs are gone, vault files are
  bounded and atomically owner-published, and session/bootstrap output no
  longer duplicates private keys. Vault, onboarding, and generated-genesis
  readers now share a no-follow, non-blocking Unix leaf opener and reject a
  symbolic-link or FIFO substituted after validation. GUI secret fields use a
  redacted, zeroizing `SecretString`, and tests keep their default data root in
  a retained temporary directory rather than the source tree. Generation/state
  persistence uses the single canonical Norito framing path. Generated VPN and
  test-fixture accounts are encoded for the manifest's declared chain
  discriminant, and the block and pipeline-event wire fixtures were refreshed
  through their registered owner.


<a id="record-12a4524d45d58f3b55b35fe70ab6ab123f303f27f877a6408e91ceccd089f38e"></a>

- Snapshot inventory hashing now uses a bounded, deterministic one-pass tree
  walk, and snapshot copy applies the same first-release depth, per-directory,
  and total-entry budgets. Oversized metadata, special files, symbolic links,
  raced source-file changes, and over-budget trees fail closed; partial copies
  are removed, and exact-budget empty directories remain valid. Storage is
  staged and rehashed before any live swap, while restarted peers must survive
  a bounded post-spawn grace check before the restore can commit.


<a id="record-4bb8f3377865be4c5ef3a3083e26ef29150367b098c5289a536f314b029efc74"></a>

- Restore swaps are journaled and directory-synced. Startup deterministically
  rolls back an uncommitted transaction or completes cleanup for a durable
  commit marker; an ambiguous marker publication preserves the installed state,
  journal, backups, and ownership lock for recovery instead of risking rollback
  of a committed restore. Readiness smoke uses one monotonic deadline across
  WebSocket setup, initial submission, and commit observation, and a timeout
  after a possibly sent submission reports an admission-unknown outcome for the
  exact signed envelope.

## 2026-08-28 ISO 20022 security remediation



<a id="record-299c0b2be8dfff8b9554c21744205dd4efd6f0abbb763afb7071ad30280ae1c5"></a>

- Codex Security scan `a53a5be3-6b38-4910-8691-83361d92dff3` (target
  `521ca5f0d287fab796e91de687b27443f4b058fb`) reported eight medium,
  high-confidence findings. Current code addresses seven local exploit paths
  across same-runtime admission, lifecycle authorization and ordering,

<a id="record-0b441dbeefbde8861b153c9e38618f440b6704d007ba1d411e398d4c5a51f012"></a>

  and queued-unsettled records from retention, and requires durable exact
  signed-transaction identity before queue dispatch. These controls do not
  establish network-wide economic idempotency.


<a id="record-0f29a4b78e47ccbd50cd63413f984b1eb122136e86c604a2537d9d07640e66b7"></a>

  the roadmap's consensus-owned claim committed atomically with the transfer;
  the hardening proposal documents that target but does not implement it.

- Hijiri's first-release production authority is on-chain: one bounded global
  `HijiriParametersV1` owns fee bands and default account risk, while bounded
  `HijiriAccountRiskV1` parameters attach governed risk to universal
  `AccountId`s. The neutral revision-1 bootstrap uses one unit-multiplier band,
  a unit penalty cap, zero default risk, and no predecessor. Kagami, Mochi, the
  test-network generator, and all seven checked-in genesis manifests seed that
  exact payload, so genesis makes the Hijiri binding explicit without silently
  enabling or changing the network's base validation-fee policy.
