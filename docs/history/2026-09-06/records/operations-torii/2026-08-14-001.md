## 2026-08-14 configuration, dataspace authority, and rollout hardening



<a id="record-2e5560679cc5886c1593b5a8f8349bb14ace51cb28e40597c7b80395224d01a9"></a>

- Configuration inheritance now rejects canonical-path `extends` cycles and
  chains deeper than 64 edges without recursive stack growth or depth-counter
  overflow. A deterministic 4,096-source expansion budget also rejects
  branching DAGs before repeated shared bases can grow exponentially. The
  boundary-depth chain and ordinary shared sibling bases remain valid.


<a id="record-f58c1305b9bfc3211de251d4dac199240947bf8539717bf2487b5c3700527a0f"></a>

- Static Nexus lanes now resolve manifest and live stake authority through
  their active physical dataspace. Policy-only lane manifests no longer mask a
  sibling cohort; conflicting manifest or lane-keyed stake projections fail
  closed; stale/retired lane statuses cannot inject authority; and catalog-aware
  validation keeps static dataspace pools separate from exact autoscale
  incarnation committees. Queue and block admission inherit only the shared
  validator bindings and quorum while retaining target-local hooks, protected
  namespaces, and privacy policy.


<a id="record-fb28cc9076bfaa7af90b93a26304486d22da60ad9bfa65aafe697e0162f60a79"></a>

- Autoscale creation now samples the prospective dataspace's static manifest or
  canonical live-stake pool before falling back to topology. Existing elastic
  manifests cannot seed or poison a later committee, and a loaded base manifest
  remains lane-local apart from the authority fields used for deterministic
  committee sampling.


<a id="record-b655b272d9b415b2b7f55e886f95600fa2eea44f7ad316f382582e15a67a5f5e"></a>

- Shared-dataspace staking now has one deterministic writable owner lane.
  Non-owner mutation, automatic activation, reward, and penalty paths fail
  closed; lifecycle and configuration changes cannot strand live stake by
  retiring, replacing, or reassigning that owner. Disabled Nexus keeps its
  exact `SINGLE`/`universal` ownership, and reward epochs remain monotonic across
  serviced lanes.


<a id="record-375165dacc6a4a8041cc452d3eaf19bc41e09d203ba2b34cebeb82920a8621b0"></a>

- The Taira rollout gate now compares every public/local status retry,
  post-canary recheck, and direct validator sample with the canonical effective
  numeric routing policy. Missing, reordered, malformed, or drifted live rules
  fail promotion even when the Sumeragi configuration fingerprint agrees.


<a id="record-f494716a9a6f5ce790a33a0ab0aee051c6d0740b786e095be87185447c5706c5"></a>

- Focused validation passed all eight configuration-inheritance regressions,
  catalog-aware manifest validation, queue and block authority-gating suites,
  same-dataspace authority/autoscale/staking regressions, all 46 rollout Python
  tests, and the complete rollout shell mock matrix. Scoped formatting, shell
  syntax, and diff checks also pass.

## 2026-08-14 Taira and Minamoto topology classification correction



<a id="record-95726d700f0060b648b97ee71df220eb765ebf077a7ca04c7380df5d3a94be99"></a>

- Corrected the deployment profiles so a dataspace denotes a physical
  validator/server and storage boundary, while a lane remains a logical
  workload stream inside that boundary. Namespace bindings remain an
  independent naming layer and do not create lanes or dataspaces.


<a id="record-d27573950d11fe7a8313f3bd732330ab6050a71ef962f2dec3d738bdaa5761b5"></a>

- Taira now declares seven logical lanes over five physical dataspaces:
  `core`, `governance`, and `zk` bind to `universal`; `dpn` binds to `dpn`;
  `external-poc` binds to `is`; `boi-mobile` binds to `is2`; and `cbsi` binds
  to `cbsi`. Minamoto and the shared Nexus defaults retain the three logical
  `core`/`governance`/`zk` lanes over the single disclosed `universal`
  physical dataspace.


<a id="record-d078d0efd51528d8f71048a6f878b0bfe6dedc328e58aa6d34d9cc2cd394c8b9"></a>

- Live inspection remained read-only. Taira's pre-correction public endpoint
  exposed the old four-lane mapping; Minamoto's public status endpoints timed
  out, so the Minamoto correction is grounded in its checked-in single-roster
  deployment profile and does not claim additional live topology.


<a id="record-dcce7cabae02fbf4020f1668775a8d0b0494956233e1b6a4dd8ccf3c29c3cb20"></a>

- Corrected the Taira storage budget from the parser-invalid
  `7500/2000/0/250/250` split to `7499/2000/1/250/250`. SoraFS remains disabled;
  the one-basis-point reserve keeps its derived cap bounded instead of invoking
  the forbidden zero/unlimited interpretation. Reset manifests and admission
  tests now bind the same exact vector.


<a id="record-984947fbfc6edd3ee22c9a1c26450281ed09c4abd5220f4c7b638df1b839593c"></a>

- Focused validation passed: four `iroha_config` profile/admission regressions;
  three xtask generator/topology regressions; the unsigned-template Nexus/AMX
  projection check; topology-profile fingerprint checks; and the Taira production
  signing projection. Python suites passed 63 renderer, 132 reset-controller, 21
  empty-reset-bundle, and 90 rollout/operator-guidance tests. The complete 68-case
  rollout shell matrix passed immediately before the final roster-shape correction,

  Taira/Minamoto checks prevent those baselines from masking this correction.

- MCP catalog projection publishes closed, bounded canonical and operator
  authentication envelopes and checks that invariant at registry construction.
  Runtime forwarding performs the same borrowed wire preflight before copying
  proof values or constructing ISO 20022 bodies. JSON-RPC dispatch moves the
  decoded request object, borrows per-call argument maps, and fallibly reserves
  batch result slots so authentication material is not deep-cloned before
  admission. The inner route remains the sole freshness, replay, and
  cryptographic authority. The VPN settlement
  helper is pinned to the exact-network `POST /v1/vpn/receipts` transcript,
  reads its seed only from a bounded direct runtime file, disables curl
  configuration/redirect/retry behavior, and emits bounded canonical JSON.
