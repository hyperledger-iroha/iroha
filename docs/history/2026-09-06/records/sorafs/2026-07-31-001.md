## 2026-07-31 SoraFS moderation strict-ingress preflight hard cut



<a id="record-ae07e41c12e06623dcbaf563caa80ec70e0c2072d75bb5abaa6c233202d5857f"></a>

- Torii now publishes one stable V1 strict-ingress handle, revision, and
  public-policy digest together with a credential-free exact-binding
  qualification API. The live in-process adapter continues to use the same
  binding and to revalidate it around submission and lookup.


<a id="record-a58e336aaec1cb1f814805c38695481234f8633a291a2bc6b76dbdcea020288b"></a>

- The common sanitized `irohad` runtime-provider catalog projection qualifies
  enabled moderation configuration against that fixed binding before the stock
  broker client or an injected registry is invoked. Standard startup already
  runs this projection before Tokio and node-owned durable state, so missing,
  substituted, stale, zero-qualified, and test-marked ingress metadata now fail
  closed in the common launcher preflight rather than during later Torii state
  construction. The built-in ingress is not misrepresented as an external
  broker dependency and no credential or private key enters configuration.


<a id="record-eb9d99a6051c06eaf734bc99f49ea145e6c7a71dad9bfa2200e0732fd3c95063"></a>

- Focused Torii exact-binding and daemon catalog/startup-order tests cover the
  accepted binding and all fail-closed classes. Cargo execution remains pending
  the coordinated build lane. This closes only the local strict-ingress
  preflight gap; genuine external moderation signer, settlement, publication,
  notification, signed archive/transparency, multi-replica recovery, and
  four-validator promotion evidence remain open.
