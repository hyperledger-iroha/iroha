## 2026-08-10 SoraFS inventory and legacy-fetch authentication hard cut



<a id="record-bfc04d043dda24093b027d8a0c061df71f62b2d89dd0d391a6f3e35e7677098d"></a>

- Legacy alias and replication projections now require canonical account
  signatures before their whole-inventory materialization; local storage state
  and the JSON range-fetch diagnostic require exact-network operator
  signatures, with fetch authentication ahead of body decoding. CAR and chunk
  reads are catalogued as authenticated protocol-handshake routes backed by
  their existing request-bound stream-token checks.


<a id="record-7ba5d0650e47305cad1678578f829ae5dd0af9430c8dc606b304bf005af1a181"></a>

- The Rust and JavaScript SDK inventory callers sign the exact filtered GET.
  JavaScript storage diagnostics require an immutable
  `OperatorSigningContext`. The two internal cache-miss hydrators no longer
  send unsigned legacy payload POSTs: local-cache reads remain, while remote
  misses return an explicit stream-capability-required error.


<a id="record-17d64939bf91f2eb2738021349decb69648f4c9c7f85a084dc927fe11d070dcb"></a>

- Catalog, OpenAPI, mount, SDK, and remote-hydration regressions cover the new
  boundaries. Validation is limited to direct formatting, JavaScript tests,
  and scoped static checks; no Cargo/rustc command, generated OpenAPI snapshot,
  `Cargo.lock`, MKHE source, or source-budget file was changed.
