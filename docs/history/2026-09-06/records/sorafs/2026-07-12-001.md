## 2026-07-12 SoraFS moderation/PoP lifecycle hardening



<a id="record-47ae8bcaf588899cbeb6caeddea85cc4e927de47c68355902dbcea07ce00862a"></a>

- Made moderation identifiers use one bounded canonical-ASCII grammar and
  aligned native moderation/PoP governance authorization with the default
  executor's genesis policy while still requiring registered issuer and
  challenger accounts. Panel sortition now freezes an explicitly supplied
  latest committed parent hash only after registration closes, rejects zero or
  stale anchors and an appellant finalizer even when that account also holds
  management permission, and persists the anchor in the selection record.


<a id="record-b24c3b5c58397c4ac70ba00be24b2de43913e17050a781178e30d132934fa4e9"></a>

- Admitted appeals now revalidate their exact historical signed PoP root,
  revocation list, issuer-policy digest, and audit link, so ordinary later
  registry rotations cannot rewrite or strand them. The emergency paused state
  continues to freeze pending use deliberately. Moderation cases retain a
  bounded canonical challenge index; unresolved challenges expire atomically
  after reveal close into a fail-safe challenged outcome without no-show
  penalties, and late/manual expiry or late accepted/rejected resolutions fail
  closed.


<a id="record-77768136e5437d98f45dda17da693c334b32068db30e11c3230cf41996067f6e"></a>

- Focused validation passed for all seven moderation-ledger data-model tests,
  all 22 moderation-panel/commit-reveal/PoP rollout-contract tests, the
  no-legacy-codec guard, targeted Rustfmt checks, and `git diff --check`. The
  follow-on slice-decode test and Core test binary were blocked before reaching
  this code by unrelated current-tree `PartialOrd`/`Ord` derive failures for
  `LaneBlockProposalV1` and `LaneBlockCommitment` in
  `iroha_data_model::block::consensus`.
