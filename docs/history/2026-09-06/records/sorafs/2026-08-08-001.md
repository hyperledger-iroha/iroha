## 2026-08-08 SoraFS paid-pin lifecycle and finalized-page documentation hard cut



<a id="record-1c10cc4fa1fb5dba67f24bebef319e8bd74520085a8a0076b22deacd4fa6ac05"></a>

- Reconciled the source-coupled SoraFS pin specifications and operator/CLI
  examples with the native first-release wire: registration is a paid public
  operation for an authenticated transaction account, not a general
  permission-token gate, and Torii accepts one exact-network signed transaction
  containing one `RegisterPinManifest`.


<a id="record-6b3ca59c53dab54b640f08d8cde1522c7dd54d96726781ce66facf36adc36e2b"></a>

- `RegisterPinManifest`, `ApprovePinManifest`, and `RetirePinManifest` no longer
  carry caller-selected event epochs. Core derives submission, approval, and
  retirement evidence from block consensus time. The manifest still commits
  its prepaid `retention_epoch`; Core requires it to be later than submission
  and processes the authenticated expiry index at consensus time.


<a id="record-0e3ccdd1d34dd23b9446b5f4e005bb7a14cadbb9a731a22b94192a9c709f59d8"></a>

- Documented the transactional global/per-account retained-record counts and
  live-content byte charges, lineage depth/fanout ceilings, expiry and
  lifecycle-status indexes, and fee collection. Manual or automatic retirement
  releases only the live-content byte charge; retained counts and successor
  fanout remain charged while their lifecycle evidence remains in consensus
  state, so register/retire cycles cannot grow durable state outside the
  configured ceilings.


<a id="record-7f3d843cfa57d6a371d223e7700a583b84b4fb43566498eecf3d5cc2459f6d9e"></a>

- Documented `PinManifestPageV1` as the only pin-list response: bounded summaries
  at one finalized height/hash, `1..=256` rows, `1024..=262144` encoded bytes,
  a non-zero exclusive digest continuation key when more rows remain, and O(1)
  consensus-maintained `charged_usage`. Offset/full-registry materialization is
  not a pin-list compatibility path; fields omitted from summaries use the
  bounded exact `PinManifestFinalizedRecordV1` route.


<a id="record-f7ccc6e3f88bd0e9e4538ad71b08a311be17ded7bcb800bd314a21e9ec11f681"></a>

- The background Prometheus registry projection now reads the same maintained
  O(1) global retained-record/live-content summary; scan-derived inventory
  gauges are retired. Finalized `charged_usage` remains the authoritative
  resource-accounting view.
