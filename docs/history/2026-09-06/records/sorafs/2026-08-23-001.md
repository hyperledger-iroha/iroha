## 2026-08-23 SoraFS bug audit



<a id="record-dd936b76950ebc240bb95cf6b7d2e65639d64179b0172b713eb0e31660973a96"></a>

- Streaming and batch chunking now use the same first eligible break boundary,
  and streaming CAR creation requires the exact planned payload digest and EOF
  instead of accepting a substituted identity or trailing bytes.


<a id="record-776dcfa61d6052d5b98bcbabd3a3c294b86b5ba3664a9ed3f56afe6e7367d0d9"></a>

- Multi-source fetches now terminate with a typed policy-eligibility error when
  every compatible provider is denied, rather than spinning with no in-flight
  work. The reason is carried through the orchestrator, fetch CLI, JavaScript
  and Python bindings, TypeScript declarations, and observability contract.


<a id="record-9eebc0e558c3574b44b5856149bc56ee6f94dfb1f8cfcdded4c69b9875d4d688"></a>

- Capacity telemetry widens arithmetic before scaling or narrowing, dispute
  resolution stages registry and ledger mutations atomically, and SoraFS CLI
  `usize` flags now enforce canonical unsigned-decimal syntax.


<a id="record-72dfd2a4dda9b6d96f6034abca2af66b4a7556c2f0eec141344c65ab7339149b"></a>

- Validation passed all 286 `sorafs_car` library tests, all 13 chunker tests,
  all 10 node telemetry tests plus the focused node library check, focused
  treasury/CLI/orchestrator/Python regressions, TypeScript declaration checking,
  targeted Rust formatting, and whitespace checks. The JavaScript-host
  regression rebuild is currently blocked by unrelated concurrent
  `iroha_config` compile errors in the shared worktree.
