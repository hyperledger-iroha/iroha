## 2026-07-23 SoraFS V1 closure audit and release hardening



<a id="record-03d48037bb1f58e787206dffa167eed223d6d0b81d368227e53c6ab1ef42b3a6"></a>

- Reconciled the current authority boundary after the protocol-local audit.
  Authenticated PDP challenge, next-work, proof-submission, status, and
  terminal-export routes are present, and PoR/PoTR plus repair protocol
  surfaces have substantial local coverage. They are not production-complete
  or evidence-only lanes: native repair task, lease, terminal outcome, slash,
  appeal, typed event, and finalized query state now exist, and proof failures
  can use the durable exact-chain native transaction forwarder. SF-8b, SF-9,
  SF-13, and SF-14 remain open until the residual production
  `RepairManager`/filesystem checkpoint and GC/publication reconciliation
  dependencies are removed and four peers prove one terminal repair outcome
  across duplicate submission and restart.


<a id="record-c051d78f5e59c9b02389c516405ba841a141060b95561781131c168298ed649b"></a>

- Added
  `specs/sorafs/v1_closure_ledger.md` as the canonical first-release
  mapping from shared contract, nine foundational prerequisites, and all 17
  readiness lanes to implementation, validation, authority-removal, and
  rollout evidence. The checked production aggregate remains honestly blocked:
  it recognizes 0 of 17 summaries, has no foundational envelope, and reports
  all 19 missing-input errors. No production readiness evidence, key, or
  synthetic envelope was created.


<a id="record-f3340f84928f9a70ad74147af5240370ebf6a744bb7c1ed5cf8f2faf7a8ba393"></a>

- Corrected the release baseline to require the existing exact
  `blake3==1.0.9` automation pin. The readiness runner now requires one positive
  explicit `--now-unix` value and carries it byte-for-byte into its dry-run
  plan and aggregate invocation, preventing clock drift between review and
  execution.


<a id="record-edd5855b195261ea6d462459fecb133671fde4330c8018e6451fb7cd3117f874"></a>

- Added the private-key-free two-phase foundational-envelope builder. It emits
  exact domain-separated bytes for an external Ed25519 signer, verifies the raw
  detached signature and trusted public key before publication, requires the
  exact ordered nine prerequisite IDs, and uses new-only atomic outputs. A
  sequence after 1 must supply the exact immediately preceding signed envelope;
  its digest, deployment, signer, sequence, deterministic encoding, and earlier
  timestamp are revalidated. Input files, response files, and output parents
  are pinned through no-follow directory descriptors, with hardlink,
  writable-file, parent-replacement, changed-during-read, and failed-fsync
  negatives.


<a id="record-edfd49fe50613bc7f7cb0504e2c61ed3fe56626964faaa173f710a95c4a93461"></a>

- Hardened the reference release packager to Ed25519-only signing. Production
  packaging accepts an externally produced raw signature; local PEM
  signing is explicitly development-only. Signing inputs are owner-safe pinned
  snapshots, the reviewed public-key fingerprint and keypair must match, raw
  signatures are verified before and after an exclusive no-clobber install,
  generated-path collisions and stale signatures fail closed, and RSA,
  symlink, hardlink, permission, substitution, and pathname-swap cases are
  covered.


<a id="record-0fefc6ddf7cf97573180df3e444fcbfa4734b94f8a09a9445113bd8fd6341bf7"></a>

- Retired the pre-release `ManualPorChallengeV1` format, routes, errors, tests,
  and documentation instead of retaining a compatibility branch. Updated the
  PoR puzzle parser, exact foundational inventories, release static contracts,
  and localized plan metadata without claiming unreviewed translations are
  current.


<a id="record-023331dc756a5c1a20689a98bcd158e88e499085acfb0ecb300e9cc0994302b4"></a>

- Closed the reviewed Governance DAG contract defects: every CID is exactly 32
  bytes, node CIDs are recomputed canonically, peer IDs are bounded, duplicate
  nodes/blocks and noncanonical order fail, and nodes, blocks, and heads use
  one Ed25519 publisher identity. Head time is bound to the tip. Full histories
  and exact newest-64 checkpoint tails share one validator; the filesystem
  publisher retains full history and separately binds source payload and
  signed-block digests. The 1,040-byte settlement payload now uses transparent
  heap indirection inside the governance payload enum, eliminating the
  large-enum stack footprint without changing Norito fixture bytes. Swift,
  Kotlin/JVM, mirrored Java Android, C#, JNI, and C wrappers enforce the same
  CID and native-symbol boundary. Repeated complete fixture generations were
  byte-identical; the golden head outcome SHA-256 is
  `c93232569f5b37e9de217e1073c0c46db2c86bc6bf61d53fa848b7a25dc170aa`.


<a id="record-b70eb12bd26bc11d43d806267b12fc43dd33829d32bcf4ab6e431a70df99cba5"></a>

- Focused validation is green for the 34 Governance DAG core cases, six CLI
  cases, strict `sorafs_manifest` Clippy with warnings denied, the
  FFI/parser/fixture negatives, both header guards (ABI 21, 23
  reference symbols and 55 constants), the Swift focused suite (four native
  cases skipped against the installed ABI-19 bridge), isolated Java, 36
  foundational-builder tests, 38 shared response-file tests, 37 release
