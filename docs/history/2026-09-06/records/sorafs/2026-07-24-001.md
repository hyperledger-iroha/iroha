## 2026-07-24 SoraFS reserve, PoR, and forwarding hardening



<a id="record-8cd9e0b2e396635ded8e2792403528360b088a3083e145c9bdafdb6b7778dbb6"></a>

- Made reserve policy activation and its journal head one atomic authoritative
  state record. First activation now requires an empty reserve namespace, so a
  partially initialized ledger cannot become active.


<a id="record-4032553fa439ff8845b06f236d72328552800dd21bab88cf89b63e0201ac36a1"></a>

- Replaced flat PoR chunk-root witnesses with bounded logarithmic Merkle paths
  across Rust, Torii/OpenAPI, JavaScript, and Swift surfaces. Proofs now cover
  every manifest admitted by the CAR chunk-count limit without a 2,048-chunk
  parser ceiling.


<a id="record-280382dd98f30ad48e82c4b38332d745f1cb9861cda65986bfda7c440bdc69e0"></a>

- Proof-outcome forwarding now restores definitely rejected local submissions
  to `Signed`, preserves `Ambiguous` only for indeterminate outcomes, and scans
  the durable outbox through a circular sequence cursor so deferred providers
  cannot starve later entries.


<a id="record-de50aa1839a8cdfc152a41e93dbbdf4fe5abb4570d0c18d2151dda77cd728fe5"></a>

- The Norito XCFramework builder now uses a process-held advisory file lock and
  no longer depends on process-table inspection.
