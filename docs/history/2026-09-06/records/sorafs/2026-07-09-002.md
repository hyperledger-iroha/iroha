## 2026-07-09 SoraFS capacity tx-stdin input hardening



<a id="record-1766f9f29a13220c9a0fd97c97eb5cc46d4f30736c6261077aefec214a53bb98"></a>

- Hardened `sorafs_tx_stdin_builder` so request/epoch/order-id flags are
  single-assignment; duplicate flags now fail before any ledger transaction
  stdin JSON is emitted.


<a id="record-38a6ee4b87e33e0a1bc5ae5a488e0822b61646385e8161fc8a72aff39c64efa9"></a>

- Hardened replication-order and completion epoch CLI parsing to require
  canonical unsigned decimal tokens, rejecting padded, plus-prefixed,
  whitespace-bearing, and overflowed values.


<a id="record-ecbe0c65b86aa85369532bd0b7efd03052db7bf527f1673863b15ea22986a598"></a>

- Hardened `complete-order --order-id-hex` to require lowercase fixed-width
  32-byte hex without prefixes or whitespace, and to reject all-zero order ids
  in line with SoraFS replication-order validation.


<a id="record-da92d189aa85e66ccdce530fed6f235e3e651909c570a193f544416dda454cba"></a>

- Added unit and binary-level negative coverage for noncanonical epochs,
  malformed/uppercase/prefixed/all-zero order ids, and duplicate options.

## 2026-07-09 SoraFS fetch CLI numeric and telemetry hardening



<a id="record-2006848a3fc3c9d760707e7fffe8ea6b13268f7d2799e1e9866319cd06055573"></a>

- Hardened `sorafs_fetch` provider specs so `#concurrency` and `@weight`
  fields must be canonical unsigned decimal tokens. Explicit zero concurrency
  now fails closed instead of silently falling back to the default provider
  concurrency.


<a id="record-b27248ab27d3486f38c76d07a25117447409711abcab594f7c6affccc0004dfd"></a>

- Hardened shared fetch limit flags, expected payload length, review-clock
  inputs, and boost-provider deltas so padded, signed/unsigned drift,
  whitespace-padded, zero-where-nonzero, duplicate, empty-name, and overflowed
  values fail before scheduling starts.


<a id="record-ec8bf6c5b76e2337068f7e6ba30d4295e0970f4eb0d2a5b2e0a86c44e3764d03"></a>

- Hardened telemetry JSON ingestion so string-valued unsigned fields must be
  canonical decimals, and string-valued score metrics reject `NaN`/infinite
  values before they can influence scoreboard provider selection.


<a id="record-afd75f47376df59a7c896ebf17d92b83b6a630c34740b754cedb32be08c8409d"></a>

- Removed a non-streamed payload length `unwrap()` from the assembled-output
  path so the length is captured directly from the verified payload buffer.


<a id="record-ef570913502832b66f64309717deb5138854c1ad745b4bae28c362278b8a193a"></a>

- Added adversarial parser coverage for zero, padded, signed, whitespace, and
  overflow inputs across provider concurrency, provider weight, shared
  fetch-limit flags, review-clock/expected-length flags, boost deltas, and
  telemetry JSON fields.
