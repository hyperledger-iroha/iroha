## 2026-07-05 SoraFS assignment-style secret sensitivity gate



<a id="record-088e695670638180bdae839032c03a9514cc77bbf390d959762751eff7a9fd16"></a>

- Extended the shared SoraFS evidence sensitivity scanner so neutral scalar
  strings such as `authorization=Bearer ...`, `Authorization: Bearer ...`, and
  encoded `auth-token=...` assignments fail closed even when the surrounding
  JSON key is not itself sensitive. Fully percent-encoded URI-like strings now
  also re-enter the URL secret scan after decoding, so encoded userinfo or
  query token endpoints cannot hide inside neutral scalar fields across
  HTTP(S), WebSocket, database-style, file, and other URI schemes. Scalar
  value scans also inspect Unicode-format-control-free aliases after decoding,
  so zero-width-hidden bearer prefixes or URI schemes fail closed. Multiline
  copied header/transcript strings are now scanned line-by-line after decoding,
  and folded secret header continuations such as `Authorization:\n ...` or
  `Set-Cookie:\n ...` fail closed even when earlier non-sensitive headers
  contain colons.


<a id="record-46b95f909f3bbfa862b1562923283172b1ab71dcd247d72100f314237d0b04e4"></a>

- Kept payload-free reference assignments such as `private_key_absent=true` and
  `request_body_digest=<hex>` plus encoded digest-reference URLs admissible
  through the existing suffix allowlist, including encoded IPFS digest-reference
  URIs plus multiline and folded digest metadata, while continuing to redact
  assignment names, URL contents, copied transcript contents, and values from
  diagnostics.
