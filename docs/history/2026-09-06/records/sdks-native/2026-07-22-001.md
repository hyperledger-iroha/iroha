## 2026-07-22 Cross-SDK and input-boundary bug-hunt repairs



<a id="record-7a21b7848fc10ca8296782909d0b7b87e8eba0987f8406bddf4fc6003aa2436b"></a>

- Restored `iroha_torii_shared` compilation after the recipient payment-request
  fields became private: lineage and receive-offer verification now use the
  public `chain_id()` accessor. The crate's 102 library tests pass. Its Android
  approve frame now carries a valid deterministic Ed25519 controller, and the
  focused fixture test proves exact decode/re-encode equality and strict account
  parsing.


<a id="record-0e679ebb8b281bdb046722c4c3c44c65bd8f14f5d343798ede1fd9209de71115"></a>

- Kotlin and mirrored Java transaction payloads now carry the complete
  nonzero-`u32` nonce range in a `Long` instead of narrowing through signed
  `Int`/`Integer`. Norito decode no longer rejects valid values above
  `i32::MAX`, forwarding APIs and fixture readers preserve the widened value,
  and the Java builders keep convenience overloads for signed-int callers.
  Focused Kotlin and Java max-`u32` roundtrip/range tests pass, as does Android
  Java test-source compilation; Swift already used `UInt32` and required no
  change.


<a id="record-42c5ad8fabd608e782132b87f1547941b91a515c4390a795f50dd9310d9de086"></a>

- Closed the same nonce boundary in fixture tooling: the Rust exporter now
  rejects top-level nonce hints above `u32::MAX` instead of wrapping them, and
  the Android fixture checker accepts only `null` or `1..=u32::MAX` (excluding
  Python booleans). The exporter overflow regression and all 30 Android checker
  boundary/manifest tests pass.


<a id="record-b8cf9ec0b5698d52111242e4ff8ab03692cbaeacf8f0f819800e2ca89b4bc85f"></a>

- Brought Kotlin and mirrored Java Ed25519 admission up to Rust/JavaScript's
  fail-closed rule with Bouncy Castle's full prime-subgroup validation. Public
  multihash and compact encoders/decoders, canonical and I105 addresses,
  multisig signatures and policies, Nexus signing, identifier/RAM-LFE policy
  parsing, and receipt verification now reject malformed, small-order,
  noncanonical, undecompressible, and mixed-torsion points. Literal parsing also
  matches Rust by rejecting normalization, unknown or case-variant prefixes,
  algorithm-prefix mismatches, and repeated prefixes. A shared adversarial
  vector set exercises the mirrored routes under the Kotlin JDK 8 guard; focused
  Kotlin/Java admission tests, Android/JVM test compilation, and the Rust shared
  receipt vector test pass. The JavaScript public encoder now applies the same
  strict rule.


<a id="record-ca55d7aefccfcc276f67d643b07ee8c9c67cddc4f9f6883b874af500341eb6fe"></a>

- Repaired the documented iOS demo launcher's two malformed Python
  here-documents, three-value state parsing, and missing option-value handling.
  Removed Bash-4-only maps and array readers from the XCFramework, Swift
  fixture, Android SBOM, full-workspace, and incentive-snapshot entry points;
  the XCFramework telemetry handoff now carries real multi-lane rows over a
  separate file descriptor. SBOM collection derives the module root from the
  complete `build/reports/bom` suffix, so identically named Gradle reports no
  longer overwrite one another. The combined shell/tooling regression set
  passes 55 tests plus five subtests on the stock macOS Bash path.


<a id="record-66436f470af5ede2ac08f7a2db4e370c53bb88ef5d03be1a792c1583aaee9ff7"></a>

- Fixed the docs-monitor proxy contract: configuration now stores an origin
  `/v1/...` sample path and the probe adds `/proxy` exactly once. The monitor,
  proxy-probe, localized-doc synchronization, and portal checks pass.


<a id="record-4f83f6db11ecd62738cf98818a4d0795e98536c5e323e6ae4e4143a429ec839d"></a>

- Continued the fail-closed cleanup after strict subgroup validation exposed a
  widely copied mixed-torsion I105 literal. Runtime scripts now pair the default
  Alice authority with its actual key, and high-priority monitoring, SoraNet,
  Mochi, oracle, BFV, transaction, validation-fee, and identifier-receipt
  fixtures use canonical positive-vector accounts. Oracle observation hashes
  are regenerated through the typed model and a new invariant binds both the
  report and feed event to the observation. The signed identifier receipt's
  payload digest, Iroha prehash, signature, and attestation digest were
  regenerated together. Larger generated/binary corpora remain queued for
  coordinated regeneration rather than unsafe text replacement.


<a id="record-07e8fa15fd9a7c3643aa7b40b4bbfb0d141446f51f8aa93c2fbb333a628b9412"></a>

- Repaired the standalone codec-sample generator for the current universal
  account/domain model and SoraFS logo URI. Its isolated two-test suite passes
  with the repository's vendored Halo2 patches; the ignored local helper lock
  was left untouched, as required.


<a id="record-f3750cc00e8070d628b425db771cf280975b87d4776f9856ade061bce0118dd2"></a>

- Made recipient payment-request expiry exclusive at the exact millisecond,
  matching Torii's fail-closed lifetime convention and the native bridge's
  adversarial receive-offer contract. Direct data-model boundary coverage now
  rejects both request validation and a valid re-signed acknowledgement at
  `expires_at_ms` while accepting the millisecond immediately before it.


<a id="record-de1a90e43c65f91a51ab14226d7a221e9c54057ea46694880b880ec3713805f2"></a>

- Closed six more lossy external-input conversions. Executor JSON byte arrays,
  IVM `OrderByTime.tif`, SoraFS proof latency/deadline/index fields, persisted
  webhook retry counts, Java/JNI signing-algorithm and ZK-mode codes, and SoraFS
  provider transport priorities now use checked narrowing instead of modulo
  casts. Overflowing values fail closed rather than becoming valid zero/small
  values; `u32::MAX`/`u8::MAX` boundaries have focused regression coverage.


<a id="record-55968f5fc1aed8d41f6500f0ebb82dc3da0e087bb5582ead11c73093be3010a2"></a>

- Closed four additional malformed-input paths. Kotlin and Java pricing
  schedules now reject values outside the signed 32-bit range before assigning
  credit and discount fields; their SoraFS gateway summaries reject negative
  counts emitted by unsigned Rust fields. Future-poll telemetry conversion now
  returns its declared error for negative or fractional identifiers/durations
  instead of panicking, and iterable query JSON rejects present-but-invalid
  pagination, projection, lane, and dataspace parameters instead of silently
  dropping a requested bound while preserving the documented `null`-as-absent
  form. Mirrored SDK boundary tests pass, including the JDK 8 guard, and Rust
  regressions cover both owned and borrowed telemetry plus absent, null, and
  malformed query parameters.



<a id="record-5d3bd7d9c15ce35755a05caf9b2631a737c6de2e3828a6ebe29f74b46f6ed5fa"></a>

- Tightened Swift's remaining numeric and structural boundaries. Android
  provisioned-proof manifest versions now require an exact `UInt32` and report
  the field that actually failed; Torii list pages reject totals below the
  returned item count and distinguish omitted totals from explicit `null`;
  JSON, Connect, and runtime-upgrade integers use exact conversions instead of
  rounded floating-point guards; and retry sleeps saturate safely rather than
  overflowing nanoseconds. Focused suites cover `UInt32`/`UInt64` edges,
  JavaScript-style rounded doubles, unsigned `NSNumber`, list invariants, coding
  paths, and timer saturation. The focused suite passes all 13 selected tests.


<a id="record-180b1fbbc32dd8e4fb605412963a1189752da317d8403194f6cd3c2dd9a2570c"></a>

- A further Swift sweep made acceleration JSON/TOML, compute manifests, Connect
  balance/control payloads, multisig clocks, Nearby timeouts, and SCCP numeric/
  hash text fail closed. In particular, `enable_simd` is no longer mistaken for
  an absent acceleration section, malformed payload-hash fields cannot bypass
  simulator verification, clock/time multiplication saturates, and Unicode or
  empty numerals are not canonical decimal/hex input. Seven affected test
  suites compile and link, and every touched file passes a direct Swift parser
  check. The selected xctest runner later ended with status 143 before emitting
  test results while other SwiftPM helpers continued holding the shared build.


<a id="record-0287159ce51f207bd51438ee010d1083b0d32f889886194e5a2f234a9bcc87f6"></a>

  longer accept values which truncate to a valid byte, Norito collection
  lengths above `Int.MAX_VALUE` fail before allocation, remaining gateway/VPN/
  multisig public-key routes enforce strict Ed25519 subgroup admission, and
  identifier/RAM-LFE policy summaries validate and retain the output-opening
  key while preserving omission compatibility and rejecting explicit malformed
  values. Focused Kotlin tests pass under the JDK 8 API guard and the mirrored
  Java harnesses pass.


<a id="record-41da6a5d6bdef0e47dc4b35647192aaccf26df1799db274014f482cef490abdb"></a>

- Mirrored Kotlin/Java subscription, UAID, and contract-response parsers now
  reject negative values emitted for Rust unsigned totals, epochs, timestamps,
  and gas fields. Java numeric extraction is exact instead of wrapping oversized
  integers, and UAID parsing no longer coerces malformed strings or silently
  drops null/wrong-type account entries. Thirteen focused Kotlin tests pass
  under the JDK 8 guard and three Java harnesses pass.


<a id="record-119b88fe2ba808b43c5ca9c50ff84e56d475040b779ebc43258cc2feb886b11c"></a>

- Removed the remaining mirrored JVM parser coercions. Subscription identifiers;
  contract booleans, text, hashes, and base64; identifier/RAM-LFE/Soracloud
  required and optional strings; and identifier/RAM-LFE required booleans now
  reject missing or wrong-type JSON instead of stringifying values or silently
  becoming `false`. Client-config manifests likewise reject malformed-present
  strings, headers, integer/boolean scalars, negative timeouts/delays, invalid
  retry counts, and empty gateway URIs instead of ignoring them, while retaining
  documented integer-string and boolean-string compatibility. All focused
  Kotlin suites pass with the JDK 8 API guard, and the mirrored Java harnesses
  pass.


<a id="record-53abce8bc88cdf3d9c4759e81fadaca2302e3bd09ad7f83a97633dd14d6c3944"></a>

- Removed the unauthoritative caller-seeded DA sampling-plan surface end to
  end. Manifest retrieval no longer accepts a block hash or returns/persists a
  sampling plan in Torii, the Rust client/CLI, Swift, or JavaScript; explicit
  local PoR inputs remain retrievability diagnostics and are not availability
  evidence for rewards, slashing, or consensus. SoraFS fetch plans also reject
  malformed digest/length leaves and non-object manifests before network work,
  and both orchestrator configuration parsers reject invalid validator-lane,
  RTT, and ASN values instead of dropping or narrowing them.


<a id="record-b39e11f1ddc8d1d496d0d6ad1e098b93f841053b4d455d1932a9694fc9182208"></a>

- Bounded physical DA ingest computation with the production
  `torii.da_ingest.max_concurrent_compute_jobs` setting (default `1`).
  Signature verification, normalization, chunking, RS16 generation, manifest
  construction, and PDP construction now run through `spawn_blocking`; each
  owned semaphore permit stays in its physical worker, so cancelling a request
  cannot release capacity while detached CPU work continues. The existing
  128 MiB generated-parity and transient-workspace limits remain enforced per
  request.


<a id="record-7fa8029b52a489d4d5db51e34090d02f23f55a27d1b62b2324a43fb302c62e5f"></a>

  N-API host's alias, SoraFS, transaction, Kaigi, replication, and time-trigger
  inputs. Values at 2^53−1 remain accepted and 2^53 is rejected before lossy

  Its broader 17-test filter also exposed an invalid two-byte default alias
  manifest CID; fixtures now generate the canonical first-release CIDv1 by
  default, with direct regression coverage.


<a id="record-44ac748dffeda5c314d6a42c74160f1247550ed2a09fb0b8c991297a581ddad6"></a>

  diagnostics, sessions, Nexus, Torii, instruction builders, browser Connect,

  rejecting coercible plain-array entries. Stale Torii tests now supply required

  instruction-builder (163) tests pass; the full Torii test file, smaller
