## 2026-07-20 Mixed native-ISI and contract-call batches



<a id="record-eea30877aae8ea117efaa8a947d6a0492caf82b8d7924e798b71533a2d208008"></a>

- Added the append-only `Executable::Batch` wire form under
  `DATA_MODEL_VERSION = 3`, with executable tag `4` and item tags `0` for a
  native ISI and `1` for a deployed `ContractCall`. Legacy executable tags and
  instruction-only canonical bytes remain unchanged. Admission rejects empty
  batches, and builders preserve the signed item order.


<a id="record-3223a756a0b6775bd05747efdceb75fdd14fcfa607fbdabeb106c10b49942704"></a>

- Core executes each mixed batch against one transaction view behind a global
  live-state scheduler barrier. Earlier native changes are visible to later
  contract calls and vice versa; any item failure rolls back the complete
  batch. One signature-bound gas limit covers explicit ISIs and calls, and the
  transaction fee settles once. Trigger actions support the same ordered,
  atomic form with one shared deterministic trigger gas budget.


<a id="record-854bea9ffea7b15679f5fc87db9da098485e7351bb23041a3233738cb3d08813"></a>

- Follow-up validation passes all six focused Core regressions,
  `cargo check -p iroha_core --lib`, scoped Rust formatting and diff checks, 19
  focused Java tests plus eight Java harness mains, the browser-JavaScript build,
  lint, and 3/3 focused tests, the C# test-project build, and Swift parser and
  type-check checks. Kotlin execution remains blocked by the unrelated dirty-tree
  private `requireExactText` access in `AccountAliasResolution.kt`; Swift package
  execution requires the missing `dist/NoritoBridge.xcframework`, and C# runtime
