## 2026-09-03 Android Debug native packaging



<a id="record-a681ff0cd82d01caf195374702fe8e846457c3fd330e8bc48da2aede7d55dec9"></a>

- `irohaDebugNativeBridge=true` opts actual Debug device builds into the same
  sealed native build, stripping and provenance used by Release. Ordinary JVM
  tests remain native-free; Release always includes the bridge. Invalid property
  values fail configuration. This build option does not change proving features
  or qualify a device provider.

  pass. Native ABI compilation and device JNI execution remain separate acceptance
  work; a task graph does not demonstrate either.

## 2026-09-03 Explicit local dirty-source Swift pin projection



<a id="record-cd394f4278051f991e6f67b66aaf48d80e39baf51e9afd3f44b12cb6d50fe772"></a>

- The Swift fallback-pin owner now accepts an explicit `--allow-dirty-source`
  in both `--check` and external `--output` modes. The bridge builder forwards
  that option only when its existing local dirty-source allowance was selected.
  The default still rejects dirty artifacts, and every mode always invokes
  repository/tool provenance verification. Exact source closure, artifact
  inventory, hashes, canonical manifest links, publication locks, and output
  preimage guards remain unchanged; no source pins or lockfiles were rewritten.


<a id="record-5ff5dc4df29cce85feee089daf3795958d270535177853054af8d696b3e9ac56"></a>

- Focused validation passed 11 pin-owner tests, 12 existing artifact-validator
  tests, and three release-contract checks; Bash syntax validation also passed.
  Pin-owner success cases use the existing labeled provenance double to check
  argument forwarding and publication guards. A separate no-mock regression
  runs the real validator and proves the opt-in still refuses invalid tool
  provenance in both modes. These tests do not authenticate a native artifact
  or establish a positive dirty-source native admission result. Existing frozen
  builds remain untouched; validation of the changed owner requires a newly
  fingerprinted source/build generation.
