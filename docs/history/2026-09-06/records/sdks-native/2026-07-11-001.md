## 2026-07-11 JavaScript Nexus Connect approval and cancellation closure



<a id="record-dcfa7b58cfa7be541c2e5583af8ae9370e6a203e7137dee97e863ee4dd6cb926"></a>

- Kept Connect proof identity separate from transaction authorization: browser
  Connect verifies the approval's X25519 `walletPublicKey` and signature, then
  the Nexus facade projects `accountId` and derives the canonical I105
  account's Ed25519 controller key for transaction signing. Approval callers
  now receive immutable wrappers with detached proof bytes, preventing one
  consumer from mutating verified state observed by another; a second approval
  frame closes the session without replacing the first verified identity.


<a id="record-b9efbb4dff6f64eb385e92a1cb9a8a2ba1080adc1d24e608dc705fbe7990d912"></a>

- Made `{ wait: true, signal }` cancellation submission-safe across built-in and
  injected Torii clients: intrinsic signal state/listeners are used throughout,
  callbacks are captured once, wait capability is required before submission,
  and the facade owns cancellation/deadline enforcement across Fetch response
  bodies and status callbacks. Error classification/context properties retain
  the phase, submission state, canonical hash, and exact `submission` reference
  so unknown or completed submissions cannot be mistaken for safe retries. The
  signal remains scoped to the optional status-wait flow.


<a id="record-defeb4df3d0948c7f468a8e71c732171dcf3e78d460bd20784c3a111ce76c804"></a>

- Kept custom status inputs bounded at 32 raw entries while acquiring iterable
  methods once and closing over-limit generators before any Torii side effect.
