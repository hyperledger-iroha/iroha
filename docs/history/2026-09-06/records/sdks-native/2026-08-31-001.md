## 2026-08-31 JavaScript SDK immutable-runtime and package closeout



<a id="record-8c8f67adf7b7f35f95312849bcc4f8828390cdb6f7dc796d0b86ed805a90a2e2"></a>

- The JavaScript SDK no longer selects native behavior through mutable process
  globals. A verified binding is snapshotted into an immutable runtime, loader
  success and failure are cached, and optional fallback hides only the exact
  missing-file condition. Crypto, transactions, Norito, validation-fee,
  confidential proof, DA, SoraFS gateway, and Torii composition now carry that
  runtime explicitly. Torii gateway, chunker, and proof work cannot escape to a
  default binding; automatic DA blob IDs use portable BLAKE3 instead.


<a id="record-d714726f0b08cde0eb9b1e73d42ae3db943b24ca250e5085418f2b97dfddc452"></a>

- The first-release surface is smaller and stricter. The pre-release
  `encodeInstruction` and `SUPPORTED_CRYPTO_ALGORITHMS` aliases are gone,
  algorithm inputs use the exact `CryptoAlgorithm` union, explicit falsey seeds
  reject, and curve geometry comes from the frozen registry rather than a
  mutable map. Pure-JavaScript instruction ownership is attempted first;
  unsupported instructions dispatch once to native and propagate its exact
  error instead of classifying English error text. SoraFS cancellation preserves
  the caller's abort reason, and `proofSummary: false` performs no proof work.


<a id="record-a2e99bbf1c2949b049e69ef8e2727744aec0b9f8da5a0471afd17b9db528ec55"></a>

- Torii credentials, canonical-auth material, origin policy, retry configuration,
  and compatibility caches are private class fields. Key byte containers are
  copied at construction, object/JSON inspection does not reveal secrets, and
  shadow properties cannot change request policy. `NoritoRpcClient` and
  `ToriiBrowserClient` now use the same private snapshot rule: request bytes and
  default headers are copied, browser URLs are exact credential-free HTTP(S)
  roots, timeout inputs cannot coerce, and callers cannot redefine successful
  route statuses. The no-op RPC `close()`, nested browser config duplicate, and
  browser `ToriiClient`/`ToriiHttpError` aliases are gone. Non-empty Norito
  transaction receipts fail closed on a missing decoder, native rejection, or
  invalid JSON; only `204` and empty bodies produce an empty receipt.


<a id="record-c27a238f49a4324d87a9342fbe6a3765fa3ddbb53712a55bbf1f6867a06bf2a8"></a>

- The registry package now contains one `dist/` runtime tree plus two portable
  recipes, rather than duplicate `src` and development scripts. A clean
  install/import passes with 161 files (4.4 MB unpacked, 873 KB tarball). Pinned
  minified closures are 814,534 bytes for eager Torii, 327,517 and 72,493 bytes
  for its reviewed lazy chunks, 1,214,544 unique bytes combined, 496,687 bytes
  for the eager browser aggregate (578,683 bytes including reviewed lazy
  chunks), 311,701 bytes for the browser transaction codec, and 361,258 bytes
  for Nexus; every hard budget remains green.


<a id="record-b87d9e974b7efb76b5ea8d5dbda1b7e64c0dca6c403945e412fa36cd64212c1a"></a>

- Validation passes strict JavaScript lint, distribution regeneration, a
  222-test portable client/runtime/declaration/package corridor, the exact
  split-bundle audit, and the clean packed-consumer smoke test. Native
  SM2/privacy/Norito parity and the complete serial unit profile remain
  unqualified because this checkout has no
  `native/iroha_js_host.node`; the host addon and Cargo workspace were not built
  while unrelated Rust builds were active.

## 2026-08-31 Python SDK first-release simplification



<a id="record-74f9482ed1f6e98ebe2eba7ac55e2fcc4226c45ea4b1b154fecf1d212784c9fc"></a>

- The high-level `iroha_python.ToriiClient` now has one deterministic, typed
  configuration and fail-closed transport contract. Ambient environment
  credentials are ignored unless an explicit environment mapping is supplied;
  origins, routes, headers, tokens, timeouts, retry policy, and caller-owned
  `requests.Session` injection are validated before I/O. Redirects are off by
  default, adapter retries may not hide beneath SDK retry policy, retry responses
  are closed, and owned sessions ignore ambient proxy settings and are closed on
  failed construction.
  Redundant `_typed` configuration/time methods, transaction signing overrides,
  retired config aliases, always-failing SCCP write stubs, and dead
  normalization helpers were removed.


<a id="record-ebdd9664923b54cd41ea8587cc6a1b622118fab89d5dad665747553560905694"></a>

- Transactions, keys, Connect frames, and secret containers now use immutable or
  exact inputs instead of lossy coercion. Direct and draft transaction paths
  share finite-JSON and bounded-unsigned-integer validation; drafts capture one
  creation timestamp and build repeatably. Public/private key consistency is
  checked, secret representations are redacted, native key factories no longer
  derive public material twice, and Connect codes, nonces, replay counters,
  envelopes, and restored session state reject booleans, floats, strings, and
  out-of-range integers before native encoding. SoraFS alias policy accepts only
  exact snake-case first-release fields and unsigned bounds, rejects falsey
  non-policy inputs before native evaluation, and preserves the canonical zero
  governance/successor grace semantics across the Python/native boundary.


<a id="record-8697babbc24ef05f5c3459c9437ddcdb8c51227e006bed71d10e16f5dc242d6b"></a>

- Validation records 1,099 passing low-level Torii tests (one additional test
  skipped), all four `norito_py` tests and 12 subtests, focused Ruff and Rust
  formatting checks, Python byte-compilation, Python fixture parity, the
  retired-codec guard, and whitespace checks. The
  same-revision native extension and high-level suite remain unqualified on this
  checkout: unrelated active Rust builds and the current Core overlay/SCCP
  compilation errors prevent rebuilding `iroha_python_rs`.
