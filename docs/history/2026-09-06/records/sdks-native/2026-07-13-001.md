## 2026-07-13 Iroha JS production native-profile closure



<a id="record-f37bbaf6bbb32fe795c081d738cc51500b7c41de4bf3d93ede6e23c43f570423"></a>

- Added one strict `IROHA_JS_NATIVE_BUILD_PROFILE` boundary shared by native
  compilation and publication. Development remains `debug` by default;
  `release` maps to Cargo release, and the production `deploy` value maps to the
  workspace's existing stripped, LTO-enabled `profile.deploy` without guessing
  a target directory.


<a id="record-1b9d74a37c3d14a7423a1bba5d1b0ddc035753bc720e6f1a8491df56a53a9c74"></a>

- Authenticated native checksum entries now record the exact Cargo profile.
  Existing profile-less manifests remain readable for compatibility, while
  production packagers can require `cargo_profile = "deploy"` and reject debug
  addons even when their checksum is otherwise valid.


<a id="record-91cdfa7a05f62bc3b5056317d02129a1885a0e8789586147b75cf69e60e3e3d3"></a>

- Native Cargo execution now records a sidecar bound to the exact compiled
  binary, profile, source Git revision, and the pre/post-build tree state.
  Publication requires that sidecar and carries `source_git_revision` plus
  `source_tree_clean` into the authenticated checksum entry; a revision change
  during Cargo, a stale target binary, or a dirty observation at either build
  boundary fails closed or remains explicitly non-clean.


<a id="record-b86f738359c98bd2751a4213a427b6bcf01a3445e80990aea68e2d4db70d7bd7"></a>

- Windows checksum entries now record `pe_unsigned_size` and
  `pe_signing_independent_sha256`. Re-signing accepts only the PE checksum and
  certificate-directory pointer mutations, at most seven zero alignment bytes,
  and one final aligned non-empty Authenticode table. Runtime fallback requires
  that signed layout; malformed bounds, missing signatures, padding changes,
  and changes to unsigned bytes fail closed. Native Windows release tooling
  must still validate Authenticode with the operating system before loading.


<a id="record-0e07efc649505325ac7c53e3b7c95da5b378caa714d8fe8627fb13c1b960a8a5"></a>

- Added focused profile/provenance coverage and retained the transactional
  native publication, crash-recovery, checksum, Mach-O/PE re-signing, and
  required-export probes. The focused JavaScript suite passes all 86 tests.
