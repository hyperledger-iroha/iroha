## 2026-05-25 SCCP TRON solid-block header proof



<a id="record-533f26d55cae0de390e02948b08226ddb87a22a2f30d1a40bca781d8ed11003f"></a>

- Added `SccpTronSolidBlockHeaderProofV1` to the TRON DPoS source adapter and
  bound it into the canonical adapter transcript.


<a id="record-c8e440abb9640dd74e23aa5fbd2e719bc847edbb450b41d4dae0af23157f896a"></a>

- TRON source verification now parses the raw `BlockHeader.raw_data` protobuf
  fields, rejects duplicate or mistyped required header fields, verifies
  `sha256(raw_data)`, derives the TRON block id from the block number and
  raw-data hash, binds `txTrieRoot` to the adapter `transaction_root`, and
  recovers the block producer's secp256k1 header signature to an active 21-byte
  TRON witness address before accepting the DPoS witness seal. The generic
  TRON source-adapter binding path now runs the same header proof, so malformed
  solid-block headers fail before production material or recursive verifier
  evidence is evaluated.


<a id="record-6c52d822db720acee7cf64cdf5733a9e8fd7285a29dfe9ec1b716ff3078a57b1"></a>

- The solid-block header proof now also carries the immediate parent raw header,
  parent witness signature, and parent raw-data hash. Verification derives the
  parent block id from that signed parent header, requires it to equal the child
  header's parent id, enforces parent height + 1 and monotonic timestamps, and
  recovers the parent producer to an active witness address.


<a id="record-fea4583d77e5f0c7e474d82514569c3e8b49e1a175e8b9fd602cc9a810186db0"></a>

- The TRON mainnet source-material template now commits to
  `sccp:tron:solid-block-header-proof:v1` in addition to the receipt-state,
  witness-schedule payload, solid-block message, witness-seal, and
  witness-schedule transition transcript families.


<a id="record-810251e62c0aa9f7b0f8b867636c18c38a70c7b95b1099db15053ab38255bbc6"></a>

- Added a bounded Ethereum-style Merkle-Patricia-Trie transcript to the TRON
  adapter as structural verifier material. This path was later reclosed for
  production because java-tron authenticates `txTrieRoot` as a transaction
  Merkle root, so a production TRON source proof needs either a
  consensus-authenticated receipt/log root or a java-tron transaction Merkle
  branch over authenticated transaction bytes.


<a id="record-9998636b78f81e241858c4485d9d5cde89066cba08105ccbf018cd95818904ee"></a>

- Added a Rust golden fixture for the TRON solid-block header transcript so SDK
  and relayer helpers can pin the same raw-header bytes, raw-data hash, block
  id, canonical proof length, and `sccp:tron:solid-block-header-proof:v1`
  digest.


<a id="record-fe07136fc6336c4f8ffeac2b8bd9e460263929aade1fcefcef49882cb4e71977"></a>

- Remaining TRON production work is full mainnet transaction/receipt value
