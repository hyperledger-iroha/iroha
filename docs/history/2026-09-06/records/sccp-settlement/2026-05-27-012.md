## 2026-05-27 SCCP Solana VoteState suffix parser hardening



<a id="record-2bf733acd2438d82c14c8a2d88deb79ba0bf3305a86ef5efe882995913c2a92a"></a>

- Hardened Rust and JavaScript, Python, Swift, Kotlin, and Java Android Solana
  `VoteStateVersions::V1_14_11`/`V3`/`V4` parsers so raw vote-account buffers
  must structurally consume the VoteState suffix after the authorized-voter
  map. V1/V3 prior-voter cursor data now requires a valid circular-buffer index
  and boolean empty flag; epoch-credit history is capped to Solana's 64-entry
  bound and must be sorted/monotonic; the final timestamp tuple must decode; and
  the remaining fixed account tail must be zero padding.

  malformed raw vote-account suffixes or alternate padded bytes before UI/mobile
  proof helpers or the Rust source adapter treat the account as a valid Solana
  finality witness.
