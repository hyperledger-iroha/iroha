## 2026-05-28 SCCP typed client destination proof gates



<a id="record-744073adb85b861ab0ef3292a80ace251311b42feb26f041d240a3981182cd9b"></a>

- Rust `SccpMessageProofQueryParams`, Python Torii client destination query
  normalization, and JavaScript Torii client query/submit normalization now
  reject artifact/job requests that include EVM/TRON destination proof material
  without the required `proof_bytes_hex`, after first validating any supplied
  hash/address fields, and reject standalone `proof_bytes_hex` without
  deployment destination fields.


<a id="record-49711d051c8b3a93a10027e1fd3cc75da14a47e30c99bc7990f1c483b87ca0cb"></a>

- The bridge-feature CLI inherits the same Rust preflight, so operator
  job/artifact commands fail before network I/O instead of relying on Torii's
  Groth16 bad-request path; the rebuilt JS `dist/` bundle carries the same
  guard as `src/`.


<a id="record-fcfbd184ba5b687f9b57e024bf07434fd2f755129158303be9ccfa6828a1f0bc"></a>

- Rust, Swift, Kotlin, and Java Android raw bridge submit preflights now apply
  the same two-way deployment relationship before posting bridge-proof or
  bridge-message JSON: destination fields require `proof_bytes_hex`, and valid
  proof bytes require destination fields. The same raw preflights now reject
  malformed recognized destination material locally, including short/invalid
  32-byte hashes or network IDs, malformed 20-byte EVM addresses, and blank
  TRON verifier addresses.


<a id="record-72c64b2457ccbbb9110717f1c8386bdba2d1f74e039abafc9e6c41141802005e"></a>

- Kotlin `core-jvm` TON SCCP message-body construction no longer declares two
  constructors with the same JVM signature; the proof-result convenience path now
  delegates through a checked wrapper while preserving wrapped-proof and bundle
  equality validation.


<a id="record-8598b086bbb864c6d0814d0fde20d40f33ab3c93d4a78469106af8df952f3617"></a>

- The pinned EVM/TRON contract smoke now proves the accepted TRON BN254 tuple is
  bound to both the statement hash and the deployed TRON destination binding by
  rejecting the same proof against a wrong statement and a different
  network-bound verifier deployment before accepting it on the governed binding.
