<a id="record-ad8539b35ef25cee1c980c41e2f6db0b2980cc9dc0d17cca4564be2d47e636ad"></a>

- Mirrored that JSON-only source-event path in
  `scripts/sccp_tron_live_evidence.py`: with a queried source bridge, live JSON
  now includes `source_event_call` and `offline_source_event_args`; `--full-toml`
  rejects `--source-event-digest` for the same governance/evidence separation.
  The live JSON summary also reports `full_toml_ready` so operators can tell
  whether the queried evidence is ready to replay as production full TOML.
  The live source-event path now also checks
  `submittedSourceEvents(bytes32)`: pre-submit mode refuses to emit an unsigned
  trigger request for an already submitted digest, while post-submit mode
  requires the mapping to be true. When the digest is fresh, live JSON includes
  the unsigned `/wallet/triggersmartcontract` request body for the owner
  transaction without signing or broadcasting it. After broadcast,
  `--source-event-transaction-id` verifies `/wallet/gettransactioninfobyid`
  readback, a successful receipt, and the exact two-topic
  `SccpSourceEvent(bytes32)` log address and digest. When `--solid` is set, the
  transaction readback uses `/walletsolidity/gettransactioninfobyid`. The same
  post-submit path also verifies `/wallet/gettransactionbyid` or
  `/walletsolidity/gettransactionbyid` raw transaction body as a single
  `TriggerSmartContract` with `contractRet = SUCCESS`; explicitly present
  top-level `ret` values must be java-tron's default `SUCESS = 0`, while
  omitted default `ret` values are accepted. The raw transaction must carry the
  governed owner, source bridge address, and source-event calldata; it also
  requires `raw_data_hex` to hash to the requested `txID` and exactly one
  canonical 65-byte TRON recoverable secp256k1 signature that recovers to the source
  bridge owner. The helper parses the signed `raw_data_hex` protobuf and
  requires its embedded `TriggerSmartContract` owner, contract, calldata,
  ref-block, expiration, timestamp, and fee-limit fields to match the same
  source-call profile enforced by Rust production admission. It now also emits
  canonical transaction protobuf bytes, their SHA-256 transaction hash, and the
  transaction Merkle branch; when `--receipt-root` plus repeated
  `--source-inclusion-branch-hex` values are supplied, it derives canonical
  `sccp:tron:transaction-source-proof:v1` bytes/hash and compares
  `--receipt-proof-hash` when present. It fetches the containing block through
  the matching TRON block endpoint, rebuilds the canonical block-header
  `raw_data` hash/TRON block id, fetches the immediate parent block, verifies
  the child `parentHash` and monotonic timestamp, recovers both child and parent
  header signatures to their declared TRON witness addresses, and recomputes
  java-tron's transaction Merkle root from the block's canonical transaction
  protobuf bytes to match `txTrieRoot`. When child and parent headers carry the
  non-zero account-state roots required by the shared SCCP transcript helper,
  live JSON also emits the canonical solid-block header proof bytes/hash;
  missing roots remain visible as a proof blocker. The live helper now also
  accepts canonical witness-schedule payload hex or a payload file, derives the
  `sccp:tron:witness-schedule:v1` hash, optionally checks an expected schedule
  hash, and requires the child and parent block witnesses to be active schedule
  members. It now accepts receipt-root, receipt-proof-hash, witness-signers
  bitmap, and repeated witness-signature inputs, derives the canonical
  `sccp:tron:solid-block-message:v1` and `sccp:tron:witness-seal:v1`
  bytes/hashes, verifies signer recovery and strict `> 2/3` signed schedule
  weight, and reports missing seal material as an explicit JSON blocker. The
  same live path now accepts bounded `--solid-block-ancestor-depth` and
  `--solid-block-confirmation-depth` reads, verifies backward ancestor linkage,
  forward confirmation linkage, active witness membership, monotonic
  timestamps, and strict `> 2/3` unique confirmation weight, and reports missing
  non-placeholder header evidence as explicit blockers.
