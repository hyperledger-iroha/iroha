  increasing transition block numbers, preventing a chain from presenting later

<a id="record-b6bfe8adc70b635d8a30bfcd5856afc717a70dc691ae403768696bf0c408454a"></a>

- Added `shard_state_leaf_index` and `shard_state_inclusion_branch` to
  `SccpTonMasterchainSourceProofV1` and bound them into the canonical TON
  adapter transcript plus `sccp:ton:shard-proof:v1`.


<a id="record-aad79aeceaaafef5aa4d42769889572498fa0668b4a50f57efe6b17277bf3483"></a>

- The TON source adapter now recomputes the submitted `shard_state_root` from
  the message/transaction root, shard-state leaf index, and bounded shard-state
  inclusion branch before accepting the signed masterchain evidence. Tampered
  shard-state branches are rejected even if the shard-proof hash is recomputed.


<a id="record-76198a311a9a05edc70996cacb9e15a918f4d9c230e5fe5d2695c27e91133afe"></a>

- Updated JavaScript, Python, Swift, Kotlin, and Java Android SDK
  shard-proof helpers so portal and mobile provers supply the shard-state
  opening material alongside the message inclusion branch.
