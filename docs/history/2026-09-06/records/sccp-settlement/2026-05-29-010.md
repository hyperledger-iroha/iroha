  `SolanaSccpSubmissionInput` requires at least one wrapped `proofResult`
  spelling.


<a id="record-8f8b226c5e9a7372ece52029b80bd2423fb97228b8d7c6461098376e48a2c463"></a>

  externally generated OpenVerify/FastPQ proof bytes must be wrapped against a
  full SDK-built AccountsLtHash or full-light audit request shape, not a minimal
  hand-written circuit-id object. The JavaScript declaration now requires the
  full request union as well, and both dynamic wrappers require the Solana
  `sourceDomain` field carried by SDK-built requests.

## 2026-05-29 SCCP EVM/TRON UI destination binding derivation



<a id="record-4633ceedff2b230d2c1b9967b8f4680c2cb249e515ec9069594b7794218d83c9"></a>

- Added JavaScript, Python, Swift, Kotlin, and Java Android SDK helpers that
  derive canonical EVM-family and TRON destination binding keys/hashes from
  user-portal/mobile deployment material instead of trusting raw destination
  binding hashes.


<a id="record-4aa970a34abe271f23975123099469c449263ad8828c6749299a577c7c6c9c49"></a>

- EVM/BSC bindings now include network id, SORA source domain, ETH/BSC target
  domain, canonical Groth16 backend, `stark-fri-v1`, verifier address,
  bridge-wrapper address, deployed verifier code hash, and verifier key hash.
  TRON bindings apply the same backend/proof-family/domain/code/key checks and
  require a valid TRON Base58Check verifier address.


<a id="record-c4bf3b4dec927a7333f614408ee04c6567418d1265aa92f32c44b1804524e040"></a>

- EVM-family and TRON web/Python proof request builders now accept
  `destinationBinding` material directly and reject any mismatched
  caller-supplied `destinationBindingHash` before invoking local prover
  callbacks. Rust now exposes the same EVM/TRON Groth16 UI proof request/result
  wrappers, binding the deployment object into request hashes, public signal
  words, and proof envelope hashes. Mobile apps can derive the same governed
  binding hash in Swift, Kotlin, and Java Android before passing it into
  existing proof request constructors.


<a id="record-19ffa4f0b86203c5452c301bec881e17d0a96836029f6b8431b71d266bfac393"></a>

- Rust EVM/TRON submission templates now use the canonical
  `submitSccpMessageProof(bytes,bytes32[6],bytes32)` signature and regression
  tests pin emitted EVM/TVM calldata to selector `0xbd57826c`, matching the
  JavaScript, Python, Swift, Kotlin, and Java Android SDK encoders.


<a id="record-9148dc5d51b96de2fe2ca2e103080ce4030c7fc880b0c3881311abbb80344506"></a>

- Regenerated the JavaScript `dist/` package from `src/` and exported the new
  destination-binding helpers through the package root, so the published runtime
  surface now matches `index.d.ts` and the `@iroha/iroha-js/sccp` subpath.


<a id="record-e342826756f8e514b36ed2e42e8968cbb2f6d57d9c5cc93e7e8dd2326d3705ba"></a>

- Aligned Swift, Kotlin, and Java Android EVM/TRON destination-binding `key`
  strings with Rust/Python/JavaScript and the evidence scripts: the network-id
  segment is raw lowercase 32-byte hex without `0x`, while returned `networkId`
  fields and the binding hash remain unchanged.


<a id="record-5fa0d733f4ec908efe90cdc333411c003127e3fee3884ca4d364dac8e9b9208b"></a>

- Added Swift, Kotlin, and Java Android proof-request and submission
  constructors that accept the derived EVM/TRON destination binding object
  directly. These constructors reject mismatched binding version, source domain,
  target domain, verifier backend, or `stark-fri-v1` proof family before
  threading the derived hash into request hashing or verifier-call packaging.
