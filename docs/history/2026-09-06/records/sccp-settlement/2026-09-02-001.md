## 2026-09-02 Atomic private-settlement auditor access and SDK closure



<a id="record-d710e363d723fe9c0ccec38adcee57c6b2102cd15813e830f628567743833b5b"></a>

- Restricted capsule reads now use a strict, identity-signed read-only `POST`
  whose body carries the complete governed access policy. Core authorizes the
  read from one committed state view: it binds the retained sidecar policy to
  the pool-governance revision effective at the manifest authority context,
  binds the request policy to the revision effective at the current height,
  performs one content-addressed sidecar read, rejects consensus-key reuse, and
  returns one uniform unavailable class for missing, expired, or unauthorized
  material. A successor revision can read retained ciphertext only when its
  signing key maps to a stable auditor identity present in the historical
  policy and wrapped-DEK set; a successor cannot submit a new approval under
  that historical policy.


<a id="record-605e88efe540b73486736d06d36d473047bbe22f6e621f8bbb46b7bd987e0bb2"></a>

- The software auditor has a runtime-only, nonempty, duplicate-free
  current-plus-retired hybrid keyring. Capsule opening selects the exact
  historical governed public key instead of trial-decrypting. The CLI requires
  an explicit owner-only `--audit-policy` file and supports repeatable
  `--auditor-retired-decryption-key-file` inputs. Current and historical policy
  bindings are carried through Torii, Rust, C/JNI/N-API/PyO3 bridges, Kotlin,
  mirrored Java, Swift, JavaScript, and Python. Only the canonical native
  response entry points are part of V1; obsolete entry points are not retained.

- Public statement and delta admission now require all three output-recipient
  identifiers to be distinct; the Prepare barrier and final receipt reject
  cross-leg reuse. Committee Prepare and the global atomic planner also reject
  reuse against finalized history. Finalization writes a derived recipient
  index in the same state transaction, while snapshot restore rebuilds and
  cross-checks that index from canonical encrypted outputs. Exact terminal
  replay is rejected without mutation. Snapshot restore accepts only the
  canonical current 188-field world and rejects every other schema. V1 has no
  pre-release snapshot bridge, retired-store decoder, retired configuration-
  default reinsertion, dynamic current-World inference, or hybrid hash
  normalization. Release evidence binds complete current-schema State, World,
  and block-wire bytes with revision/SHA/schema-order provenance and full
  WSV/Kura checkpoint-manifest continuity. These mutable-checkout results
  establish the implementation contract but are not immutable-candidate
  release evidence.

<a id="record-90152ef7b38448cd7adedbd1ebb4f74e6fa76e09374e2e97e22cf46cf649cc6a"></a>

- A pinned 333 ms N=3 test binary was rejected as release evidence after three
  fresh-network attempts: two failed before committing genesis; the third
  committed genesis after roughly seven minutes but then left the activation
  transaction queued at height two until the client's 600-second timeout. At
  that cadence the 3.33-second round deadline is too short for sixteen local
  validators to process and relay mandatory DA reliably. The source now keeps
  the N=3 correctness smoke on the release-like four-second cadence and pays
  the full 300-height privacy-governance notice; the ineffective one-
  transaction activation shortcut was removed. The subsequent current-source
  rerun brought all 16 processes (three four-validator dataspaces plus the
  four-validator global committee) to the same committed/highest/locked and
  Commit-QC height 4. It then stalled at height 5 with `BodyUnavailable`,
  missing-finality recovery, repeated status-staleness 503 responses, and the
  activation transaction queued for 1,200 seconds; the client failed after
  1,541.08 seconds. No private-settlement transition ran and no strict subset
  of legs became visible. This is an underlying Sumeragi/mandatory-DA liveness
  failure under the 16-process local load, not positive atomicity evidence. The
  full real N=2/3/4/8/16 fault, leakage, latency, soak, clean-candidate,
  independent-audit, and DOI gates remain outstanding. The feature therefore
  remains governed, disabled by default, and not production-ready.

  Producer lease. The source now uses one exhaustive census for idle, active
  CertifiedServe, and active ProducerTurn states while preserving idle-only
  finalization. It accepts exact parked Broadcasts with live or terminal paired
  Signs, rejects Ready Broadcasts that claim a terminal pair, and retains all
  digest, generation, geometry, replay-authority, and ledger joins. A
  two-parked-Broadcast Serve-to-Producer regression passes, as do the paired
  live/terminal and Ready-plus-terminal negative, all 27 finalization-filtered
  Core tests, all 9 terminal-owner tests, the two successor-recovery formal
  contracts, formatting checks for the modified production sources, and the
  repository whitespace check. The
  exact current-source N=3 binary rebuilt successfully at SHA-256

  These are source-level correction results, not replacement network evidence;
