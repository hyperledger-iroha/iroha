## 2026-05-26 SCCP Solana StakeHistory sysvar bincode layout



<a id="record-cf0e28478038f55db2ce3d69c324bd49a16e5c48e059140fb53fb39c299d0ec0"></a>

- Refined `sccp:solana:stake-history-sysvar-data:v1` canonical bytes from the
  SCCP-local version/count encoding to Solana's StakeHistory sysvar account
  bincode-vector layout: a little-endian `u64` entry count followed by
  newest-first `(epoch, effective, activating, deactivating)` `u64` records.

  reverse entries only when deriving the sysvar account `data_hash`.

## 2026-05-26 SCCP Solana account-data transcript binding



<a id="record-2a8cee75f8479a942e29da9a5929b14eb94c85225c6fbd3ddcf29998508e0f5d"></a>

- Bound Solana validator vote/stake account opening `data_hash` values to
  canonical semantic account-data transcripts. Vote-account transcripts now
  commit to node pubkey, authorized voter, authorized withdrawer, commission,
  rooted slot, and the 31-slot active post-root Tower stack under
  `sccp:solana:vote-account-data:v1`; stake-account transcripts now commit to
  staker, withdrawer, delegated vote-account pubkey, delegated stake,
  activation/deactivation epochs, and `credits_observed` under
  `sccp:solana:stake-account-data:v1`.


<a id="record-110079480d514a323ab6f8d82cb3b667a75e8de32d22c85c012d2d3a109fb55e"></a>

- The Rust Solana finalized-vote verifier now requires one semantic
  vote-account data transcript and one semantic stake-account data transcript
  per validator. It checks that authorized voters, root/Tower slots, delegated
  vote accounts, delegated stakes, and activation/deactivation epochs match the
  signed finality context before comparing transcript hashes to the account
  opening `data_hash` values.


<a id="record-796671f67a6e8c7d569f82d59389adbba5707642dea0738307613314e5314622"></a>

- JavaScript, Python, Swift, Kotlin, and Java Android SDKs now expose matching
  canonical-byte/hash helpers so web portal and mobile UI provers can derive
  the same semantic account-data hashes before submitting source proofs
  on-chain.


<a id="record-3bc1d1b90f80cb762643d3347dca3dddd4e2b97d82f79a29f42b3abe670fcbd1"></a>

- Updated bridge-proof docs and roadmap wording. Remaining Solana production
  work is authenticated raw account/sysvar inclusion proofs, full Tower
  vote-account/state replay, bank execution/fork-choice checks, recursive
  verifier deployment, and live
  submission validation.
