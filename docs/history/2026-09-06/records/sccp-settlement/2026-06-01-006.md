## 2026-06-01 TAIRA TRON SCCP XOR settlement admission

  payloads: the TRON bridge now accepts the recorded transfer payload bytes,
  parses route/asset/recipient/amount on-chain, binds the proof by recomputing
  the SCCP transfer message id, and treats `publicInputs[1]` as Iroha's
  canonical SCCP commitment payload hash.


<a id="record-4192e5a3ec479ce5fdf07bbb239c9ae09e9bc95cb4d255820c00305bc6a66ca2"></a>

<a id="record-69133617f66920eeb3e022f4ac2d47774172aeba4c18105359e8e91034e6b727"></a>

- Hardened TAIRA XOR TRON finalize calldata generation so externally supplied
  canonical payload bytes are parsed as the exact SORA->TRON XOR route before
  hashing, optional cleartext fields must match those bytes, and TAIRA
  recipient hash helpers reject account aliases unless callers deliberately
  pass raw recipient bytes or a precomputed hash.


<a id="record-35ffc8977b14f7e23be72686daab85865fb055344649caabf91e91ab1155d6a4"></a>

- Hardened `taira_tron_xor` source-record admission so an `IvmProved`
  execution that records a TAIRA-to-TRON XOR SCCP transfer must carry a
  same-overlay `Burn<Quantity, Asset>` settlement from the payload sender.
  Admission resolves the settlement asset from `nexus.fees.fee_asset_id`,
  aggregates required burns per sender, and rejects malformed record payloads,
  wrong routes/assets/senders, fractional burns, and burn reuse.


<a id="record-c7fa19ce8dd01d1378fb596670308290eeebe60302403f4dadbf418853e1ea3f"></a>

  network id, and destination-binding fields so WalletConnect bridge UIs can
  derive proof material from normalized manifests.


<a id="record-9e3a6854cb3d20da5b2e04cebbe1e3e0152e90f4f355a06b54e1a9af352205be"></a>
