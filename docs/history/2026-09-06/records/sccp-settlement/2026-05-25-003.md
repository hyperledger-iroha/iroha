<a id="record-bfef1c7aa20d9deb8ceeff5935e7329b6a49e370a4dfed342d9df0c02a8e87bf"></a>

  `transaction_signature` and `emitter_program_id` bytes. The verifier now
  recomputes `message_proof_hash` from the source event digest,

## 2026-05-25 SCCP TON BoC proof-cell helper parity



<a id="record-a5b4e4c728a1d8e412f3bd02fe0ef2351d644c435d1458a7696972b740d2e4e5"></a>

- Extended the bounded TON BoC root-hash helpers in `iroha_sccp` and mirrored
  them in the Python, JavaScript, Swift, Kotlin, and Java Android SDK surfaces
  so web and mobile proof material can derive the same SHA-256 cell root hashes
  checked by Rust fixtures.


<a id="record-0885b07262cfd0fdf1e2c5f7bfcd27444a3325e755d1bfec2231e0a1e8d1019f"></a>

- The helpers verify CRC32C trailers when present and reject unsupported header
  flags, explicit hash descriptors, unsupported exotic cell types, non-forward
  refs, malformed descriptors, invalid partial-byte cell padding, and oversized
  BoC/cell shapes. They now support ordinary cells plus pruned-branch,
  Merkle-proof, and Merkle-update exotic cell hash/depth semantics, including
  embedded Merkle proof/update hash-depth consistency checks. The parser also
  accepts the legacy 280-bit maskless pruned-branch form emitted by existing
  TON proof tooling as an implicit level-mask-1 branch, and the JavaScript and
  Swift walkers now advance ordinary-cell hash levels correctly when a pruned
  child raises the level mask. This is still an incremental verifier primitive
  only: HashmapE dictionary and shard-state extraction/evaluation plus
  recursive verifier/contract deployment remain required before the TON lane is
  production-ready.
