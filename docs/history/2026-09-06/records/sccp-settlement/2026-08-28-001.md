## 2026-08-28 SCCP four-mainnet release-integrity gate



<a id="record-18d0f58ce1ab4156763e22ae50fc62787ca896cd5d5279018448fa638bd7fb38"></a>

- The production release-evidence inventory is now exact and fail closed over
  four profiles: Ethereum mainnet, BSC mainnet, TRON mainnet, and TON mainnet.
  TON mainnet is mandatory; a legacy three-lane bundle, TON testnet evidence,
  an unexpected profile, a duplicate row, or a missing row leaves global
  readiness false. A complete inventory has four distinct lane-evidence
  artifacts, four lane-validation receipts, four semantic-proof artifacts and
  receipts, and eight independently signed circuit-audit reports. Cardinalities
  are derived from the authenticated policy inventory rather than legacy
  three-lane constants.


<a id="record-96bc04883be47f1ef3aa30a4ea9babd5c36651ec3f642902a7bf80399c0dce02"></a>

- Proof policies, independent audit reports, honest-proof claims, and Rust
  receipts carry a closed `proof_curve`. Ethereum, BSC, and TRON bind `bn254`
  to their exact circuit/backend ids; TON binds `bls12-381` to its exact
  circuit/backend id, canonical eleven-signal schema, BLS12-381 key, semantic
  profile, and proof-profile commitment. The Rust validator performs canonical
  curve-specific decoding and pairing verification; a curve/id, schema, key,
  route, or signed-artifact mismatch fails closed.


<a id="record-d683b1a223da2c547e7cbf097014fe22ee3a0b41ee3b12d2bbeaebd69890be87"></a>

- Authenticated TON destination evidence is mainnet-only and binds global id
  `-239`, masterchain finality, the governed route revision, Jetton master and
  wallet code, route code, embedded-verifier code, and the canonical
  single-root code and initial-data BOC hashes. Exact StateInit representation
  hashing proves the governed basechain Jetton-master and route addresses from
  those code/data cells. The same bidirectional route contract is the native
  source emitter and destination executor; registry validation rejects a
  different source address, code hash, or route configuration.


<a id="record-da39799ab48ea6c7084b7b39421fdaad9685b66a5270367d46652353ed33aed6"></a>

- TON native inbound admission authenticates a governed zero state and
  masterchain checkpoint, ordinary-catchain or Simplex Ed25519 finality, the
  selected shard, transaction pre-state account code/configuration, and exact
  outbound message. Torii exposes the governed concrete BN254 request for the
  EVM/TRON/Solana family or BLS12-381 request for TON, while submission accepts
  only the closed `BridgeSccpDestinationProofV1` envelope. Consensus reserves
  deterministic TON Ed25519 key/signature work and one BLS12-381 pairing before
  dispatching proof-controlled cryptography.


<a id="record-1f7c6db4010c998e0714e7c022a6c8567cea06eca8bdd5248b2e0aaed0dd2657"></a>

- The TON contracts now allocate a distinct monotonic identity for every
  rejected-deposit refund, acknowledge completed mint replays against the
  current verified request, reject non-V1 finalize envelopes before proof
  work, and require retry callers to replace the operation-value budget. Rust
  and Tolk share the exact typed 14-cell finalize BOC: four linked signal cells,
  fixed `48/96/48` proof cells, and fixed `50/100/100/remainder` payload cells.
  This closes duplicate-deposit fund trapping, proof front-running liveness,
  schema confusion, generic-snake ambiguity, and permissionless bridge-balance
  drain paths.
