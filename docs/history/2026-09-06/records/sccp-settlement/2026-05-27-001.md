## 2026-05-27 SCCP TRON live evidence collector



<a id="record-ae76277f36c684da8c51350f33e23e4859bf29288750ebd3ebfbbbb118b1fc93"></a>

- Added `scripts/sccp_tron_live_evidence.py`, a read-only TRON HTTP API helper
  for deployed SCCP contracts. It calls source bridge and destination verifier
  view functions through `/wallet/triggerconstantcontract`, optionally reads
  `/wallet/getcontract` bytecode metadata, recomputes
  `sourceBridgeConfigHash()` and `destinationBindingHash()`, and emits the
  matching arguments for `scripts/sccp_tron_source_bridge_evidence.py`.
  TronGrid API keys can be supplied at runtime through `--tron-pro-api-key` or
  `--tron-pro-api-key-file`; the key is sent as `TRON-PRO-API-KEY` and is not
  included in the evidence JSON. Destination evidence now also renders the
  `network_id_hex`, `tron_verifier_address`, `verifier_code_hash_hex`,
  `verifier_key_hash_hex`, and `expected_destination_binding_hash_hex` fields
  accepted by Torii SCCP artifact/job requests and the matching CLI options.
  Torii recomputes the EVM/TRON destination binding from those deployment fields
  and fails closed before artifact/job generation when the expected binding hash
  does not match. Operators can pass `--solid` to read source and destination
  view functions through TRON's
  `/walletsolidity/triggerconstantcontract` confirmed-state endpoint.


<a id="record-382da1c67230679c9305d5bed3558917c91f90b5859d6a79b505afef64700842"></a>

- Added focused fake-node tests for successful source/destination collection,
  source config-hash mismatch rejection, non-production source-lane rejection,
  destination binding-hash mismatch rejection, and runtime API-key header
  handling without secret echo. The success test also asserts the Torii/CLI
  destination-query params derived from the live verifier views, and the solid
  endpoint test asserts the confirmed-state constant-call path is selected.


<a id="record-312a454eaf448f9a3c9c540ca74d1075ca74ed3c5a0af047544072a1fa4b9bcf"></a>

- Extended the live collector with an optional governed source-record preflight:
  when operators supply the source component hashes, source-adapter deployment
  receipt hash, and expected source material/deployment record hashes, the helper
  recomputes those canonical TRON records from live source bridge evidence and
  fails closed on mismatch. A supplied source bridge code hash must also match
  `/wallet/getcontract` runtime bytecode when metadata lookup is enabled, and
  destination verifier metadata must match the deployed verifier's
  `verifierCodeHash()` view. Operators can also pin the deployment/governed
  `SourceBridgeConfigured` value with `--expected-source-bridge-config-hash`,
  so owner or lane drift fails before production full-TOML output. Diagnostic
  offline arguments include that expected pin only after it matches. Direct
  full-TOML output requires that config pin. When full source records,
  destination evidence, and
  route allowlist material are present, the JSON also emits
  `offline_full_toml_args` ending in `--full-toml` plus
  `offline_full_toml_sha256` for the internally rendered governance TOML, and
  `--full-toml` prints that verified TOML directly instead of JSON.
  The all-lanes rollout preflight now has regression coverage that merges this
  verified TRON live full-TOML output into a complete SCCP evidence bundle and
  revalidates the TRON source record hashes against the live collector output.


<a id="record-7076329c59113f84e4e11cbc29fdbd668080cf04baf1b8240695bc4a86753085"></a>

- Updated the TRON contract README, bridge-proof docs, and roadmap so operators
