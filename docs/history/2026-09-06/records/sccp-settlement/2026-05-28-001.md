## 2026-05-28 SCCP UI proof capsule base64 binding



<a id="record-fc94a9f0551ab105a34dc98f64797578668605f340a300cee8343b29773db7cd"></a>

- JavaScript and Python Solana source-state proof capsule normalization now
  rejects supplied `proofBase64` / `proof_base64` metadata unless it exactly
  matches the canonical base64 encoding of the supplied proof bytes.


<a id="record-65a6b1bf76307dd6b1c2e648a87aeaa38d620680bd53319a5928d363d4ee9494"></a>

  proof hashes are derived, so web portal and mobile-facing backend proof
  capsules cannot carry UI-visible proof text that differs from the bytes later
  submitted on-chain.

- Swift, Kotlin, and Java Android source-state capsules already derive
  `proofBase64` from stored proof bytes instead of accepting caller-supplied
  base64. Added regressions proving returned proof-byte views cannot mutate the
  capsule or its derived base64 string.
