## 2026-05-31 SCCP source-state prover metadata canonical comparison



<a id="record-59ebea618feb1f9a02cd20899c168dbdbd8f0c6fd94adb15fb6907e87edab3f5"></a>

- JavaScript and Python source-state proof wrappers now compare normalized
  metadata for UI-generated proof results against the canonical prover request.
  Numeric slot/role-code echoes, uppercase canonical hex hashes, and Solana
  camelCase audit-role aliases can no longer be rejected after normalizing to
  the same request-bound value.


<a id="record-2f482209e597ede2b1974ff2a8611445a0a394332525cdcb9f88067cd96797d3"></a>

- Optional FastPQ public-input and transition result objects are compared after
  canonicalizing camel/snake aliases, numeric slots, uppercase hex
  roots/DSIDs/tx-set hashes, and byte/hex transition values. Public-input
  columns remain exact request transcript values.


<a id="record-b144b48d1d712c6c4592659ec66fced53cee357b23569a4a28ad15e2bb20f5f3"></a>

- Structured source-state prover result version aliases are single-alias
  checked and must normalize to `v1`, so `proofVersion`/`proof_version` echoes
  cannot be ignored while the SDK wraps proof bytes for submission.


<a id="record-2314a839f8b897a0f2b4d2a99876a7b7d4955786e64f125e048d005cdd685fc4"></a>

- The JavaScript package declarations now expose that flexible FastPQ
  result-metadata shape for browser proof engines while keeping SDK-built
  request objects readonly and canonical. They require one accepted alias for
  each FastPQ root/hash and transition byte field, matching the runtime
  single-alias guard.


<a id="record-415e173871bbd9e1fdf4a5570fe29594c0845a1e5eda2f09af71fa0b381af0cd"></a>

- Source-state proof capsule declarations now require proof bytes and one
  circuit-id alias, while structured prover result declarations require proof
  bytes but keep request-bound circuit-id echoes optional.


<a id="record-96a1a3cd36da6ca4b903b1ec9c386135215143b1036162bd378a684cfba3d87d"></a>

- Padded plain string metadata still fails before wrapping, so browser and
  portal callbacks cannot smuggle display-only whitespace into circuit ids,
  parameter sets, verifier ids, or audit-role echoes.


<a id="record-c62aa18a909e92e1733e5f0ce84900b793204f66c47154664a0e0a6f3f6e8730"></a>

- Rebuilt `javascript/iroha_js/dist/sccp.js`, `dist/index.js`, and
