## 2026-05-29 SCCP EVM wrapper production backend hardening



<a id="record-4fd15e341bfa8f113c219f18583fdeafac3baa14c930e9e51d40f988ca757809"></a>

- Hardened `SccpMessageBridge` so production EVM-family deployments can bind
  only `evm-groth16-bn254-v1` with `stark-fri-v1` and a non-zero immutable
  verifier-key hash. The reference secp256k1 verifier remains available for
  direct fixture coverage, but `SccpMessageBridge` now rejects that backend
  before any wrapper deployment can advertise it.


<a id="record-ace16803afe3df9efac00f0fe95bfbeb671757c2e8c430336e4dae88c822cf67"></a>

- Updated the Ganache smoke test to keep secp256k1 attestation checks as direct
  verifier tests and to exercise bridge submission/replay/constructor checks
  through the Groth16 wrapper path.


<a id="record-62955021c0ebf0884383a0763110b0969235383cc21af5452e91e4a35afb3512"></a>

- Tightened Rust manifest readiness so a caller cannot promote a mutated
  `evm-secp256k1-keccak-v1` manifest to production merely by flipping the
  `production_ready` flag; the flag is honored only when the manifest still
  matches the canonical backend, verifier target, and proof family for its
  counterparty domain.


<a id="record-8cee0b8510fae8ad122e2f53d971b54725fdc7d84d98ffd59dce3022474635b0"></a>

- Aligned `build_sccp_evm_destination_binding(...)` with the hardened wrapper:
  it now derives deployable EVM destination bindings only for the canonical
  Groth16 backend with non-zero verifier key material. Reference secp256k1
  tests use an explicit fixture binding that is not parsed as governed
  deployment material.


<a id="record-e5a5dd3c31da66cb05ff96f093316970ac13b3f8402e451b726674bce3696993"></a>

- Updated Torii capability discovery, disabled-lane messages, destination
  material validation, and diagnostic fallback handling to use the same
  effective manifest readiness helper instead of trusting the raw
  `production_ready` flag.
