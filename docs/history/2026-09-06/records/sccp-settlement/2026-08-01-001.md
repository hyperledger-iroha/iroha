## 2026-08-01 SCCP detached transaction TTL parity repair



<a id="record-47602782df1eeb172bbd3c41f47af0a959169ad08ef834af7dc64451d4dc533c"></a>

- Restored the closed SCCP prepare-to-submit transaction contract after
  signature-bound transaction lifetimes became mandatory. Rust client and
  Torii validation now require the standard 100-second builder TTL and no
  nonce, so Torii accepts the exact payload it prepared while missing or
  non-default lifetimes still fail closed.


<a id="record-90b0e78d4272c86b84d58d0a76e9a4f9affc242280328b6445a3bee9b8f79fab"></a>

- Mirrored the exact TTL invariant in the Swift and C# SCCP validators. Their
  fixtures now use the current ten-field transaction payload, including the
  default lifetime, typed signature-bound admission intent, and absent
  attachments, and cover missing and non-default lifetime rejection. The
  detached-flow specification records the same wire contract.


<a id="record-50576e1cd53299938ea6b8c82d997c457b01cbb33a2d0329c03ee592e2d4ab16"></a>

- The complete `iroha` library suite passes with 513 tests and one ignored;
  the focused Torii direct-submit regression and all 42 focused C# SCCP tests
  also pass. The Swift fixture and validator changes pass diff validation, but
  Swift test execution was unavailable because this host has no `swift`
  executable.
