## 2026-05-30 SCCP TRON route-canary transaction-owner/call binding



<a id="record-6d8c25c05e59cdf2042ecf0a9896ca1b337a5256ed7ccb962adaf6e077199671"></a>

- Added a first-class `tron_route_canary_transaction_owner_address` field to
  TRON route canary evidence, runtime config, Torii conversion, core test
  config helpers, direct/full TOML rendering, live evidence replay args, and
  all-lanes validation.


<a id="record-aec62acb4533fa6b60c951cc4d9926451b1f3e826e3e37bc316a1d2f97cd81e5"></a>

- All-lanes and Rust readiness now fail closed if the owner field is missing,
  malformed, comment/record drifted, or mismatched against the recovered
  signer, preventing a `signature_recovers_to_owner = true` flag from standing
  alone without the explicit owner it recovered to.


<a id="record-f1ff7291f64f298585067b39b671259803f24c97c51e5c3aab2e4ecae3ebda1c"></a>

- The canonical `iroha:sccp:tron-route-canary-evidence:v3` hash commits the
  transaction owner, transaction block number/timestamp, raw-data owner binding
  flag, signature SHA-256, recovered signer address, recovery flag, exact
  `submitSccpMessageProof(...)` calldata SHA-256, decoded payload hash,
  target-domain word, finality-height word, finality block hash, proof version,
  and proof source domain. Direct TRON
  TOML, live replay, all-lanes preflight, and Rust readiness now reject
  route-canary records whose call transcript drifts while the emitted
  `MessageProofAccepted` event tuple remains the same.


<a id="record-8149f1135d13a73bd7dc64ef15e046634a9fcc7f9039164a84c93dc326a0dd45"></a>

- Runtime config, Torii conversion, core all-lanes validation helpers, bridge
  proof fixtures, and ZK consensus policy hashing now carry the TRON v3 call
  transcript fields as first-class `tron_route_canary_*` route records instead
  of dropping them after TOML parsing. The consensus policy hash now also
  commits the existing EVM route-canary transaction fields so governed launch
  material cannot drift outside the signed policy digest.


<a id="record-aaeda622bba27650e37dcffcdd3f5cd9d3da125d29b4e8d39df233e8a672520b"></a>

- Rust builder coverage now also proves the TRON route-canary helper refuses to
  attach evidence when the v3 transcript uses a zero calldata hash, zero payload
  hash, wrong target domain, zero finality words, wrong proof version, or wrong
  proof source domain.


<a id="record-5f3cc37022c7e273aa045d254db1d0af058cdfe38c78d1d16eda73d62da17476"></a>

- Source-event JSON replay args are now rebuilt from the saved source bridge
  domains, owner, digest, canonical source-event calldata, and, for
  post-submit JSON, the raw transaction/signature summary plus canonical
  successful source-proof transaction `Result` bytes. Poisoned stored
  `offline_evidence_args`, drifted domains, mutated calldata, self-consistent
  failed result bytes, and tampered source-event transaction summaries no longer
  emit `offline_source_event_args`.


<a id="record-b00dd660872b25634bbeb8ccb8f6f2f32ee2fc90301e773cc2ed4e03e0136937"></a>

- Source-event witness seals and witness-schedule transition seals now
  explicitly recover every signature to the witness selected by the signer
  bitmap and enforce strict `> 2/3` signed weight before canonical seal
  serialization or production readiness can proceed.
