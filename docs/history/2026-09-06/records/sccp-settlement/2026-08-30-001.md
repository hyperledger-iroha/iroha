## 2026-08-30 SCCP first-release audit closeout



<a id="record-0c6442349db23b58830d7d6b61cda3ea5102b506ea928e0167fd4e7d341f8795"></a>

- SCCP V1 now uses one exact protocol vocabulary across Rust, shared fixtures,
  release tooling, circuits, and SDKs: transfer discriminant `0`, the current
  domain/codec/commitment identifiers, canonical I105 account bytes, and the
  canonical native-transfer wire. Outbound value movement accepts only the
  supported single-key Ed25519 SORA authority, TON transfers cannot target a
  Jetton master, capability reporting requires the outbound material path, and
  retained-state startup still performs SCCP semantic validation.


<a id="record-92349907ed434c69281b70d8b5ca0600904a7ccb508ebf8120e67b215514e534"></a>

- Stale cross-language vectors and circuit metadata were replaced. The Go
  circuit KATs and manifests now use the exact V1 identifiers; their previous
  R1CS, proving/verifying keys, verifiers, and deployments are explicitly
  non-admissible. The validator builder closes symlink cycles, and the TON
  StateInit golden was regenerated and rechecked with the pinned official
  Acton 1.1.0 archive. Non-Rust SDK write methods that could not authenticate
  the exact prepared transaction are removed or internal until they can match
  the Rust admission contract.


<a id="record-507f08a7c6a14d83b7b66ab95ead9aeb0a162b3f7c955e7f3766cf1336117b85"></a>

- Focused validation passes the `iroha_sccp` library check, Go KAT/inventory
  tests and offline build, Python SDK suite (127 tests), JavaScript SCCP suite
  (56/56), Kotlin exact/V1 and mirrored Java harnesses, and C# build plus exact
  (48/48), replay (5/5), and TRON (2/2) suites. The six-suite Python release-
  tooling run passed 331 tests with 28 environment-dependent skips; the
  subsequently expanded TON-golden suite passes 9/9. The full Swift package is
  blocked by the missing ABI-23 `NoritoBridge.xcframework`, and neither the
  workspace-wide gate nor production deployment corridor is claimed here.
