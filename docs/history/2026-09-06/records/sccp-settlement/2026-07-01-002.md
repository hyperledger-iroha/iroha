## 2026-07-01 SCCP bridge proof/receipt replay hardening



<a id="record-257979aba37df0b57471036dd086969819393d4832f0153344f772e988ca7cd2"></a>

- Rejected exact duplicate `SubmitBridgeProof` submissions instead of treating
  them as idempotent success, so replayed proof transactions cannot continue
  into later receipt or settlement instructions.


<a id="record-8440e938bf0a809a9a64591bf5320f53722474312a0fdbc2117b5d722e41014a"></a>

- Bound `RecordBridgeReceipt` to a verified bridge proof hash recorded earlier
  in the same transaction and consume that hash once, preventing fake receipts,
  later receipt replays, and duplicate receipt emission for one proof.


<a id="record-95f38d2b52ca1935c7e5e034ea25ad2e8599a2145fb9c6178636bdfa375afc69"></a>

- Bound typed SCCP transfer receipts to the decoded message proof payload:
  direction, source message id, amount, asset id, and recipient must match the
  transfer, and non-transfer SCCP messages cannot emit bridge receipts.


<a id="record-ffdf8eb6a4edcc38709414f6126a708606f0b524fc8b798886b766f59295e2b5"></a>

- Bound `BridgeReceipt.lane` to the active transaction lane and the
  authoritative Nexus lane catalog/dataspace mapping, so receipts cannot label
  themselves as a different active lane, a retired lane, or stale derived
  geometry.


<a id="record-0cd7eb11639e7539217b8ea77473ffdad146f02ecc2bda2fb634e52429d142f9"></a>

- Required outbound `RecordSccpMessage` execution to carry an active
  transaction lane from the authoritative Nexus lane catalog/dataspace mapping,
  so missing lane context, retired lanes, and stale derived geometry cannot
  record SCCP outbox messages.


<a id="record-3d82853c0c2160e571e025bf7eb337b5867231d13b8d5919b69c6f9f8a663c89"></a>

  bridge proof hash, bridge backend, and decoded SCCP message key, so identical
  proof submissions, overlapping backend ranges, SCCP same-message artifacts,
  and their receipts serialize deterministically under conflict-aware execution.
