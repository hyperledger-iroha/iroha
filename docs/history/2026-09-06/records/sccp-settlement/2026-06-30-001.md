## 2026-06-30 SCCP outbound outbox replay guard



<a id="record-e2a4bde6f168839615fe342149ee55b56598a34151834feecdcc33a17cd30b86"></a>

- Added a durable SORA-origin SCCP outbound outbox registry keyed by
  `(source_domain, target_domain, message_id)` without lane identity, so dynamic
  lane additions/removals cannot replay the same SCCP transaction through a new
  lane to mint twice.


<a id="record-a4c9a323a96ef841ba1ff34839ff0fe1a8cd811ebc346057566944e956020bdb"></a>

- Proposal SCCP commitment roots now exclude messages already present in the
  committed outbox, and SCCP block collection skips failed transactions,
  non-SORA records, and duplicate outbound keys.


<a id="record-819d55261aaf37bd48dae1faf90dff0a5f24ac4766ec5356171530d19e2d1c4f"></a>

- SCCP commitment roots are validated after transaction execution results are
  written, so a failed SCCP record transaction rejects a block that signed a
  commitment to an unrecorded outbound message.


<a id="record-f6dbc9884f76cf5fecc433dac3030aa0cb948d479c10ad005439c7927a79abca"></a>

- Signed-block SCCP collection, committed transaction replay, and approved
  transaction event production now use canonical external-entrypoint indices,
  so sealed/private entrypoints before a signed SCCP transaction cannot shift a
  failed result into an apparent success.


<a id="record-11afe4630d2d1b85665c7c82aa15272b0fdef33552cd21dc437a6dca32f1be4e"></a>

- Proposal-time SCCP collection now explicitly matches the same signed
  entrypoint surface as committed blocks: plain external transactions and
  sealed reveals can record outbound SCCP messages, while sealed commitments,
  and time entries are ignored. Regression coverage keeps sealed-reveal records
  at their canonical entrypoint index after a preceding sealed commitment.


<a id="record-23ce506fa36eddc2163ffd4c34fbd6499495310d35157c2d5d5237daf308066a"></a>

- SCCP record access derivation now writes the deterministic outbox key for
  valid SORA-origin records and serializes invalid or inbound records globally;
  SCCP record overlays are treated as durable state changes, and committed
  outbox records reject same-message replays on later blocks even if the current
  lane changes.


<a id="record-53a60d2669fedec8aaea84488677391aa59467510d135cba18339f7d5fb12c76"></a>

- Added adversarial coverage for record encoding aliases and rollback:
  canonical binary and lowercase-hex representations of the same SORA-origin
  SCCP record now derive the same scheduler write key, and a duplicate-record
  rejection inside one transaction overlay does not leave a durable partial
  outbox write.


<a id="record-396d1c4226fc40ad73f721b8e668de71f417a719e2c5f86cc293a719eef022f6"></a>

- Failed IVM-proved overlays now have direct regression coverage proving the
  SCCP proof-authority flag is restored before a later plain overlay can try to
  record SCCP messages in the same state transaction.


<a id="record-d45c3e372cae4eaa8ef7e9b3bb0a2cdc77d5c896060846eaf26b5dbdd99c8c6c"></a>

- Snapshot and tiered-state persistence now explicitly preserve the SCCP
  outbound replay registry, so restart recovery and cold-tier rebuilds cannot
  silently drop committed outbox keys and allow cross-lane replays after dynamic
  lane topology changes.


<a id="record-9d692b270e8458ebf79eec00cacebe819ff1d049620977f159d6e70a34d324d8"></a>

- Core SCCP launch-readiness fixtures were realigned with the current governed
  source-adapter material: BSC uses the config-aware source material constructor
  and Solana/TON use governed full-light-client audit hashes, keeping the broad
  SCCP core filter green while preserving cross-domain material rejection.
