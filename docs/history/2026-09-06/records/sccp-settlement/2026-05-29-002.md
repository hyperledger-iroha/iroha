## 2026-05-29 SCCP TRON route-canary transaction evidence



<a id="record-db5c53560e86cd0fc8f4041be56cb54333e84086e0b5d519f22e4877f519d1da"></a>

- Extended `scripts/sccp_tron_live_evidence.py` with
  `--route-canary-transaction-id`. The live helper now reads the TRON verifier
  transaction receipt, verifies the `MessageProofAccepted` log against the
  deployed destination binding, backend, proof-family, and network views, binds
  the validated route allowlist hash, then fetches the raw transaction and
  validates its `TriggerSmartContract` call to
  `submitSccpMessageProof(bytes,bytes32[6],bytes32)`.


<a id="record-b1cd0ab79376ca8f39379d26457e8aceeafc1ee6ae2218af6517c3545d6fc4e8"></a>

- Route-canary readiness now checks the submitted selector, ABI public inputs,
  statement hash, non-zero 384-byte Groth16 proof tuple, proof header
  version/source-domain/message/commitment fields, raw `txID == sha256(raw_data)`
  binding, destination verifier address, canonical recoverable secp256k1
  signature recovery to the transaction owner, zero value/token fields, and
  receipt success before querying `usedMessageProofs(messageId)` on the same
  verifier and deriving the route canary evidence hash only when current
  contract state marks the accepted message id consumed.


<a id="record-bf9d5f5b84960eb2b4b998c85d2382ebb13b3df8029b2529d27a6807d3416a01"></a>

- If operators provide both `--route-canary-transaction-id` and
  `--route-canary-evidence-hash`, the manual hash must match the
  transaction-derived value. Live `offline_full_toml_args` and `--full-toml`
  output now require the verified transaction-derived canary, and the rendered
  TOML carries route-canary transaction metadata comments plus the
  `usedMessageProofs` state-check result, raw transaction owner binding result,
  signature hash, recovered address, and signature-recovers-to-owner result.


<a id="record-50b98bea006561acf863d0d5ff81219c795f2ef0253304ab93856c357df27478"></a>

- All-lanes preflight now requires those TRON canary transaction comments and
  recomputes the expected canary evidence hash, rejecting missing or drifting
  live TOML metadata before accepting the proof event. The direct TRON
  renderer now requires the same `--route-canary-transaction-*` metadata for
  `--full-toml` plus `--route-canary-used-message-proof`,
  `--route-canary-raw-data-owner-matches-transaction`, and
  `--route-canary-signature-*` recovery metadata, derives the canary hash when
  no manual hash is supplied, and rejects transaction/hash mismatches.
  Added positive and mismatch regressions plus manual-hash-only,
  destination-binding mismatch, missing `usedMessageProofs` state, wrong raw
  verifier contract, wrong submit selector, public-input drift, proof-header
  drift, direct-renderer transaction mismatch, missing/bad signature recovery,
  and all-lanes transaction/state metadata drift rejections.
