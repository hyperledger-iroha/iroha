## 2026-08-27 TRON SCCP recipient and concurrency hardening



<a id="record-c6236659f3582eb9b58670e3c33f605d993e3c108975ebf4696e94fd46ad0e90"></a>

- A complete scoped Codex Security audit found three medium-severity TRON/TVM
  SCCP issues. The shared Solidity codec now enforces Ed25519 prime-subgroup
  membership and rejects the canonical mixed-torsion fixtures that native
  Taira rejects, preventing an irreversible burn to an uncreditable account.


<a id="record-6f13c32646b8059cbea922359b1d7b423ed0dba38b6d314740253322593c9039"></a>

- TRON outbound transfer nonces are caller-specific, so unrelated holders may
  use the same nonce without invalidating one another; sender binding keeps the
  resulting messages distinct. Direct TRC20 allowance replacement now requires
  an owner-authenticated zero-first transition even when a spender has already
  consumed the visible allowance.


<a id="record-907b5111e1a2c6716b115dc25417a57a7037178b01f717d8862f06b6c18b1789"></a>

- The authenticated Solidity 0.7.4 contract smoke, including the new subgroup,
  two-holder nonce, and allowance regressions, passes. The TRON route runtime is
  23,800 bytes (776 bytes below the deployment ceiling), the regenerated
  artifact lock passes the static TVM corridor, and all 52 artifact-corridor
  Python tests pass. Focused Rust execution was not started while unrelated
  Cargo jobs were actively using this checkout; the native transfer selector
  and wire payload are unchanged.
