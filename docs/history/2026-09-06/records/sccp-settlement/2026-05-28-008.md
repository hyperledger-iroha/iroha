  BOC submission builders now reject transparent public inputs whose target
  domain is not TON before a portal/mobile UI can invoke a local TON prover or

<a id="record-57dde83f5417dc55887442cbc0ab2cddb37d22c2d88d98537c8dabfdda8794e6"></a>

  prover wrappers now bind the 12-word Groth16 ABI proof tuple to the request

  public-input binding before emitting `submitSccpMessageProof(...)` calldata,
  closing the SDK path where a structurally valid proof tuple could be paired

<a id="record-1525f9370b4d73c9e18446831f4a8717901715a28f3b73cec93ba8bdb033a5bf"></a>

- The JavaScript package entrypoint now exports the same low-level
  transparent public-input ABI-word encoder and checked
  `submitSccpMessageProof(...)` calldata encoder already available to other SDK
  consumers, so web portals can package wallet calls without relying on
  internal-only helpers.
