## 2026-07-11 Kotodama V1 data-processing corridor (validation in progress)



<a id="record-91bc127db89af4871697e6e5f5a1559cc6ccfb68a5f6b94c1a5f8484c06c07cb"></a>

- Implemented the clean Kotodama V1 source break. Rust-style tail expressions,
  active-only `Option::some`/`Option::none` and `Result::ok`/`Result::err`,
  exhaustive namespaced patterns, `if let`, same-family postfix propagation,
  named struct literals, and non-mixed named calls now lower through the typed
  IR. Retired placeholders, positional structs, unsafe indexing, mixed call
  styles, and raw compiler-internal helpers fail with stable diagnostics and
  safe fix-its where the compiler can prove the rewrite. The branded
  `seiyaku`/`誓約`, `kotoage`/`言挙げ`, `hajimari`/`始まり`, and
  `kaizen`/`改善` pairs remain the only paired declarations.


<a id="record-98f930db8d57dd1db2ca23a6c583a69513dc2265444bce8cf86c146458dc122d"></a>

- Added compiler-owned `List<T, N>` values with capacities `1..=64`, contextual
  literals, bounded comprehensions, safe transactional mutation, nested value
  equality, and contiguous deterministic storage. Recursive List schemas carry
  their capacity across entrypoint and state boundaries; resource and
  zero-sized elements are rejected. Sugar-equivalence tests compare final
  emitted executable code, not only intermediate nodes.


<a id="record-cd210942d2e0c7f87498bd1600fecdfb68c0e8875b4ac22ee2c7ae6e25f92735"></a>

- Added the canonical V1 numeric family: signed 512-bit `int`, exact signed
  `decimal`, and nominal non-negative `quantity`, with canonical scales
  `0..=28`. Exact arithmetic, finite exact division, and explicit rounded
  division use deterministic limb work; constants fail during compilation and
  runtime failures remain VM errors. Pointer IDs `0x0010`, `0x0011`, and
  `0x0012` name schema-bound `QuantityValueV1`, `IntValueV1`, and
  `DecimalValueV1` frames, while `0x0013` is unknown and unassigned. Retired
  `Amount` source syntax is rejected without retaining an ABI tombstone.
  Legacy source spellings, cross-typed pointers, and noncanonical numeric
  payloads fail closed.


<a id="record-b2bc644c161b9e9296e337afd85116ecd912f9c08eaa9fe0ad15a6f2dff878e1"></a>

- Hardened V1 pointer materialization and host decoding so canonical argument
  TLVs can spill from INPUT into allocated HEAP without being rejected by
  ledger mutations, core queries, codec helpers, or nested-call decoding.
  Production decoders now reject stack, OUTPUT, unallocated HEAP, and arbitrary
  code offsets through the central provenance validator.


<a id="record-20c353a97a1cf51690839119317ee8f92a01217c0ff6c7edac27119262ee8a87"></a>

- Completed the asset-mutation caller migration to canonical `QuantityValueV1`
  TLVs, including generated mint bytecode and WSV/CoreHost fixtures. Generated
  fixtures now authenticate pointer literals in `LTLB` and load them through
  `LDLIT`. Typed `JSON_GET_JSON` quotes accept HEAP-backed input and cover a
  HEAP-sized result plus the sum handle.


<a id="record-bdc2eb9a685048ea00fb0ea8dcbebc0c18379580922ae41c2b9841071a2896bf"></a>

- Pure Kotodama `#[test]` suites no longer require a deployable runtime
  entrypoint: runtime projection is optional, while suite execution, coverage,
  and profiling continue from the test artifact.


<a id="record-45fa3c0f81abe1e754ce1b9243b27667359cf70655a7ecdf36bccad440ebffe0"></a>

- Added canonical native `json { ... }` and `json [...]` construction, recursive
  List/Option/int/decimal/quantity conversion, lowercase byte hex, duplicate-key
  rejection, and typed `Option<T>` getters for the canonical numeric family.
  The account, asset, asset definition, domain, and NFT query families now
  return typed views or bounded `QueryPage<T>` projections in canonical ID
  order. Hosts perform one ledger query and one projection decode, and
  deterministic gas covers query items, collection elements, numeric limbs,
  and encoded bytes.
