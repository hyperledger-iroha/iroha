## 2026-08-26 Kotodama correctness hardening



<a id="record-b8ca2628434b1413953bd5f94a442c3aedf19bef3e0703f0693b231a7c7217f8"></a>

- Parser recovery now respects top-level item delimiters in minified source instead of swallowing
  the next valid declaration. Semantic analysis keeps bounded-loop bindings scoped, applies numeric
  context to both ternary branches, and tracks returns, propagation, breaks, continues, and scalar
  state writes through expression-valued control flow.


<a id="record-9ef8a93059f54964bac80b2cfa9dc6e781e6bd093602cb38d71c629fcc722f99"></a>

- Loop-tail uses now count for state/parameter lints. The on-chain policy checks function parameter
  types and recursively inspects `Option`, `Result`, `List`, and `Secret` wrappers for invalid
  `StateMap` keys.


<a id="record-fc73ed7b45e064c486b126ba970ffba09ecfcc2a28077c9d3acb6d40f8ab4d86"></a>

- Source reentrancy analysis uses the canonical builtin effect registry, preserves expression
  evaluation order, carries state writes across branches and loop iterations, and no longer treats
  similarly named user functions as host calls. Manifest access facts now remain conservative when
  dynamic call sites precede literal or authority-derived arguments.


<a id="record-fbbf020380c117d85570814d4086ffaf8f03599dad45da5b1b3fb1c1ff13649f"></a>

- Isolated validation passed: all 1,027 library tests, 56 integration tests, and the crate doctest;
  scoped formatting and whitespace checks; and strict all-target Kotodama Clippy with dependency
  linting disabled. Workspace-wide formatting and dependency Clippy remain blocked by unrelated
  dirty-tree syntax/strict-lint failures outside Kotodama. No ABI, wire-format, or lockfile changes
  were made.

## 2026-08-26 Windows native-SDK CI portability repair



<a id="record-1376fc79166b96368099086200cb430bba21412901720d9881e82fef81e1a11d"></a>

- Replaced unstable Windows `std::fs::Metadata` identity/link extensions in
  Core, genesis, and IVM security-sensitive readers with stable
  `GetFileInformationByHandle` snapshots. Path sampling opens reparse points
  without following them, retains volume/file identity plus revision fields,
  and fails closed on directory, reparse, replacement, and hard-link-policy
  violations.


<a id="record-86f262f497535474cf590c184e1761a94a1bf350bd47c65aa8a34ff718985f8c"></a>

- The readiness Git-isolation self-test now supplies an explicit synthetic
  author identity for every commit, removing its dependency on hosted-runner
  Git configuration.


<a id="record-5a99f10c70940b941e9747e59c4d42cb963d664d520f1c0b3c4c8cde34332011"></a>

- Validation passed: Core library check; Windows-target `iroha_file_mmap` test
  compilation; native `iroha_file_mmap` tests (3), focused genesis test (1),
  IVM state-overlay tests (8), native-artifact checker tests (70), the mobile
  Python 3.12 contract, shell/Python syntax checks, workspace formatting, and
  scoped diff checks. Full local Windows dependency-graph validation remains
  unavailable without MSVC/native C tooling; the hosted Windows lane is the
  authoritative follow-up. The readiness self-test passed its repaired Git
  control locally before reaching an unrelated macOS extended-attribute
  custody failure in this checkout.
