## 2026-08-29 derive first-release simplification



<a id="record-2de3b10adf4671c7fbb37c9995cb14ebeb2a6ee9f7aae89c511c037f5eef4d7b"></a>

- `FromVariant` now parses its two conversion controls directly with `syn` and
  emits conversions only for the exact newtype field. The unused implicit
  container-lifting path and `skip_container` compatibility attribute were
  removed, eliminating hidden allocations, extra implementations, and their
  coherence risk. Invalid or duplicate helper attributes produce accumulated
  diagnostics instead of being ignored.


<a id="record-7749262e6d4cffe40bfdb07e4129429338c41b162d759586173b91d6424c286f"></a>

- `ReadConfig` now has one field-name-based schema. The unused `key` remapping
  path and duplicate-effective-key machinery were removed, and the two live
  remapped fields were renamed to their canonical first-release configuration
  names. Wrapper analysis recognizes only the supported `Option` and
  `WithOrigin` spellings without recursive type allocation, while indexed
  generated bindings prevent user field names from shadowing macro internals.


<a id="record-bd8148f2d3555516da0404306708f5d0e746a9015e81f4eddd2b59d3a8e653a1"></a>

- Normal derive builds no longer activate `iroha_derive_primitives`' optional
  `darling`/`strum` repr parsing stack; those dependencies are gated behind its
  `repr` feature. Unit, doctest, trybuild, downstream macro and
  telemetry-function tests, plus strict all-target Clippy, cover the simplified
  behavior and retired attributes.



<a id="record-5a4b547494ee5628b1e7295fad963c78d23b581dfa6197376eeed96c2db5cd9c"></a>

<!-- Original context: Status / 2026-08-29 Telemetry first-release simplification -->
- Status telemetry now has one complete V1 Norito layout. Three parallel
  compatibility payload mirrors, progressive/truncated decoders, conversion
  copies, and compatibility defaults were removed; incomplete binary payloads
  are rejected and exhaustive round-trip tests cover every status field.


<a id="record-f4d91891b77ae249983c1097128cdef13234ee868277465b0520bbc2dbbfeadb"></a>

<!-- Original context: Status / 2026-08-29 WSV first-release simplification -->
- The IVM mock WSV now accepts provenance-valid V1 typed TLVs for account and
  asset registration instead of raw integer stand-ins. The parallel integer
  maps, snapshot copies, and constructor variants were removed, and positive
  host tests now exercise the same typed boundary as production.


<a id="record-df646a63c1a17a043c5f89471a77315be0d274c4b1f7c5161ae51a3657f903c6"></a>

<!-- Original context: Status / 2026-08-29 Torii MCP security, protocol, and stale-surface audit -->
- Faucet prepare/submit are restored as schema-derived write tools after adding
  a signature-bound marker version to new prepared faucet transactions. Core
  derives an authority-scoped semantic-claim key, stages it during stateful
  admission, serializes parallel candidates on that key, and persists it only
  after transaction execution, fees, and triggers succeed. The marker lives in
  durable consensus state and therefore also protects generic transaction
  ingress and replay after restart; failed transactions do not burn claims.
  Every prepared faucet transaction must carry the complete marker, and Core
  rejects prepared-faucet metadata that attempts to omit it.
  Nodes with no faucet runtime configuration omit both tools from discovery and
  reject direct calls uniformly as `tool_unavailable` before schema or dispatch
  work.
