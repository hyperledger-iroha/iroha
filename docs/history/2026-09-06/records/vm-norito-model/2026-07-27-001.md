## 2026-07-27 ABI-21 native SDK artifact gate (rebuild still pending)



<a id="record-0c3dcb38c10b7b896f131ade1f0171960fc8430fd8967af02634ebc092752742"></a>

- Added a canonical host-artifact manifest for C/JNI, C#, Node, and Python that
  binds stable artifact bytes to one exact clean Git commit, calls the ABI
  probe, requires ABI exactly 21 plus the lane's appeal-finance symbols, and
  rejects noncanonical manifests, links, replacement races, stale source, and
  ABI 19/20/22.


<a id="record-44a86a48317c46fb543c09879a8d2df0c6dafdb05587ab4ca2fda6e2b325ba77"></a>

- Node staging, runtime loading, and release-provenance collection now reject
  missing/dirty/stale native provenance. The then-current local, ignored Node
  manifest recorded a dirty source tree and was therefore intentionally
  unusable as release evidence; no checked-in production manifest exists until
  a genuine clean rebuild supplies one.


<a id="record-a105df5e53c9c8d24ac8bc34a7df3a10f96148d8b955da0233a81d9614b6b9c5"></a>

- The host JNI and C# lanes record and reverify the new manifest. The Python
  SoraFS lane is pinned to 3.12, derives its target from the actual interpreter,
  and rejects skipped native reference tests. The obsolete tracked
  `_crypto.cpython-39-darwin.so` was removed. Its mandatory runner now rejects
  every tracked package `.so`, `.so.*`, `.dylib`, `.pyd`, or `.dll`, activates
  the selected virtual environment, covers the cancel-asset-lock,
  reference-validation, and provider-ingest suites, and rejects JUnit skips.
  The separate SoraFS pin-register SDK workflow, runner, and guard are also
  pinned to exact Python 3.12 and install only `requirements-ci.lock` with
  `--require-hashes --only-binary=:all:`; a lock-removal negative control
  prevents a return to implicit or unpinned dependencies.
  Swift and Android packages remain under the separate source-sealed per-slice
  mobile artifact checker.


<a id="record-1765d0722f0677304644a4c9c323c750143b8e77ed2a331c9e1a0c14fcf013c5"></a>

  Node tests with zero skips, 116 SoraFS release-automation tests, and all 9
  static Python workflow-file checks. A fresh isolated CPython 3.12.13
  pin-register venv passed 3/3 tests; its positive static guard and changed
