## 2026-06-30 Kotodama scoped transfer and contract receipt surface



<a id="record-71801574508a051ebd8c8249bfe2b11df9fe3a31574d87e7cb9ac04f57b4938a"></a>

- Added the ABI v1 scoped numeric-asset transfer syscall surface for
  Kotodama-driven private-IS settlement. The new contract form passes
  `from`, `to`, `AssetDefinitionId`, `Numeric`, and `DataSpaceId` through
  registers `r10`-`r14`; the ledger host queues a scoped
  `Transfer::asset_numeric` against the dataspace balance.


<a id="record-3f3dc607cb8b124b7a0776638e1e17289d541535485b681a48ce44db5a625c8b"></a>

- Refreshed Kotodama semantic lowering, register allocation, compiler access
  hints, default/core/mock host validation, syscall docs, and golden syscall
  tests for the first-release scoped-transfer ABI. The batch-internal
  `TRANSFER_V1` surface remains separated from the public scoped transfer
  syscall.


<a id="record-e7b42220a07fc6ec494169e39ee045b891d694ed0d772f36f9284fec5bd19205"></a>

- Added normalized `operation_receipt` evidence to Torii contract call/deploy
  responses and Rust contract helper output. Receipts include operation kind,
  status, transport, dataspace, contract identity, hashes, gas metadata, and
  a payload digest without exposing private keys or raw payloads.


<a id="record-f3e270b7979c1264b81a5ed87513c414e4a4c5f1eb18af82a42131065b85430e"></a>

  `payload_digest_hex` with the deployed artifact `code_hash_hex` so Torii and
  the Rust deploy helper report the same artifact digest, and regenerated the
  ABI hash section in `specs/ivm_header.md`.
