## 2026-08-28 Kagami first-release simplification and hardening



<a id="record-7915d6a8a299d5426fcdaba37fcd1a4f0bb189a2062d4a9f29b2fe2da7797a65"></a>

- Kagami now exposes one validator PoP/key-generation path and one Docker
  manifest path. The duplicate `genesis pop` and `swarm` commands, two unowned
  development binaries, empty `codec` and redundant `bls` features, redundant
  localnet random-key switch, terminal/private-JSON key shapes, and obsolete
  developer scripts were removed. BLS remains mandatory through `node-crypto`.


<a id="record-2d8c49952a1c6fea5bdfe994062f50ac7db42930fe5402be85eeccfac43f971e"></a>

- `kagami genesis sign` accepts only an owner-held, mode-0600, single-link,
  canonical private-key file. The key encoding supplies its algorithm and the
  manifest supplies its consensus mode, so raw private-key, seed, algorithm,
  and consensus-mode signing switches no longer create alternate first-release
  paths. Secret-bearing arguments are not `Debug`/`Clone`, seed buffers are
  zeroized even after an exact-length hexadecimal decode failure, malformed
  secret-bearing TOML diagnostics discard their source, banners never disclose
  seeds, and canonical wire encoding—not a filename extension—is the
  signed-genesis invariant.


<a id="record-4c9c2f8f52ae8f43cd6addd7bc8f282c749a91a48e3a27404b39503599f09a81"></a>

- Codec, Kura inspection, and Compose generation share one atomic output
  publisher. Failed renders preserve existing output; symbolic links, special
  files (including non-blocking FIFO rejection), input/output aliases, and
  writes into protected prepared-config trees fail closed. Prepared config,
  peer override, codec, block-index, block-wire, and private-key reads have
  explicit first-release bounds, and codec output accounting includes headers,
  summaries, ANSI decoration, and final line terminators.


<a id="record-92e3f06c0524e46d4ca376a3ac279943515971506a86c4ee7858b7debd3a7aaf"></a>

- Kura inspection delegates sidecar decoding and height/hash validation to the
  canonical indexed-pipeline reader. It processes indices in fixed batches and
  reuses a block buffer, avoiding request-sized index allocations and repeated
  block-buffer allocation. Checked-in development configs now have one
  four-peer naming scheme, and repository/public docs and callers use only the
  canonical commands.

  Clippy passes with `-D warnings`; its dependency build still reports seven

## 2026-08-28 IVM lifecycle, rollback, and durable-overlay closure



<a id="record-630702da300cfb5198f03e3fc1e360e1d4b0e9f392ea0aae409daf8acb142a12"></a>

- Made the decoded-op ceiling a cache-retention policy rather than a program-
  validity rule. Identical bytecode now has identical admission and execution
  results on cold, warm, disabled, enlarged, and subsequently tightened caches;
  oversized decoded programs execute without being retained.


<a id="record-7bbfd625ff8efbded17fa6e7d54542f183b46a71e90096145adff1f65fed7476"></a>

- Hardened reusable-memory lifecycle boundaries. Shorter program loads clear
  stale code tails, program replacement scrubs the complete physical heap and
  allocator state, transaction rollback survives template-cleaning operations,
  and runtime templates carry an unforgeable per-memory lineage. Production
  Core, executor, and Soracloud pools now retain each reusable VM together with
  the exact template that created it, including overlapping cold replacements.


<a id="record-a9b417c9a04da64787baf2734956d219aab835fbf6ca92a5713b34be911ade06"></a>

- Made sequential block rollback exact and fail-stop. Checkpoints preserve
  metering, argument escrow, staged contexts, diagnostics, memory provenance,
  and access logs; unsafe checkpoint creation during a syscall or isolation
  scope is rejected. `IVMHost::restore` returns a typed error, and any missing,
  failed, or panicking rollback detaches and poisons the host before the VM can
  execute more work.


<a id="record-f7497a340664038cb78f226b9b5c7939e6b0110e5e8bcef63116f98e444238c8"></a>

- Replaced path-relative overlay persistence with retained-directory-handle
  traversal and sibling publication on Unix and Windows. Every deferred lookup
  parent is revalidated, clones serialize publication and poison state, and a
  durability error after atomic replacement retains the published in-memory
  image while making later writes fail stop. Unix rejects group/world-writable
  final parents and non-sticky writable lookup namespaces; same-UID,
  privileged, ACL-authorized, and Windows final-DACL writers remain documented
  operator trust boundaries. Two independent read-only security reviews found
  no remaining blocker in the scoped delta.
