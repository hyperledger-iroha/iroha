## 2026-07-13 Kotodama V1 security, numeric, and artifact closure



<a id="record-a8a6634ae88c525e6d5f7d406f0327d03a7f7177194906d6d6eab04b667bf503"></a>

- Kept the branded declaration surface as the language identity:
  `seiyaku`/`誓約`, `kotoage`/`言挙げ`, `hajimari`/`始まり`, and
  `kaizen`/`改善` are first-class, while their English feature aliases remain
  rejected. The only source numeric types are the exact signed `int`, exact
  base-10 `decimal`, and nominal non-negative `quantity` domains. Retired type
  spellings are rejected for declared types and source-unit identities, but
  remain valid in value and function namespaces, including entrypoint names.


<a id="record-e2089cf6335b20fbc6850f95440df8b668bcd57f9e9be13bbd990f83fda9ecd3"></a>

- Extended that branding through the complete source capability surface:
  execution context, seiyaku queries, exact kotoage grants, and local test
  invocation now use `seiyaku`/`kotoage` spellings. Their former English
  `contract`/`entrypoint` paths are rejected rather than retained as aliases;
  internal ABI, syscall, and data-model identifiers remain unchanged.


<a id="record-cccfa4e4caaaa2337c53f9b26560b3af26e177970cc6eece235496b0a626f693"></a>

- Unified deployable project construction in the Rust compiler driver. `koto
  build|doc`, `musubi build`, and `iroha contract dev` now share portable
  project-relative source names, the content-addressed `ModuleBuildGraph`,
  linked-interface generation, cache authentication, and atomic publication.
  Musubi no longer owns a second `.ko` walker or logical-path normalizer;
  deterministic package discovery is sorted, bounded, symlink-free, and skips
  generated/cache roots. All three frontends thread an explicit ZK compiler
  policy, and the no-metadata default links only the selected root with no
  invented imports or wildcard exports.


<a id="record-b4263b2b24bea5ad0d1eb719f37152fe3b8d39d2a1f56620c24885ba305e83de"></a>

- Made project validation share that typed-HIR graph instead of falling back to
  isolated source checks. `iroha contract dev` linting now consumes the exact
  root/import/package request, retains module-owned warning sources plus their
  locked package identities and cross-file error spans, and groups records
  deterministically. `koto check|build --project` and contract dev consume one
  versioned Norito JSON graph with exact root imports, locked package
  identities, module paths, exports, and transitive imports. Positional checks
  and LSP documents never infer cross-file authority: modules are independent,
  root/module mixtures require an explicit manifest, and multiple `seiyaku`
  roots are rejected. `koto lsp --project` checks open-buffer overlays against
  that same exact graph and uses its locked sources for unopened files.
  Diagnostic spans retain package identity separately from
  logical path, and one canonical source file cannot be owned by two graph
  nodes even through a symlink alias.


<a id="record-a9890308876b94dc4cd4f80f68c8ab8bb834960923b7a2371408013a06979611"></a>

- Closed the remaining compiler resource-budget bypass. Named product types
  are canonical shared `Arc` DAGs whose memoized expanded node/depth facts are
  enforced at declarations, explicit use sites, and every inferred typed
  expression. Exact depth 256 and five repeated shared-DAG references remain
  valid; depth 257 and six explicit or inferred repetitions fail with `K2008`
  at exact spans. ABI word counting stops immediately after crossing the
  13-register argument window.


<a id="record-db5756520b780ab1c31f0a9220c1303a09aff7cdcc868342c5e1767061ba6461"></a>

- Preserved exactly-once public argument decoding across quarantine preparation
  and mandatory live-state rebuilds for both `ContractCall` and raw
  self-describing IVM transactions. Reuse requires the exact signed canonical
  record and compiler schema under the pinned Norito layout; changed bytes force
  a fresh decode, while every rebuilt VM still prepays decode/materialization
  gas.


<a id="record-49d7cbe745c82797a8a5ccd83cef4fa75fed1eaec495a599b9eaad695a7c6a17"></a>

- Restored scheduler precision for direct, literal `StateMap` entries without
  trusting CNTR. Prepared bytecode now proves that one authenticated canonical
  `Name` literal reaches each selected state syscall on every path before an
  exact hint is accepted. Distinct proven children remain independent and the
  same child conflicts; dynamic keys, helper-hidden calls, ambiguous paths,
  forged hints, and failed preparation retain `state:*`. Compiler metadata now
  marks computed StateMap paths incomplete and emits exact child keys without
  the former non-conflicting base-key over-approximation.


<a id="record-051913f172005be5a965bc5b99136d029ead9b90d08d291165828e867b82b419"></a>

- Removed the empty pre-execution opcode denylist and its artifact-sized scan.
  Preparation remains the single authority for opcode/syscall validation and
  predecode; live dispatch now applies header, ZK, governance-fuel, and cycle
  policy from authenticated prepared metadata only. A warm-cache regression
  resolves the summary with no artifact bytes and proves that policy causes no
  hash, preparation, or opcode rewalk.


<a id="record-7ba79541a577676ad8b19093940ba7817ac8dcecd501c16f80b56ebe45655177"></a>

- Threaded the same immutable `PreparedContract` from transaction overlay
  construction into scheduler access derivation for deployed, raw, and proved
  calls. Manifest and bytecode-fence checks now consume prepared metadata and
  predecode directly; bound calls borrow world-state manifests and avoid
  cloning code records. IVM triggers retain and decode-validate the canonical
  deployable hash once, then use the shared prepared cache. A repeated-access
  regression proves no artifact allocation change and no additional hash,
  metadata parse, decode, prepared load, or runtime-template build.


<a id="record-e861d2273bbd74124ed7bb1c5de01263dd906709034cfe69142832eb7358b7a9"></a>

- Replaced whole-function register-pool selection with deterministic
  call-aware intervals. Values live across an internal or host ABI clobber and
  host operands whose multi-step staging is not yet complete occupy preserved
  homes; parameters and values born, consumed, or confined between calls reuse
  `r10..r22`. Spill-split reload clusters stop at clobbers, internal arguments
  and tuple returns use cycle-safe parallel ABI moves, and high-pressure leaves
  save only the preserved registers they actually use. Added loop, join,
  multi-call, pressure, determinism, stack-traffic, and runtime tuple-return
  regressions; focused execution is pending while the shared validation
  corridor owns Cargo.


<a id="record-fe26c394e705d36710eed232e5d33a733909cf4fa2ae8e103fdca42e618744ad"></a>

- Added all seven direct exact-decimal, five isolated runtime-phase, and the new
  interface-summary Criterion identities to the fail-closed candidate inventory
  and bound that policy to the benchmark sources so added, removed, duplicated,
  misclassified, or unsampled paths are rejected. The historical
  `kotodama_phase_semantic` ID again measures its exact pre-reset
  `resolved.type_effect()` workload; signature-only work now has the distinct
  `kotodama_phase_interface_summary` identity. The selected comparison parent
  contains none of the 13 new identities, so CI runs each revision's native
  harness and forbids copying candidate benchmark source into the base.
  Promotion into the 5% set requires an independently captured predecessor
  with the same identity and workload.


<a id="record-63a8c2533717fe90b219dcf91bb63fd031adfd6e5eef71b37264f2ae5bbae2b2"></a>

- Hardened executor result framing to a fixed `u64` total length, a deterministic
  1 MiB cap, and a fully readable VM slice before canonical decode. Validation
  and migration reject short, oversized, cross-region, trailing, malformed, or
  noncanonical results; migration no longer assumes success for undecodable
  guest output, and the host performs no guest-sized result allocation.


<a id="record-2b7e75a8ba67ebbde243a9f71a7513409e2407de438e464021a475d9f6fd194a"></a>
