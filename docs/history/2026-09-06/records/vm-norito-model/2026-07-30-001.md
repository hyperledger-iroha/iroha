## 2026-07-30 Governed IVM heap ceilings



<a id="record-a1cc4b5b5c2ae39935ba87bc1ad5cbc2906c5d561d17529925d6d4e03ddc7000"></a>

- `smart_contract.memory` and `executor.memory` now define exact IVM heap
  ceilings in bytes instead of inert read-back values. Both default to the
  complete 1 MiB ABI-v1 heap window, and governance rejects larger values
  before changing world state.


<a id="record-12c51e8f691ade7d9a502c6314294a0212db5bb4b9f7288d2f20a5055a353307"></a>

- Cold, warm, generic, nested, trigger, view/simulation, proved
  derivation/replay, and runtime-executor VMs apply the matching governed
  ceiling. Heap growth cannot bypass it, and runtime pool keys include it so
  parameter changes never reuse stale memory authority.


<a id="record-9d3ef36ed6898e7228fd5c40e79c6bedf7daa02a275d3986e409fbe54dcd12ac"></a>

- Regression coverage exercises the absolute memory ceiling, cold/warm cache
  separation, generic and nested runtimes, executor runtimes, and governance
  boundaries. Exact Rust formatting and whitespace validation pass; focused
  Cargo validation remains pending the shared serialized validation lane.

## 2026-07-30 IVM parallel fail-closed execution



<a id="record-664494204e5ce0e04ef1cf98be30c1ea8214f912ad00af263e1ccf200713e9c1"></a>

- Simple-instruction ILP batches now derive and reserve their complete checked
  gas cost before launching Rayon workers. An unaffordable batch performs no
  work or state mutation; a started batch retains its reservation even if an
  independent instruction faults.


<a id="record-4789461223dc33aee14d83928d3cc022898014fd162ca283ad42c46e9e1237f4"></a>

- Parallel transaction executors no longer convert panics into normal
  zero-gas failures. Panics propagate after deterministic cleanup restores the
  worker's prior SIMD override and the VM's temporarily shared host.


<a id="record-264fa2615a310955256b1c3a740c34bef7cfb016e70f2c3ebb5d361da94747f4"></a>

- Removed the redundant manual `Sync` implementation and the obsolete manual
  `RefUnwindSafe` marker from `IVM`; compiler-derived auto traits now reject
  incompatible future fields. Focused panic, reservation, structural-trait,
  and Metal-feature validation is queued for the serialized Cargo lane.

## 2026-07-30 Bounded identifier and JSON data-model invariants



<a id="record-89027142f80fdd48a0af31eab31b4d20ae7551874ce3f509664d6c58bd676f59"></a>

- `Name` now has one 255-byte UTF-8 ceiling across borrowed/owned
  construction, NFC normalization, JSON input, and both Norito decode paths.
  Unicode control characters (including NUL) and bidirectional controls are
  rejected before a value can become an identifier or metadata key.


<a id="record-4a57bbb52cb7b9261cd3b1a815b71ce31d47a8deeb7cc032f16c751d5226863c"></a>

- `Json` now admits only one well-formed Norito JSON document, with a fixed
  1 MiB UTF-8 ceiling and the existing deterministic V1 structural-depth
  ceiling. Its slice and archive decoders inspect the nested string length
  before allocating, and the former safe unchecked constructor has been
  replaced by the fallible strict `from_raw_json` API.


<a id="record-efc1446fc6003884dadeddb89ad5f714a026795d4014becaf9fb11a596443f3a"></a>

- Constructor, JSON, packed-slice, and framed-Norito regressions cover exact
  byte/depth boundaries and malformed/control/bidi bypass attempts. Public
  wire layouts are unchanged; SDKs should mirror the documented preflight
  rules, while node-side decoding remains authoritative. Exact formatting and
  whitespace validation pass; focused Cargo validation is pending the shared
  serialized build lane.
