<!-- Original context: Status / 2026-06-29 CUDA Production Hardening -->
- Hardened the Norito `jsonstage1_cuda` binary sequence planner so malformed
  GPU-validated layouts no longer copy partially written spans back to callers
  and invalid fixed-offset plans no longer publish a successful `out_used`
  value. Length-prefixed plans now reject impossible declared element counts
  before CUDA allocation/launch, and oversized span counts are rejected before
  allocation-size arithmetic.


<a id="record-25c36f9738300e5b872b1a57af339427d94924ca728e07f26948b8bd00312daa"></a>

- Fixed grouped IVM cache-capacity coverage so it installs test-local runtime
  cache limits with `CacheLimitsGuard` instead of assuming the global cache has
  not already been initialized by an earlier grouped test.


<a id="record-3feac64c933f45bd3867ae1a293bc6988e75546059d2407fa24bf8c9d30aa58b"></a>

- Cleared the CUDA-feature strict clippy gate for IVM by removing mechanical
  CUDA-path lint debt while preserving scalar fallbacks and the existing
  kernel-launch behavior. The Soracloud full-bootstrap native-envelope byte
  validators are now available in non-`zk-stark` builds so
  `iroha_core --features cuda` compiles.


<a id="record-a2aca6048ca4fc4ab619c05ad4e3cd3f3d442c184be2074a744f8258798a3c25"></a>

- Replaced the remaining source-level SIMD/GPU TODO in Norito's fixed-point DCT
  path with an explicit deterministic scalar reference contract: accelerated
  variants must prove bit-exact parity against that implementation before use.
  The DCT golden now has separate default floating-point and fixed-point
  expectations so both deterministic references are covered.


<a id="record-161b270fd7d87a1c573f80c2292936c312c1fba8655f7ce0ab4c097be274ece4"></a>

<!-- Original context: Status / 2026-06-29 - Localnet OOM Hardening -->
- Tightened generated perf-profile localnets specifically: Kagami now writes
  explicit channel-specific P2P frame caps, including 4 MiB consensus/block-sync
  caps, a 256 KiB default transaction-gossip cap, a 1 MiB Nexus transaction
  gossip cap, and smaller control/peer/health/other caps. The perf profile also
  writes a runtime `[sumeragi.block].max_transactions = 256` proposal cap while
  preserving the on-chain performance genesis `block.max_transactions = 10_000`.
