## 2026-08-27 Kotodama first-release simplification



<a id="record-01c0085c054d613b9733a33879391bf368a4df4b26d3dd9a00ea167f073822ee"></a>

- Removed the unowned public source/bytecode analysis and partial fuzz-interpreter modules, the
  self-tested-only wide-encoding wrapper facade, rejected manual-access parser/storage fields, and
  the test-only legacy transport-IR optimizer. Kotodama now has one production optimization
  authority in strict SSA and exposes the canonical IVM encoder directly; useful metadata,
  split-spill, and checked-trap assertions were moved to the production path. The scoped compiler
  diff removes more than 3,700 lines and is net-negative by more than 3,100 lines.


<a id="record-64f67651ce07af28c4d18f1c0cde22abde6679f06363cc931a5fa981ad7c0ea6"></a>

  30-test SSA suite, and the 8,192-value copy/dead-chain regressions. Strict crate-only Clippy with
  `-D warnings`, scoped Rust formatting, and whitespace validation are clean. Dependency-inclusive
  Clippy reaches 59 unrelated pre-existing `iroha_crypto` findings and was not used to expand this
  change.

## 2026-08-27 IVM first-release simplification and hardening



<a id="record-29642f58e4297f262e2ae4a17c2d61b14044db9081ee42a8a18b0ef64f8eaf14"></a>

- Reduced the IVM/ABI/admission implementation by more than 4,300 net lines. IVM now has one
  canonical fixed-width 32-bit decoder, prepared representation, and interpreter. Removed the
  compact/simple interpreter, instruction-level ILP executor, branch predictor, segmented/register
  facades, transaction-group/result-buffer scheduler facades, `VmEngine`, dynamic instruction
  lengths, and their self-owned tests. Every remaining workspace caller now uses the canonical
  `encoding::wide` and `instruction::wide` APIs directly.


<a id="record-dfe9db9e3e8b8a25f10ccd3a6c4f9514feeaa29a43597782d030d6053cd3f610"></a>

- Parallel workers now return deferred outputs. One coordinator publishes successful state batches
  in transaction-index order and releases conflicting successors only after publication; failed
  outputs are discarded. Each batch holds one safe-Rust state write lock, declared access sets are
  borrowed while building the graph, and transactions and state-update keys move instead of clone.
  Ordinary VM construction no longer allocates a scheduler or worker pool.


<a id="record-9ed4451cdc67814eb4507f4ba3ebd1dac3aece541d0f020cc820441c5807aca1"></a>

- Register writes defer Merkle hashing until a root/path is requested, clean clones reuse the tree,
  and trace-enabled clean writes update only one leaf. Decode/prepared caches are keyed only by code
  bytes and no longer maintain duplicate size maps. Register-logger installation is internal and
  fail-closed on nesting; both logger and pointer-policy guards are pinned to their installing
  thread so thread-local state cannot be restored on a different worker.


<a id="record-9ecbad1ccc1892256853808548536a650fe53965baaa699e9a852324616a265a"></a>

- Validation passes for all 702 IVM library tests, all ten grouped integration targets at compile
  time, the complete all-target surface including benches/examples/developer binaries, focused
  ordered-commit/cache/Merkle/logger/pointer-policy regressions, strict crate-only Clippy with
  `-D warnings`, and locked offline workspace metadata. A clean isolated Core library check covers
  the downstream error/cache API migrations; unrelated dirty-tree workspace validation is not
  claimed.
