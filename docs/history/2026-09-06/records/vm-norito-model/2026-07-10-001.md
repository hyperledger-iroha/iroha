## 2026-07-10 Kotodama V1 full-stack reset



<a id="record-781d71991e68662a254d37e575c88029f226c9ec748c129efbe218daae641bbd"></a>

- Landed the canonical branded V1 grammar (`seiyaku`/`誓約`,
  `kotoage`/`言挙げ`, `hajimari`/`始まり`, and `kaizen`/`改善`) with strict
  resolution and types, namespaced builtins, caller `authorize(...)`, bounded
  control flow and state, stable error enums, and ZK-only noninterfering
  `Secret<T>`. English declarations, syntax aliases, implicit preludes, raw
  host operations, and compatibility editions are rejected.


<a id="record-7038e3e0bbb43b9b144a8e6e85936e1845e3e5362ec86289558b7f6bd656f34d"></a>

- Added a lossless, ranged recovery CST and an AST parsed from the same token
  stream, a reusable compiler session, structured human/JSON/SARIF diagnostics,
  one exhaustive builtin registry, the unified `koto` driver and
  content-addressed publisher, the Rust-backed asynchronous Node binding, and
  the browser compiler-service client. The lexer-owned keyword/operator tables
  are synchronized with documentation, TextMate, and LSP consumers in CI.
  AST, typed HIR, and MIR nodes are not yet generally spanned: most retain only
  function line/column data, and the early semantic diagnostic pass currently
  locates ranges by matching the canonical token stream. A true
  CST-to-spanned-AST-to-resolved-HIR pipeline remains release work and must not
  be described as complete.


<a id="record-df9a5520745373356034ac36e2b619db16e3bbc99c644c752104ecceb7109efc"></a>

- Corrected the ABI-v1 security and execution contract: `code_hash` covers the
  complete canonical image including its execution header, CNTR, literals, and
  code; debug data lives in hash-keyed sidecars; validated bytecode supplies
  transitive effects and access with conservative dynamic scheduling; gas uses
  quote/debit/execute ordering; public arguments use one prepared canonical
  Norito record decoded once; and compiler budgets plus the mandatory,
  hash-covered cycle ceiling fail closed.


<a id="record-8fd5ba42be696a4d2c4178e7315fbc5bc0d4ee92c0b5bd231409dc66e74e0a34"></a>

- Closed two additional adversarial corridors found during release review.
  Named `authorize` requirements now travel through block overlays and proved
  replay, conflict with every permission/role mutation, run before direct,
  nested, trigger, and overlay VMs, and are rechecked against live state before
  any queued or durable effect is applied. Canonical argument preparation now
  proves gas affordability before decoding, keeps the complete signed record
  host-owned behind a domain-separated guest binding, proves the full TLV
  allocation sequence before writing, and spills large typed values into owned
  HEAP rather than trapping on the 64 KiB INPUT boundary. Exact 1 MiB wire-cap,
  over-cap, insufficient-gas, pointer-substitution, constrained-heap, trigger,
  overlay-apply, and full block denial tests cover these invariants; integrated
  Cargo execution of the newest tests is in progress.


<a id="record-ee368e5e7ae7a75c19842ccde48a5c093f90059de6faa9e94fc3e295839aa519"></a>

- Added indexed literals, relaxing near control flow with far trampoline
  islands, SSA optimizations, call-aware allocation with live-interval
  splitting, prepared-contract caching and dirty reset, phase/runtime
  benchmarks, and authenticated no-op builds.


<a id="record-a65b713093f9b639cdfa78e384ec915cc53cdf68df9df418b317cc7178342249"></a>

- Current validation evidence is green: `cargo test -p kotodama_lang --lib`
  passed all `654/654` tests; the Python documentation, performance, and golden
  helper suites passed `24/24`; the JavaScript compiler suite passed `20/20`;
  the JavaScript contract-call suite passed `8/8`; and the Torii Python suite
  passed `123` tests with `1` skip. Remaining runtime and integration Cargo
  lanes, non-skipped four-peer evidence, and complete checked-in golden
  regeneration/size/no-op verification are still pending and V1 is not yet
  release-ready.


<a id="record-844f1e9b3d7b874a7fd46e9857aa37ae3156e2227c27e1809d79b6563b3a65a3"></a>

- Added one Rust-generated shared `EntrypointArgumentRecordV1` fixture binding
  the compiler-emitted schema, schema hash, Torii JSON payload, and canonical
  Norito record bytes. JavaScript, Python Torii, Kotlin/JVM, mirrored Java, and
  Swift consume that fixture through their existing contract-call JSON
  boundaries and explicitly do not implement a second record codec; none of
  those SDKs currently exposes a signed `ContractInvocation` encoder. The new
  JavaScript, Python, and Swift focused tests pass. Rust Cargo execution and the
  Kotlin/Java fixture tests remain pending because Cargo is owned by the
  runtime validation lane and this host currently has no Java runtime.

Historical Kotodama entries below preserve the implementation state at the
time they were written. References to English declarations, pre-reset `int` semantics,
`permission(...)`, prelude injection, an independent JavaScript compiler,
the standalone `koto_compile`, `koto_lint`, and `koto_test` binaries, embedded
debug metadata, flat legacy builtins, production rejection of dynamic access,
or compiler/CNTR claims as a security authority are superseded by this reset
and must not be read as current language, compiler, or operator guidance.

## 2026-07-10 Kotodama mandatory cycle ceiling



<a id="record-3706d03172a1fe7f59829000c8045f591e7abe003b7a44a67acd20d5f245cbb4"></a>

- Made `pipeline.ivm_max_cycles_upper_bound` a non-zero configuration value
  with the `1_000_000` release default. TOML decoding rejects zero; the policy
  deliberately has no environment-variable alias, and the retired
  `max_ivm_cycles_upper_bound` custom parameter cannot raise, lower, or disable
  node policy.


<a id="record-ed350e9e89695c3dfdeba012568ba291d4a2ec26e19faff8ebca6310af6113d1"></a>

- Executable admission, contract-byte persistence, raw IVM trigger
  registration, overlays, quarantine execution, and trigger execution now
  consume the same mandatory ceiling. Zero-valued artifact headers fail
  closed, runtime gas derivation requires `NonZeroU64`, and generated Soracloud
  service artifacts carry a positive hash-covered cycle limit.


<a id="record-cc7821158b89009b604df566fe19435cc6538a7e4a02a4be27fcf675c9f53c18"></a>

- Added configuration, exact-bound/over-bound admission, retired-custom-
  parameter, and trigger-cycle regressions. Static validation completed with
  targeted `rustfmt --check` and `git diff --check`; focused Cargo tests remain
  part of the integrated Kotodama validation matrix.
