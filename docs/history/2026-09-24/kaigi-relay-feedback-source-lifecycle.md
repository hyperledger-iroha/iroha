`ReportKaigiRelayHealth` is authorized by the active call host and records an observation about a relay in that call's current manifest. Its `reported_at_ms` is the observation time. The final V1 admission rule now requires that time to be at least the call's creation time and at most the admitting block time. A report before the call existed cannot enter new state, and a report after its end is already refused because the instruction requires an active call.

The retained feedback restore scan previously checked the feedback's relay registration, storage home, size, and ledger-time bound, but accepted a row naming no Kaigi call. It now resolves the exact referenced call from authoritative domain metadata and requires `created_at_ms <= reported_at_ms`; for ended calls it also requires `reported_at_ms <= ended_at_ms`. The same scan runs on both the current domain layer and the latest undo layer before publishing the rebuilt dependency index. Domain references are sorted in place for a bounded lookup per retained relay feedback row, without allocating a copy of every call record. Rejected rows leave authoritative metadata unchanged.

The focused tests cover a valid active observation, an observation exactly at the finalized end, missing-call, pre-creation, and post-end rows, an orphan row in the undo layer, and live pre-creation rejection with no record or event side effects. Existing health ordering and Unicode tests now represent earlier retained calls when they submit observations from a later synthetic block.

This guard does not prove that a restored `reported_by` account signed the historical report. That property needs authenticated historical operation evidence across account-id rekeys; it remains a Kaigi release blocker alongside relay transport, HPKE key possession, multi-validator recovery, and independent review.

## Next cut: historical reporter authorization

The retained `KaigiRelayFeedback` row carries `relay_id`, `call`, `reported_by`, `status`, `reported_at_ms`, and notes. It carries no transaction hash, signed instruction ordinal, finalized block anchor, or authorization witness. Its `reported_by` value is copied from the live execution authority; decoding the row after restart does not itself prove that authority signed a successful report. The restore code currently receives a `WorldReadOnly` view and the authenticated ledger-time ceiling. It rebuilds current and latest-undo domain metadata, relay registration, and account-dependency indexes; it does not receive an exact signed transaction source from Kura.

The final V1 source should be an authenticated, successfully applied `ReportKaigiRelayHealth` instruction in a canonical signed block, bound to the exact network, call, relay, reporter, feedback content, block identity, entrypoint index, and instruction ordinal. The transaction signature alone establishes the submitter, not successful execution or the host's authority at that block. `StateTransaction` already exposes `current_tx_hash` and `current_entrypoint_index` for signed application, but there is no Kaigi-specific direct instruction ordinal or durable feedback source receipt. If nested IVM execution remains allowed, the source must also bind a deterministic authenticated execution trace; a direct-only instruction policy is a possible V1 interface decision, not an implemented restriction.

At admission, the same state transaction that writes feedback would have to persist its exact source reference atomically. At restore, a State-level verifier would resolve that reference through Kura's canonical `SignedBlockWire`, check finality and successful ordered execution, verify the signed reporter and exact instruction fields, and compare the resulting row digest to retained metadata in both current and undo layers. It must use bounded memory and work, and fail closed when the original block, result, or inclusion evidence is missing. A self-asserted source field inside the feedback row is insufficient without that independent block check.

Host authorization also has a time dimension. `AccountRekeyRecord` retains predecessor IDs with typed `AccountIdRekey` versus `AliasReassignment` provenance; alias reassignment explicitly breaks controller continuity. Current terminal lineage is not by itself a proof that the reporter was the call host's authorized successor at the report's block. The verifier needs authenticated rekey state at that block, obtained by bounded source replay or a finalized historical state/transition receipt. It must reject a reporter linked only by a later rekey or by alias reassignment, while accepting a genuinely authorized predecessor whose account was retired after the report. This construction, its exact wire fields, resource bound, and adversarial restart tests remain unimplemented.
