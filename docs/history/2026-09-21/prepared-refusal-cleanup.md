# Returned preparation refusal cleanup

Checkpoint144 makes MV preparation return its original journal, local error and
original cleanup owner together. Map and Cell share `PublicationCleanup`; it
retains successful preliminary identity observations, partially acquired writers,
prepared reader notifications, final identity refusals and installation capacity.
Both explicit abort and normal refusal carry these original owners. The admitted
wrapper keeps cleanup within the original allocation scope.

Runtime and TriggerSet collect cleanup from every completed prefix and the failed
component. World returns the failed field in its original prepared shell, restores
all original journal boxes to their original vector, and retains the prepared
vector with installation custody. Carrier World/runtime refusal releases the
other acquired components and State/Queue/Kura fences before this cleanup.

New MV controls cover admission refusal, second-writer contention and identity
change after admission. They verify deferred callbacks and resource refunds,
original data, callback reentry and no signal for an unacquired Busy writer. The
map control retains its immutable check view before arming notifications; a new
reader would emit an unrelated release and test successor acquisition instead.
Core registers a real first-field waiter after prefix acquisition, forces a late
World refusal and checks callback reentry only after enclosing release, preserving
original boxes and exact retry. Existing controls cover every busy carrier family.
Source bindings, ledger declarations and mutation controls track those consumers.
Scoped validation is recorded in `dist/sumeragi-main-work/validation144.json`.

This does not finish acquisition-panic cleanup, standalone TriggerSet/runtime
Drop, earlier State/Kura/Queue partial probes, native stale-map writer acquisition,
successor acquisitions or ordinary Apply's enclosing Queue observer. Complete
State effects and membership shard/resource preparation, configured admission,
production retained Validate/Apply/native runner cutover and unchanged four/seven-
validator qualification remain open. All L1–L6 milestones remain active.
