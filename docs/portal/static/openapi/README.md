OpenAPI signing
---------------

- Release Torii OpenAPI specs (`torii.json`) must be signed, and the manifest is verified by `cargo run -p xtask --bin xtask -- openapi-verify`.
- First-release development snapshots may carry an unsigned manifest only when CI passes `--allow-unsigned`; this still verifies the artifact path, size, SHA-256, and BLAKE3 digest, but skips the Ed25519 signature check.
- Generator provenance is explicit. Clean manifests record `generator_commit` as the exact lowercase 40-hex Git SHA-1, set `generator_dirty` to `false`, and omit `generator_source_sha256_hex`. A dirty unsigned development snapshot instead sets `generator_commit` to `null`, sets `generator_dirty` to `true`, and records a deterministic SHA-256 digest of all non-generated tracked and untracked source state. Canonical OpenAPI outputs and manifests are excluded from that source digest so identical source produces the same digest across regenerations.
- Dirty provenance is development-only: the generator refuses to sign it, and release verification rejects it even if a signature is injected into the manifest. Commit or clean the source changes and regenerate before signing a release artifact.
- The checked-in `allowed_signers.json` intentionally contains an empty `allow` array. This is a valid version-1, fail-closed trust root: unsigned development snapshots still require their explicit opt-in, while every signed artifact is rejected because no release signer is provisioned.
- Production release operators must provision a separate version-1 allowlist containing only operator-held Ed25519 public keys, then pass it to portal sync with `--allowed-signers=<path>` and run `ci/check_openapi_spec.sh` with both `OPENAPI_REQUIRE_SIGNED=1` and `OPENAPI_ALLOWED_SIGNERS_FILE=<path>`. Signed mode rejects unsigned root/latest/current artifacts; the immutable unsigned `2025-q2` development snapshot remains an explicit historical exception. Never use a public fixture, example, or deterministically documented key as a release trust root.
- The canonical `xtask` dependency compiles Torii's supported documentation profile (`app_api`, `telemetry`, `profiling`, `schema`, `p2p_ws`, `connect`, `gov_vrf`, `zk-verify-batch`, and `push`). The generated operation set is the exact enabled `RouteCatalog` OpenAPI projection; do not hand-add disabled or uncataloged paths to a snapshot.
- To re-sign after a key rotation:
  1. Update the separately provisioned operator allowlist with the new public key; do not add production keys to the checked-in empty allowlist.
  2. Regenerate/sign the spec: `NORITO_SKIP_BINDINGS_SYNC=1 cargo run -p xtask --bin xtask -- openapi --output docs/portal/static/openapi/torii.json --sign <ed25519-key-hex-path>`.
  3. Run `npm run sync-openapi -- --allowed-signers=<operator-allowlist-path>`, then verify with `cargo run -p xtask --bin xtask -- openapi-verify --allowed-signers <operator-allowlist-path>` to confirm the manifest matches the provisioned trust root.
- If the signing key is held outside the checkout, generate the spec first, have the operator sign the exact bytes of `docs/portal/static/openapi/torii.json`, then refresh the manifest with `NORITO_SKIP_BINDINGS_SYNC=1 cargo run -p xtask --bin xtask -- openapi --output docs/portal/static/openapi/torii.json --signature-envelope <signature-envelope-json>`. The detached envelope must be JSON shaped as `{"algorithm":"ed25519","public_key_hex":"...","signature_hex":"..."}` and is verified before `manifest.json` is written.
- For unsigned first-release snapshots, use `NORITO_SKIP_BINDINGS_SYNC=1 cargo run -p xtask --bin xtask -- openapi --output docs/portal/static/openapi/torii.json --unsigned-manifest`, then run `npm run sync-openapi -- --allow-unsigned` from `docs/portal`.
- Sync stages and validates the complete prospective artifact tree and version index before the first tracked write. Existing non-`current` version directories are immutable; create a new label for each release. Unchanged entries retain their recorded `updatedAt`, while changed entries derive it from the validated manifest timestamp, so filesystem mtimes cannot rewrite historical metadata.
