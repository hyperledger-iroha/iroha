# Fixed experiment ownership

`FixedExperimentCustody` creates one evidence root and one disjoint private
runtime root, retains their original ancestor descriptors, and admits one
immutable ten-trial plan before creating trial processes. Its only run order is
pair 1 through 5, with one lane then four lanes in each pair. Every trial uses
the same workload, limits and account count, apart from the declared lane count
and paired deterministic seed. The plan must reserve at least 100 measurement
requests and a trial deadline longer than its native workload lifetime.

The owner derives three bounded public inputs from typed identity, original
executable images and the actual five-file worker source owner. Declared build
and hardware metadata do not prove an authenticated build-to-image relationship
or complete runtime dependency closure. No runtime paths, private TOMLs or
development seeds enter these public controls.

`begin_run` returns an opaque originating slot. Only its `create_trial` method
creates the accepted `FixedTrial`; the owner separately pins its original paths
and actual instance. Handoff requires that instance, its completed native
operations and its original deadline. It retains eight original load/native
descriptors, copies exactly five public genesis files and transfers original
capture custody before closing private trial state. A caller-created receipt,
copied result, substituted trial or changed slot cannot satisfy this boundary.

Only an originating completed handle can publish the raw run and receipt.
Those JSON bytes are derived from the retained native authority. They include
complete timing/Applied identities, public evidence bindings, readiness
attestations and all three proof-stage process identities, with allocation
checked before encoding. Private account configs and retained signed request
bodies remain outside the projections. A later mismatch invalidates every
earlier run. Cleanup follows the owner's retained original resources even if
caller-visible slot or row fields have changed.

The final metadata fence performs no callback, directory enumeration or body
read. It generates the already-admitted exhaustive capture-member grammar in
lexical order, checks original capture metadata, then every retained public
control, managed directory edge and the original experiment deadline. Normal
full checks still hash the actual retained evidence before this closing fence.

## Manifest, independent replay and observed report

After all ten runs publish their summaries, `publish_manifest()` derives the
three input bindings, all fifteen original public file bindings for every run,
complete admitted budget and exact capture censuses. The public publisher keeps
the original descriptors; publication does not create a replacement admission.

`ResourceExperiment.from_completed(owner)` asks that exact owner to create its
sole borrower. The borrower receives only the original native process identities,
timing, file bindings and allocations. It independently replays each raw journal
and capture scope and passes the complete result to the original run's native
authority. Every signed request and global/local application observation must
reconcile before proceeding. Full replay bodies are dropped after each join;
only immutable original projections and resource reductions remain across runs.

`publish_report(borrower)` requires all ten successful joins. The report contains
exact rational throughput, complete-cohort integer latency, observed resource
maxima and three separate measurement criteria. Throughput compares the median
of five four-lane runs to the median of five one-lane runs. Latency compares the
pooled complete measurement cohorts, including the drain tail. No latency array,
private runtime input or combined release verdict is copied into the report.

`verify_report()` independently rederives both controls, reads their original
descriptors and compares the exact canonical bytes. Original projection
references, result identities, complete measurement values and current replay
scopes are rechecked after the final runtime callback, before the closing
metadata/deadline fence. Clearing a completed result is a failure. Every failure
invalidates all original native authorities; cleanup uses the originally minted
token and continues even if one authority rejects invalidation.

The borrower may close only after report publication. It closes no original
evidence descriptors. Final verification requires that borrower to remain open;
the experiment owner closes its original files only during explicit cleanup.

## Remaining release integration

The fixed launch entrypoint now composes dependency admission, typed launch
inputs, retained invocation resources and the execution service. Its original
caller owns both launch descriptors and observes the final process status.

The protected bootstrap now composes the original preflight, fixed launch,
independent archive/native replay and canonical parent execution record. The
release receipt consumes that record and its authenticated source relationship.
