# Ordinary physical Android support

This source-only callable support is not an executable conformance suite. It introduces no
`@Test`, instrumentation selector, native endpoint replacement, startup constructor, mock,
transport, policy flag or provider response. Its opaque C/E inputs must be obtained from the
product's genuinely installed shared Native coordinator. Its service input must be obtained
through the actual shared ordinary-service factory with the same admitted application/account,
protected original transport and existing wallet signer. Expected observations are detached DATA;
they cannot reopen an owner or admit a server result.

`collectNativeOriginal` uses the actual shared persistent Android key store and Native generation
fence. It compares signed C515/full C signing transcript512, the full65-byte key, original alias and
sole canonical Android platform container. `proveAndObserveBoundOriginal` requires genuinely
admitted raw314, signs the Native E424 through the real persistent-key adapter, separates returned
Native receipt from retained P-256 DER, and invokes the existing certificate-input pairing guard.
That guard checks same coordinator/C/key/raw/scope/alias and Native Google policy. A required Google
token must come from the actual shared provider; its managed carrier alone grants no Google origin
or issuer verdict. This helper does not request/decode Google evidence, send the request, or copy
its token-bearing body into an observation. Actual protected server PKIX/app-pin/revocation,
StrongBox/TEE, Google and issuer checks are still mandatory.

The helper uses the SDK's existing internal E-purpose validator from the SDK androidTest friend
module; it is not a published product-test artifact. The opaque E itself authorizes its Native
signer path. The current same-C/raw/E pairing API requires already consumed DER, so the helper
checks this pairing after possession and before exposing a bound observation. The production
workflow obtains its holders from one coordinator. A runner must preserve that acquisition;
these helper parameters do not acquire or prove a common initial owner before signing.

`assertRecoveredOriginal` accepts genuinely reacquired opaque Native holders. It reads retained
originals, compares complete C/raw314/container/key/E/DER/receipt bytes and corroborates that the
same Android Keystore key entry/full generation-time chain remains. Native may finish consumption
of its already retained DER. This helper never collects, reserves, generates, requests Google,
sends HTTP, cancels an attempt or invokes the signer during recovery. Native freshness/lease guards
remain intact, with no app clock, reset, timeout relaxation or expiry bypass. Keystore entry
existence and matching chain do not prove future signer availability or server acceptance.

`beginOrResumeInstalledEnrollment` and `assertSameRetainedEnrollment` call the actual service for
protected issuer/PI/wallet/FI completion and exact same FI-result comparison. They do not claim that
enrollment, a receipt or Bootstrap establishes monetary State/Guard readiness. Physical test entry
must inspect the same coordinator originals separately; the detached FI result does not expose C/E.

## Required real harness entry and controls

An admitted product-host instrumentation owner must first supply the genuine installed runtime,
authenticated release/root inventory, held native AccountClient/current account, original lease,
real journal and fixed source registration consumed by Native startup. The exported Rust startup
type and public Kotlin `open(storagePath)` are present. Generic JNI installation refuses an absent
registered source; the inspected SDK AndroidJUnit/Taira runners do not acquire that owner. A raw
account/path, saved originals, test callback or compatible ABI does not fill this prerequisite.
The SDK test-host package/signing identity is not the product's independently admitted Play pin.
No executable test can safely be added until the genuine product acquisition/runner is supplied.
An independently admitted SDK test-host policy could qualify that separate test application only.
Using this source in a product-host test also requires a real SDK/test-module integration for the
internal validator; copying it into another module is not a demonstrated compatible build.

The owner-run physical controls should use these helpers with real owners and retain external
command/runtime/source/device/server evidence. They are not executed by this COPY packet:

| Control | Actual call and expected result |
| --- | --- |
| Persistent key | Native C -> real collection -> raw314 -> Native E -> real possession -> bound observation; no finite-use/OEM feature gate is introduced. |
| Lost collection result | Supervisor interrupts after actual durable original output; genuine reopen recovers the same C/alias/point/full container. No test mock claims a platform call occurred. |
| Lost possession result | Supervisor interrupts after actual retained DER; `assertRecoveredOriginal` compares the first exact E/DER/receipt without another hardware signature. |
| Lost issuer/FI reply | Actual protected same-attempt transport retains unknown reply; same-service explicit retry compares original FI ID/certificate. Native/issuer durable outcomes must be independently inspected. |
| Restart | Genuine startup recovery restores original owner and actual lease; compare all first originals. Expired original owners stay errors; no new timestamp/subject/key is substituted. |
| Reinstall/key loss | Uninstall may delete the app-owned Keystore key and local originals. Missing genuine owner/key/originals must error, without asserting same-key success or starting a new attempt. Authenticated server recovery/rotation/retirement is separate unfinished lifecycle work. |
| Foreign/changed original | Genuine Native pairing and full expected comparisons reject different coordinator/C/raw/key/E/scope; expected DATA alone cannot authorize the operation. |

For loss/restart controls the first observations must be retained by a product-specific supervised
evidence owner outside the interrupted process. This support adds no archive parser or trusted
checkpoint constructor. The capture is comparison data and must never be fed to a Native factory.
Actual runner selection, supported loss injection points, admissible product packaging, server/PI
installation, reinstatement/rotation/retirement and deadline-qualified execution remain prerequisites.

No Gradle/compiler/device/provider run, native qualification or qualified ABI25 release is established
by this source proposal. It leaves existing diagnostic single-use/OEM and monetary tests untouched.
