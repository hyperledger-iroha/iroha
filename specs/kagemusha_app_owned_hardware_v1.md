# KAGEMUSHA app-owned hardware V1 contract

This normative contract freezes the existing financial signing message S and the ordinary-app approval message W. Implementations must satisfy the roles, admission, signing and recovery requirements below. The contract does not establish an installed issuer, qualified monetary profile, physical attestation result or offline support. The current implementation gaps are stated separately and must not be filled by decoded bytes or synthetic admission.

## Roles and capability boundary

| Role | Native type or proposed binding | Permitted claim |
|---|---|---|
| Ledger account key | Existing Ed25519 AccountId / account-possession proof | Account authorization; never platform app identity or offline counter evidence |
| App identity / approval key | Persistent Android Keystore P256 or App Attest key, enrolled by KagemushaAppEnrollmentCertificateV1 and independently verified authority policy | Authentic app-key approval under exact app/account/network/release enrollment |
| State protection | Separately admitted native qualification bound to exact enrolled key/lane/protocol and KagemushaAuthenticatedCoreOwnerV1 | Only the counter / one-use / replay / rollback / recovery guarantees genuinely qualified for that protocol |
| Enrollment issuer | Existing independently pinned Ed25519 app-attestation and retail issuer policies | Certifies verified raw platform evidence and exact native enrollment scope; cannot supply a monetary StateGuard |
| Financial credential issuer | Existing governed compact hardware credential issuer and proof-release roots | Financial credential binding only after its actual native qualification and proof relation |

Identity enrollment does not require a custom SE applet, OMAPI, OEM provisioning, hardware one-use limit, or creation of a spendable state. Android policy accepts authentic TEE or StrongBox only; prefer StrongBox and allow TEE fallback only under an explicit policy and definite unavailability. The current new shared persistent Android key store and Python verify_android_raw already follow this identity boundary. The Python verifier rejects usage-limit tag405 for the persistent approval key.

Keep the current financial profile masks and Guard rejection intact until a reviewed split is implemented: AndroidKeyMint currently requires identity + P256 + hardware-one-use, hardware.rs compares the exact mask, and phase2 of the native monetary enrollment delegate requires its retained qualification before accepting the issuer challenge. Add an identity enrollment result/branch owned by the existing native attempt journal; do not fabricate a HardwareCredential or remove checks from that financial branch.

An assertion counter is not automatically a rollback-resistant wallet journal. A reusable P256 signature is not a one-use successor authorization. App enrollment, compilation and online fraud checks do not grant strong offline spending capability. For App Attest, online assertion acceptance may permit a counter gap; the separately qualified financial counter protocol must retain its exact-next relation, lost-result rules and no-fork evidence. No extra platform signing invocation may be hidden inside a retry or recovery.

## Canonical messages

S remains exactly the current model-owned KagemushaHardwareTransitionSelectionV1 signing bytes: NUL-terminated `iroha:kagemusha:v1:hardware-transition-selection`, LE64(403), fixed body; total460 bytes. Fixed field order is versionLE16; release/provider-policy/app-policy/credential/network/lane/profile raw32; policyEpochLE64; hardwareEpoch raw32; generationLE64; operationTag1; transition/candidate/terminal raw32; secureIndexBefore/AfterLE128. Tags are MintFold1, SendSplit2, ReceiveFold3, RedeemSplit4, Rotate5; Bootstrap0 is not signed through this financial selector. Core derives every field from its original owner, predecessor, checked operation and current admitted release. After must equal Before+1. Outgoing candidate and terminal commitments are nonzero exactly for SendSplit/RedeemSplit. Storage Norito bytes are not S.

W is the existing KagemushaAppOperationApprovalChallengeV1 canonical signing message: NUL-terminated `iroha:kagemusha:v1:app-operation-approval`, LE64(275), versionLE16, purpose01; operationID, durable native nonce, model account binding, independent app-authority policy digest, attested-key ID, enrollment digest, SHA256(S), normalized Guard digest (eight raw32 fields); issued/expiresLE64. Its maximum interval is120seconds and archive maximum4096 bytes. The clock/lease comes from the original admitted native policy, not a handset timestamp or echoed server field.

Ordinary-app approval transcript: Android SHA256withECDSA signs exact W; App Attest receives clientDataHash=SHA256(W). The Python raw assertion verifier can already verify exact W without another client-data hash. The existing Swift financial selection uses SHA256(S). The current owner-added model now defines typed AndroidKeystore DER and AppleAppAttest raw-assertion evidence for W. Each operation must explicitly select its contract purpose; migrate ordinary app approval to W and never treat an existing S-only assertion as W approval. S itself remains unchanged. No application constructs either financial subject or W from DTO fields.

## Enrollment possession purpose and platform-facing native capability

Platform key generation/attestation and enrollment proof of possession are different operations. The original native enrollment challenge C is KagemushaOrdinaryAppEnrollmentChallengeV1: fixed451-byte body under NUL-terminated `iroha:kagemusha:v1:ordinary-app-enrollment-challenge`, with version LE16, C platform tag Android1 or Apple2, thirteen raw32 scope fields, then policy epoch LE64, original hardware epoch LE64, issue time LE64 and exclusive expiry LE64 in that exact order. The original hardware epoch is a scope selector, not admission of non-forking financial capability. The retired443-byte body is rejected; there is no dual-layout decoder. Its attestation challenge is SHA256(C). Play Integrity requestHash is SHA256(`iroha:kagemusha:v1:play-integrity-enrollment\0` + C + attestedKeyId), represented as canonical unpadded base64url. Issuer-selected raw challenge, release/account/network/profile/financial-authority commitment and time are authenticated before key generation; app-generated DTOs cannot choose these selectors.

Enrollment key possession uses a separate native-produced message E after the original attested public key has been independently accepted. E has NUL-terminated domain `iroha:kagemusha:v1:app-enrollment-possession`, LE64(371), versionLE16=1, purpose01=IdentityEnrollment, eleven raw32 fields in order: enrollmentAttemptID, original client nonce, original server nonce, account binding, raw NetworkId, admitted app-authority policy digest, releaseID, profileID, laneID, attestedKeyId, raw-platform-evidence digest; then issue/expiryLE64. All fields must be nonzero, nonces different and the interval must equal the original signed C issue/expiry, exclusive and bounded120seconds; E does not renew it. The native projection uses platform tags Android5 or Apple4 and maps these explicitly to C1/C2. Account binding uses the same model-owned AccountId encoding/hash as W. A decoded E is public correlation data, not admission. Android signs E with its persistent enrolled key; App Attest receives SHA256(E) and its original assertion/counter is durably consumed under identity enrollment. E must not authorize a monetary operation or stand in for W or S. The final scoped identity credential binds this exact original possession evidence. Missing or uncertain results recover only the original E/key/evidence.

The sole ordinary Android alias is `kagemusha-ordinary-app-v1-` plus lowercase hexadecimal SHA256 of `b"iroha:kagemusha:v1:ordinary-app-key-alias\0"` concatenated with the full original C451 canonical signing bytes, including its domain and length. This name is correlation only; the native owner retains the exact key-generation original and reopens it on retry. User-chosen aliases, retired273-byte preparation or C443 layouts cannot select or recover an ordinary key. Apple retains its original canonical App Attest key ID instead.

The public SDK signer consumes a process-local opaque `KagemushaNativePreparedAppApprovalV1` or `KagemushaNativePreparedAppEnrollmentPossessionV1` returned by the genuine coordinator. Neither has a public DTO/byte constructor. The read-only signing projection carries exact W/E bytes plus opaque owner handle/attempt ticket and operation/enrollment identifier; decoding that projection does not recreate the capability. Before exposing/signing bytes, before device invocation, and before publishing approval, the implementation rechecks the retained native owner, original selection, key identity, current interval and journal revision. The platform invocation is fenced durably before it happens. A succeeded or uncertain invocation cannot be retried as a new signature. A completed original can be replayed only byte-identically for the same ticket. Core alone verifies and consumes raw evidence through the typed platform equation and retains the original result. No callback, JVM/Swift object or arbitrary signing-byte buffer may create Core authority.

Coordinator API integration must retain prepare/approve/recover/cancel for W and prepare/complete/recover for E under the actual enrolled-session/identity-attempt owner. The current closed method inventory1..18 must not be repurposed; any additive method receives exact bounded request/response validation, installed backend dispatch, native-owner origin checks, JNI/Swift private factory and conformance tests together. A default unavailable result remains required where the genuine owner is absent. Success cannot be substituted by a test-only delegate, public parser or callback that echoes W/E.


## Pending raw attestation before possession

The pending raw admission is a distinct issuer purpose, not a final credential. Its only signing message is the NUL-terminated domain `iroha:kagemusha:v1:raw-app-attestation-admission`, LE64(250), and body250: versionLE16=1, purpose01=RawAttestationBeforePossession, SHA256(full original C)32, admitted app-authority policy digest32, C platform tag Android1/Apple2, security tag TEE1/StrongBox2/AppAttest3, exact uncompressed SEC1 point65, keyID32=SHA256(point), SHA256(full raw platform original)32, actual app signer/RP digest32, initial AppAttest counterLE32=0, and the exact original C issue/expiryLE64. It does not renew C or replace the policy-required separate Play Integrity check. The issuer authenticates C, policy, raw platform originals and key before signing. Final identity publication requires the same immutable raw reservation and durably verified E, plus any actual policy-required Integrity evidence.

The public pending original is exactly body250 plus Ed25519 signature64 (314bytes). The sole purpose-specific private Rust encoder accepts stdin `KRAC01` (six ASCII bytes), body250 and the independently selected Ed25519 signer pin32 (288bytes), with its seed only through the inherited `--key-fd` descriptor. It returns the actual shared-model314-byte original. Public decoding or formatting is correlation only and never establishes issuer, platform, offline capability or financial authority. There is no old raw purpose, generic signing operation or alternate transport fallback. Native current owner and durable enrollment fences remain required before any key or attestation invocation; the model encoder alone does not implement those lifecycle calls.
