# SoraFS source-contract open work

The source-contract tests authenticate the exact path and marker text in
`fixtures/sorafs/source_contracts/open_work.tsv`. This is an inventory of
remaining work, not release or deployment evidence. A changed, new, or removed
marker requires updating the reviewed inventory. The tests independently reject
all three changes; they do not allow directory, prefix, or wildcard exemptions.

The September 30 review retains these implementation boundaries:

- Native release-manifest and role-16 topology authority, custody, Check proof,
  and operation producers remain incomplete. Admission and promotion stay closed
  until their purpose-owned adapters authenticate the required State and finality.
- Provider-ingest composers and completed-operation drivers remain test-only
  until authenticated archive, grant-resolver, signer, and supervision owners
  are joined. Receipt consumers and production state adapters remain open.
- JavaScript child, archive, package, qualification, runtime custody, and Python
  consumer artifact owners still require their retained producer and signed
  aggregate integration. Component coverage does not establish qualification.
- SDK governance action bodies and phone attestor pins still need their typed
  validation. Mixed-content files also contain unrelated bounded query, fanout,
  profile, memory-owner, and Taira Parliament work; the broad source scan records
  those markers without pretending they are completed SoraFS work.
- Configuration path defaults, release proof/work/RSS reports, governance-account
  registration, and production signing workflow qualification remain explicit
  implementation or deployment tasks.

Numeric Node test-runner `todo` counters are metadata, not work markers.
Removing incomplete-work markers without completing their work would conceal
blockers; no guard may require that.
