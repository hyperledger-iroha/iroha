# Fixed JavaScript child observation boundary

The five `scripts/sorafs_javascript_child*.mjs` input, load, session, entry and
bootstrap modules connect the existing Node 24 event, cache and snapshot owners.
This is a component boundary. The source-owned parent producer, original-index
adapter and actual installed SDK/native execution remain unfinished; no release
consumer accepts these observations as qualification.

The parent must retain the original package, nine dependency archives, candidate
source, clean native ABI23/checksum manifests, runtime and process inputs. It
holds the exact installed and qualification-source tree owners through execution.
An inherited private regular descriptor 3 contains canonical bounded input JSON;
argv contains only its independently retained SHA-256. The child keeps that
original descriptor, rejects malformed or noncanonical layouts and rechecks its
bytes and full stat identity before teardown. It never reopens a historical
producer input path.

The input has schema `sorafs.javascript.child_input.v1`, with exactly
`environmentRoot`, `temporaryRoot`, `native`, `catalog`, `source`, `installed`
and `tools`. Member rows are sorted `{path, sha256, size, mode}` records. Native
fields are `originalPath`, `sha256`, `size`, `checksumSha256`, `checksumSize`,
`sourceCommit`, `nativeSourceTreeSha256` and `workspaceSourceTreeSha256`.

The exact 191-file qualification core lives at `qualification/core`; the
separate eight-file tool extension lives at `qualification/tools`. It consists
of the five child modules plus `sorafs_javascript_test_events.mjs`,
`sorafs_javascript_native_cache.mjs` and `sorafs_javascript_child_files.mjs`.
Installed subjects resolve from the original `node_modules` projection through
four public exports and the two original private `dist/native.js` and
`dist/toriiTestHooks.js` modules. These tools do not widen the source-core census
or introduce public SDK test exports.

A private prepared session retains the genuine native cache and file owners
before installed imports. The normal installed loader must provide the actual
binding, verified clean commit/native-source relation, same-binding ABI23 and
required callable exports. Native bytes are compared through the existing
snapshot owner; the unlike workspace source domain remains a parent join.
All six unchanged registration functions receive their exact selected exports,
original fixture URLs, owned temporary root and actual native binding. The
orderbook suite's intentional mocks remain unchanged component assertions.

The fixed programmatic `node:test.run` uses one entry, `isolation: "none"` and
serial execution. One original final hook rechecks input/native/source owners.
The bootstrap consumes the actual structured stream through EOF with the
55-case event owner, demands the completed original hook, rechecks again, and
closes all retained owners before emitting an observation frame. Failed cleanup
cannot emit a success frame. Preparation is one-shot; no arbitrary subject,
case list, callback, filter or command is supplied by the input.

The synchronous load observer requires positive original source observations
for all six subjects and seven suite/helper modules plus the entry. CommonJS,
JSON, cached resolutions and builtins have explicit joins. Unknown URLs, changed
bytes, multiple loads, missing positives or loss of the actual native cache
refuse. Limits are 16,384 observer events and 4 MiB aggregate observation text;
these do not bound allocations made by Node before the observer receives data.

Hooks are observations, not a sandbox or mapped-code attestation. A later hook
can call the observer and then transform returned source; inert controls retain
that counterexample. Parent-authenticated bootstrap/candidate/runtime originals
remain necessary. Named file before/after observations supplement complete
parent tree custody and cannot prove absence of transient restored changes.
