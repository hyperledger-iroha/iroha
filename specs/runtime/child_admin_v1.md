# Independently governed data space roots

In SORA Nexus, an independently signed data space root can select the new
`iroha.runtime.child_admin.v1` service. This source addition preserves the
Universal root's SORA Parliament path and every installed baseline descriptor.
A data space catalog entry or validator key confers no administrator authority.

## Authority and foundation

The addition owns `world.runtime_child_admin_state`, a canonical cell containing
the full child network, parent network, full-width data space and native instance
identity, an explicit administrator policy, and the next certificate nonce.
Ordinary storage installation writes `None` and grants no authority. The selected
service refuses an absent policy, an unselected cell, or a foreign root.

A fresh child genesis can sign one canonical `runtime_child_foundation_v1`
parameter (`ChildRuntimeFoundationV1`). It contains the exact compiled foundation
selection and revision-one policy, without the eventual genesis hash. The fixed
foundation composes the baseline, lifecycle storage and child administration.
Only `AuthenticatedGenesisOutputSource` can select that original recipe. The
pristine genesis installer checks its signed child scope, actual genesis network,
exact source position, empty authority and expected selection before publishing
the initial State. A substituted source, duplicate recipe, Global scope or
different selection is refused. Failed later genesis execution discards the
entire unpublished overlay.

Genesis retains the original source capability through execution and requires
the final recipe, selection and initial authority to remain unchanged. Ordinary
parameter writes and executor data-model reconciliation cannot replace or remove
the founded child's recipe. The immutable recipe anchors the child's activated
selection history. Current policy rotation does not rewrite that anchor.

Snapshot decoding retains the exact current and predecessor administrator cells.
Both cuts validate the retained foundation and policy; the State restoration owner
also compares their network and native instance with the restored root. A baseline
snapshot omits this uninstalled cell and restores it empty. An installed cell is
required, and a local decoder refusal remains retryable without changing either cut.
These structural checks do not replace certified-history authentication.

This foundation applies only to new signed genesis sources. There is no live
initializer, reset-based upgrade or inferred adoption path for existing children.

## Administrative actions

`AuthorizeChildRuntimeActionV1` carries the complete exact action plan and
threshold certificate. The plan binds every root identity component, policy
digest and revision, next nonce, an inclusive first height, an exclusive expiry
height, and one action: schedule, cancel or rotate the administrator policy.
Administrators and signatures are strictly sorted and unique, bounded at 64.
Every supplied signature must verify; reaching threshold does not excuse an
invalid extra signature. Policy frames are bounded at 64 KiB; action certificates
at 8 MiB. Policy rotations advance the revision exactly once and never reset the
nonce. Exhausted counters refuse further actions.

Policy and plan identities stream their domain and canonical Norito frame into
the hash without retaining an encoded frame. Serializer scratch refusals retain
their original retry cause. Administrative signature preimages reserve their
complete domain and frame in the original allocation scope.

The new instruction must be the sole direct instruction of the original signed
native transaction. Any ordinarily admitted payer can relay it; the certificate
owns administrative authority. A private one-use source token binds the exact
outer transaction and instruction. VM effects, callbacks, deferred instructions,
captured obligations, substituted instructions and mixed instruction vectors do
not receive that authority. Local decoding or unavailable-crypto refusals retain
their original unfinished-execution cause.

Scheduling freezes the committed notice into the ordinary change-set record and
checks its block delay, declared provenance policy, projected predecessor,
successor closure, migrations and obligations. Activation still uses the existing
block-start engine, both committed-time notice bounds, and support from every
current validator. Rotation invalidates unsubmitted old-policy certificates;
already scheduled changes retain their original approval and may be cancelled.
Only a still-scheduled local change can be cancelled.

`AttestChildRuntimeSupportV1` records validator release support through its own
direct source. Administrator approval never substitutes for validator support,
and validator membership never substitutes for administrator approval. The
operator attestation route and CLI preserve the signed root in the instruction
family they draft and relay. Upgrade drafts use the founded child's exact scope.

## Qualification

The model, source-bound handlers, canonical State owner, genesis foundation,
lineage reader, queue scope, support-draft integration and snapshot checks are implemented
in source. Current-candidate compilation and execution, the authored snapshot/current-and-undo
regressions, full four-validator governed journeys, restart and every-root
retirement evidence remain required. Component fixtures that populate a World
exercise those components only; they do not establish signed-genesis or network
qualification.
