# Experimental device runtime fixture

This standalone crate links the current canonical Rust provider and complete experimental engine. It is installed only in disposable test application namespaces. Its public fixture issuer keys and synthetic ledger events cannot select production funds.

`./build-apple.sh` builds the real iPhone static archive in the persistent `target/aarch64-apple-ios/release/` lane. The explicit iOS 18 deployment floor applies to Rust and C dependencies. The Apple app project lives in `../ios/runtime-project.yml`; it consumes `SPARTAN_DEVICE_ARCHIVE` and `SPARTAN_DEVICE_ARTIFACTS`. The C callbacks are specified in `spartan_device_fixture.h`.

The final host recursive-chain test emits `program-bundle.norito`, `parameter-manifest.norito`, and `parameter-signature.bin` when `KAGEMUSHA_SPARTAN_DEVICE_ARTIFACTS` names an output directory. They contain the actual eight fixed-point verifier programs and independent fixture-root authentication. No placeholder artifact is accepted.

The run performs real native enrollment custody and existing Ed25519 account admission, actual hardware Bootstrap, restart recovery, a fixture-genesis BLS-certified synthetic Load100 event, hardware-signed Request, a self-Send10 confirmed through the platform authentication UI, complete Payment verification, Receive, and exact outgoing retry. Each operation checks retained custody before preparing. Re-running after process termination must return the same retained Payment without another Send. The generated `complete-payment.bin` is the complete peer object; its actual size is reported separately from performance or qualification claims.

The installed experimental profile contains Bootstrap, Load, Send, and Receive. Its Bootstrap initializes spending controls and the time-anchor commitment to zero, and those four operations cannot enable or refresh them. This fixture therefore exercises controls-off Send with the native floor-derived interval. Controls-on arithmetic exists in the relation, but a reachable controls-on wallet requires additional authenticated RefreshPolicy and RefreshTimeAnchor operations plus protected direct-time custody; this fixture does not claim that integration or accept a caller-supplied clock.

Apple E5 uses the real App Attest service and key-binding assertion, with effect dispatches and returned originals retained through the actual EnrollmentOwner. Android uses the actual nonexportable hardware key and its original KeyMint attestation chain. This fixture issuer **does not independently verify FI attestation policy before signing E6**. Therefore these runs test native proof/key custody and recovery, not production FI admission, pinned-root/revocation qualification, or physical cross-device payment. The separate host chain covers two wallet identities. No successful full device run is claimed until its actual output is preserved.

Android instrumentation entry: `KagemushaSpartanRuntimeDeviceTest`. Package the actual `libkagemusha_spartan_device_fixture.so` as an androidTest JNI library and the three programs under androidTest assets `spartan-artifacts/`. Use the explicit disposable application namespace through the existing `kagemushaEnrollmentProbeApplicationId` test property. The dedicated nonexported Activity invokes Android strong biometric or device-credential authentication over the exact Native review before Send. It never accepts an app PIN or an injected success flag.
